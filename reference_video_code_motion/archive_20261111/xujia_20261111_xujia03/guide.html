03｜App图标与人物模型的分界，是工具能力的硬边界吗？

不是。Blender是建模/动画/渲染工具，Three.js是浏览器三维库，两者可以协作而非二选一。简单厚片图标可由几何体、圆角轮廓或贴图平面表达；复杂人物涉及拓扑、骨骼和权重，适合专用内容工具，但已有GLB人物同样可在Three.js播放。onetake的3d.md案例恰是Blender建模导出GLB、Three.js布光与逐帧渲染。人物级只是经验法则，不是官方限制。

本次未运行Blender或Three.js，实际成片是原创CPU透视面片实验。

04｜倾斜的App截图，为什么也能显出“3D感”？

透视投影让近物变大、远物缩小；相机、平面的位置和旋转变化就能形成纵深。单张界面贴到一个面上常叫2.5D：有空间运动，但并没有补出截图背后的真实结构。练习用8顶点厚片，旋转后按x_screen=cx+f·x/(d−z)投影，再由远到近绘面。图标符号与厚片共用变换，所以会随正面一起转动；它不是把平面效果冒充人物重建。

d−z须大于0；简易画家排序不等于生产级深度缓冲/PBR。

渐进问答 05—06

05｜“不用关键帧，用函数”真的完全没有关键时刻吗？

没有手工拖关键帧，不等于没有时间控制点。Blender官方手册将关键帧定义为在某时刻存属性值；代码可以用关键时间+插值函数表达同一件事。关键进步是整个状态由t直接算出，而非每帧x+=v·dt累计。本练习的pose(t)只依赖t，顺序和逆序寻址结果一致；smoothstep(u)=3u²−2u³使区间两端速度为0。它适合可控动效，但不是通用真实物理模拟。

已测乱序寻址一致；控制点与插值存在，不能宣传“没有任何关键时刻”。

06｜onetake的渲染脚本到底依赖页面提供什么？

固定候选render.py先用Playwright打开合成HTML，等待window.__ready，再按每帧时刻调用并等待window.__seek(t)；时长可由window.__meta.dur声明，__motion(t0,t1)可提供屏幕运动估计。__ready必须覆盖字体、贴图与模型解码；__seek完成必须意味着本帧已绘制，而不是只改了状态变量。若调用先后影响画面，并行分帧和子帧模糊都会错。接口存在也不等于其语义已通过实测。

渐进问答 07—08

07｜节奏、连续运镜与“像PPT”，是同一个指标吗？

不是。节奏看快慢、停顿、爆发；carry指跨段仍存续并驱动下一段的对象或因果。onetake的rhythm.md公开案例里，节奏检查全过的片仍被人拒绝为PPT，因为每段只是替换下一张图。练习用同一个图标贯穿入场、停留、旋转、回位：时段约1.2/1.9/5/2.7/1.8秒，长短比4.17；边界参数差最大1.69×10⁻⁵。但这些只是结构与数值，不等于真人认为有节奏或有创意。

不执行上游oracle，不报告carry分数，也不把参数连续等同叙事连续。

08｜运动模糊为什么不能简单加一个模糊滤镜？

快门积分是曝光期间物体在多个位置贡献光，而高斯模糊只是对一张静帧做空间平均。180°快门在24fps下曝光1/48秒；练习在窗口内4次寻址同一场景，再在线性光中平均，实际生成312帧。onetake会参考__motion自适应样本数、识别静止跳过重复截图，并在硬切边界只选同侧子样本。本练习是固定4采样连续场景，不含自适应或硬切检测，快动作仍可能出现离散重影。

已执行CPU四采样；不能把这个缩小实验称为完整onetake实现。

渐进问答 09—10

09｜同样黑白各一半，为什么平均不是128？

sRGB的数字不是线性光强。对0与255直接平均得到128，会把本应等能量的曝光压暗。正确流程是先解码sRGB到线性光，求均值0.5，再编码回sRGB，结果约188。本次断言实得188，对照数值128。这个实验验证颜色空间处理，不证明整个成片颜色校准、显示器或HDR输出正确；若混合预乘Alpha、色调映射等，还要按真实管线处理。

使用标准sRGB分段传递函数，不是简单“gamma=2.2”近似。

10｜“配乐和节奏由代码完成”如何让音画不各跑各的？

把事件放进同一BEATS表：enter/land/orbit/reframe/settle时刻同时驱动pose(t)的分段与音效采样位置。音频样本索引round(t·48000)，视频帧数由13·24得312。练习原创衰减正弦音效与谐波底床，624000个PCM样本、峰值0.452683、削波0；5个事件恰好落在样本网格，量化误差0。视频24fps最近帧量化最大约16.67ms；真实AAC编码、播放设备延迟和真人听感是另外的验收，不能宣称“听觉零延迟”或原片同款音乐。

音频与视频FFprobe均13秒，完整解码无报错；没有试听认证或BPM推断。

五个用途与不适用范围

  1. 应用图标短片：由一个图标的入场/旋转/回位学习透视和时间线，不必先建立复杂人物模型。
  2. 产品功能演示：把UI变化、镜头与点击声写进共享事件表，避免画面和音效分别手调后漂移；真实UI需使用获授权素材。
  3. 批量尺寸与文案变体：同一f(t)和事件逻辑替换内容，逐变体检查可读性与边界；不是承诺自动完成本地化。
  4. 渲染回归测试：随机抽时刻、反序seek、计帧和解码；同时保留实际图像，不能只信页面自报通过。
  5. 技术/许可评审：区分模型产码、资产工具、渲染器与商用授权；不要把Apple Metal参数或作者性能搬到Linux。
