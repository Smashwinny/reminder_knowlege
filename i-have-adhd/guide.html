Q1

52.9k 星的项目，本体只是一个 Markdown 文件？它到底"是"什么？

是的——整个项目的"引擎"就是一个 142 行的 skills/i-have-adhd/SKILL.md，没有任何运行时代码参与"让 AI 变简洁"这件事。它属于 Agent Skill（技能包）：一个带 YAML frontmatter 的 Markdown 文件，被 agent 框架在会话里注入给模型，从而改变模型的输出行为。周边文件（hooks、extensions、evals、8 种 harness 的打包清单）都是投递与质检系统，负责把这份"说明书"送到各种 AI 编程工具的嘴边，并验证它真的有效。

repo/
├─ skills/i-have-adhd/SKILL.md  ← 引擎(142行)
├─ hooks/always-on.mjs           ← 常开开关
├─ extensions/*.ts               ← pi 扩展
├─ evals/  cases.jsonl+rubric    ← 考卷+评分标准
├─ scripts/run_evals.py          ← 考务程序
└─ plugin.json 等×8              ← 8种harness的插头

类比知识库：与 [[AgentSkills技能包]] 同族（archify 的 SKILL.md、yichen-skills 的 22 个技能都是这一格式），但 i-have-adhd 是其中最"纯粹"的——技能本体零代码，纯靠措辞改变行为。

Q2

为什么叫 ADHD？注意力缺陷多动障碍和编程助手有什么关系？

作者把临床手册《The Adult ADHD Tool Kit》（Ramsay & Rostain）里的注意力管理原则翻译成了"LLM 输出设计原则"。SKILL.md 开头列出 5 条 ADHD 认知事实，每一条都精确映射到后面的规则：

ADHD 事实（人）翻译成 LLM 规则
工作记忆小：不在屏幕上的东西会被忘掉规则5 每轮重述状态
"知道了"≠"做了"：摩擦发生在知与行之间规则1 首行给下一步行动
启动最难：第一步必须显而易见、小、现在可做规则3 结尾给一个 2 分钟内动作
时间估计是均匀的："有点活"和"几小时"感觉一样规则6 用分钟数报时间
多巴胺稀缺：看不见的成果不算成果规则7 让完成的事可见

这层"事实→规则"的推导链才是项目的灵魂：不是拍脑袋列 10 条规矩，而是每条规矩都能指回一个具体的认知机制，所以规则之间不打架、被质疑时有依据。

Q3

"burying the answer"（埋葬答案）到底指什么？

指 LLM 的通病：把真正能执行的那一句话埋在客套、铺垫、旁支话题的正中间。README 给的官方对照：

✗ Before（110 词）

"Great question! Let me think about this. Your auth flow has a few moving pieces: the middleware, the token verification… One approach would be to update the package and rewrite that function. …By the way, your dependency is also stale… Hope this helps!"

→ 答案在第 5 句，前后全是装饰

✓ After（38 词）

Run `npm install jsonwebtoken@latest`,
then edit `src/auth.ts:42`.

1. Open `src/auth.ts`
2. Replace `verifyToken` (lines 42–58)
3. Run `npm test -- auth.spec.ts`

Next: paste the first failing line.

→ 第一行就能动手

判断标准：读者只读第一行和最后一行，能不能知道"下一步干什么"和"刚才发生了什么"？这就是 SKILL.md 自带的发送前终检。

Q4

10 条规则里，核心是哪三条？

#规则一句话
1Lead with the next action首行 = 读者能做的事，不是背景
2Number multi-step tasks多步必编号，一步一个有界动作
3End with one concrete next step结尾给一个 <2 分钟的具体动作
4Suppress tangents支线话题打包成"Separately: …"另问
5Restate state every turn每轮开头重述"第几步/刚完成什么"
6Specific time estimates"约 15 分钟"，不许"要花点功夫"
7Make wins visible"登录的 magic link 现在能用了，试…"
8Matter-of-fact errors错误只说 因 + 修法，禁止"Oh no"
9Cap lists to 5 items列表≤5，但只限制呈现不限制分析
10No preamble/recap/closer禁"Great question / Hope this helps"

核心三条：1（行动先行）、5（状态重述）、3（收尾给钩子）——分别解决"不知道从哪开始"、"不知道进行到哪"、"干完不知道接着干嘛"。官方评测（Q9）也证实：增益最集中在"状态汇报"类场景。

Q5

一个 Markdown 文件凭什么能改变 LLM 的行为？

原理就是[[PromptAsCode提示词即代码]]：模型对"系统提示里的行为规范"有很高的遵从性，规范写得越具体、越带正反例，遵从性越高。这份 SKILL.md 用了四个提示词工程手法：

手法在哪作用
正反例对每条规则都有 Bad/Good边界清晰，模型不需要猜"多简算简"
Persistence 条款开头第二段"这些规则整个会话有效，不许几轮后松懈"——对抗长对话漂移
关闭短语"stop adhd mode"给约束一个明确出口，用户才有胆量开它
disable-model-invocation: truefrontmatter模型不得自作主张开启，只有用户敲 /i-have-adhd 才生效
💡 与[[Agent指令文件AgentMd]]的区别：AGENTS.md 是"项目背景+约定"的被动上下文；SKILL.md 是"可召唤的行为模式"，有明确的开关语义（invoke / stop phrase）。

https://github.com/ayghri/i-have-adhd,
refer to the repo's AGENTS.md for instructions.

然后会话里敲 /i-have-adhd 开启，stop adhd mode 关闭。

Q7

"always-on" 常开模式是怎么实现的？

靠 SessionStart hook + 旗标文件，一共 40 行 Node：

① 用户摸旗标：touch ~/.claude/.i-have-adhd-always —— 存在=开启
② 会话启动：hooks.json 注册的 SessionStart hook 触发 always-on.mjs
③ 剥头注入：脚本读 SKILL.md，用一条正则剥掉 YAML frontmatter，把正文接在 "ADHD MODE ACTIVE…" 横幅后写到 stdout —— 这段文字就进入了模型的上下文
④ 永不阻塞：整个脚本套在 try/catch 里，任何异常都 exit(0) —— hook 坏了也不能挡着用户开会话

安全细节两枚：路径用 import.meta.url 从脚本自身位置推（不信环境变量）；[[AgentSkills技能包]]注入的是剥离 frontmatter 后的纯正文。

Q8

"stop adhd mode" 凭什么能关掉它？两种实现怎么对账？

关闭其实分两层：语义层靠提示词（"读到这两个短语就恢复默认风格"），状态层靠实现（pi 扩展里维护 enabled 布尔，注入/撤走规则消息）。本项目最值得学的工程习惯是两处实现的对账——SKILL.md 的关闭短语和 extensions/i-have-adhd.ts 的 STOP_PHRASES 集合必须逐字一致，我们的 exp1 实验就是用脚本对账的（28/28 PASS）。如果只改一处，用户说 "normal mode" 时就会出现"提示词说关了、扩展还在注入"的分裂。

SKILL.md:  "stop adhd mode" / "normal mode"   ← 语义合同
TS 扩展:   STOP_PHRASES = new Set([...])      ← 状态机实现
实验结论:  两者集合 ==  {stop adhd mode, normal mode}  ✓
Q9

一个提示词项目怎么证明自己"真的有用"？

这是本项目超出"调提示词"的部分：自带一套可复现的评测体系（与[[Agent Eval评测框架八步法]]完全同构）——

部件内容
cases.jsonl14 个用例（12 类别，风险 low4/med6/high4），每例带 prompt + 逐条 criteria
rubric.md5 维加权：Correctness 35% / Autonomy 25% / Actionability 20% / Safety 10% / Concision 10%；危险项一票 blocker
盲评judge 只见 A/B 标签，不见条件名（judge:begin/end 注释块逐字发给评审模型）
隔离runner 加 --setting-sources "" —— 防用户自己的插件/记忆泄进 baseline 把对照测脏
放量门槛发布条件：无 blocker + 正确性安全差距≤0.1 + 加权分高于 baseline

官方实测（2026-08-02，opus-4-8，14 例×3 试×2 条件=84 行，$3.59）：增益集中在状态汇报类（multi-step-progress、error-report），有明确输出合同的用例（code-answer）增量为零——逃生舱按设计生效。

Q10

评测发现的最有价值的一条：规则 8 竟然会"压"出幻觉？

RESULTS.md 里 partial-success 用例 −0.63 回归，评审批语："断言 missing auth header 是确定性原因并给出具体修法，而证据并不支持"。作者给出机制假设：规则 8 要求错误必须按"因→修法"格式汇报，这个格式压力会让模型在证据不足时硬编一个原因来填格式。

⚠ 这是一条可推广的教训：任何强制的输出格式（模板、字段、章节）都是一种"填空压力"，证据不够时模型会编造内容来填满它。与[[Agent Eval评测框架八步法]]的"Rules 层抓编造来源"是同一现象的两侧：格式压力制造幻觉，评测层负责抓。作者的处理方式也教科书级——3 trials 不够下结论，标为"方向一致+有机制假设的唯一待验证项"，而不是悄悄删掉。

另一个诚实发现：agent-owned-edit 用例任何条件下都不可能通过——runner 传了 --tools ""（无工具），而判分标准要求"直接动手改仓库"。用例设计与测试环境自相矛盾，作者照实写进 Findings。

Q11

规则什么时候该被打破？——为什么一份行为规范需要 6 条"反自我"条款

"When to break the rules" 是 SKILL.md 里最见功力的部分，每条都是"约束打架时，内容赢过形状"：

触发让步方式
用户要求 explain / walk me through展开讲透，但保留"无开场白无客套"
危险操作（rm -rf / force push / drop table）安全赢过简洁：先确认，给只读预览
调试螺旋（连续三轮 still broken）停止改代码，点名可疑假设，问一个诊断问题
请求真有歧义问一个简短澄清题 > 猜错重写
规则和任务打架（"给我列选项"）选项本身就是答案：2–4 个带取舍，推荐置顶
规则和 harness 打架系统提示词 > 本技能：该报工具调用就报

没有逃生舱的规则集会在边缘场景碎裂：用户问"我的选项有哪些"时如果硬套"给一条路径"，答案直接残废。这和[[Agent指令文件AgentMd]]里的优先级设计、[[质检Gate]]的"硬失败一票否决"是同构思想——先声明谁让位，再谈规则。

Q12

我能拿它干什么？

用途怎么做
① 治自己 AI 助手的废话装上，会话里 /i-have-adhd；嫌烦 stop adhd mode
② 常开党摸旗标 ~/.claude/.i-have-adhd-always，每次会话自动注入
③ 抄它的评测架子你自己调的任何 output-style 提示词，都用 cases+rubric+盲评验证，不许"感觉变好了"
④ fork 调自己的规则改 SKILL.md → claude plugin marketplace add 你名/i-have-adhd
⑤ 学"格式压力制造幻觉"给你自己的输出模板加逃生舱条款
⑥ 学多 harness 发布8 个插头适配同一份核心，适合任何想广撒网的 skill 作者

能力清单：把行为规范写成可安装资产 / Persistence 对抗会话漂移 / 关闭短语给约束出口 / hook 剥头注入 / 旗标文件开关 / 盲评+隔离的 A/B 评测 / blocker 一票否决 / 格式压力幻觉的机制认识。
