Q1

ChatGPT Dots 是什么？一句话能说清吗？

OpenAI 的常驻 Agent：每个 dot 有云端电脑和浏览器，个人设备离线时云端工作可继续。2026-11-22 当前文档已非“只用 GPT-6 Astra”：不同任务部分可用不同前沿模型，GPT-6.1 Terra 正在加入。可连接多台个人电脑，但每个线程一次使用一台。

Q2

任务到底在哪执行？三个位置要分清

执行位置条件边界
云端电脑无（默认常驻）不自动继承本机登录态；离线继续工作
本机电脑每台需本机授权；使用时在线+ChatGPT 应用开启可连接多台；每线程一次一台，云浏览器不继承本机登录
派生任务（Work/Codex）各自产品额度Dot 对话不占 ChatGPT 限额，派生任务各自计费

官方明确：消息渠道、插件权限、电脑连接分别管理——一个授权不代表另一个。这和 [[沙箱与审批正交]] 是同一架构语言。

Q3

本地交接协议：真实 JSON 快照与审计

官方边界：当前页面描述 Take over / Return control 和云端状态保留，但没有文档化快照创建、恢复或回滚。以下快照、红线与 JSON 落盘全部是本地自写协议。

Q7

给常驻 Agent 岗位的三条通用纪律（跨产品可用）

  1. 执行位置声明：每个任务标注在云还是本机跑，边界不同；
  2. 交接留痕：每次 takeover/handback 写一条审计记录；
  3. 停止条件前置：红线动作（付款/删除/外发）写进岗位契约，任何状态直达 STOP。
Q8

与 vault 定时分类职责的对照

本仓库的租约可用于对照“执行位置与控制权”，但规则不能写错：过期租约是保护/待续租状态，不等于任务完成；ready 项只能续租或自然过期，不能 release 清空。任务完成只由用户本人点击。产品形态不同，只能局部类比，不能把仓库协议说成 Dots 实现。

一页总结

  • Dots=多模型常驻 Agent：云端常驻+可连多台本机，每线程一次一台；
  • 执行位置三分类：云/本机/派生，边界与计费各不同；
  • 本地交接协议：真实 JSON 留痕/快照，但不冒充官方快照功能；
  • 授权分面管理：一个授权≠全部授权；
  • 纪律只能局部类比：过期租约≠完成，ready 不 release，用户才点完成。
