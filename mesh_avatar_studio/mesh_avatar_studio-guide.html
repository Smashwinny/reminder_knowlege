Q2人机怎么分工？（最有意思的设计）

Q3docs/agent-guide.md——写给 agent 的 201 行作业指导书

这是本仓库最值得学的文件：一份完整的"给 coding agent 的生产级任务书"。要点：① 顺序执行+每步带检查（"不要跳过检查：结果质量取决于查看你自己的输出并修正"）；② 模型资质声明——先告诉用户自己是什么模型，不在推荐清单（Claude Opus 5.5 / GPT-6.1 Sol）里就明说"可能不达标"并询问是否继续；③ 项目存 projects/<name>/ 永不提交。与 SKILL.md（路由型）、agent-guide（作业型）构成 agent 指令文件的两种体裁。

Q4视觉自检 calibration——agent 先证明自己看得准

开工前强制跑 tools/vision-check.py：生成带编号标记的标定图 → agent 读图写 JSON 答案 → 评分。分数不达标就停下告诉用户"这个模型读坐标可能偏，后面大部分工作要手工修"。这是"能力前置验证"模式：不让 agent 直接开干再返工，而是先量化它的视觉能力是否够格——把返工成本变成 10 秒标定测试。

Q5编辑器微调：拖点即所见

人工步骤全是"看+拖"：左侧选部件 → 图上高亮该部件的关键点 → 拖到对的位置 → 右侧预览实时跟新。眼睛/手部轮廓、头发遮罩区域等值还决定图层切割方式——改了会弹横幅"保存并重建图层"（几秒）。口型检查（Lip sync）按元音口形核对。设计哲学：AI 产出的几何误差，用最直觉的拖拽交互收敛。

Q7边界与风险（诚实清单）

① 效果依赖强视觉模型（官方仅认证 Opus 5.5 / GPT-6.1 Sol 两档）；② 最佳输入限制严格（正面半身透明底 PNG）；③ Windows 有专门章节的坑（ZIP 解锁/projects 目录权限继承）；④ 5 个测试在无 symlink 权限的 Windows 上失败（见 Q10）；⑤ e2e 需要 Playwright 浏览器，本机未跑。

Q9这个项目给我什么（能力清单）

① 人机四步管线：Agent→人查→人修→Agent 的审核式分工模板。
② 能力前置验证：vision-check 把"模型行不行"变成开工前的标定分。
③ agent 作业书体裁：顺序+检查+资质声明的 201 行范本。
④ 2D 网格动画机理：切层+关键点+物理摆动的 Live2D 平替实现。
⑤ 路径安全测试法：用 symlink 构造攻击样本测自己的 API。
⑥ 许可分层意识：代码 MIT 但角色资产单独保留的边界写法。
