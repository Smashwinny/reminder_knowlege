# Windows 手动同步 Dot 学习成果

在仓库根目录双击 `sync-reminder.cmd`，或者在 PowerShell 执行：

```powershell
cd F:\reminder
.\tools\reminder_manual_sync.ps1
```

这一轮先读取本人已配置的 Reminder 账户和清单，分页下载真实网站报告，校验原记录版本及六类产物的 SHA256，保存到 `完成/.pipeline/dot/`。同时将完整报告的 PDF、HTML、练习 ZIP、实测日志、云端知识提案和云端审核复制到普通可见目录 `完成/云端学习备份/日期/项目名/`，打开其中的 `README.md` 即可查看每份 PDF 和实际 Git 状态。可见目录也属于私有备份，不直接提交 Git；正式入库后仍沿用原项目/vault 目录。失败时保留云端和本机原件，不使用旧缓存冒充本次同步成功。重复执行不重复创建报告，用户修改过的副本不覆盖。

随后处理协调者登记的公开文件清单，自动提交并推送到 `Smashwinny/reminder_knowlege`，再回读远端确认。每批文件都有审核时的 SHA256；文件改动、来源变化、验收失效、其他 owner 或未知暂存都会停止该批 Git 同步。推送失败保留本地提交，下次重试，不重新创建同一提交。不自动 rebase、reset、强推或跳过 hooks。

Git 使用独立的 `完成/.pipeline/knowledge-publication` 工作区，主工作区未提交改动保留。主工作区暂存区非空时先停止 Git，需协调者核清归属。私密原记录、初步分类报告、凭据和运行数据库不提交。首次 Git 同步需要已登录的 Git 凭据；程序不显示令牌，不交互索要密码。

脚本不运行模型，不代替独立内容审核，不自动合并 Obsidian 笔记，不修改网站任务完成状态。尚未审核/入库的完整报告会计入待办，用户无需逐条授权；协调者应在验收、入库后及时登记文件清单，随后同一个手动入口完成 Git 备份。

同步结果：`完成/.pipeline/手动同步结果.md`；机器状态：`完成/.pipeline/manual-sync-status.json`。两者均为本机私有文件。`knowledgePending` 和 `gitPending` 非零表示还有收尾工作，`local=verified` 只表示原件校验通过。

只拉取、不进行 Git：

```powershell
.\tools\reminder_manual_sync.ps1 -LocalOnly
```

查看上次结果，不连接网络：

```powershell
.\tools\reminder_manual_sync.ps1 -StatusOnly
```

## 协调者如何登记 Git 文件清单

这一步由已完成实际审阅的唯一协调者操作，不交给用户逐条选择。沿用共享队列的 start → ready → 独立 review → confirm-analysis；完成 learn-project 第 8 步并在原 `handoff.json` 标记 knowledge=merged。清单必须包含指南 PDF、HTML、实测日志、已合并项目笔记、知识总览，以及本次练习和概念增补文件。

把本批次已经检查没有私密原记录的**逐文件相对路径**写入私有文本文件，每行一个，不写目录或通配符，然后：

```powershell
python -X utf8 tools/reminder_manual_sync.py prepare `
  --task TASK_UUID `
  --files-file 完成/.pipeline/public-files.txt `
  --message "learn: 项目指南、实验与知识入库" `
  --review-notes "实际审阅的页数、实测证据、知识查重和隐私检查结论"
.\tools\reminder_manual_sync.ps1
```

`TASK_UUID` 是已验收原队列任务 ID；一次可多次指定 `--task`。登记不会自动把未验收项目变成已验收。同步时再次核对本次网站真值、原队列审核和文件指纹。回执留在 `完成/.pipeline/git-publications/`，这是 Git 交接记录，不是第二套学习任务队列。

工具代码的备份使用 `prepare --maintenance`，只允许明确的 `tools/` 文件、根目录 `sync-reminder.cmd` 和 `.gitattributes`，同样必须填写实际审阅说明；不关联或伪造学习完成。

已有登录备份任务和 Dot 云端日程保持原设置，新增入口由本人手动运行。
