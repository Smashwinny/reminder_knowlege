# 云端交付与本机同步

2026-10-06 分工更新：Dot 唯一协调者直接通过自己已授权的 GitHub 连接完成知识合并、独立审核与公开学习成果提交/推送。Ubuntu 只维护网站授权、私有报告和处理状态；下文的服务器 delivery 回执消费是已开发的可选路径，生产发布器未启用，不是学习收尾前置条件。

Dot 直连 Git 与 Windows 回读仍待真实端到端验收。现有默认脚本已增加下面的直连成果清单核验；代码/本地夹具测试通过不等于本人的真实成果已同步。保持原项目布局、原 vault 和本机冲突保护，不重新学习或抢旧 owner。云端执行规范见 `../reminder-dot/cloud-reference/RUNNING_IN_DOT.md`。

直连 Git 模式不依赖网站新接口：从真实网站备份 full 原件，再从固定公开仓库 main 查找 `<项目>/delivery/publication-manifest.json`。该清单不含网站私有身份，使用 `reminder-learning-publication-v1`、基线 commit、确切文件/哈希、六类原件哈希与独立审核日志路径；审核须在云端发布前真实完成，Git 字节核验本身不代替内容审核。脚本找到真正修改该清单的提交，核对父基线、提交不夹带清单外文件、六原件绑定及所有公开文件的实际 Git 字节后，单独记录 `dotDirectGit`，不伪造网站 cloudDelivery 回执。公开版可清理私密上下文，私有原六件保持原样。网站未部署的 delivery 工具不会在此路径被调用。

用户已授权的新架构将知识合并和 Git 收尾移到云端。本机不再需要唤醒某个 Codex 聊天才能完成云端发布。
当前是开发/待部署阶段；原学习报告仍可正常备份。没有实际 cloud delivery pushed 回执，脚本不会把旧报告认定为已推送。

Windows 可双击根目录 `sync-reminder.cmd`，或在 F:\reminder 执行：

```powershell
powershell -NoProfile -File .\tools\reminder_manual_sync.ps1
# Python PATH 不可用时，指定真实 Python 3.10+：
powershell -NoProfile -File .\tools\reminder_manual_sync.ps1 -PythonPath 'C:\实际安装目录\python.exe'
# 只备份私有网站原件，完全不访问 Git：
powershell -NoProfile -File .\tools\reminder_manual_sync.ps1 -LocalOnly
```

使用既有私有配置 `完成/.pipeline/dot-backup-config.json` 中的已确认 accountId/listId，以及 `SHIYI_TOKEN` 或 `tools/.shiyi_token`。令牌不写命令行、日志或公开 Git。配置缺失则不访问网站。

默认入口执行 `reminder_manual_sync.py sync --cloud-only`：

1. 从真实网站分页拉回当前列表报告，验证来源/报告/六原件哈希，保存私有原件。
2. 已有完整报告附带 pushed 回执时，从固定公开知识仓库只读获取实际提交，验证 main 包含提交、文件及基线 SHA256、原 PDF/HTML/日志绑定。
3. 在原协调者锁与备份锁内复制到原项目目录和 vault。只更新明确文件；保留上一版本到私有撤销目录。已有笔记必须仍等于已确认的 Git 版本才可更新，手改笔记写 conflict，不覆盖。
4. 分别记网站、原件、本机知识、云端知识与 Git 状态。失败保留原件和重试状态，不运行学习、不修改 task.state、不释放旧任务 owner、不提交或推送 Git。
5. 核验六原件及实际备份归档后，向限定网站列表发送本机备份回执；只传哈希与阶段。网站记录为客户端已校验，不能冒称服务器访问过电脑。回执失败单独记待确认，不否定已核验的 Git 与本机副本。

多份报告连续合并 MOC 时，按真实 Git 祖先关系只同步最新被审核版本，旧回执保持可追溯。不能把“网站声称 pushed”或本地缓存当作实际 Git 证据。

原共享队列仍有 task/project owner 时，项目与知识覆盖保留待处理；只读备份和已验证云端 Git 状态仍可记录。必须由原协调者核验旧票后明确交接，脚本不会释放、抢占或以网站 full 替代原 owner 的审核手续。

原件/PDF 入口：`完成/云端学习备份/README.md`。阶段与冲突：`完成/.pipeline/手动同步结果.md`、`manual-sync-status.json` 和 `dot/<账户>/<列表>/handoff.json`。公开成果进入原项目目录，Obsidian 打开原 `vault/` 即可；此同步不另建知识库、不生成新复习计划。

已有 Windows 登录备份 job 使用同一默认同步入口；不新增周期分析任务。电脑离线时原件留网站，云端成功发布后电脑再上线拉取。原本机发布模式仅 `-LegacyLocalPublisher` 显式启用，仍要求唯一协调者真实验收/知识合并、逐文件登记及明确公开授权；它不是新默认模式。

服务器详细配置、增量 OAuth、MCP Events 订阅与验收：`reminder-dot/repo/docs/CLOUD_DELIVERY.md`。本机工具改动与服务器变更分别管理；不能为备份工具而顺带上传尚未授权的私有历史。
