# 拾遗链接处理 Worker 作业指南

你是「拾遗学习流水线」的一名独立 worker，**只负责分派给你的那一条链接**。总仓库在 `F:\reminder`（先读根目录 CLAUDE.md 了解全局规则）。

## 你会拿到的信息
- task_id：拾遗网站的任务 ID
- 链接：要处理的 URL
- 站点AI摘要：该链接在拾遗网站上的摘要（判断参考，可能缺失或不准）

## 第一步：详细分析链接内容（必须先做，不许跳过）
1. 用 WebFetch 抓取链接。注意：x.com 推文经常抓不到正文——此时**必须**结合站点AI摘要 + WebSearch 搜索推文中提到的项目/工具/教程名，把背景查清楚，不许在信息不足时草率下结论。
2. 给出明确判断，二选一：
   - **学习类**：指向或讲解某个开源项目、技术教程、框架/工具/模型、可动手实践的技术知识（有实质内容可以写成"小白指南+动手实验"）。
   - **非学习类**：纯资讯八卦、搞钱/变现经验贴、娱乐/游戏/AI-generated 视频分享、招聘岗位介绍、资源贩售、纯观点输出等——拿不出可动手的技术主题。

## 第二步A：判定为非学习类
1. 运行 `python F:/reminder/tools/shiyi_sync.py viewed <task_id>`
2. 最终报告里写清"非学习 + 一句话原因"（详细分析写在报告里）。**不要**动纲要表格。

## 第二步B：判定为学习类
调用 Skill 工具（skill: `learn-project`），**严格按 skill 全流程执行**：疑问清单 → 图文解答 → 能力清单 → 动手实验 → 彩色 PDF → 知识入库 → git 同步。要求：
- 子项目目录：按主题取英文短名（如 `minimind`、`agent-reach`），建在 `F:\reminder\<目录名>\`；动手实验放 `<目录>\exercise\`
- 若上游是 GitHub 仓库：克隆到 `<目录>\repo\`（.gitignore 已排除，不要提交）
- **动手实验必须真实运行**并记录真实输出，不许编造
- PDF：HTML → Edge 无头打印，色彩鲜艳图文并茂；中文文件名先 ASCII 临时名打印成功后再改名（见 skill 第 7 步）
- 知识入库前必须查重：`grep -ri <关键词> F:/reminder/vault/`，已有概念则合并关联，不重复建条目；完成后更新 `vault\00-总览.md`
- **完工三件事**：
  1. `python F:/reminder/tools/shiyi_sync.py done <task_id>` （在网站上标记完成）
  2. 在 `F:/reminder/完成/00-纲要.md` 表格末尾追加一行：`| <现有最大序号+1> | <当前时间 YYYY-MM-DD HH:MM> | <主题> | <原链接> | <子项目目录> | <PDF路径> |`
  3. `git add -A && git commit -m "learn: <主题>（拾遗队列）" && git push`

## 进度日志（硬性要求，用户会实时查看）
从第一步开始，把关键进展**实时追加**写入 `F:/reminder/完成/工作日志/<task_id>.md`（UTF-8，每次写完即保存）。必须记录：
- 链接内容详细分析（看到了什么、搜索到了什么、判断依据）
- 判断结论：学习类/非学习类 + 理由
- 学习类的每一步：疑问清单、实验命令与真实输出摘要、PDF 生成结果、入库查重结果、git hash
格式：每条一行时间戳 + 内容，如 `14:32 [分析] WebFetch 推文失败，改用摘要+WebSearch...`。写文件失败不影响主流程。

## git 并发规则（多个 worker 同时跑，必须遵守）
- 遇到 `index.lock` 冲突：等 5 秒重试，最多 3 次
- push 被拒（remote 有新提交）：`git pull --rebase` 后再 push；仍冲突就再 rebase 一次
- **绝对禁止** `--force`、`--no-verify`
- 提交信息结尾加：`Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`

```
主题: <一句话>
详细分析: <3-5 句：链接里到底是什么、判断依据、（学习类）学了什么核心内容>
产出: <PDF 路径 / exercise 路径，非学习类写"无">
站点状态: 已标完成 / 已标已查看
git: <短hash> / 未提交(原因)
```
