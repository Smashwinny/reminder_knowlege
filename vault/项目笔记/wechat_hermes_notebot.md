# wechat_hermes_notebot

**这是什么**（一句话）：微信随记机器人——给常驻主机上的 Hermes（可换 OpenClaw）单开一个微信专用 Agent profile，微信里发文字即原样存进 Obsidian 笔记目录并经 Git 推送 GitHub 私有仓库，多端 Obsidian 可读。

**它给我什么能力**：
- 把"随手记录"的摩擦压到一次发消息（capture-first 移动入口）
- 常驻 Agent 网关 + 微信 ClawBot 扫码通道的完整接入知识
- 一套可复用的"保存脚本契约"：写文件→复读校验→只提交本条→拉取合并→推送，失败话术分级
- 一键配置提示词模式：把整个配置流程写成结构化提示词交给 Codex 类工具代办

**引入的概念**：
- [[Agent网关与消息通道]]
- [[原样捕获与工序分离]]
- [[能力地板选型]]

**实验记录**（做了什么、结果、坑）：
- 本地零依赖复刻整条管线（exercise/）：`remote_hub.git` 裸仓库模拟 GitHub 私库 + `host_vault`（主机端，部署 save_note.py）+ `other_pc`（另一台电脑）
- 5 用例全部真实通过：①单条随记回复"保存并同步成功。"，front-matter+正文逐字节校验过；②连发两条各自独立成笔记（时间戳文件名防覆盖），多行正文含双空格原样保留断言 True；③voice 消息被拒"请发送一条纯文本随记。"退出码 2；④other_pc pull 后 3 条随记全到达，远端每随记一 commit；⑤远端不可达输出"已保存，同步失败：pull 冲突…"退出码 3，文件不丢，修复后重推成功
- 坑：脚本必须以部署位置定位笔记库（`__file__` 所在目录），在 exercise 根目录跑会写错位置——真机同理，脚本与 vault 路径要显式绑定
