# system_design_primer

**这是什么**（一句话）：GitHub 最热门的系统设计教程（约 180k★），教"从一台服务器到百万用户系统"的后端架构设计与面试方法论，有中文版。

**它给我什么能力**：① 完整的后端架构词汇（DNS/CDN/LB/缓存/队列/分片/一致性…每个技术都讲"不利之处"）；② 可复用的设计方法论（场景约束→高层设计→核心组件→扩展 四步法 + back-of-envelope 估算法）；③ 8 道真题完整解答（repo/solutions/）；④ Anki 抽认卡 + 互动编程挑战 + 真实公司架构附录。

**实验记录**（做了什么、结果、坑）：
- 实验：`exercise/system_evolution.py`（零依赖，复用 [[零依赖编程]]）——用 M/M/1 排队近似模拟四阶段：单机（500/s，利用率80%延迟翻5倍，100%崩溃）→ 负载均衡×4（容量线性到2000/s）→ 缓存（命中率95%把DB利用率从1000%拉回50%）→ 异步队列（10倍洪峰下同步5倍过载全超时 vs 异步20秒排干积压）。四阶段全部实测，PDF 中附真实输出。
- 坑 1：第一版脚本模拟参数和文字结论不一致（表格全 OVERLOAD、结论却说健康）。教训：先定"每个阶段讲什么故事"，再反推参数，每个数字要能被公式解释。
- 坑 2：利用率 80% 是隐形红线——延迟对利用率非线性，生产系统 70~80% 就报警。
- 环境坑：无（纯教程无需依赖；已 setx PYTHONUTF8 1 备用）。
