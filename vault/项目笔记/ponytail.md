# Ponytail：保留边界的简洁编程

**这是什么**：供编程智能体阅读的实现取舍方法。核心是先理解真实流程，再按七阶顺序选择最早够用的方案；Skill、紧凑 AGENTS 规则和会话 hook 是不同载体。

**固定版本**：`e15862bb04d04285233a164460ced063941d9ef5`。静态阅读核心技能、载入实现、真实任务及历史评测；没有安装插件、运行全局 hook 或请求付费模型。

**得到的能力**：按需求选择实现；沿真实调用链定位根因；审查多余层次与依赖；保留安全/数据/错误/可访问性边界；记录简化上限与升级条件；区分作者基准和自己的工程验证。

**知识关联**：新增 [[最小实现决策阶梯]]；沿用 [[零依赖编程]]、[[AgentSkills技能包]]、[[Agent指令文件AgentMd]]、[[事实与判断分离]] 和 [[证据优先质检ProofOverClaims]]。同契约测试与基准口径作为旧概念的新案例，未另建同义概念。

**真实实验**：上游 `benchmarks/agentic/tasks.py` 的 sql-user 任务提供静态依据；两版自写实现使用一次性 SQLite 内存数据库和假数据。六步命令实际执行，两版各 21 项同契约检查通过，共 42 项；故意拼接 SQL 的负对照暴露假记录，证明测试能识别该类问题。最小版 10 行/0 类/1 函数，分层版 38 行/5 类/7 函数或方法，口径是非空非注释物理行，含 docstring，非上游 git diff 新增行。

**独立审核**：云端另一执行者复跑六步并额外检查 28 项边界，修正字体缺字后查看最终 10 页 PDF。Windows 又逐页查看 10 页，重跑六命令，42 项检查与负对照通过；独立取得固定提交，19 份选取来源哈希、原始任务片段和 MIT 许可均吻合。原始练习文件未改动。Windows 没有把云端额外 28 项冒称本机重跑。

**评测阅读结论**：2026-06-18 作者报告使用 Haiku 4.5，12 个功能任务，每组每任务 4 次，LOC 为 diff 新增行。历史安全分母是 5 项安全任务×4 次=20，不能混入后续 harness 的 7 项任务。功能部分未启动服务器/浏览器，当前评分器 `correct` 主要据非零新增行判断，因此不能据它证明功能等价。本次未重现模型、token、费用、时间等作者数值，也不证明全面安全。

**产物**：[10 页彩色指南](../../ponytail/Ponytail-小白指南.pdf)、[HTML](../../ponytail/guide.html)、[练习说明](../../ponytail/exercise/README.md)。ReportLab 直接生成 PDF 已逐页核验；HTML 浏览器视觉未验收，不能宣称与 PDF 逐像素一致。网站已保存完整分析，任务是否勾选完成由本人决定。

**限制与后续**：实验未覆盖鉴权、生产数据库、并发、自定义 row_factory 或所有上游任务。遇到真实多后端等需求后重新评价层次；模型效果应另建隔离基线和真实功能验收，不以行数代替功能或安全。
