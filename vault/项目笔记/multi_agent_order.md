# multi_agent_order

**这是什么**（一句话）：把抖音视频《两年大模型开发，被一个多 Agent 协作乱序问题干沉默了…》（06:21 面试向技术内容）的技术主线完整还原成一个可动手的小项目：复现多 Agent 并发乱序竞态，再用 DAG 编排 + 双层调度 + 输出协议逐层修好。

**它给我什么能力**：看图识险（30 秒指出多 Agent 架构里的乱序风险边）、Kahn 判环、百行内前沿调度器、Agent 间输出 schema 与冲突消解设计、重试上限+降级自愈、"风险→方案→生产"三层面试答题模板。

**引入的概念**：
- [[多Agent协作乱序竞态]]（问题本体 + 五类失效家族）
- [[双层调度架构]]（规划层/执行层分离）
- [[Agent输出协议契约]]（schema 协议门 + 置信度冲突消解）
- 激活旧概念：[[工单任务图与前沿调度]]、[[共享状态与Reducer]]、[[LangGraph与Agent编排]]、[[质检Gate与自我纠错循环]]

**实验记录**（做了什么、结果、坑）：`multi_agent_order/exercise/dag_orchestrator.py`（Python 3.14.7，PYTHONUTF8=1），5 个子命令全部真实跑通：
- `race`：完成序实测 D(0.05s)→C(0.1s)→B(0.2s)→A(0.8s)，摘要在数据就绪前运行拿到 "None 条"——乱序坑复现
- `cycle`：Kahn 排序报 `循环依赖！['A_抓数据','C_写摘要','D_排版']`——环连带下游一起点名
- `dag`：前沿调度后总耗时 0.95s，周报严格按依赖序输出，摘要拿到 42 条——修复成功
- `heal`：B 连挂 2 次第 3 次重试成功，全链无人工介入交付
- `protocol`：2 条坏结果被协议门拒收，40 vs 42 冲突按置信度(0.95)统一
- 坑：`msedge` 不在 PATH，要用完整路径 `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe` 打印 PDF

**后续可深入的方向**：把调度器改造成支持运行时动态加节点（视频提到的"动态扰动"）；对照 LangGraph 的 `StateGraph` 并行分支与 Checkpointer 重做本实验；给调度器加节点级超时预算与结构化日志。
