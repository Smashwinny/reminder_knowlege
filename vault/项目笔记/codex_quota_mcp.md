# codex_quota_mcp

**这是什么**（一句话）：数字生命卡兹克（@Khazix0918）2026-09-17 的 X 文章《分享一个大幅节省Codex额度的邪修方法，不要浪费了你的ChatGPT Pro会员》——利用订阅内**互不结转的双额度管道**（网页版 GPT-6 Pro 200 次/周 vs Codex 额度池），把"规划"搬到几乎免费的网页端（挂自建只读 MCP Server 看生产数据），"添加到 Codex"一键接力后执行端只付每任务 4% 额度。

**它给我什么能力**：
- 会算额度账：先画出订阅的额度管道图（几条池/怎么计/多久重置/是否结转）再摆工序
- 会给 AI 开生产数据只读口：三道闸 + 审计的百行 Python 模板
- 会跑"贵想便宜干"双账户工作流（官方通道，无风控风险；三方桥接反代是雷区）
- 会用"三视角喂料"提升规划质量

**引入的概念**：
- [[规划执行分账]]（主线：双账户省额度，[[混合模型分工流水线]] 的账户维度特例）
- [[只读闸门三原则]]（只读/最小权限/可审计的工程落地）
- [[三视角喂料]]（代码=理论/生产数据=实际/PR历史=为什么）
- [[上下文接力]]（"添加到 Codex" 与方案文档当管道）

**实验记录**（做了什么、结果、坑）：
- 全部真实运行（Python 3.14.7 / Windows 11，`PYTHONUTF8=1`），exercise\ 下 4 步：
- step1 造模拟 AIHOT 生产库（users=200、api_costs=164，Ultra 单价×25 还原"规划贵"）
- step2 只读 MCP Server：stdio JSON-RPC；闸1 工具白名单（仅 2 个只读工具）、闸2 SQL 纯 SELECT 校验、闸3 SQLite `mode=ro`、JSONL 审计逐请求记账
- step3 客户端验收 **10/10 PASS**：INSERT 被 `attempt to write a readonly database` 拒（驱动层）、三条写 SQL 被应用层拒、sqlite_master/目录外工具被白名单拒、8 请求=8 行审计对账
- step4 额度账：旧 14%/任务→周吞吐 7 vs 新 4%→25（**3.6×**）；60 任务/周 一年省 **$14,400（67%）**；$200 档 200 次 Pro/周够 60 次规划，$100 档不够
- 坑：Edge 无头打印需全路径 `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`（msedge 不在 PATH）；文章数字（10%/4%/200 次）是 2026-09 时点，学思维不背数字
