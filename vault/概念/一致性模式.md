# 一致性模式

**一句话定义**：数据多副本时"写入后多久能被读到新值"的三档保证——强一致（等所有副本写完才返回）、最终一致（先返回成功，后台慢慢追平）、弱一致（尽力而为不保证）。

**属于领域**：分布式系统 / 数据复制

**通俗理解**：改完微信头像、朋友那边过几秒才变——这就是最终一致性，它在"用户无感"和"系统开销小"之间做了漂亮交换。多节点复制像老师布置作业：强一致是"等全班都抄完才下课"，最终一致是"先下课，课代表课后帮没抄完的同学补齐"。

**与已有概念的关联**：
- 相关：[[CAP理论]]（CAP 中的 C 落到工程上就是这里三档的选择）
- 相关：[[缓存]]（缓存本质上是"故意制造的不一致"——用可能过期换取速度，同一种权衡）
