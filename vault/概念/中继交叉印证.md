# 中继交叉印证

**一句话定义**：采集不可控第三方平台（如 X）的内容时，用"免费公共中继负责发现 + 官方通道独立验证"两条通道，只有 author、帖子 ID、时间戳、可见文本逐项咬合才接受为证据，并在记录里写明溯源标记（如 `x-oembed+fxembed`）；第三方聚合页只许当链接索引，永远不许当证据。

**属于领域**：数据采集 / 信任链设计（无付费 API 条件下的可信采集）

**通俗理解**：公共中继（FxEmbed/api.fxtwitter.com）就像热心的二手转述者——免费、能拿到长帖全文，但你不能只听他的；X 官方 oEmbed 则像当事人本人的一句简短确认。转述者的故事必须和当事人的确认**逐字咬合**（作者、帖子号、时间、可见文本前缀）才算数，长帖扩展才能被采信。至于其他聚合网站说的，连"转述者"都算不上，只配当"哪里有帖子"的黄页。这样即使中继某天被投毒或篡改，单通道伪造过不了官方通道的核对。此外还有一条引用纪律：只存短摘录 + 全文内容哈希（不整篇转载），既留证据又守版权。

**与已有概念的关联**：
- 与 [[双数据源适配器隔离]] 分工不同：那边是"主备容灾"（一个源挂了换另一个），这边是"双源互证"（两个源必须互相咬合才可信）——一个解决可用性，一个解决可信性
- 与 [[数据源降级链]] 衔接：channels 分 mode 记账（profile-relay → community-discovery），降级只降覆盖度不降证据标准
- 防篡改思想与 [[提示注入]] 同源：外部内容不可自证可信，必须经独立通道核验
- 溯源标记 provenance 与 [[证据优先质检ProofOverClaims]] 呼应：每条数据自带"我从哪验证的"

**实测锚点**：codex-claude-resets 实测六个时间线候选 19/11/16/14/21/18，全部经 X official embed 核对后入库；仓库 README 明文规定"社区页面提供 fallback 链接，仅此而已"。
