# 知识层永不回滚原则

**一句话定义**：WikiSkill（arXiv:2608.27454）的门控纪律——候选**技能集**上验证集，分数不超历史最优就整批回滚到上一代；但 **wiki 知识层无论收拒一律保留**，且每次验证由外层程序向 `skill-impact.md` 程序化追加审计（提案元数据+diff+分数+收/拒），供提案员不重复踩坑。

**属于领域**：AI Agent / Harness 工程

**通俗理解**：技能是<u>说明书</u>（可以整批重印回收），wiki 是<u>账本和领悟</u>（只进不出）。这次照着说明书做砸了，说明书退回去，但"我们搞清楚了这类题为什么难"这件事永远为真——下次参谋换个思路从维基里重新长出更好的说明书。本仓库 toy 实验 ex2 实证：坏技能（系数×2）候选 62.5%<87.5% 被门控拒绝回滚，wiki 页数 4→4 只增不删，审计拦下重复提案。

**为什么这样设计**：
- 技能=**行为**，错了立刻 measurable（验证分数），必须拦住不让系统退步
- 知识=**理解**，本身无对错，其价值经由下一轮提案间接兑现；回滚知识=烧掉图书馆
- 审计账本由**确定性代码**写、LLM 只读——[[事实与判断分离]] 的留痕版
- 代价（论文局限 2）：严格门控会错杀"中性但长期有价值"的提案；审计按提案粒度记录，同义新 diff 仍可再提
