# 阶梯降级与保险丝

**一句话定义**：预算受限时的处理范式——把"压不进预算"拆成**硬编码顺序的多档降级**，每档只在上一档不够用时启用、**能塞下就立刻停手**；所有档位试完仍塞不下就**主动 throw（保险丝）**，把决定权交还调用方回退，绝不静默产出畸形结果。

**属于领域**：软件工程 / 降级设计（也用于 LLM 上下文预算管理）。

**通俗理解**（比喻，讲完落回术语）：像**行李箱装箱**——先原样装（full）；装不下先卷衣服（截工具输入 1000→200→60 字符）；再不行抽真空袋（旧文本掐头去尾→整条变一行注记）；再不行把鞋盒压扁（旧调用缩成一行式）；最后还能把袜子塞鞋里（相邻调用串合并复用信封）；**全试过还装不上，就换箱子（throw），而不是硬把盖子捆上**——捆上的箱子过不了安检（超出模型请求上限直接报错）。

**工程要点**（fast-jev-compaction `fitState` 复刻实测）：
- **档位顺序 = 破坏性递增**：先动可再生数据（工具输入），再动旧文本，最后动结构（调用行/消息串）；钉扎区（首条+最新 N 条）永远最后动。
- **能塞就停**：每降一档立刻重新记账检查，预算松时连第一档都不触发（实测 8000 tok 预算 state 4367 直接 full）。
- **保险丝哲学**：宁可"这次没压成"（回退内置摘要），不可"压出一份错误记忆"。配套 [[ClaudeCodeHooks与fail-open]]。
- **配套估算纪律——宁高勿低**：token 用无分词器启发式（英文每 6 字母 1 tok、数字 0.5、其他符号 0.9），刻意高估 2~18%：高估只是提前降级多花一点，低估会真撞请求上限。复刻实测：中文 chars/4 粗算法少算 263%、JSON 重度 state 少算 51%——无分词器启发式明显更稳。
