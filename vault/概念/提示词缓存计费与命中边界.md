# 提示词缓存计费与命中边界

**一句话定义**：API 提示词缓存要分别核对可复用前缀、断点与变化边界、TTL/路由、写入价格、命中读价和真实 usage，不能把“前缀相同”直接等同于“命中并省钱”。

**属于领域**：AI 应用 / API 成本与可靠性。

**机制与纪律**：以 2026-11-22 OpenAI 当前文档为例，GPT-5.6+ 的最小可缓存可见前缀为 1,024 token；隐式断点跟随最新合格消息，也支持显式断点，不是固定每 128 token 一个断点。变化点之后不能复用，不应夸张成“任意变化让全部缓存归零”。30m/12h 是最短覆盖口径而非保证删除时刻；命中还受路由等条件影响。

**成本口径**：GPT-5.6+ 的 30m 写入为普通输入 1.25×，Responses API 12h 为 2.5×；多数型号命中读 0.1×，部分当前型号为 0.05×，所以必须锁具体型号与文档日期。首次写入、新增 token、命中率和调用次数共同决定平衡次数。本地公式只能做敏感性分析，真实结算看 `usage.input_tokens_details.cached_tokens`、写入与 TTL 字段及账单。

**与已有概念的关联**：
- [[KV缓存与上下文]]：推理侧中间结果与服务侧提示词缓存相关但不同层，不混为同一计费对象。
- [[缓存有效期与发布边界]]：都强调有效期不是唯一正确性条件；本文讨论模型 API，不是 Web 发布缓存。
- [[付费调用回执与预算熔断]]：缓存命中和写入必须落到回执与预算账。
- [[能力地板选型]]：具体型号决定能力、参数支持和缓存费率。

**验证边界**：[[项目笔记/gpt6_handbook]] 仅以本地文本和公式估算 0.1×/0.05× 两种全命中情景，没有发真实 API 请求，未验证实际命中率、延迟或账单。
