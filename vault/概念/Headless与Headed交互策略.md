# Headless 与 Headed 交互策略

**一句话定义**：headless 是默认的受限桌面交互策略，不允许抢焦点或移动真实鼠标指针；headed 则由用户明确授权物理输入。二者是权限与副作用策略的选择，不是“后台失败就自动切前台再试”的恢复开关。

**属于领域**：AI Agent / 人机协作 / 权限边界。

**通俗理解**（比喻/例子，讲完落回术语）：headless 像远程助理先查阅控制面板，不碰你正在用的方向盘；headed 像你把方向盘明确交给助理。若读不到某个控件，正确反应是报告限制并请求授权或换方案，而不是擅自抢键盘鼠标。授权也不保证目标应用一定接受操作。

**工程含义**：同一观察—动作核心可通过策略限制 focus steal 和 cursor move；并发 Agent 不因此自动获得隔离桌面。真实截图、trace、剪贴板和命令输出可能含隐私，授权物理输入前还需明确日志与发布范围。

**与已有概念的关联**：
- [[无障碍树语义桌面自动化]]：语义读取与物理输入是不同能力，能读不代表能无干扰操作。
- [[动作投递语义与安全重试]]：改变交互策略不是消除投递不确定性的办法。
- [[预执行安全网与执行事件]]：都是把危险动作前的确定性约束放在模型判断之外。
