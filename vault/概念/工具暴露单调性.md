# 工具暴露单调性

**一句话定义**：MCP 端点运行期间工具面只增不减——权限开启时工具才注册进快照；权限撤销时**工具名仍留在快照里**（保护客户端缓存的工具列表），但 handler 每次调用实时校验当前权限，关闭即返回 TOOL_DISABLED。

**属于领域**：AI Agent / MCP 工程设计（[[MCP服务器]] 的权限生命周期管理；[[工具调用三段式流水线]] 的注册环节）

**通俗理解**（比喻/例子，讲完落回术语）：像**公司门禁名单只进不出**——员工离职（权限撤销）不把名字从通讯录里划掉（客户端都缓存着旧通讯录，划掉会导致对不上账），而是把他的门卡停用：名字还在，刷卡时拒绝。chat-on-steroids 的动机写在 kernel.ts 注释里：ChatGPT 会缓存工具快照，运行中把工具从 schema 删掉会让缓存失效、整段对话的工具列表错乱。配套两个细节：① **readOnlyHint 注解是真实行为不是文档**——ChatGPT 把没有 readOnlyHint 的工具一律当写操作、每次调用弹确认框，纯读工具老实标注就能少打扰用户；② 新端点可整体以"只读模式"构建（写工具从一开始就不注册），而运行中的端点永远单调。

**与已有概念的关联**：
- [[MCP服务器]] / [[MCP协议]]：工具列表的动态性如何与客户端缓存共存，是自建 MCP 服务器的必答题
- [[沙箱与审批正交]]：单调性管"面"（快照稳定），沙箱/审批管"点"（每次调用）——两层都要有
- [[LLM工具调用]]：客户端视角的工具发现与缓存

**首次接触于**：[[项目笔记/chat-on-steroids]]（src/main/mcp/kernel.ts，实验 E3 用 60 行模拟复现 7/7 PASS）

## AI Native 手册：撤销要以新的资源请求验收（2026-10-05）

[[项目笔记/ai_native_handbook]] 复用“工具快照可保留、当次执行实时判定”的区分，补充父子委托与撤销案例。短期凭证只能缩短风险窗口；手册建议撤销时同时停止签发、清除允许缓存并处理下游会话。它不等于等待到期，也不意味着已返回的数据能被收回。

已有自编实验中，正确路径不缓存允许结论，每次请求都检查当前委托及全部父链：撤销根委托后，原根委托与既有子委托的后续读取各为 0；从已撤销父委托再派生子委托也被拒。整例读取数仍含撤销前的成功读取，不能把“撤销后 0 次”误写成整例 0 次。

故意不安全的对照实现命中旧允许缓存时直接放行，跳过当前撤销状态检查，实际造成撤销后 1 次合成文件读取。因此总计 17/17 满足预期，包含 16 项正常设计检查和 1 项缺陷展示；负对照通过表示测试看到了漏洞，不是缓存实现安全。这个程序没有 MCP 工具注册或客户端快照，不能借该结果验收原项目的工具暴露单调性实现。

范围只到单进程顺序执行的后续新请求；未实现运行环境关闭检查、真实凭证或会话终止，未验证分布式撤销传播、并发中断、崩溃恢复或父委托更新后旧子委托是否错误复活。与 [[托管Harness与会话即资源]]、[[沙箱与审批正交]] 互链时仍保留这些边界。
