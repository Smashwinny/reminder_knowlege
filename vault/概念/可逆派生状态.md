# 可逆派生状态

**一句话定义**：当底层记录没有直接给出某个状态时（"这个子 agent 完成了吗？"），系统只能推断；推断必须遵守两条纪律——**只用"可逆的、当前事实的纯函数"填补真空，且永远不许覆盖已记录的事实（ground truth）**。

**属于领域**：系统设计 / 状态推断（监控看板、任务调度、健康检查通用）。

**通俗理解**（比喻讲完落回术语）：像**班主任判断学生还在不在写作业**——"作业本翻开着、笔在动"（pending 工具调用）是铁证；"三分钟没听见动静"只是猜测，学生一落笔就必须立刻改判。zoetrope 踩过的两个坑是最好的反例：① 把派生子 agent 时工具返回的"launch ack"（`Async agent launched successfully`）当成完成通知——**回执不是完成**，子 agent 还要跑几分钟；② 子 agent 143 秒无输出就判"已完成"，结果它随后报出的工具错误被当历史丢弃。正确做法：终止通知（task-notification / journal result）是终态，锁死；pending 工具调用是"还活着"的铁证，优先于一切推测；都没有时才允许"120 秒活跃窗口"这类**可逆**启发式——一旦它又动了，状态立刻翻回 Running。判定启发式合法的试金石：**它是"当前事实的可逆纯函数"且"填补真空"而非"覆盖事实"**。

**与已有概念的关联**：

- 相关：[[质检Gate与自我纠错循环]]（同为"客观证据优先于主观推断"）
