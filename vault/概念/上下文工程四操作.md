# 上下文工程四操作

**一句话定义**：LangChain 对"每轮该给模型看什么"的分类框架——Write（记下来）/ Select（挑出来）/ Compress（压下去）/ Isolate（隔开来）四个动词覆盖上下文管理全流程。

**属于领域**：AI Agent / 上下文工程

**通俗理解**：把上下文窗口当一张每轮都要重新摆的桌子：Write 是把新到的货入库登记，Select 是这桌只上该上的菜，Compress 是把整箱货压成一行清单，Isolate 是味道太大的货搬去别的房间（子 agent 独立上下文）。关键洞察是**上下文"太多"和"太少"一样有害**：旧信息以数量优势骗过注意力（agent-engineering 实验2：6 条 v1 旧文档对 2 条新文档，词频 21:4，关键词策略全量喂时选中已废弃的 v1；四操作处理后 token 681→265 反而选对）。省 token 和提准度是同一件事。

**与已有概念的关联**：
- [[Compaction上下文压缩算法]] 是 Compress 一格的内核实现（阈值触发→切割点→模板摘要）
- [[上下文预算与战略压缩]] 是预算策略（50% 早压缩、逻辑断点才压）
- [[KV缓存与上下文]] 是底层账本；[[Handoff交接简报续跑]] 是 Select+Compress 的跨会话版
- 本框架的价值是**分类学**：已学的具体算法各占一格，它给出全景坐标
