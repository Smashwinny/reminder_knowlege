# 能力层与后端路由

**一句话定义**：不给 Agent 新写功能，而是站在所有具体工具之上做"选型、安装、体检、路由"的胶水层——每个平台维护一个**有序后端候选列表**，第一个真实可用的当选，坏掉的给出修复处方，接入方式换代时只调列表顺序、不动业务代码。

**属于领域**：AI 工具生态 / 编程智能体基础设施

**通俗理解**：你新招的 AI 员工什么都会干，就是"没眼睛看互联网"。能力层就像一个 IT 管家：Twitter 现在哪家 CLI 还活着？装它。小红书必须登录态？给你三条路选。哪家工具被平台风控封了？悄悄换备选，你无感。管家自己不搬数据（Agent 装完后直连上游命令，零包装层零性能损耗），只管"哪个工具当下最稳"。Agent Reach 是它的教科书实现（88k stars，MIT）：`channels/twitter.py` 的后端列表是 `twitter-cli ▸ OpenCLI ▸ bird`，B站 2026-06 被风控 412 封死 yt-dlp 后改路由 `bili-cli ▸ OpenCLI ▸ 搜索API`。

**与已有概念的关联**：
- 与 [[MCP协议]] 互补不替代：MCP 标准化"工具接口"，能力层解决"工具运维"（哪家还活着、怎么登录、被封了换哪家）；Agent Reach 内部全网搜索也走 MCP（Exa via mcporter）
- 是 [[MCP服务器]] 生态的上层管家：MCP 只管插上，能力层管插哪根线、线断了换哪根
- 与 [[AgentSkills技能包]] 是搭档：CLI 负责装环境，SKILL.md 负责教 Agent 调什么命令——"管家 + 说明书"两半组合
- "首选+备选有序列表"与 [[负载均衡与反向代理]] 的健康检查踢除坏节点同构，只是粒度从"服务器"变成"CLI 工具"
- 分层 tier0/1/2（零配置/免费Key/登录态）是"最小授权"思想的渠道版：默认只装无风险渠道，登录态渠道用户点名才装
- 金融数据聚合的孪生模式见 [[数据源降级链]]（daily_stock_analysis 的 19 个行情 fetcher）：同一"有序候选列表+第一个可用者当选"，那边更重运行时限速与超时强杀
