# 材质名契约重建

**一句话定义**：当资产格式搬不动源端的复杂材质（glTF 带不走 Blender 节点图）时，只导出**几何体 + 约定好的材质名**（web_front/web_edge/web_back/web_gold…），消费端按名字把**自己用 shader 重建的同款材质**装配上去——名字是两边唯一都要认的行话。

**属于领域**：三维图形 / 跨端资产契约

**通俗理解**：像钢琴考级曲目单：评委（glTF）只记录"弹了哪首曲子"（材质名），不录音（节点网络）；两位演奏者（Blender 与浏览器 shader）各自照同一份乐谱（UV 公式）弹，效果"接近但非逐像素一致"——skill 交付时要求明说这一点，不许吹"完全一致"。**红线**：卡面 mesh 必须真几何，不许拿平面截图冒充"导入的模型"。

**与已有概念的关联**：
- 与 [[JSON-IR类型化中间表示]] 同构：传输带不动的复杂物，换成"最小契约 + 各自重建"
- 依赖 [[glTF与GLB资产管线]]：GLB 只可靠搬运几何/UV/材质名
- 2026-10-03 实测：手写 1512 字节 GLB（两块平面+正确材质名）即可让 RuiC-card-skill 官方 viewer 走 WebGL 路径渲染并过 33/33 全量验收——**契约是真实可依赖的公开接口，不是宣传语**
- 验收哲学见 [[证据优先质检ProofOverClaims]]：契约靠"比渲染帧"证明，不靠 ready 旗标
