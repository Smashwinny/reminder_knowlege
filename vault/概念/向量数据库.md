# 向量数据库

**一句话定义**：专门存放向量（意义的坐标）、并按"语义距离最近"来检索的数据库，核心概念是 Collection（集合，类 table）、Point（点 = id + vector + payload，类一行记录）、Payload（JSON 元数据，类其他列）。

**属于领域**：数据库系统 / 信息检索

**通俗理解**：MySQL 按"精确匹配"提问（title 等于 X 吗？答案非对即错）；向量数据库按"谁最像"提问（返回一张相似度排序的榜单）。分工口诀：**vector 管"像不像"，payload 管"是不是"**——向量走 HNSW 索引做语义近邻，payload 走普通索引做条件过滤（[[HNSW近似最近邻索引]]、过滤搜索）。"找相似"技术进化四代：LIKE 字面匹配 → 倒排索引（ES/BM25，仍字面）→ 自管向量暴力比对（慢、无过滤）→ 向量数据库。

**选型**（库 vs 服务、专职 vs 兼职两维度切开）：FAISS 是索引算法库（无服务）；Chroma 是嵌入式原型玩具；Milvus 重运维；pgvector 适合数据已在 PostgreSQL；Elasticsearch 适合已用全文检索想顺带向量；**Qdrant = 生产可用的专职向量数据库，过滤+向量复合查询最强**（filterable HNSW：在图里只走满足条件的路，而不是先搜后滤）。
