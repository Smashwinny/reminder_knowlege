# 逐轮模型路由与哨兵代理

**一句话定义**：在 CLI（Claude Code/Codex）与模型 API 之间插一个本机回环代理，用"假模型名"当自动挡开关，每轮用户输入先问决策模型选档，再改写请求里的模型名转发——让"用哪个模型"从人工选择题变成自动分诊题。

**属于领域**：AI Agent 工程 / 模型路由（harness 改造范式）。

**通俗理解**：自动挡汽车你只管踩油门，变速箱自己换挡。哨兵模型就是那个"挡位杆"：请求里的模型名是 `jev-router` = 挂在 D 挡（自动）；你手动选任何真模型 = 拨回手动挡，直通不改写。

**架构三件套**（jev-router 实现，可平移到任何 CLI）：
1. **回环代理**：启动时把 ANTHROPIC_BASE_URL 指向本机代理，再 spawn 真 CLI；代理只改模型名，不碰授权头（转发 CLI 自带认证）
2. **哨兵模型**：利用"Claude Code 走自定义 base URL 时不校验模型名"的特性，往 /model 列表注入假模型 `jev-router` 作为路由开关信号
3. **本地策略兜底**（policy.mjs 纯函数）：低置信（<0.3）不降级、升级封顶均衡档；人类点名（"use opus"正则）优先；上下文 >2 万 token 拒绝降级（prompt cache 作废反而更贵）；一切失败收敛"保持现状"，无档可保时退最安全档 opus（fail-open）

**实测证据**（mock Jev 驱动真代码）：琐碎问答→haiku(0.95)/jev；普通任务→sonnet(0.80)/no-change；困难任务→opus(0.92)/jev；低置信 0.10→sonnet/low-confidence-capped；"use opus"→explicit-override；Jev 宕机→rewrite 退默认档 opus，会话不阻塞。
