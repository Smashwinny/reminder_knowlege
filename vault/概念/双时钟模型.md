# 双时钟模型

**一句话定义**：可回放的交互系统里要把"内容时钟"（回放对象自身的时间戳，即播放头位置）和"呈现时钟"（观看者的真实秒表）严格分开——**状态读内容时钟，动画走呈现时钟**。

**属于领域**：交互系统 / 时间建模（视频播放器、回放调试器、可视化监控通用）。

**通俗理解**（比喻讲完落回术语）：看**比赛录像**时，"比分是多少"取决于录像带走到第几分钟（内容时钟），你拖来拖去它都答得对；而"我看了多久"是你自己的秒表（呈现时钟），暂停就停。zoetrope 发现混淆这两者是"本项目最常见 bug 之源"：把动画余晖按内容时钟算，进度条一拖 chip 就乱闪；把状态按"最后一条记录"算，一个开头就写好的"用户已停止"标志让整个回放从头错到尾。归纳成两条铁律：① 状态必须是"播放头处时间戳事件的函数"，任何方向拖动都可重建；② 动画只随真实观看时间老化，暂停冻结、倒带不重播。

**与已有概念的关联**：
- 应用：[[JSONL事件日志与折叠模型]]（事件带时间戳，才能支撑"任意播放头处状态可问"）
- 类比：[[Checkpoint存档与持久执行]]（拖动=从快照恢复；双时钟保证恢复后 UI 状态正确）
- 相关：[[三层记忆]]（呈现层与内容层分离思想的又一例）
