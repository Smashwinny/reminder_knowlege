# WikiSkill共演化循环

**一句话定义**：Google Research（arXiv:2608.27454）的技能演化框架——把智能体的经验仓库拆成 **wiki（理解，只增不删）+ skills（可执行步骤，严格验收可回滚）** 两层，四个角色（Inference Agent / Wiki Maintainer / Skill Proposer / Gating）循环演化，让 9B 小模型+技能（47.4%）反超 27B 大模型裸考（39.4%），权重零改动。

**属于领域**：AI Agent / Harness 工程

**通俗理解**：像一家公司：员工（Inference Agent）干活留案卷（raw/）；档案员（Wiki Maintainer）把踩坑教训写进公司维基（wiki/，只进不出）；参谋（Skill Proposer）翻维基写出新操作手册（skills/）；质检员（Gating）试用手册，<u>手册不行整批退回重写，但维基里学到的理解永远保留</u>。手册是消耗品，维基是资产——经验从一次性消耗变成复利。

**关键数字**（5 基准 × 5 模型，全列第一）：
- Qwen-3.5-9B+WikiSkill **47.4%** vs Qwen-3.6-27B 裸考 39.4%（3 倍参数差被外挂知识抹平）
- 增益随规模递增：4B/9B/27B 分别 +12.3/+17.5/+23.9 → 技能与规模**互补**
- 消融：Proposer 读 wiki 63.7% vs 无 wiki 48.7%（**+15.0**）；推理时也读 wiki 有害 63.7→60.9（开卷抄作业让轨迹失去信息量，训练 rollout 必须禁读 wiki）
- 跨模型迁移：27B 技能→9B SpreadSheet 50.5%（自演化 33.6）；**负迁移**：4B 技能→Gemini-Flash 50.5→18.1（弱模型的低层 workaround 捆住强模型）

**与已有概念的关联**：
- [[第二大脑LLMWiki]] 回答"知识库怎么分工（raw 只读/wiki 归 LLM）"，本概念回答"知识库怎么让智能体越用越强"——前者是静态架构，后者加上进化闭环
- [[记忆四层模型]]/[[三层记忆]] 讲经验分层压缩；WikiSkill 补一刀：压缩原料必须来自"真实暴露的失败"，喂料端被污染整线退化（推理 agent 禁读 wiki 的原因）
- [[本能学习与置信度评分]] 是另一条"经验→技能"路线：ECC 靠置信度渐进固化，WikiSkill 靠验证集门控严格验收；两者都把 [[AgentSkills技能包]] 当产出物
- [[提示词爬山法PromptHillClimbing]] 的亲戚：都靠"生成→评分→保留更优"外循环提能力，WikiSkill 优化对象从单条 prompt 换成技能集+知识库
- 门控与审计见 [[知识层永不回滚原则]]

**局限**（论文自认）：技能全量注入未测检索触发；严格门控错杀中性提案；wiki 无自动剪枝；未覆盖超长程在线适应。
