# 消息队列与异步削峰

**一句话定义**：请求先入库排队、后台 worker 按自己的节奏消费（异步）；队列太满时主动限流/拒绝（背压），防止下游被压垮。

**属于领域**：分布式系统 / 流量治理

**通俗理解**：消息队列是水库——上游随便洪峰，下游恒定泄洪。实验数据：10 倍洪峰持续 5 秒，同步架构 5 倍过载全线超时；异步架构 API 层秒级"已受理"，洪峰后约 20 秒排干积压。关键取舍：用户拿到的是"已受理"而不是"已办完"。

**与已有概念的关联**：
- 相关：[[系统设计与可扩展性]]（异步是"读多写多都扛不住"时最后的降压阀）
- 相关：[[构建流水线与Pass]]（队列把紧耦合流水线拆成可各自伸缩的阶段）
