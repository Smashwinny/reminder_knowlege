# 多Agent协作乱序竞态

**一句话定义**：多个 Agent 并发执行时，"谁先干完"由线程调度和各 Agent 耗时方差决定，一旦完成顺序偏离业务要求的依赖顺序，系统就产出错误结果（如摘要在数据就绪前定稿，拿到空数据）。

**属于领域**：AI / 多智能体编排工程（LLM 应用架构）

**通俗理解**（比喻讲完落回术语）：像后厨同时开火的四口灶——凉菜 1 分钟就出，硬菜要炖 40 分钟；传菜员"谁好上谁"，结果凉菜先上、主菜的配料却还没到位。术语上这是并发系统的固有属性：`as_completed` 式"完成即合流"把**完成顺序**当成了**数据顺序**。Agent 场景下更凶，因为 LLM 耗时方差极大（1s~60s，取决于输出 token 数、限流、重试）。关键区分：**时间上对齐 ≠ 逻辑上就绪**——"所有任务都在跑"是时间状态，"下游的上游结果在手且合格"才是逻辑状态；治理乱序就是给每个节点换成逻辑就绪门。完整失效家族：依赖错乱、职责边界重叠、结果口径不一、单点故障、循环依赖（+动态扰动）。
