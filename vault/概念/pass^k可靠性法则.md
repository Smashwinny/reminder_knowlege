# pass^k 可靠性法则

**一句话定义**：Agent 输出有随机性，单次成功什么也不证明——**pass@k（k 次任一成功即过）适合探索类任务，pass^k（连续 k 次全成功）才是企业自动运行要的可靠性**；配套 3/n 法则与置信区间，防止被统计噪声骗。

**属于领域**：AI Agent 评估 / 统计素养

**通俗理解**：单次成功率 80% 时，连续 5 次全成功只有 **0.8⁵=32.8%**；而"5 次里成 1 次"（pass@5）是 100%。实测（agent-eval 实验 3）：v1 在 12 条 common 任务各跑 5 次，单次成功率 76.7%，pass^3 只有 41.7%、pass^5 只有 16.7%，10/12 条是 flaky——**单次数字好看，pass^k 才把不稳定打回原形**。用户只给一次机会时单次成功率最接近真实体验；任务反复自动运行时 pass^k 更快暴露问题（Princeton Agent Reliability 研究：能力提升不会自动带来同等可靠性提升）。

**三条统计防骗守则**：
1. **3/n 法则**：n 次独立试验零失败，95% 置信下真实失败率上界 ≈ 3/n——跑 100 次零越权，上界仍是 3%，低频高损失风险要专门 challenge set + 硬控制，不能靠零观察；
2. **置信区间**：80/100（CI95 [71.1%, 86.7%]）vs 83/100（[74.5%, 89.1%]）区间几乎全重叠——n=100 时 3pp 差距不构成证据，诚实结论是"未发现重大回归"；实测分清 80% vs 90% 要 n≥400；
3. **配对比较**：同一批 case 先跑 v1 再跑 v2，直接看翻转（哪些失败变成功/反之）；两边各拿随机题会把任务难度差混进系统差。
