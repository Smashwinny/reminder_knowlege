# CAP理论

**一句话定义**：分布式系统不能同时完全做到一致性（C：所有节点看到同一份数据）、可用性（A：每个请求都有响应）、分区容错性（P：网络断了还能干活）三者——而网络分区总会发生，所以 P 必选，真正的选择只有 CP 或 AP。

**属于领域**：分布式系统 / 理论基础

**通俗理解**：CP 系统分区时宁可不让你查（银行转账：宁可拒绝也不能显示错的旧余额）；AP 系统分区时继续服务、容忍暂时不一致（朋友圈少刷一条新动态无所谓，但不能整个刷不出来）。P 不是选项而是现实——网线、交换机、机房总会出事。

**与已有概念的关联**：
- 相关：[[一致性模式]]（CAP 说的"一致性"粒度，落到产品上就是强/最终一致性模式的选择）
- 相关：[[关系型数据库与NoSQL]]（多数 NoSQL 选 AP，多数 RDBMS 单机天然强一致）
