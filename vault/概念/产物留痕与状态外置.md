# 产物留痕与状态外置

**一句话定义**：长任务能稳定推进的关键不是模型"想得久"，而是**每一轮的产物落盘成为下一轮可读取的依据**——任务状态放在环境（文件/锁文件/日志/报告/遗留清单）里，不放在模型上下文里；"不要让 AI 靠记忆硬撑，要让工作过程留下可以继续使用的东西"（sitin Agents API 科普文金句）。

**属于领域**：AI Agent / Harness 工程（[[AgentHarness智能体挽具]] 上下文工程职责的执行侧心法）

**通俗理解**：靠记忆硬撑 = 让 agent 把 20 轮前的报错和方案全背在上下文里，压缩一次就失忆、换会话就清零；产物链 = 每轮把"改过的配置、报错日志、diff 审单、遗留清单"写成文件，下一轮**只读文件不靠回忆**。最终交付物也从一句"升级完成"变成一组能让人复查的变更和结果——终点从"AI 写完了"推进到"可被人接手"。

**实测**（ex6_mini_harness.py，纯标准库）：turn1 产物落盘（turn1_deps.txt + events.jsonl 11 条事件）→ 进程重启后从 session 恢复并只读产物继续；验收 Gate 真跑运行时检查，抓住"构建 PASS 但 render_template 已在 2.0 被移除"的谎报——产物链 + 确定性 Gate 才构成完整闭环。
