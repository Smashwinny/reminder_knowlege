# 产物留痕与状态外置

**一句话定义**：长任务能稳定推进的关键不是模型"想得久"，而是**每一轮的产物落盘成为下一轮可读取的依据**——任务状态放在环境（文件/锁文件/日志/报告/遗留清单）里，不放在模型上下文里；"不要让 AI 靠记忆硬撑，要让工作过程留下可以继续使用的东西"（sitin Agents API 科普文金句）。

**属于领域**：AI Agent / Harness 工程（[[AgentHarness智能体挽具]] 上下文工程职责的执行侧心法）

**通俗理解**：靠记忆硬撑 = 让 agent 把 20 轮前的报错和方案全背在上下文里，压缩一次就失忆、换会话就清零；产物链 = 每轮把"改过的配置、报错日志、diff 审单、遗留清单"写成文件，下一轮**只读文件不靠回忆**。最终交付物也从一句"升级完成"变成一组能让人复查的变更和结果——终点从"AI 写完了"推进到"可被人接手"。

**实测**（ex6_mini_harness.py，纯标准库）：turn1 产物落盘（turn1_deps.txt + events.jsonl 11 条事件）→ 进程重启后从 session 恢复并只读产物继续；验收 Gate 真跑运行时检查，抓住"构建 PASS 但 render_template 已在 2.0 被移除"的谎报——产物链 + 确定性 Gate 才构成完整闭环。

**与已有概念的关联**：
- [[Checkpoint存档与持久执行]]：它管"怎么续跑"（快照+读档），本概念管"续跑时喂什么料"（产物文件）——互补互链
- [[JSONL事件日志与折叠模型]]：事件留痕的日志实现，本概念是它承载的内容策略
- [[上下文预算与战略压缩]]：状态外置后压缩不再是失忆事故——重要的东西在文件里，不在上下文里
- [[证据优先质检ProofOverClaims]]：验收看的"证据"就是过程产出的产物，产物链是它的原料侧
- [[三视角喂料]]：代码×生产数据×决策历史三路喂料，喂的正是历史过程留下的产物
- [[托管Harness与会话即资源]]：Agents API 的 items/artifacts/traces 资源就是产物链的产品化

## Easel：薄索引传位置，文件保留内容与意图（2026-10-05）

[[项目笔记/easel]] 将同一思想用于内容工序：`.easel.json` 记录产物路径、步骤状态与简短摘要；正文保存在成品文件，受众、基调、钩子及 do/don't 等不能从成品可靠反推的创作意图放入 `brief.md`，再把它登记为输出。索引回答“去哪里读”，简报回答“为什么这样做”，摘要不能代替两者。

固定版本的 `manifest record` 追加调用方提供的记录，不自动证明文件存在、内容正确或媒体可解码；`latest` 也可能返回 `failed`。下游必须实际读取文件、检查步骤结果，并按产物类型验收。与 [[分镜表驱动生成]] 互补：前者是项目级薄索引，后者是镜头级结构化输入，不是同一 schema。展示标签、工序结果与外部效果的分层见 [[证据状态机]]。
