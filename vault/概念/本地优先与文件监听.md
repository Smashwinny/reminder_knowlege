# 本地优先与文件监听

**一句话定义**：应用把用户的正数据存成开放格式的本地文件、自己只做"文件的视图"，并通过监听文件系统变化保持界面与磁盘同步。

**属于领域**：软件架构 / 数据主权

**通俗理解**：多数在线工具把你的稿子存在它们的服务器上——工具跑路，稿子陪葬。Local-first 反过来：**草稿就是一堆普通 .md 文件，应用只是这些文件的一个"取景器"**。类比：银行保险柜（云端存储）vs 自家书架（本地文件）——书架上的书任何人都拿得走、读得懂。落回术语：local-first 的两个技术支柱是 **① 开放格式落盘**（.md 谁都能打开）+ **② 文件监听**（火星编辑器叫 vault_watch：外部任何程序改了文件，编辑器发现并重载界面，方向是双向的）。

**火星编辑器桌面版实例**：
- 应用数据库只存界面状态；**刻意不碰 CLI 自己的会话文件**（~/.claude/projects/ 等内部格式，随时会变）——对外部工具的内部格式保持"只围观、不依赖"
- 容错哲学：Agent 面板坏了"最坏也只是面板停了，稿子照样改"——**关键路径（文件）与展示路径（面板）分离，坏一层不坏全局**
