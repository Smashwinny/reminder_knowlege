# 棋盘格假透明修复

**一句话定义**：图像工具没有真 alpha 通道时会把透明区**画成灰白棋盘格**存成普通 RGB（人眼看像透明，下游抠图全废）；确定性修复 = 在图像边框检测"两主色周期网格"（格子 8~64px），命中后按棋盘相位逐像素还原真 alpha。

**属于领域**：图像工程 / 质检

**通俗理解**：就像"透明胶片"被复印成了印着灰白格子的不透明纸——人眼骗得过，程序骗不过。修复器是个"验钞机"：先看边框（背景几乎总在边上）是否有两种主色按周期排列，再用"邻居一致性"保护（一个像素周围 8 邻居多数也符合各自相位色才判为背景），所以角色白头发落在白格子上也不会被误抠。

**与已有概念的关联**：
- 是 [[质检Gate与自我纠错循环]] 的具体检查项：RuiC-card-skill 的 validate_assets.py 在进 Blender 前拦截"无 alpha 且非棋盘格"的层；是棋盘格则自动转换并记入 asset-validation.json
- [[确定性脚本]] 的典型应用：同输入同输出，无 AI 参与，转换结果可回归测试
- **实测盲区（2026-10-03）**：体检门对"反色线稿"（白线黑底）失明——数值检查只验"有暗有亮"，不验谁是底谁是线；印证 Gate 数值检查必须配人眼复核（双保险）
- 修复对账数据：自制 24px 棋盘格假透明图还原后与原始真 alpha **98.3% 像素完全一致**，平均差 1.93/255（残差全在抗锯齿边缘）

## Qwen-Image-2.1：输入通道、输出 alpha 与视觉效果分别取证（2026-10-05）

[[项目笔记/qwen_image_2_1]] 复用“看起来透明不等于具有真实透明通道”的检查纪律，但不能移植上方旧修复器的像素一致率。固定 `pe_core.py` 的 `load_image` 会把供提示改写器使用的输入转换为 RGB，并按像素上限缩小；这是源码观察，本次没有调用图片加载或解码。

改写器输入转换为 RGB，不足以推出图像生成模型能否输出 RGBA。官方 README 对透明生成的声明、VAE 四通道配置、真实产物是否有有效 alpha、边缘合成效果，是四种不同证据。此次没有模型推理、输出图像、alpha 通道或透明边缘质量实测。

未来若单独开展已获准的透明图研究，应分别保存输入通道与处理记录、输出文件通道、alpha 数值检查，以及合成后的边缘检查；文字写“透明背景”或示意图画棋盘格都不能替代这些证据。关联 [[证据优先质检ProofOverClaims]]、[[图像提示八要素]]。
