# 双层调度架构

**一句话定义**：把多 Agent 系统的调度拆成两层——**规划层**（LLM 慢思考：拆任务、定依赖、查环，产出一张已验证无环的 DAG）和**执行层**（毫秒级事件驱动：前沿调度、并发池、重试、超时、合流），故障只在执行层消化，不回炉重新规划。

**属于领域**：AI / 多智能体编排工程（系统架构）

**通俗理解**（比喻讲完落回术语）：导演画分镜表 vs 片场执行导演——分镜表（DAG）开拍前一次画好并严格校验，开拍后片场按表推进，NG 一条只重拍那一条（节点级重试），绝不会全组开会重画分镜。术语上为什么必须分层：执行层每次故障都回头重新规划，会打爆 LLM 费用且拆分结果不稳定；规划层顺手管并发，又跟不上毫秒级事件。**规划的归规划（对正确性负责），执行的归执行（对时效性负责）**。
