# 评分契约与护栏

**一句话定义**：当 LLM 要输出"结构化决策"（评分/分级/动作）时，先用一份全项目统一的刻度契约（如 decision-scale-v1：80-100 强烈买入 → 0-19 卖出 五档）钉死口径，代码强制归一越界值，再用护栏规则（如"高分却配保守动作必须写明降级原因"）拦截自相矛盾的输出，最后把每条建议沉淀为可后验查询的资产。

**属于领域**：AI / LLM 应用架构（LLM 输出可靠性工程）

**通俗理解**：像裁判打分体操比赛——动作分有公开的难度系数表（契约），裁判不能随心情给 87.5 这种表外分数（归一化），打了高分却写"建议弃权"必须提交书面说明（guardrail），每张评分单存档备查、来年统计哪位裁判准（可后验）。daily_stock_analysis 的实现：`decision_band_for_score()` 把任何输入分强制映射进五档，越界返回 None；score≥60 但 action 是 hold/watch 时必须有 `guardrail_reason`，否则信号提取时强制对齐；每条建议存成 DecisionSignal（入场区间/止损/失效条件/过期时间），事后能统计命中率。

**与已有概念的关联**：
- 与 [[质检Gate与自我纠错循环]] 同思想：Gate 是"检查不过就打回"，护栏是"输出语义自洽性检查"
- 依赖 [[事实与判断分离]]：正因为评分由代码兜底，契约才有硬锚点可对齐
- [[PromptAsCode提示词即代码]] 的"输出负向块"是它的提示词侧轻量版：都在约束模型输出的形状
- 诚实披露（数据缺失要在报告里明示，有专门测试盯着）是护栏的被动 half
