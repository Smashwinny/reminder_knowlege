# 单源双宿主

**一句话定义**：把"视图"做成只吃一坨 JSON 数据的独立页面，让两个宿主（IDE 插件壳 / 静态导出器）各自挂载同一份渲染代码——写一次，两处运行。

**属于领域**：软件工程 / 前端架构

**通俗理解**：视图像一个"只认卡片的放映机"，插件和导出器是两个"送卡片的人"——放映机不关心卡片从哪来。Vault Graph 用这招同时拥有 Obsidian 插件（挂进 Obsidian 视图容器）和单文件 HTML 导出（连数据打包进静态页），没有复制第二套 UI 代码。收益：功能零漂移（两个形态永远长得一样）、bug 只修一处；成本：数据接口要提前设计干净。

**与已有概念的关联**：
- 相关：[[零依赖编程]]（导出形态因此能做成零网络、零外部资源的自包含单文件）
- 相关：[[构建流水线与Pass]]（esbuild 在构建期把页面+数据内联打包，是典型的一次性构建 Pass）
- 对照：[[能力层与后端路由]]（那边是"多后端一个能力接口"，这边是"多宿主一个视图接口"——同一种解耦思路的两个方向）
