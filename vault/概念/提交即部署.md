# 提交即部署

**一句话定义**：小数据量应用把全部状态存成仓库里的 JSON 文件，定时任务跑完把变更 `git commit` 进公开仓库，托管平台（Vercel 的 Git 集成）监听提交自动构建发布——**每次提交 = 一次数据入库 = 一次上线**，git 历史天然成为审计日志。

**属于领域**：软件工程 / 零运维架构（个人小工具的免费全链路方案）

**通俗理解**：传统做法要"数据库 + 后端 + 服务器"三件套；提交即部署把这三样全换成你已经会的东西——JSON 当表、git 当事务日志、CI 当 cron、静态托管当 CDN。codex-claude-resets 实测：GitHub Actions 每小时 7/17/27/37/47/57 分跑采集器，`data/events.json`（78 条）等五个 JSON 提交进公开仓库，Vercel 自动 `node scripts/build.mjs` 出 711 页静态站。零数据库、零服务器、零付费 API；公共仓库的 runner 还不消耗私有 Actions 分钟数。审计能力是白送的：哪条公告何时被验证、规则修复改判了谁，`git log` 全程留痕。

**适用边界**：单写者（定时任务）、读多写少、数据量 MB 级——公告聚合、状态页、排行榜都合适；高频写入或隐私数据（凭证绝不能进仓库）不适用。

**与已有概念的关联**：
- 数据文件即快照，与 [[快照契约与不可变只读]] 一脉相承：失败时保留旧记录，坏采集永远不能清空历史
- 与 [[发布交换与健康门回滚]] 配套：健康状态（health.json）随数据一起提交，部署失败浏览器自行"变陈"，不留永久绿灯
- 与 [[Serverless边缘函数]] 是"零后端"的两极：那边逻辑上边缘、数据在云；这边连逻辑都跑在 CI、线上只有静态文件
- 构建期注入数据、运行时零后端，是 [[单一馈送与schema冻结]] 的静态站实现版
- 审计留痕思想同 [[JSONL事件日志与折叠模型]]：git log 就是天然的事件日志
