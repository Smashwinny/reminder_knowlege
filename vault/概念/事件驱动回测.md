# 事件驱动回测

**一句话定义**：把历史行情切成一条条带时间戳的事件（tick/成交流），推进一个模拟时钟，让策略像实盘一样逐事件响应——回测和实盘跑同一套策略代码，只是"行情源"从交易所换成了历史数据文件。

**属于领域**：金融量化 / 交易系统架构

**通俗理解**：普通回测是"翻相册"（按整根K线批量算， lookahead 偏差很难避免）；事件驱动回测是"重放录像带"——每个 tick 按真实时间顺序进引擎，策略此刻只能看到此刻之前的数据，天然杜绝未来函数。NautilusTrader 的引擎三步：`add_venue()` 建模拟交易所（含撮合规则、手续费、保证金）→ `add_data()` 灌历史数据 → `add_strategy()` 挂策略 → `engine.run()` 走事件循环；报表从 `engine.trader.generate_*_report()` 取。Rust 核心 + 纳秒时间戳（nanosecond epoch），所以同一套 Python 策略代码回测完可直接接实盘行情源上线。

**与已有概念的关联**：
- 相关：[[确定性脚本]]（同一批历史事件重放，输出必须逐字节可复现才是可信回测）
- 相关：[[JSONL事件日志与折叠模型]]（行情本质是只追加事件日志，fold 出任意时刻的持仓/盈亏状态）
- 相关：[[双时钟模型]]（回测时钟是模拟时钟，走数据时间而非墙钟；快慢分离的思路同源）
