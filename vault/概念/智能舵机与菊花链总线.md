# 智能舵机与菊花链总线

**一句话定义**：智能舵机 = 普通舵机加上"单片机+串口协议栈"——主机不发光驱波，而是发带 ID 的串口指令包（"转到位置 2048"），舵机内置编码器自己闭环，并把位置/速度/温度/负载回报给总线；多个智能舵机**并联在一根半双工 UART 上靠 ID 寻址**，就是菊花链总线（Microduck：15 舵机 + 1 IMU 板共一根线）。

**属于领域**：机器人 / 嵌入式硬件

**通俗理解**：[[舵机与PWM角度控制]] 的哑巴舵机像"对讲机里只收得到'转到 90°'的哑命令，答不上话"；智能舵机像**有工号的员工**——群里@工号派活，干完了还主动汇报进度和体温（堵转/过温）。Microduck 的省钱杀招是 fast sync read（0x8A）：16 个设备的应答**接力追加**进一个状态包，省掉 15 个帧头和 15 次总线换向——50Hz 控制环每拍只有 20ms，总线时间是硬约束。

**与已有概念的关联**：
- 对照 [[舵机与PWM角度控制]]（哑巴舵机：PWM 单向广播、无反馈、各占一条信号线）；智能舵机的"报 ID 喊话、被叫者应答"与 [[MQTT协议与发布订阅]] 的主题寻址、[[MCP协议]] 的标准化接口是同一个"用协议降复杂度"思想
- 板子太弱跑不动大模型 → 重活 WebRTC 推给云端 HF Space，是 [[控制面与数据面]] 的机器人版：板载 50Hz 安全控制面永远本地，重推理数据面上云
- 总线协议完整性靠 CRC-16（poly 0x8005）兜底，篡改一位即拒收——同 [[质检Gate与自我纠错循环]] 的"先验货再入库"

**实测要点**（microduck 硬件拆解补充篇实验 2，全真实运行）：逐位法与查表法双实现交叉一致，且命中 CRC-16/BUYPASS 标准校验值（"123456789"→0xFEE8）；构造 Sync Write(0x83) 16 设备广播包 122 字节回读逐字节一致，篡改 1 位被正确拒绝。15-DOF 地图 = 头3(head_pitch/yaw/roll) + 颈1 + 双腿各5(hip_yaw/roll/pitch+knee+ankle) + 喙1。
