# Agent输出协议契约

**一句话定义**：规定每个 Agent 的交付物必须是字段固定、类型固定、机器可校验的结构化对象（如 `{agent, section, content, confidence}`），下游收货先过 schema 校验（协议门），缺字段/类型不符直接拒收。

**属于领域**：AI / 多智能体编排工程（Agent 间接口设计）

**通俗理解**（比喻讲完落回术语）：像食堂交菜必须用统一餐盘、贴好标签——用自家碗端来的（自由文本）、没贴菜名的（缺字段），打菜窗口一律不收。术语上它解决的是"**结果口径不一**"的根因：Agent 交回自由文本时，下游无法机器校验，两处报 40/42 条的矛盾到读者眼前才暴露；有协议 + 冲突消解规则（同 section 冲突按 `confidence` 置信度或权威源裁决），矛盾在合流口就被统一。协议管"单条消息长什么样"，[[共享状态与Reducer]] 管"多条消息怎么合并进共享白板"。

**与已有概念的关联**：
- 本质是 [[质检Gate与自我纠错循环]] 的思想搬到 Agent 间通信；同族还有 [[评分契约与护栏]]、[[事实与判断分离]]
- 字段 `confidence` 的用途呼应 [[本能学习与置信度评分]]
- 依赖它的上层机制：[[工单任务图与前沿调度]] 的依赖校验（前置结果合格才算就绪）
