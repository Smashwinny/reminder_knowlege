# 规格书先行SpecDriven

**一句话定义**：在派发任何施工 agent 之前，先把测量到的客观规格（精确 CSS 值、交互模型、逐状态内容）写成 spec 文件，作为"侦察与施工之间的合同"。

**属于领域**：AI 协作工程 / 前端逆向

**通俗理解**：像装修前先请人拿激光尺量房、出图纸，再让工人照图施工——而不是"你看着办，差不多就行"。ai-website-cloner-template 强制每个组件先写 spec（全部值来自 `getComputedStyle()` 真实测量，禁止目测"看起来像 18px"），builder 的提示词里内联完整规格、零猜测。走样时可回溯：spec 错→重测，spec 对→施工错，责任可定位。核心洞见：**主观感受不可复现，客观测量才能当合同**——与 [[确定性脚本]] 同源。

**与已有概念的关联**：
- 相关：[[构建流水线与Pass]]（spec 是 Pass 之间的交接物）、[[质检Gate与自我纠错循环]]（spec 是 Gate 判错的依据）、[[AgentSkills技能包]]（该纪律写在 SKILL.md 里随技能包分发）
- **官方工业版**：GitHub Spec Kit 把本思想做成产品（2026-10 补记），纲领叫"权力反转"——规格书从服务代码的脚手架反转为源头，代码只是规格的表达产物；配套 [[项目宪法Constitution]]（跨功能约束）与 [[规格收敛循环Converge]]（验收侧闭环）
