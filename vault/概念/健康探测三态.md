# 健康探测三态

**一句话定义**：检查"命令装没装"不能只看 `which()` 找不找得到文件——必须真的执行一条无副作用探测命令（如 `--version`），并把结果分成 **missing（没装）/ broken（在但跑不起来）/ timeout·error（能跑但行为异常）** 三种状态，每种状态配不同修复处方。

**属于领域**：软件工程 / 运维与工具链（CLI 健康检查）

**通俗理解**：`shutil.which()` 只能回答"这个文件在不在 PATH 里"，回答不了"能不能跑"。经典翻车现场：系统 Python 升级后，pipx/uv 用旧 venv 的解释器路径写的 shim 脚本还在——`which()` 找得到它，一执行就 FileNotFoundError。如果你按"文件在 = 已安装"判断，就会得到一份满纸谎言的体检报告。Agent Reach 的 `probe.py` 把探测结果分三态，broken 态直接附处方："重装即可修复：`uv tool install --force xxx`"。

**与已有概念的关联**：
- 是 [[能力层与后端路由]] 的"体检器官"：doctor 命令的可信度全建立在三态探测上（单渠道异常降级为 error 不拖垮整份报告，同 [[质检Gate与自我纠错循环]] 的隔离思想）
- 与 [[确定性脚本]] 同精神：探测命令必须无副作用（幂等），因为失败会按 retries 原样重跑
- 通用模式：任何"检查依赖是否就绪"的代码都该用三态而不是布尔值——布尔值把两种修复方式完全不同的故障混为一谈
