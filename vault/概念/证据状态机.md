# 证据状态机

**一句话定义**：对"外部声明"类数据，用确定性规则把每条记录同时打上 **kind（事件种类）× state（说法状态）** 两个标签——state 至少分 announced（预告将做）/ reported（当事人自称已做）/ unconfirmed（证据不全）/ information（纯资讯）四态，并规定只有特定状态才能驱动下游动作（如倒计时）。

**属于领域**：数据采集 / 可信系统（公告追踪、状态聚合类工具的通用纪律）

**通俗理解**：同一句"reset"，说的人在不同时刻说的完全是不同的事——"明天会重置"（预告）和"重置好了"（完成通报）差着十几个小时，"网友说重置了"（未经证实）更是另一个物种。证据状态机强迫系统把这几种话分开存放、分开展示，**UI 永远不许把"他说他要做什么"渲染成"已经发生了"**。codex-claude-resets 的实现：`src/evidence.mjs` 里 100% 确定性正则（RULES_VERSION 1.4.2，零 LLM），截断的帖子一票否决跌入 unconfirmed；每轮采集还用当前规则对全部存档原文重分类——规则修复会自动清洗历史误收，但网络失败和证据不足永远不能删掉已验证的完整记录。

**与已有概念的关联**：
- 是 [[事实与判断分离]] 在"采集侧"的变体：状态判定必须交给确定性代码，绝不交给模糊语义（不请 LLM 猜一句话算不算官宣）
- 是 [[AI味模式库与信号非证据]] 的工程化正面示范："信号只是线索，证据才可行动"，两者共享"截断/歧义一律不确认"的保守底色
- 与 [[健康探测三态]] 同族纪律："查无"（零命中=健康）与"查不了"（来源失败=覆盖不完整）必须分态，正如 missing/broken/timeout 分态
- 下游动作准入制与 [[评分契约与护栏]] 呼应：只有 confirmed 状态才允许生成倒计时，相当于给"渲染层"加了护栏

**实测锚点**（2026-10-03 本机直调 classify()）：
- `Global reset landing tomorrow 10am PST for all paid ChatGPT accounts.` → global/announced/explicit-announcement
- `Reset has propagated. All reset for everyone.` → global/reported/explicit-completion
- 同一文本加 truncated:true → 一律 signal/unconfirmed/truncated

## Easel：展示状态、步骤结果与外部效果分开（2026-10-05）

[[项目笔记/easel]] 的项目展示头 `status` 接受 `draft/ready/published`，步骤记录的 `status` 接受 `done/failed`。`meta` 只更新显式传入的字段；`record` 追加历史；`latest` 返回按可选 layer 过滤后的最后一条登记记录，不自动排除失败。

真实本地组件实验中，`latest` 返回过 `failed`；修订后步骤历史为 `done → failed → done`，项目标签仍是 `draft`。因此最近记录不等于最近成功，步骤成功不自动推进展示状态，手工写成 `published` 更不等于外部平台已收到内容。外部效果仍须单独取得回执或可复核结果。

这里复用“把证据对象分开”的纪律；Easel 的两个状态域不是本文 `announced/reported/unconfirmed/information` 分类器的实现，也没有自行构成强制发布状态机。产物与记录分离见 [[产物留痕与状态外置]]；验收范围见 [[证据优先质检ProofOverClaims]]。
