# 证据状态机

**一句话定义**：对"外部声明"类数据，用确定性规则把每条记录同时打上 **kind（事件种类）× state（说法状态）** 两个标签——state 至少分 announced（预告将做）/ reported（当事人自称已做）/ unconfirmed（证据不全）/ information（纯资讯）四态，并规定只有特定状态才能驱动下游动作（如倒计时）。

**属于领域**：数据采集 / 可信系统（公告追踪、状态聚合类工具的通用纪律）

**通俗理解**：同一句"reset"，说的人在不同时刻说的完全是不同的事——"明天会重置"（预告）和"重置好了"（完成通报）差着十几个小时，"网友说重置了"（未经证实）更是另一个物种。证据状态机强迫系统把这几种话分开存放、分开展示，**UI 永远不许把"他说他要做什么"渲染成"已经发生了"**。codex-claude-resets 的实现：`src/evidence.mjs` 里 100% 确定性正则（RULES_VERSION 1.4.2，零 LLM），截断的帖子一票否决跌入 unconfirmed；每轮采集还用当前规则对全部存档原文重分类——规则修复会自动清洗历史误收，但网络失败和证据不足永远不能删掉已验证的完整记录。

**与已有概念的关联**：
- 是 [[事实与判断分离]] 在"采集侧"的变体：状态判定必须交给确定性代码，绝不交给模糊语义（不请 LLM 猜一句话算不算官宣）
- 是 [[AI味模式库与信号非证据]] 的工程化正面示范："信号只是线索，证据才可行动"，两者共享"截断/歧义一律不确认"的保守底色
- 与 [[健康探测三态]] 同族纪律："查无"（零命中=健康）与"查不了"（来源失败=覆盖不完整）必须分态，正如 missing/broken/timeout 分态
- 下游动作准入制与 [[评分契约与护栏]] 呼应：只有 confirmed 状态才允许生成倒计时，相当于给"渲染层"加了护栏

**实测锚点**（2026-10-03 本机直调 classify()）：
- `Global reset landing tomorrow 10am PST for all paid ChatGPT accounts.` → global/announced/explicit-announcement
- `Reset has propagated. All reset for everyone.` → global/reported/explicit-completion
- 同一文本加 truncated:true → 一律 signal/unconfirmed/truncated

## Easel：展示状态、步骤结果与外部效果分开（2026-10-05）

[[项目笔记/easel]] 的项目展示头 `status` 接受 `draft/ready/published`，步骤记录的 `status` 接受 `done/failed`。`meta` 只更新显式传入的字段；`record` 追加历史；`latest` 返回按可选 layer 过滤后的最后一条登记记录，不自动排除失败。

真实本地组件实验中，`latest` 返回过 `failed`；修订后步骤历史为 `done → failed → done`，项目标签仍是 `draft`。因此最近记录不等于最近成功，步骤成功不自动推进展示状态，手工写成 `published` 更不等于外部平台已收到内容。外部效果仍须单独取得回执或可复核结果。

这里复用“把证据对象分开”的纪律；Easel 的两个状态域不是本文 `announced/reported/unconfirmed/information` 分类器的实现，也没有自行构成强制发布状态机。产物与记录分离见 [[产物留痕与状态外置]]；验收范围见 [[证据优先质检ProofOverClaims]]。

来源：[Easel manifest 实现](https://github.com/ZJU-REAL/Easel/blob/6c049ceb73b1b74a73448664dcd4dbc7e051442a/skills/shared/scripts/manifest.py)、[组件实验日志](../../easel/delivery/easel-experiment-log.md)。

## OpenMuse：不确定外部写入不能强判成功或失败（2026-10-06）

[[项目笔记/openmuse]] 为证据状态补充 outcome_unknown 案例。固定 ActionService 将执行器显式标为结果未知的错误保存为该状态；恢复函数可将遗留 executing 动作转为未知。再次决定遇到非 awaiting_review 状态，返回已有提案而不自动再次 execute。

历史自写变式使用真实 PGlite 正常关闭/重开，注入提供方故意抛出“结果未知”的合成错误，最终仍为 outcome_unknown；提供方 fixture 总调用一次。它证明本地持久化和控制路径，不证明现实中发过邮件、Google 接受过请求或真实网络回执丢失。

未知不是成功，也不等于肯定未发生；直接重发可能重复，直接展示完成又缺证据。需要另取提供方记录或明确幂等能力再决定处置，当前机制没有自动完成外部对账、补偿或 exactly-once。本文原 announced/reported 等分类器与这个动作状态枚举是不同实现，只复用按证据分态的纪律。关联 [[工具调用生命周期]]、[[Checkpoint存档与持久执行]]、[[证据优先质检ProofOverClaims]]。

来源：[固定动作状态处理](https://github.com/CopilotKit/openmuse/blob/b06caad7005ac5b6d2b451752a3794a6ae1759c1/apps/server/src/actions.ts)、[中断动作恢复](https://github.com/CopilotKit/openmuse/blob/b06caad7005ac5b6d2b451752a3794a6ae1759c1/apps/server/src/db.ts)；[历史实验日志](../../openmuse/delivery/openmuse-experiment-log.md)。

## WeChatBridge：Retry 与 Delivered 只说明各自观察层（2026-10-06）

[[项目笔记/wechat_bridge]] 的 Freeze 先把集合记为 Delivering，再返回冻结批次。历史恢复检查在同一进程中新建服务并读取磁盘，遗留 Delivering 变为 Retry；部分中断状态是 harness 构造的。Retry 说明可以继续处理，不证明上一轮肯定没有粘贴，也不是强杀/断电或多消费者故障验收。

固定 BatchOutcomeKind.Delivered 的源码口径为激活目标应用并粘贴请求，不能当作接收服务器回执、上传完成或模型分析完成。本次没有执行原生前台控制、剪贴板或粘贴；Copied 的检查也仅为模型元数据。C05 只验证 schemaVersion=8 的较新账本拒绝，不能扩展成任意损坏账本均已覆盖。

因此文件存在、请求消失、投递流程返回与目标实际效果分开记录；保留源 ZIP 有利于恢复，不构成永不遗漏/重复保证。本例与 Easel 展示状态、OpenMuse outcome_unknown 相关，仍各自保留实现语义。关联 [[工具调用生命周期]]、[[产物留痕与状态外置]]、[[证据优先质检ProofOverClaims]]。
