# 用量、额度与估算费用的计量分层

**一句话定义**：Token 用量、官方窗口余量、货币余额、按价格折算的参考费用与实际结算账单，必须按来源、单位、时间范围和可用性分别建模，不能互相替代。

**属于领域**：软件可观测性 / AI 用量计量 / 数据建模。

**通俗理解**：汽车的里程表、油箱百分比和加油小票都跟“使用了多少”有关，但不是同一张表。落回 AI 工具：

- 本地处理量：从日志或指定来源的用量事件归一后统计，单位是 Token；覆盖面受来源与解析规则限制
- 官方窗口额度：提供方快照描述特定周期的余量，常为百分比或 Credits；不能由本地 Token 总量倒推
- 余额：货币金额，必须携带币种；数值小于 15 或大于 100 不自动变成百分比告急或异常值
- 估算费用：按模型价格与 Token 组成折算；缺少价格时应保留未计价，不冒充零费用
- 实际账单：依赖真实套餐、折扣与结算记录，不能用前面任一显示值直接替代

## Metrik 的固定版本案例

v0.21.1（提交 637444bdc8d91475f66f5319a15dda0e4be1c652）的 Rust TokenVector 将处理量定义为：未缓存输入 + 缓存读 + 缓存写 + 输出。reasoning_output 是输出子项，不重复加总；各来源的 input 口径须先经适配器归一。这部分只有源码审阅，没有 Rust 实测。

教学算例：100 未缓存输入 + 200 缓存读 + 50 缓存写 + 30 输出（其中推理 10）= 380，而不是 390。该式帮助解释口径，不算已执行的后端测试。

真实 JS 合成场景中，balance_cny 为 8.4 不会参与 15% 百分比告急筛选；唯一余额窗口为 168.5 时原值保留。该结构沿用 remainingPercent 字段承载金额，提醒消费者同时看类型。详细选择规则见 [[多窗口额度的展示选择规则]]。本地调用合成窗口不等于取得了真实官方余额。
