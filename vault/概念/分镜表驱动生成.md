# 分镜表驱动生成

**一句话定义**：把"主题→成片"的生成流水线拆成多个独立工序，工序之间传递的不是媒体文件，而是一份结构化 **Storyboard（分镜表）JSON**，每帧一条记录（解说词、图像提示词、素材路径、时长），各工序只负责往表里填空。

**属于领域**：AI 视频生成 / 流水线架构

**通俗理解**（比喻/例子，讲完落回术语）：像工厂的**流转单**——一件衣服经过裁剪、缝纫、熨烫，跟着走的不是衣服本身而是单据，每道工序在单据上勾掉自己的栏目。Pixelle-Video 的 `StoryboardFrame` 就是这张单：文案站只写 `narration`/`image_prompt`，素材站补 `audio_path`/`image_path`，合成站回填 `duration`——**表填满只说明结构化输入已登记；成片仍需文件存在、媒体可解码、实际渲染及声画同步与质量证据**。

**与已有概念的关联**：
- 是 [[提示词模板]] 的下游：LLM 输出被 JSON 字段钉死（每句解说 5~20 词、提示词 30~60 词），后续工序只认字段不认人话
- 与 [[JSON-IR类型化中间表示]] 同构：都是"生成结果先落成类型化中间表示，再由确定性代码消费"
- 是 [[构建流水线与Pass]] 在媒体域的实例：Pass 间传送带从代码变成数据

**首次接触于**：[[项目笔记/ai_shortdrama_tools]]（Pixelle-Video `pixelle_video/models/storyboard.py`，实验 ex1~ex5 用同构 JSON 离线复刻全链路）

## Easel 对照：字段齐全不等于产物有效（2026-10-05）

[[项目笔记/easel]] 的项目级 manifest 是 [[产物留痕与状态外置]] 的薄索引案例：登记路径、摘要和步骤状态，不自动验证路径所指文件或媒体。Storyboard 的镜头级字段与该索引有不同 schema，但都需要消费者读取真实产物并核验。不能把填表、路径登记或组件检查通过写成视频已经生成；验收应遵循 [[证据优先质检ProofOverClaims]]，保留文件、解码、渲染与质量证据。本次 Easel 实验没有执行视频生成或渲染。
