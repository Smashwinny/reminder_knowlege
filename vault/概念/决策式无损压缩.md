# 决策式无损压缩

**一句话定义**：上下文压缩的第三流派——不重写任何历史，只让决策模型（Jev）对每次工具调用/结果对逐个打置信分，**还有用的逐字保留、没用的整条删除、中间态截断**（留头部 + `re-run the tool if needed` 注记）。

**属于领域**：AI Agent / 上下文工程。同问题第三种解法：[[Compaction上下文压缩算法]] 是"切割点+模板摘要"（有损改写），[[双边缘上下文压缩]] 是"滑动擦除+冻结"（边走边擦），本流派是"**只做减法**"——删除可审计（decisions 里有每条的打分与理由），留下的每个字都是原句，所以不可能"压出一份错误的记忆"。

**通俗理解**（比喻，讲完落回术语）：像**搬家时的断舍离**——传统摘要是雇人把全部家当"描述成三句话"（描述丢什么谁也说不清）；决策式压缩是请一位估价师对每件物品打分"还需要吗"，**不要的整件扔掉，要的原样搬走**。底气在于：被扔的东西本质都是"能重新拿回来的"——文件能重读、测试能重跑、搜索能重搜（README：*the assistant can always re-run a tool or re-read a file*）。

**核心设计**（fast-jev-compaction 实测）：
- **双问题置信评估**：每个候选调用问 Jev 两个正交 `noul` 问题——`keepCall`（"知道这事发生过、参数是什么"还重要吗）与 `keepResult`（"输出原文还需要、且重跑不可代"吗）；两分组合出三分支：keep 全留 / drop_result 截留 / drop_call 整删（阈值 0.5）。例：Edit 过 `src/generated` → 内容无用（重读可得）但"动过生成目录"必须记住 → 截留。
- **只动工具对**：用户/助手文本永不改写（约束、报错、路径不蒸发）；无结果的调用不进候选；重建后不存在孤儿结果。
- **state 全量旁观**：发给 Jev 的是完整对话史（结果换成 `ok, N chars (omitted)` 注记，不总结），每批问题都重发同一份 state——考官永远看着全貌打分。
- **降压缩率闸**：压完减少量 <25% 就放弃成果回退内置摘要（短会话压无可压）。
