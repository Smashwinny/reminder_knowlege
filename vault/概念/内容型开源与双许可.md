# 内容型开源与双许可

**一句话定义**：仓库的价值大头是素材/数据而非代码（代码往往只是几十行的"查询壳"），因此按内容类型划界用两套许可——代码 MIT、视觉资产 CC BY-SA 4.0。

**属于领域**：开源工程 / 版权合规（workout-guide：80 行 TypeScript API + 906 张 SVG 插画）

**通俗理解**（比喻/例子，讲完落回术语）：像卖精装画册附赠一支普通笔——笔（代码）随便拿随便改随便转卖（MIT），画册里的画（资产）可以商用但必须署名、而且你若临摹修改后再分发，修改版也得用同样的许可继续开放（CC BY-SA 4.0 的"相同方式共享"，类似 GPL 的传染性但只传染"图"）。workout-guide 的 npm 包 license 字段特意写成 `SEE LICENSE IN LICENSES.md`，逼用户在看包信息时就必须意识到有两份许可。

**实测要点**：
- 二创溯源落到每个文件：manifest 906 帧中 76 帧逐帧记录 `attribution.source`（Everkinetic 的 URL + changes 改动说明），CC BY-SA 的署名义务被结构化元数据承接
- 用原版图 = 署名即可（App"关于"页放一行）；改图再分发 = 改动部分必须继续 CC BY-SA 4.0
- 上游（Everkinetic）与下游许可相同（均 CC BY-SA 4.0），许可链兼容不打架
- npm 包把资产和数据一并发布（35MB），代码与资产同仓不同权
