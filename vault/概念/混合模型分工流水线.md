# 混合模型分工流水线

**一句话定义**：在一条生产流水线里按**任务类型**给每道工序指派最便宜且胜任的生产者（代码旗舰/图像模型/专用 3D 生成/Headless 脚本），而不是让一个旗舰模型包揽全场；所有工序的产物最终集成回主车道。

**属于领域**：LLM 工程 / 多模型生产流水线。

**通俗理解**：装修队不会让水电工顺手做雕花——PaperRoute 的路由表：玩法物理与绑骨→Astra（天才区）；角色概念图→ChatGPT（便宜快）；带脸 3D 网格→Meshy（8 美元/个的专用工具，比烧旗舰额度便宜几个数量级）；40 栋建筑→Astra 写脚本 Headless 批产（模型只写脚本不画模型）；最后角色网格**拉回 Astra 绑 23 根骨骼**——集成永远回主车道。路由的单位是"任务类型"而非"项目"。

**与已有概念的关联**：
- 选型原理：[[能力地板选型]]（按任务的能力地板选最便宜的生产者——本概念是它在多模态流水线上的展开）
- 组织学基础：[[多智能体协作]]（拆=指令专注+工具专管）、[[构建流水线与Pass]]（每级只加工上一级的中间产物）
- 资产工序配套：[[机制流与资产流隔离]]（各车道对话物理隔离）、[[程序化建模]] + [[glTF与GLB资产管线]]（批产车道的技术底座）
- 反面教材：单一模型包揽→上下文角色混乱、成本爆炸（98% Token 是缓存读取）

**实测**：paperroute 实验把 12 条真实开发任务按规则路由，与作者实际选择一致率 12/12，成本系数 12.00→6.90。
