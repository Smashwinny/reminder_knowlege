# WebRTC机器人应用

**一句话定义**：机器人应用可以是一个纯静态网页，通过 WebRTC（浏览器原生实时音视频+数据通道）经中央信令服务器直连机器人——用户点链接就用，零安装，应用本身托管在 Hugging Face Spaces 上形成"一键安装"的应用商店。

**属于领域**：机器人 / 应用生态

**通俗理解**：传统机器人软件要装驱动、配环境，分享给别人等于劝退。Reachy Mini 把"打电话"的思路搬过来：网页 ↔ 信令服务器 ↔ 机器人，像视频通话一样把控制指令和摄像头画面实时传过去。于是"逗我的机器人"可以做成一个 URL 发给朋友；50+ 社区应用（对话、收音机、手势追踪）都长在 HF Spaces 上。对比之下 Python 应用走 daemon REST/WebSocket，适合机上控制环，两者可互调（JS 应用也能调 Python daemon 的 REST）。

**与已有概念的关联**：
- 控制通道仍是 [[机器人守护进程架构]]（daemon 统一收口硬件/WebRTC 数据通道）
- "浏览器即客户端"与 [[单源双宿主]] 的零安装分发思想同族
- 信令服务器的"租约/中继"角色类似 [[控制面与数据面]] 里的控制面
