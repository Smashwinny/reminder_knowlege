# 派生会话ID与结构脱敏

**一句话定义**：查询用的标识不由库里直接给出，而是用 `sha256(域分离串 + 快照身份 + 原始标识)` **现场派生**，且输出只给昵称等展示字段——让标识"随证据批次失效"，从结构上断掉跨批次的串联追踪。

**属于领域**：数据安全 / 隐私工程（标识最小化）。

**通俗理解**：医院不把你的身份证号写在科室叫号屏上，而是**每来一次发一个当天的号**："33 号请到诊室 2"——同一个人今天 33 号、明天 77 号，偷看叫号屏的人拼不出你的就诊历史。讲完比喻落回术语：yichen 读取器的 `chat_id = sha256("yichen-wechat-windows-reader/chat-id/v1\0" + snapshot_id 字节 + "\0" + username)[:24]`，域分离串防止跨系统撞号，snapshot_id 让同一 wxid 在不同快照里得到不同 chat_id，历史/搜索/导出**只接受 `chats` 返回的精确 chat_id**，不接受昵称模糊匹配（防同名误伤）。

**与已有概念的关联**：
- "结构字段脱敏 ≠ 全文脱敏"是该概念自带的红线：内部 username 字段不进输出，但**消息原文仍可能自然包含 wxid/手机号**——脱敏只到结构层，看全文永远要授权
- 与 [[提示注入]] 同属"数据面防御"：一个防"数据被当指令执行"，一个防"数据被当身份串联"
- 域分离派生（`domain\0` + 上下文 + 实体）与 [[内容寻址与镜像分层]] 的哈希纪律同源：哈希即身份，但不泄露原像
- 快照级隔离补充了 [[CleanRoom只读读取器]] 没覆盖的一层：CleanRoom 保证读的过程干净，派生标识保证**读完之后的数据不构成追踪档案**

**实测要点**（yichen-skills 合成快照，2026-10-03）：本地按公式派生群会话 ID 与 `chats` 返回值**逐字节一致**（同一 snapshot 内稳定、可复现）；`chats` 输出只有 display_name（"客户甲/测试群"），原始 `fixture_group@chatroom` 不出现——实验断言最初因此失败，**脱敏是设计不是 bug**；无 `account_username` 时收发方向输出 `unknown` 而非猜测。
