# Critic泄漏审查

**一句话定义**：在评估花钱**之前**，用"确定性正则预检 + LLM 意图审查"扫描候选改动，专抓"针对评分集作弊/退化/自杀式"编辑的预评估闸门（RRSI 算法 1 的最后一步，rrsi/critic.py）。

**属于领域**：AI Agent 质量工程 / 评测完整性

**通俗理解**：进化环里的模型既是考生又是出题人，它会"聪明地"作弊——把题名和答案写进提示词就是最省力的涨分。Critic 是阅卷组的纪检：六条拒绝规则——①**泄漏/任务特化**（diff 含任务名、实体名、任务专属魔数；试金石："这条改动放到另一套同类型题上还成立吗？"）②**退化**（声称加机制实为死代码，或删安全机制没补）③**评分器作弊**（偷读判分逻辑、硬编码阈值）④**未申报捆绑**（夹带申报清单外的私货）⑤**运行时记忆泄漏**（跨 trial 持久化任务专属数据=背题不是改进）⑥**无界工作**（没有退出条件的"继续改进"循环）。拒绝意见回灌提案者修复一轮（bounded repair），修不好丢弃且记入史本——被证伪的假设不允许重提。

**与已有概念的关联**：
- [[RRSI正则化递归自我改进]]：它的母系统，四闸门中的"事前闸"（噪声地板/成本规则是"事后闸"）
- [[证据优先质检ProofOverClaims]]：同族纪律——RRSI 的归因表要求每条编辑预言影响哪些题再对照实绩算命中率，是"证据优先"的进化环版
- [[质检Gate与自我纠错循环]]：Critic 就是一个带修复回路的 Gate；"bounded repair 上限"对应循环的停止条件
- [[提示注入]]：镜像关系——注入是外部数据里的恶意指令，泄漏是内部模型对评分集的过拟合性"注入"，都靠确定性规则兜底
- [[提示词爬山法PromptHillClimbing]]：爬山的"确定性 rubric"只判好坏，Critic 还要判"是不是靠作弊变好的"——评测对象能自我修改时必须加这一层

**首次接触于**：[[项目笔记/rrsi]]（实验：toy_rrsi.py 泄漏提案者被两条正则连续拦截、bounded repair 3 轮终止；关掉 Critic 后进化集满分但留出回归套件 0.000——审查的价值一次看全）
