# 确定性快进与真渲染取证

**一句话定义**：给"会动的网页程序"做自动化验收的套路——固定时间步模拟 + URL 参数 `?t=秒数` 让页面在加载时一步不跳地快进到指定时刻并停表，再用无头浏览器抓 DOM 里的 HUD 状态做断言、抓 GPU 截图做像素级比对。

**属于领域**：前端/游戏自动化测试。

**通俗理解**：动画程序最难测，因为它"每一帧都不一样"。解法是把时间变成输入：把"播放"变成"快进到第 4.6 秒然后站住"——同一时刻永远同一画面，截图才能对比、HUD 才能有标准答案。证据分两层：HUD 文本（页面自报状态）只能算口供，GPU 截图的像素差（真渲染产物）才是物证——页面自己汇报"我走了 3.8 格"不算数，截图里人物位置变化 + 两帧像素 diff 才算数。等价于给浏览器版的程序加了个"时间机器命令行"。

**与已有概念的关联**：
- 地基：[[纯函数游戏引擎与种子复放]]（固定时间步 + 种子 PRNG，快进才可复现）
- 证据观：[[证据优先质检ProofOverClaims]]（HUD=自述，截图=实证，口供不作数）
- 上游：[[质检Gate与自我纠错循环]]（14 项断言 fail 即退出码非零，可挂 CI）
- 实操坑：无头 Edge `--screenshot` 必须绝对路径（相对路径"拒绝访问"）；用户数据目录磁盘缓存可能让页面吃到旧 JS 造成"幽灵 flake"，换 `--user-data-dir` 或清缓存再判
