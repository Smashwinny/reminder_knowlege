# 指令优先级层级

**一句话定义**：Agent 上下文里同时飘着安全约束、用户当前指令、项目规则、全局偏好、历史记忆五种指令源，冲突时按"安全 > 当前指令 > 项目规则 > 全局规则 > 技能与记忆"仲裁——越靠近"当下、具体"的越优先，越"陈旧、泛化"的越靠后。

**属于领域**：AI 工具生态 / Agent 工程

**通俗理解**：就是操作系统的**中断优先级表**搬进提示词工程：着火警报（安全）永远压过老板昨天说的废话（记忆）。不写这张表，多源指令冲突时模型只能"猜"，猜错一次就是一次事故——比如历史记忆里"用户喜欢简短回答"盖过了今天的"详细分析这份合同"。AGENT.md 模板把它列为第二板块，因为它是其他一切规则能生效的前提：先说清谁听谁的，规则才有执行的秩序。

**要点**：
- 开源模型实测里 "记忆/历史偏好覆盖当前明确指令" 是最常见的翻车模式，当前指令显式优先正是治这个
- 项目内 AGENTS.md 只在该项目范围内补充或覆盖全局规则——作用域思想与配置系统一致
- 顶层必须钉死"遵守系统、平台和安全约束"：这是压警告类规则的保险丝（实验证明"别加未经请求的警告"规则会把真风险提示也压掉，见 [[Agent指令文件AgentMd]] 的双刃剑）

**与已有概念的关联**：
- 是 [[Agent指令文件AgentMd]] 六板块中的仲裁核心
- 与 [[提示词权威边界]] 互补：权威边界管 skill 内部"谁有权改哪一段"（横向产权），本概念管"多层指令谁听谁"（纵向序）
- 与 [[提示注入]] 直接相关：注入攻击的本质就是想把你伪造的指令塞进优先级更高的一层，层级越清晰、注入越难找空子
- 仲裁序思想同 [[能力层与后端路由]] 的"有序后端列表，第一个真实可用者当选"——都是"预先写死仲裁规则，免得运行时临场猜"
