# CleanRoom只读读取器

**一句话定义**：独立实现的、只解析静态数据文件而不触碰目标进程的读取器——"不获取密钥、不重签名、不注入、不 Hook"。

**属于领域**：数据安全 / 逆向工程的合法边界设计。

**通俗理解**：把微信数据库想象成别人家的保险柜。Hook/注入是"在保安身上装窃听器"（混入进程，可被察觉、可被惩罚）；clean-room reader 是"你本人把钥匙和柜子借给我，我只在你家客厅读文件、不还手不复制钥匙"。读的是死数据，进程完全无感知，所以边界清晰、风险低。讲完比喻落回术语：clean-room = 不依赖目标程序运行时、纯离线解析其存储格式的独立实现。

**与已有概念的关联**：
- 是 [[事实与判断分离]] 里"事实层"的数据来源前提：只读保证了事实不被篡改
- 授权材料（schema-2 salt-key 由本人提供）把"能不能读"从技术问题变成授权问题，呼应 [[提示词权威边界]] 的"授权硬门"思想
- 读取链路的三道门：SQLCipher 整库加密 → WCDB 的 zstd 压缩消息体 → 明文（见项目笔记实测）

**实测要点**（wechat-intelligence-hub）：无授权数据库时 `home`/`db-status` 明确报"找不到数据库"，不降级、不猜测；macOS 有实验性接入助手（重签名副本，需单独确认），Windows 首次取钥未合入。
