# RAG 架构谱系

**一句话定义**：在基础 RAG（先检索后回答）之上，针对"检索时机、文档质量、问题难度、全局视野"四类痛点演化出的五个改进架构。

**属于领域**：AI / 检索（Agent 架构）

**通俗理解**（各治什么病）：
- **Agentic RAG**：普通 RAG 不管要不要都先检索 → 把检索降级成 Agent 的一个工具，何时查、查什么、查几次自己定（一个小 ReAct 循环）。
- **CRAG**：检回一堆无关文档照样用 → 每篇文档打三档分（相关/模糊/无关），多数无关就降级走网络搜索兜底。
- **Self-RAG**：检索时机靠运气 → 模型自发输出 reflection token（needs_retrieval、相关性、支持度），Python 合成取舍。
- **Adaptive RAG**：简单问题也走全流程 → 先给问题分类定级（免检索/单跳/多跳），按级路由。
- **GraphRAG**："全书/全库讲了什么"这类全局问题向量检索抓瞎 → 抽实体关系建知识图谱，社区聚类+每社区预生成摘要，全局问题读摘要。
