# 上下文接力

**一句话定义**：规划现场（贵模型的对话窗口）与执行现场（编码 Agent）分属两个产品面时，用官方一键搬运（如 ChatGPT 的"添加到 Codex"按钮）或一份方案文档（`PLAN.md`/spec），把规划的全部推理成果零损耗送进执行端的上下文——**规划的产物是文档，执行的输入也是文档，文档就是那条管道**。

**属于领域**：AI 工具生态 / 工作流。

**通俗理解**：老中医开完方子，不用你抄一遍再跑去药房——医院系统直接把方子推到药房窗口（"添加到 Codex"）。没有这条管道时退化为手动接力：把方案落成 md 文件，执行端开工时读取。执行端的接法也有讲究：用**授权式**执行 Prompt（"验证并做掉方案里所有值得做的优化"）而非逐条点名，把二次决策也交给执行端；执行档位开"高"，轻度档反复失败省下的小钱会被重试烧回去。

**与已有概念的关联**：
- [[规划执行分账]]：分账之后两本账之间怎么交货——本概念就是那条传送带
- [[规格书先行SpecDriven]]：接力物件的规范写法（实测值/验收标准进 spec）
- [[Agent指令文件AgentMd]]：md 文档当行为管道的同族用法（一个管"怎么干"，一个管"干什么"）
- [[构建流水线与Pass]]：每级只加工上一级的中间产物——接力就是 Pass 间的传送带
- [[人机协同Interrupt]]：反向通道（执行端暂停等人），与正向前送互补
