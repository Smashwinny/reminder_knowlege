# 净边际与多跳套利环

**一句话定义**：跨所搬砖的可行性判据 **净边际 = 毛价差 − 双腿手续费 − 滑点 − 延迟惩罚**，不过门槛直接拒绝；推广到多跳是**把每跳汇率取 −log(rate×(1−fee)) 变边权，找边权和为负的回路（Bellman-Ford 负环）**——负环 ⟺ 绕一圈钱变多。

**属于领域**：金融量化 / 套利 + 图论

**通俗理解**：净边际是"搬砖前先称重"——看起来两地米价不同，但来回路费比差价贵就不搬。多跳版本是"货币兑一圈"：美元→日元→欧元→美元，绕一圈变多就是机会；取 −log 是为了把"乘积汇率>1"变成"边权和<0"，乘法变加法，才能用图论成熟算法一次扫全图。

**CloddsBot 的实现**（docs/V2_HFT_ARBITRAGE.md）：venue planner（选买入所/卖出席位，扣手续费/陈旧报价/延迟/库存惩罚，输出双腿执行计划，分 taker_taker / maker_taker / maker_maker 三档）+ multi-hop planner（3~4 跳环搜索、逐跳传导容量）+ **延迟感知排序**（同等条件优先低延迟路径——套利的本质是抢时间）。

**实测数据**（cloddsbot ex2/ex3，2026-10-03，真实行情）：
- OKX vs Kraken BTC 毛价差 0.0007%~0.011%，双 taker 费 0.36% → 净边际 **−0.36%**，两方向全拒；
- OKX 三元组 BTC→USDT→ETH→BTC 扣每跳 0.1% 后边权和 +0.0030，资金乘数 0.997，无负环。

**大坑**：环方向汇率语义写反（该用"换到÷换出"却用倒数），负环"满地都是"报出 71 亿倍乘数——**套利检测器最危险的 bug 是把必亏报成暴富**。
