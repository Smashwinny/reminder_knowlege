# 格式压力编因

**一句话定义**：任何强制输出格式（"必须按 因→修法 汇报错误"等模板/字段/章节）都会对模型施加**填空压力**——当证据不足以填满格式时，模型倾向于编造内容来填满它，而不是留白。

**属于领域**：LLM 可靠性 / 评测（[[Agent评测框架八步法]] 的负面机制）

**通俗理解**：格式像一张必须写满的答题卡；模型手里的证据只有半格，但它不会交白卷，会现编半格。"错误必须说因和修法"的规则 + 证据只有症状 → 模型硬指认一个原因。i-have-adhd 官方评测的 partial-success 用例 −0.63 回归正是此机制：评审批语"断言 missing auth header 为确定性原因而证据不支持"。

**与已有概念的关联**：
- 检测侧：[[LLM裁判与自动评估]] / Rules 层抓编造来源——格式压力制造幻觉、评测层负责抓，是同一现象的两侧
- 防御侧：给模板加逃生舱（"证据不足时只报症状，不下因"），规则声明"内容赢过形状"
- 诚实下结论的示范：3 trials 不够下结论时标注"方向一致+有机制假设的待验证项"，不悄悄删数据——[[证据优先质检ProofOverClaims]]、[[AI味模式库与信号非证据]]
