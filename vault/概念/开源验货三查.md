# 开源验货三查

**一句话定义**：自称"Open Source"的项目要查三样——LICENSE 文件在不在、关键功能是源码还是闭源二进制、宣传能力与仓库实货是否一致；本项目（Faceplugin 人脸 SDK）三条中两枪。

**属于领域**：软件工程（开源合规与供应链审计）

**通俗理解**：README 挂个绿色 "License-Open Source" 徽章不等于开源——仓库里没有 LICENSE 文件时法律上默认"保留所有权利"，商用就是裸奔。同样，核心功能（如人脸对齐+姿态）编译在 70KB 的 `FaceUtil.dll/.so` 里只给你 ctypes 调用壳，这也只是"源码开放的周边+闭源的核心"。闭源 ≠ 完全黑盒：`strings`/`nm` 读未剥离符号表就能静态取证——libFaceUtil.so 里的 Jacobi SVD、Cholesky、Rodrigues 函数名直接暴露了"2D 关键点拟合 3D 人脸模板做 SVD 最小二乘解姿态"的经典套路。

**与已有概念的关联**：
- 三查清单：① LICENSE 类型（MIT/Apache 随便用，无文件=风险）② 关键路径是源码还是 dll/so/exe ③ 权重是否随仓库发布（外链挂了项目就死）
- 宣传 vs 实货：README 宣传活体检测/表情分析，代码里只有检测+关键点+特征+比对四样——以 "Current Capabilities" 和代码为准（[[证据优先质检ProofOverClaims]] 的选型版）
- 闭源二进制静态取证：符号表/字符串/导入导出表是合法侦察面，黑盒对拍是兜底验证
- "离线承诺"也要验证：抓包/断网实测，本 SDK 属实（与 [[本地推理引擎]] 的隐私哲学互链）
