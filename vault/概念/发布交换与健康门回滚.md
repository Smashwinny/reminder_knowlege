# 发布交换与健康门回滚

**一句话定义**：OTA 更新不走"打补丁"，而是把新版本作为完整目录下载 → 验签 → 切换 `current` 软链接 → 重启 → 问控制环"你还健康吗"，不健康自动切回旧版。

**属于领域**：软件发布工程 / 嵌入式 OTA

**通俗理解**：换轮子不补轮子——新轮胎整只拿上来，坏了整只换回去。microduck（updaterd）在 $399 的玩具鸭子上执行了比很多大厂还严的发布纪律：签名验证 → 整目录交换（发布是**切换**不是**修改**，永远有退路）→ **健康门**（health gate：重启后必须由 robotd 自证健康，否则自动回滚）→ boot counter 兜底防"崩溃循环"（反复起不来的版本直接拦在引导计数上）。整套纪律跑在一台 $399 的设备上。

**与已有概念的关联**：
- 与 [[Checkpoint存档与持久执行]] 同属"出事退回上一个好状态"家族：checkpoint 退进程状态，这里退整个软件版本
- "发布=原子切换指针"与 [[内容寻址与镜像分层]] 的不可变镜像 + 引用切换同构
- 健康探测思想同 [[健康探测三态]]
