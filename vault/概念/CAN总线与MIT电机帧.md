# CAN总线与MIT电机帧

**一句话定义**：CAN 总线 = 汽车/机器人级 2 线差分串行总线，一条线按 ID 挂多颗电机；MIT 模式帧 = MIT 猎豹约定的 8 字节电机控制帧，把 q/dq/kp/kd/tau 五个控制量用定点压缩塞进 64 bit（16+12+12+12+12）。

**属于领域**：机器人学 / 嵌入式通信

**通俗理解**：一条 CAN 线像"一条对讲总线，每个电机有工号喊话"（同 [[智能舵机与菊花链总线]] 的思想，只是协议换成汽车级、速率更高）；MIT 帧则像"把五个浮点数叠进 8 个信封"——定点映射 u=(x-min)/(max-min)×(2^bits-1) 后逐位拼装：q 占 16bit（±12.5rad，分辨率 0.00038rad），dq/kp/kd/tau 各 12bit。反馈帧另有一种位排布：D0 高 4 位藏 9 种错误码（过压/过流/过热/失联…），低 4 位是电机 ID。**命令帧与反馈帧位排布不同**——OpenArm 实测坑：拿反馈布局解命令帧，tau 误差能到 18.97 N·m（应为 ≤0.0024）。

**与已有概念的关联**：
- 相比 [[舵机与PWM角度控制]]（一舵一线 PWM 脉宽）与 [[智能舵机与菊花链总线]]（单总线轮询），CAN 是工业级多主总线
- MIT 帧里的 kp/kd 就是 PD 增益，配合 [[QDD准直驱与反驱力控]] 的重力补偿前馈构成完整力控指令
- OpenArm 用 Python 逐位复刻实测：手算 0x8A3D 一致、1000 组 roundtrip 误差全 ≤ 半分辨率
- 上位协议与 [[策略观测向量与动作契约]] 的"逐槽对齐"同哲学：位排布即合同
