# PromptAsCode提示词即代码

**一句话定义**：把图像生成提示词从一次性文案升级为**有固定结构、有参数槽位、可批量生成、可质检的代码资产**——主体任务、构图布局、文字标签、风格材质、整体氛围、比例输出+负向约束六块各占一个"代码块"，变量用 `[大写占位符]` 声明。

**属于领域**：AI / 提示工程（图像生成方向）

**通俗理解**：散文式提示词像跟装修师傅口头说"装得温馨点"；Prompt as Code 是**施工图纸**——哪面墙什么颜色、插座打在哪全部写死。模型失去自由发挥，你失去惊吓。实测好提示词平均 1257 字符（awesome-gpt-image-2 全库统计），一句话抽不出好图。

**要点**：
- 六块协议顺序可变，但缺块就会"抽卡"；其中**文字渲染必须逐字锁定**（图像模型最大翻车点）
- 每个领域有现成模板可填空（awesome-gpt-image-2 提供 21 套工业模板，每套带避坑指南）
- JSON 进阶模板直接可作 Agent/API 入参，生成前还能校验字段
- 模板是**模型无关**的：GPT-Image、即梦、GLM 出图都适用

**与已有概念的关联**：
- 同源思想：[[提示词模板]]（LangChain 管文本话术槽位，本概念管整条图像提示词的架构）
- 官方版同源：[[图像提示八要素]]（OpenAI 官方 8 条原则，与六块协议互查补位：官方讲为什么、六块讲怎么填）
- 质检配套：把避坑指南翻译成确定性规则即 Prompt Lint，见 [[质检Gate与自我纠错循环]]
- 人格/语气类提示工程：[[角色提示]]（管人格，本概念管画面结构）
- 技能化：该库自带 Agent Skill，见 [[AgentSkills技能包]]

## Qwen-Image-2.1：检查点与提示协议作为一组配置（2026-10-05）

[[项目笔记/qwen_image_2_1]] 复用提示词资产化与版本化思路，但本例不表示上文六块模板可无条件跨模型通用。固定版官方改写器把文生图扩写与编辑改写分成两个经过后训练的检查点，各自配套系统提示；它们共享代码，不共享一份可任意互换的提示协议。图像生成模型、生成管线的文本编码器和这个独立改写器也是不同组件。

可复现条件应一起记录：检查点版本、系统提示文件内容及指纹、`t2i/edit` profile、输入形状、实际生效的采样参数、解析器版本与依赖状态。已有实验读取并核对了 profile：t2i 的 `presence_penalty=1.5`、token 预算 16256；edit 为 0 与 24000。这是配置对象的真实执行检查，没有运行采样或证明改写质量。

源码中的 `load_system_prompt` 优先选显式文件，否则查找检查点目录的 `system_prompt.txt`；这只是文件选择规则，不能校验提示语义与权重真的匹配。`resolve_image_paths` 对 t2i 带图报错、要求 edit 至少一张现存图片；这些路径及系统提示读取仅作源码观察，未纳入 21 项执行检查，文件存在也不等于解码或安全检查通过。

本次将“检查点与提示协议整体版本化”保留为配置管理项目案例，不把它与 [[提示词模板]] 的变量槽位、[[LLM采样与温度]] 的采样机制或 [[固定版本中的跨文件时间漂移]] 的文档同步问题强行合为同义词。旧 Prompt Lint 分数只代表其规则命中，不迁移为 Qwen 出图质量保证。
