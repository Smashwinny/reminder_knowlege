# 集成编排层

**一句话**：当散件生态成熟到"每个组件都会装但没人会连"时，集成编排层（装什么版本/谁先起/端口分配/健康重启/能力降级）成为独立价值层——ODS 是本地 AI 域的样本，"编排 know-how"是被低估的资产。

**领域**：集成编排 / 运维架构。来源：[[项目笔记/ods_local_ai_server]]（1046 collected→2500 passed 全量测试，平台归因诚实）。

编排三职责：生命周期（装/起/重启）、拓扑（端口/发现/互连）、能力映射（硬件档位→模型档位→云端回退）。

集成项目≠脚本合集的分水岭：组件是否各自带测试/契约。

隐藏成本律：一行命令吸收集成工序，不吸收运维本身；预发布期识别。

反模式：把编排层当组件用（锁死单组件升级）；忽略平台真实（macOS/Linux-first 项目的 Windows 支持要查证测试）。
