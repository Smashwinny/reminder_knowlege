# 预执行安全网与执行事件

**一句话定义**：GUI Agent 动作落地前的**确定性核查层**——用最新 UI 层级核对"要碰的元素还在不在原处"（坐标小漂移直接自愈，失败分 shifted/occupied/disappeared 三类），失败不开新会话不派修理工，而是开一个**执行事件（execution incident）**带着连续失败计数持久挂进 Operator 上下文，直到某动作真正成功才自动销毁。

**属于领域**：AI Agent / 可靠性（[[质检Gate与自我纠错循环]] 的"动前 Gate"版 + [[护栏模式Guardrails]] 的确定性校验内层）

**通俗理解**（比喻/例子，讲完落回术语）：像**手术前的三方核对**——护士（validator）拿清单核对"这正是要切的那个器官"（目标元素还在屏幕上吗），位置差一点直接帮医生把手挪正（坐标自愈）；发现对不上就大声报出来并**写在手术室的板上**（执行事件挂上下文），主刀医生（Operator）自己决定换术式，直到某一步真正成功才把板擦了。两个反直觉的设计：①**没有独立的"修理工 Agent"**——恢复是主力的责任，不另立角色；②**失败计数如实展示**——连续失败几次就是几次，不当 filter 掉也不渲染成顺利。

**配套细节**（ARTEMIS 实现）：收尾动作逐个过安全网；多个快速动作可打包成 **fast-action burst** 连发跳过安全网——这是打"瞬逝 UI"（自动消失的播放条/Toast）的官方姿势，安全与速度按需切换而非一刀切。

**与已有概念的关联**：
- [[质检Gate与自我纠错循环]]：Gate 管放行，事件管"Gate 拦下之后怎么办"
- [[护栏模式Guardrails]]：确定性校验（XML 层级比对）永远包住模型判断
- [[Agent设计模式目录]] 的反思模式：事件是"生成-批评循环"的轻量挂载点，批评结果进上下文而非外部队列
- [[证据状态机]]：同样的"状态要如实可追溯"纪律——失败计数不是装饰，是给模型看的事实
- [[GUIAgent与多模态定位]]：安全网核对的正是定位结果，两者组成"找得准 + 碰得稳"
