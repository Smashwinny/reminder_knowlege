# Agent后训练SFT与RL

**一句话定义**：让 Agent 背后的模型比"调 API"更进一步的两种训练法——SFT 拿专家轨迹教"动作长什么样"（模仿），RL 拿可验证奖励教"怎样做得更好"（超越）；CMU 11-768 用整整四讲（SFT→RL 基础→高级算法→RL Systems）讲这条流水线。

**属于领域**：AI Agent / 模型训练（区别于推理侧的 [[Agent循环]] 与 [[AgentHarness智能体挽具]]）

**通俗理解**：SFT 是"把老师傅的操作录像放给徒弟看"——任务→一系列推理+工具调用+观察→成功收尾的完整轨迹当训练数据，徒弟学会招式但超不过师傅；RL 是"让徒弟自己下场做题，对了给糖"——奖励来自**自动可判定的信号**（测试通过没、棋赢没、引用真实没），所以能突破示范者上限。

**为什么 harness 和 eval 必须在前面**：SFT 的训练样本格式 = harness 跑出来的轨迹日志格式；RL 的奖励信号 = eval 框架的判定函数。**没有 harness 就没有数据，没有 eval 就没有奖励**——这就是 11-768 作业链（Harness→Eval→Training）的方法论根据。

**RL Systems 的工程真相**：瓶颈常不在梯度而在 **rollout**——要对海量任务各自跑完整 agent 轨迹，沙箱基建、生成吞吐、样本回收才是系统设计题（课程为此给作业配了 Modal 云沙箱+算力赞助）。

**与已有概念的关联**：
- [[AgentHarness智能体挽具]]：训练数据的"生产线"；[[LLM裁判与自动评估]]：奖励信号的来源
- [[上下文预算与战略压缩]]：训练侧也吃上下文账，rollout 轨迹的长度直接决定成本
- 机器人 RL 见 [[Sim2Real与MuJoCo仿真]]（奖励同样来自仿真可判定信号，但模态不同）
