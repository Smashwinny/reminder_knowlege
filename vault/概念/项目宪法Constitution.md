# 项目宪法Constitution

**一句话定义**：在 AI 施工项目里先写一份 `constitution.md`（核心原则 + 质量红线 + 技术约束），**全项目只写一次，之后每个功能的规格/计划/任务生成时都必须引用它做合规检查，冲突时宪法赢**。

**属于领域**：AI 协作工程 / 规格驱动开发（github/spec-kit 首创环节）

**通俗理解**：单个功能的规格书管"这个功能长什么样"，宪法管"这个项目永远不许干什么"——好比公司章程与项目计划的区别：换十个项目经理（功能），章程不变。宪法写了"测试先行不可谈判"，AI 就不许在任务清单里把补测试排到最后；写了"Library-First"，每个功能就得先长成独立库。Spec Kit 用 `/speckit-constitution` 一次生成，存在 `.specify/memory/constitution.md`，属于"记忆"目录——它是**跨功能持久的约束**，与一次性工件（spec/plan/tasks）分开放。

**与已有概念的关联**：
- 是 [[提示词权威边界]] 的项目级放大：那边宪法管一次生成的风格产权，这边宪法管整个项目的质量红线，同为"把约束写成文件、按优先级裁决"的结构
- 是 [[规格书先行SpecDriven]] 的上层配套：spec 是单功能合同，宪法是所有合同共同的缔约原则
- 载体是 [[AgentSkills技能包]]：/speckit-constitution 技能负责生成，其余技能施工时引用
- 思想同 [[修改与约束分离]]：约束（宪法）一旦定下，施工层不得越权修改
