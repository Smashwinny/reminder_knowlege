# Agent指令文件AgentMd

**一句话定义**：放在仓库/配置目录里的纯 Markdown 行为契约——Agent 软件每次接任务时自动把它拼进系统提示，让模型的行为基线（沟通风格、优先级、干活姿态、测试力度）可由用户用文本定制，不用改软件源码。

**属于领域**：AI 工具生态 / Agent 工程

**通俗理解**：模型每次会话都是"新员工"，没有记性，所以规矩必须每次重新发一遍——AGENT.md 就是那张贴在墙上、每天上班先看一眼的《员工守则》。写成文件而非写死在代码里，换来三样东西：用户可改、git 可管（diff 一眼看清哪条规矩哪天改的）、换 agent 软件可带走。它管的是**行为纪律**（你怎么干活），不是人格设定（你是谁）也不是单条话术（说什么）。

**要点**：
- 卡兹克 GPT-6 Astra 模板的六板块覆盖 AI 员工完整生命周期：沟通（说中文/先结论/少列表）→ 指令优先级 → 执行方式（先干完再问/别迎合/别瞎警告）→ 测试与验证（按改动大小分级）→ 工具与并行（rg/批量读/子代理克制）→ 规则来源（SSOT）
- **好规则的标准：每条规则必须对应一个真实被烦到过的失败模式**——"保持专业高质量"这类装饰性规则等于没写
- 真机 A/B 实测（glm-4.6，3 场景×各 3 次，正则确定性打分）：列表行 3.33→0、结论先行 0→100%、未经请求的 SQL 注入警告从"首行就是⚠️警告"压到 0——**规则不是玄学，效果可测量**
- 双刃剑：压警告的规则会把真风险提示也压掉，安全红线必须放在系统层（模板自己也把"遵守系统、平台和安全约束"列为最优先）
- 单轮问答任务上效果很小——这些规则治的病（磨叽、中途反复问、过度测试）主要发生在长会话 agentic 工作流里
