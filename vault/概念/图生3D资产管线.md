# 图生 3D 资产管线

**一句话定义**：把一张设计图经"生成 → 导出 → 批量清洗 → 接入引擎"四步变成能进游戏/网页的 3D 资产的商业化生产流水线（Tripo Studio 是代表）——研究模型（[[LRM大型重建模型]]）只负责"一次前向出网格"，产品管线要管贴图、拓扑、面数、朝向、显存一整条后处理链。

**属于领域**：三维图形 × AI 生成 × 资产工程

**通俗理解**：研究模型像"一次性把泥坯捏出来"，产品管线是"泥坯到上货架之间的整条工厂线"：灰模要上色（贴图生成，另付费）、面要数过（口径陷阱）、型要归一（y=0 落地 + 按对齐维度缩放）、街要摆得下（近景 AI 远景程序化分层）。花叔《3D Vibe Coding》386 页实测记录了全链路的价目与坑：几何底价 15 积分、贴图档 2K+15/4K+25/8K+35，默认价的一半在买你导出时就要降掉的 8K 贴图——生成选 2K 导出选 1k，两头都省。

**与已有概念的关联**：
- 学术底座：[[LRM大型重建模型]] + [[Triplane三平面表示]]（TripoSR 是同一家 Tripo/VAST 的开源研究版，本地 2 秒出灰模；产品版按积分计费并带全套后处理）
- 产物格式：[[glTF与GLB资产管线]]（注意 KHR_mesh_quantization 的 normalized int16 坐标坑）
- 工序哲学：[[混合模型分工流水线]]（设计图→提示词→GLB 是资产流）、[[机制流与资产流隔离]]；分层判据 §15"近景要细节给 AI 模型，远景只要那儿有个东西给代码"（巴黎 2 万株程序化树 9 draw call vs 150 株 GLB 树=预算 26 倍）
- 接 Agent：CLI / Codex 插件 / MCP 三条路共享一个与 Studio 订阅**不互通**的 API 钱包（[[MCP协议]] 的 tripo mcp 路线）；四边面存不进 GLB（quad 强制 FBX）
- P2.0 接入五道工序：FBX转GLB → 降8K贴图 → 定yaw（六视图法，包围盒推不出朝向）→ 烘变换进顶点 → A/B帧时间

**坑清单（实测）**：响应式框架托管的输入框改 DOM 不改状态（面数 15000 提交成 5000，65 积分白花；ArrowRight 硬验证法）；"自动保存设置"跨会话记加项却不记面数；浏览器自动化停在系统"另存为"弹窗（走 API 直链绕开）；P2.0 只出 base color 一张图，别找不存在的法线图。
