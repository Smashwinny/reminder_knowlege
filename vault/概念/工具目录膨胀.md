# 工具目录膨胀

**一句话定义**：MCP 客户端要把每个工具的名称+描述+参数 schema 全量塞进模型上下文，工具一多（TikHub 1007 个）目录本身就是最大的 token 开销——实测 TikHub 单平台（TikTok 162 工具）目录 JSON ≈ 24,846 tokens，约占 128k 窗口的 20%。

**属于领域**：AI 工具生态 / MCP 架构；是 [[KV缓存与上下文]]（上下文是按 token 计费的稀缺资源）在工具接入维度的具体账单。

**通俗理解**：给 AI 发一本 1000 页的工具电话簿——它每次干活都得先把整本读完再动手。电话簿不是免费的：按 token 计费、挤占真正干活的思考空间。所以"工具越多越强"有个隐含上限。

**主流解法谱系**：
- 按域拆分服务器（TikHub：17 平台各一台，"只挂你用的"；粗粒度，单平台内仍全量 tools/list）
- 小入口常驻+大主体待命（[[分层按需加载]]，Agent-Reach 默认只激活 6 渠道）
- 动态工具发现（AgentKey find_tools：Agent 先搜工具再调用，目录不常驻）
