# 工单任务图与前沿调度

**一句话定义**：把一个 spec 拆成带**阻塞关系**的工单（ticket）有向无环图而不是线性步骤清单——任何时刻"入度为零"的工单构成**前沿（frontier）**，可以并行派发给多个施工子代理；每完工一张，前沿就向外推进一格。

**属于领域**：AI 协作工程 / 多智能体施工编排（mattpocock implement-spec skill）

**通俗理解**：步骤清单是**接力赛**——1 号跑完 2 号才能跑，全程只能有一个人在跑；任务图是**跳水决赛**——裁判（spec）把动作拆成互相独立的打分项，没有依赖关系的选手同时上场。关键操作只有两个：① 挑出当前所有"没人挡路的工单"（frontier）；② 谁完工了就重新算一遍谁是新的"没人挡路"的。本仓库的 implement-spec 微型实验里，T1(分词) 无阻塞先跑，T2(排行) 只依赖 T1，T3(命令行) 依赖 T1+T2——T1 完工瞬间 T2 即入前沿，不是傻等 T1→T2→T3 排队。

**与已有概念的关联**：
- 是 [[规格书先行SpecDriven]] 的**执行侧续篇**：spec 是合同，任务图是把合同拆成可并行验收的工单
- 物理隔离靠 [[GitWorktree并行隔离]]：每个施工子代理在自己的 worktree/分支上干活，完工 merge 回 integration 分支
- 编排思想同 [[多智能体协作]]、[[LangGraph与Agent编排]]（图+依赖拓扑），但粒度是"整个功能"而非"一次对话"
- 收尾调用 code-review，衔接 [[质检Gate与自我纠错循环]]
