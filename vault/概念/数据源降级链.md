# 数据源降级链

**一句话定义**：把多个不稳定的上游数据源做成同接口适配器，按优先级排成有序列表，第一个成功的当选、失败的自动降级到下一个，外加限速与超时隔离，保证"上游随时会挂"的现实下聚合层永远有数据产出。

**属于领域**：数据工程（金融行情聚合是典型场景）

**通俗理解**：像打车软件派单——滴滴叫不到就叫高德，再不行叫美团；乘客（业务代码）只说"我要去机场"（统一接口），从不关心哪家车队接的单。daily_stock_analysis 里 19 个 fetcher（efinance→akshare→tushare→pytdx→baostock→yfinance→longbridge）排队上岗，每个还有三件保命装备：**子进程+超时强杀**（爬虫库卡死不拖垮主流程）、**随机限速 2~5 秒**（防封禁）、**列名归一化**（各源中文列名统一成 open/close/high/low/volume 才能进同一根管道）。

**与已有概念的关联**：
- 与 [[能力层与后端路由]] 同构：都是"有序后端候选列表 + 第一个真实可用者当选"，只是路由对象从 CLI 工具换成行情 API；区别是降级链重在**运行时容错**（限流/断网自动切换），能力层还管安装体检
- "超时强杀子进程"与 [[健康探测三态]] 的 timeout 态呼应：探测不能证明能跑，超时必须当失败处理
- 新闻线与行情线**双管道分离**，新闻失败不阻断主分析、报告里如实标注——诚实披露思想同 [[评分契约与护栏]]
