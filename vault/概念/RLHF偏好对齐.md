# RLHF偏好对齐

**一句话定义**：预训练/SFT 之后的"学人类口味"阶段——让模型不仅"答得对"，还要"答得让人喜欢"：收集人类（或 AI 裁判）对多个回答的偏好排序，用 DPO（直接对比排序）或 PPO/GRPO（强化学习最大化奖励）把模型往高偏好方向推。

**属于领域**：AI / 大语言模型（后训练 / 对齐）

**通俗理解**：SFT 是学徒看师傅示范学招式；偏好对齐是"顾客点评"——同一个问题给两个回答让人挑哪个好，模型学着多产被挑中的那种。DPO 是"直接记对比笔记"（好回答的相对概率要压过坏回答），PPO/GRPO 是"先立个打分裁判（奖励模型），再下场打比赛赢高分"。

**关键事实**（MiniMind 全部手写实现，管线最全的开源教学项目之一）：
- 阶段谱系：RLHF（人类标注）→ RLAIF（AI 反馈替代人类）；MiniMind 两者都覆盖
- DPO：`train_dpo.py`，数据为"好/坏回答成对"，loss 直接优化偏好对数几率，无需单独训练奖励模型，稳定便宜
- PPO：`train_ppo.py`，经典 Actor-Critic + KL 惩罚（防模型偏离太远崩掉）
- GRPO：`train_grpo.py`，DeepSeek-R1 带火的算法——对同一问题采样一组回答，用组内相对排名当优势函数，**不需要价值网络**，省显存好并行
- CISPO：MiniMind 新增的剪辑重要性采样变体
- 工程真相：RL 阶段的瓶颈常在 rollout（采样生成）而非梯度计算，与 [[Agent后训练SFT与RL]] 的洞察一致
