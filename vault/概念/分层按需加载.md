# 分层按需加载

**一句话定义**：把大知识库分成"小入口常驻上下文 + 大主体躺在磁盘"，AI 先读入口、命中才去磁盘取对应层，从而用 3% 的上下文预算撬动 100% 的知识。

**属于领域**：AI 工具生态 / 编程智能体（Agent Skill 的核心架构手段）

**通俗理解**：图书馆只有"馆内地图 + 常备手册"拿在手里（入口层 SKILL.md），工具书架在旁边（蒸馏速查层），密集书库凭调卷单取书（modules/cases）。nihaixia 实测账本：全库 230 万字符（≈138万~230万 token），入口 SKILL.md 只有 62,481 字符，**占全库 2.71%**——不分层根本塞不进任何模型的上下文窗口。

**与已有概念的关联**：
- 是 [[AgentSkills技能包]] 能装下"一整个学科"的前提：Claude Code 只把 SKILL.md 的 frontmatter description 常驻用于匹配，命中才载入正文，正文再引用模块文件——三级递进
- 与 [[RAG检索增强生成]] 的分工：百万字级 + 结构清晰 → 纯文本分层（可 grep 对账、零基础设施）；更大规模/语义模糊 → 向量检索（[[向量数据库]]）
- 与 [[三层记忆]] 同思想：逐层压缩、按需展开
- 类比 [[KV缓存与上下文]]：上下文是稀缺资源，分层就是在做"什么值得常驻"的预算管理
