# 决策头与非生成式读出

**一句话定义**：把生成式骨干网络（如 Qwen3-0.6B）的 LM head 拆掉，给每条"候选路径"末尾 token 的 hidden state 接一个共享标量头（LayerNorm→Linear→1），softmax 成候选概率分布——全程零自回归解码、零输出 token。

**属于领域**：AI / 决策模型（生成式骨干的非生成式用法，"编码器化"读出头范式）。

**通俗理解**：生成式 LLM 做选择题像让作家口算——先组织语言再抠答案，几十个 token 慢又飘。决策头是给骨干装一个"电压表"：每条候选接同一对探针，表针偏转多少就是分数多少，一次全量程读完。表（共享标量头）只有 hidden+1 个参数，可接 2~255 个任意候选——因为读的是"路径表示"不是"分类槽位"。

**关键事实**：
- 每条候选路径 = 分段分词拼接的 `State:\n… → Question type:… → Candidate:\n… → Decision:`+EOS；必须先分段编码再拼 token id（BPE 边界合并会破坏共享前缀，"分词先锁定"是硬约束）
- Boolean 只有一条语义路径，z 直接当 sigmoid logit；Score 是 2~10 级 softmax 的期望
- 读出后缀（如 `\nDecision:`）固定，取 hidden 的位置靠索引不靠"最后一个非 pad token"
- 代价：只会判断不会生成——编题质量就是能力上限；需要目标数据训练（随机初始化的标量头不是现成分类器）
- NanoJev 实测：0.596B 参数，RTX 4070 加载后显存 2.23 GiB，一次前向出 3 题 9 路径分布，decode_steps=0
