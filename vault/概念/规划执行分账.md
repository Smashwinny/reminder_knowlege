# 规划执行分账

**一句话定义**：订阅常同时包含**多条互不结转的额度管道**（如 Codex 编码池与网页版 Pro 对话次数），把一次任务的"规划（贵推理）"和"执行（便宜执行）"两道工序拆开、分别记到更便宜的那本账上，同额订阅吞吐成倍提升。

**属于领域**：AI 工具生态 / 额度经济学。

**通俗理解**：健身房年卡其实含器械区（Codex）和私教课（网页版 Pro）两样。多数人以为卡只有器械区，让最贵的私教器械包揽"想"和"干"——规划一次烧掉 Codex 周额度 10%；卡兹克的"邪修"是把"想"挪到每周白送 200 次的私教课（网页版 GPT-6 Pro，给它挂只读 MCP 看生产数据），Codex 只付每任务 4% 的执行钱。实测账：周吞吐 7 件 → 25 件（3.6×），60 任务/周场景一年省 $14,400（67%）。省的大头不是规划费本身，而是**固定开销归零后吞吐量翻倍**。

**与已有概念的关联**：
- [[混合模型分工流水线]]：同思想的"任务类型"维度（按工序选生产者），本概念是其"账户维度"特例（工序不变，按哪本账便宜分配）
- [[能力地板选型]]：规划要顶配、执行按地板选——同一选型原理的双账户展开
- [[上下文接力]]：两本账之间的物料搬运（"添加到 Codex" / 方案文档）
- [[只读闸门三原则]]：分账的前提是给规划端开一条安全的生产数据只读口
- [[上下文预算与战略压缩]]：同是预算管理，一个省 token 窗口、一个省会员费
