# 双边缘上下文压缩

**一句话定义**：在对话历史的时间轴上维持两条独立的"橡皮擦边缘"——**文本边缘**（depth 1：旧 UI 树等重型文本一有新观察立即擦成短文本）和**截图边缘**（depth K：K 步前的图片就地替换成异步生成的"视觉转变摘要"几行字）；滑出两条边缘的消息**逐字节冻结永不回改**。

**属于领域**：AI Agent / 上下文工程。同问题第三种解法：[[Compaction上下文压缩算法]] 是"切割点+模板摘要"（一次性大手术），[[上下文预算与战略压缩]] 是"预算观"（何时主动压），本笔记是"滑动连续擦除"（边走边擦，无需停机压缩）。

**通俗理解**（比喻/例子，讲完落回术语）：像**公司前台的白板**——今天的日程写满整板（原文）；昨天的一擦只剩一行结论（文本边缘）；上周的直接贴一张会议摘要卡盖上原稿（截图边缘）；而**归档柜里的旧白板拍照存底后永不再改**（冻结不变量）。三个工程细节（官方单测逐条验证，本批实验 169 测全绿）：①冻结消息后续任何压缩 pass 重新看到它都逐字节相同——模型看到的不会"变卦"；②ephemeral 临时块（每轮提醒/告警）一出近窗口即焚，绝不混进长期历史；③文字编辑与图片替换是两个独立边缘，摘要没按时回来有宽限期，**占位符永不回填假摘要**（宁可显示"摘要不可用"）。

**适用场景**：每步都产"大块观察"的 Agent（GUI Agent 每步一张 1080×2400 截图 + 一坨 UI 树；视频分析同理）——大块、结构固定、旧观察价值快速衰减的历史，滑边擦除比攒到阈值再压缩更平滑。
