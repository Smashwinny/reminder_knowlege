# 双数据源适配器隔离

**一句话定义**：把"依赖易变外部系统"的适配器与核心管线彻底隔离，两者只通过统一抽象接口（如 ChatSource）对话，并额外提供一个不依赖外部系统的备用数据源给管线保活。

**属于领域**：软件工程 / 依赖易变外部系统的架构设计。

**通俗理解**：像小区的<b>双路供电</b>：市电（微信实时读取）可能随时检修停电，但小区还有备用发电机（JSON 文件入口），楼里的电梯和灯（渲染/导出管线）只认"插座"这个统一接口，不关心电从哪来——市电挂了，插上发电机一切照常。讲完比喻落回术语：微信适配层六个模块与渲染、导出模块零耦合，消息统一走 `ChatSource` 抽象；即使微信 4.x 某次升级打挂适配层，`JsonChatSource` 驱动的整条导出管线仍可独立工作、独立测试。

**与已有概念的关联**：
- 是 [[能力层与后端路由]] 的"接口统一"思想的另一面：后者统一多个后端的调用口，本概念隔离单一易变后端
- 备用数据源让管线可离线测试，呼应 [[质检Gate与自我纠错循环]]（确定性测试前提）和 [[确定性脚本]]
- 与 [[CleanRoom只读读取器]] / [[进程取钥与副本解密]] 组合：不管哪条读库路线，都收敛到同一个数据源接口

**实测要点**（wechat-ai-memory）：真实踩坑——包 `__init__.py` 会连带 import 微信适配层，导致"只想用 JSON 入口"也必须装 zstandard/pycryptodome：隔离是模块级的，但<b>import 图还不是完全懒加载</b>，这是该范式的实现细节教训。
