# 程序化工具调用

**一句话定义**：不让模型一轮只发一个工具调用，而是让它**写一段代码**在沙箱里一次执行完整个多步策略（枚举→模拟→评估→选优）——把 N 次"模型拍板"压缩成 1 次代码执行，又称 CodeAct / code-as-action。

**属于领域**：AI Agent / 工具调用模式（[[LLM工具调用]] 的进阶形态）

**通俗理解**：普通工具调用像"每走一步都打电话问军师"；程序化调用像"军师直接写好一份作战程序，部队照着一次跑完"。棋类、数据处理这类**组合搜索型**任务收益最大：`for move in legal_moves: simulate(move)` 一行循环，传统模式要模型推理几十轮。

**安全边界（CMU 11-768 作业 1 Part 3 实例）**：模型写的代码 base64 编码后送进沙箱的 `sandbox_python.py` 执行——工具函数在沙箱内可直接 import、棋局服务器在沙箱本机可达，**agent 进程从头不碰这些代码**，返回值只是打印出的 JSON。代码永不逃逸沙箱（[[提示注入]] 防线的执行侧）。

**代价**：错误更难定位（一整段程序失败 vs 单个调用失败）、沙箱开销、以及模型写代码本身要烧推理——简单任务不如一次普通调用。

**与已有概念的关联**：
- [[AgentHarness智能体挽具]]：harness 负责"送代码进沙箱、取 JSON 回来"这条管道
- [[LiveCoding现场编程]]：同为"模型写代码"，但那是交互式改真实工程，这是沙箱内的一次性策略程序
- [[Agent后训练SFT与RL]]：程序化轨迹的 token 效率更高，也更适合当 RL 训练的动作空间
- **已官方产品化**（2026-09-10 [[托管Harness与会话即资源]]）：OpenAI Agents API 里就是一个开关 `{"type": "programmatic_tool_calling"}`，开源 codex 仓库有 code-mode ×4 crate 家族——从课堂概念到云 API 参数只用了一年
