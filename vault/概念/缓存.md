# 缓存

**一句话定义**：把"贵的计算/查询结果"暂存在便宜快速的地方（通常是内存）；有效的原因是局部性——热门数据总被反复访问。

**属于领域**：分布式系统 / 性能优化

**通俗理解**：实验数据最有说服力：10000/s 读请求、DB 只扛 1000/s 时，命中率 95% 就把 DB 利用率从 1000% 拉回 50%——缓存不是锦上添花，是让数据库活下来的生命线。本质是"故意制造的不一致"：用数据可能过期换取速度。更新策略：缓存旁路 / 直写 / 回写（有丢失风险）/ 到期驱逐（LRU）。要防"缓存雪崩"（缓存集体失效瞬间打穿 DB）。

**与已有概念的关联**：
- 相关：[[一致性模式]]（缓存是弱一致/最终一致的自愿使用者）
- 相关：[[延迟数与估算法]]（内存比磁盘快约 100 倍，是缓存有效性的物理根源）
