# 个人记忆流水线

**一句话定义**：个人上下文从"原始散落"到"Agent 可用"要经过的三段式分工——<b>进料口（原始数据→规范格式）→ 加工车间（规则提炼→人可读情报）→ 仓库检索台（长期存储→任意 Agent 查询）</b>。

**属于领域**：AI Agent / 个人知识记忆基础设施。

**通俗理解**：像<b>中央厨房的食材流水线</b>：进料口负责把菜市场运来的毛菜（微信聊天记录）洗切成分装好的净菜（规范 JSON 档案）；加工车间把净菜做成一盒盒按标签摆好的半成品（情报日报、行动信号）；仓库则是冷库+取餐窗口，任何厨师（Agent）随时凭单子取用。三个岗位谁也不能替代谁——没有进料口，仓库存的是毛菜；没有仓库，净菜只能在当天的车间里用掉。讲完比喻落回术语：进料口管<b>数据可得性</b>（数据源适配、格式规范化、可追溯引用），车间管<b>信息提炼</b>（确定性规则打信号），仓库管<b>持久化与检索供给</b>（分层记忆+混合检索）。

**三个实例的分工对照**（已学项目）：
| 段位 | 项目 | 输入→输出 | Agent 接口 |
|---|---|---|---|
| 进料口 | [[项目笔记/wechat-ai-memory]] | 微信库 → PDF/MD/规范 JSON 三件套 | 暂无（v0.8 路线图：只读 MCP） |
| 加工车间 | [[项目笔记/wechat-intelligence-hub]] | 微信记录 → 情报日报+行动清单 | 无（人看报） |
| 仓库检索台 | [[项目笔记/memmy]] | 各 Agent 会话 → 四层记忆+混合检索 | <b>已有</b>（HTTP API/CLI，跨工具共享） |

**与已有概念的关联**：
- 进料口读取层：[[CleanRoom只读读取器]] 与 [[进程取钥与副本解密]] 两条对立路线之争
- 车间提炼层：[[确定性信号引擎]]、[[事实与判断分离]]、[[AI味模式库与信号非证据]]（信号附证据原句）
- 仓库供给层：[[跨工具个人记忆层]]、[[记忆四层模型]]、[[混合检索与RRF融合]]、[[三层记忆]]
- 整条线的"原料合同"：规范化 JSON 的 `id/sender/timestamp/type/is_outgoing/reply_to` 六要素，是 [[Agent输出协议契约]] 思想在数据层的体现

**实测要点**（wechat-ai-memory）：进料口当前只出到"档案文件"，语义检索/RAG/MCP 均未实现；其 JSON 输出已可直接被 Memmy 类系统当语料摄入——两段拼起来即是最小可行流水线。
