# 控制面与数据面

**一句话定义**：一个服务里"看目录/建会话"（控制面）和"真干活/取数据"（数据面）是两套通道，认证与计费闸门装在哪一侧是一种架构决策——TikHub 实测控制面全开放（假 Key 也能 initialize + tools/list），闸门只设在 tools/call 上游。

**属于领域**：后端架构 / API 经济；分析任何付费 API/MCP 服务时先用假 Key 探测闸门位置，5 分钟摸清它的免费边界与安全模型。

**通俗理解**：自助餐厅的菜单随便看（控制面免费开放=获客橱窗），夹菜才刷饭卡（数据面计费）。对照：AgentKey 是"进门先刷码"（initialize 就 401，走 [[OAuth资源发现]] 引导）；TikHub 是"菜单随便翻，取餐付钱"。

**401 的两种形态**（实测）：
- 网关层 401：HTTP 401 + `www-authenticate` 头，完全无凭证时触发
- 数据层 401：HTTP 200 的 MCP 成功信封里内嵌 `{"error":"unauthorized","status":401}`——"协议成功、业务失败"，错误以工具结果回流，LLM 读得懂原因并自我纠正（[[Agent循环]] 的燃料）
