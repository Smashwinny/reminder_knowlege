# 动作投递语义与安全重试

**一句话定义**：把一次桌面动作区分为未投递、投递不确定、已投递未验证、已投递已验证等状态，再决定是否允许重试；只有明确 `not_delivered` 才对应 `retry:safe`，其余状态必须先观察副作用，不能用“没收到成功回执”作为重复点击的理由。

**属于领域**：AI Agent / 分布式式失败语义 / 副作用控制。

**通俗理解**（比喻/例子，讲完落回术语）：按发送键后屏幕没变化，可能是没送到，也可能已经送到但界面还没刷新。再按一次可能重复提交表单、重复发送消息。安全重试关心“副作用是否可能发生”，不是只关心有没有漂亮的成功 JSON。`delivered_verified` 也只证明动作层验证范围，不自动证明业务任务完成。

**判断表**：
- `not_delivered` → 可按原恢复建议安全重试。
- `delivery_uncertain` → 先重新观察，禁止盲目重复。
- `delivered_unverified` / `delivered_verified` → 不自动重放原动作。
- `unknown` → 证据不足，不能映射成 safe。

**与已有概念的关联**：
- [[快照限定Ref与严格重识别]]：目标身份未证实通常在投递前拒绝，因此可以安全修正后重试。
- [[质检Gate与自我纠错循环]]：纠错必须读取最新观察，不能对不确定副作用做机械重放。
- [[证据状态机]]：失败、未知和成功是不同事实，不可压成布尔值。
