# 多窗口额度的展示选择规则

**一句话定义**：多个周期额度竞争一个主读数位置时，选择规则须显式处理可用性、周期有效性、单位、告急阈值与稳定排序，不能简化成无条件求最小值。

**属于领域**：可观测性界面 / 信息压缩 / 确定性状态选择。

**通俗理解**：短期和长期“油箱”同时限制行程，平时显示最常用的短周期，某个周期快见底时再把它提到前面；已经跨过重置点的旧读数退出比较，货币余额也不能直接参与百分比排名。

## Metrik 固定版本的真实算法

v0.21.1 的 bindingWindow 接收按后端 quota_window_rank 预排序的窗口列表，自身不排序：

1. 保留 view.available 为真且 view.resetExpired 为假的窗口；没有有效项时返回 null
2. stale=true 不会单独导致剔除，函数也不自行推导新鲜度
3. 在非余额窗口中筛 remainingPercent ≤ 15 的告急项；余额的识别是 key.startsWith("balance")
4. 有告急项就取这些项中余量最小者，同值保留输入顺序
5. 没有告急项就返回有效列表首项；余额仍可作为这个首项正常返回

已有真实函数合成场景：短窗 80%、周窗 40% 时选 80%；周窗为 15% 时选 15%；周窗为 15.01% 时又选 80%。两个告急窗取较小值，平局取输入靠前者。有效 0 参与选择，不可用的占位 0 被排除；resetExpired 被排除，stale 保留。

余额 8.4 不因数值小而抢占百分比窗口；唯一余额 168.5 可原值返回。百分比托盘是另一层：trayBadgeSpec 取状态列表第一位 Agent，不是跨 Agent 求最低额度；金额保护位于 App.jsx 调用层，该层未做运行验证。
