# GUI Agent 与多模态定位

**一句话定义**：让多模态大模型看屏幕截图 + UI 树、自主决定"点/滑/输"来操控真实设备（手机/电脑）的 Agent 形态；其可靠性核心是**三层定位 fallback**——元素索引（UI 树直接给序号，最快最准）→ 坐标定位（OCR+XML 融合算坐标，索引失效时兜一层）→ 视觉定位（模型看图找目标，自绘界面/游戏兜到底）。

**属于领域**：AI Agent / 具身操作（是 [[Agent循环]] 在"屏幕"这块画布上的特化：观察=截图+UI树，动作=触屏原语）

**通俗理解**（比喻/例子，讲完落回术语）：像给新员工指路——先递工位号（元素索引，对号入座零歧义）；工位牌被人挪了，再说"靠窗第三排"（坐标）；整个办公室重新装修了，只能带他现场看一圈"就那个绿色的沙发"（视觉定位）。**便宜的通道永远先用，贵的通道最后上**：标准 App 九成情况停在第一层，只有游戏/自绘 UI 才动用昂贵的多模态视觉调用。ARTEMIS 实测：标准动作集 12 个（click/swipe/input_text/press_key…），索引失效才升级坐标，视觉定位是最后 fallback。

**可靠性配套**（ARTEMIS 给出的生产级答案）：
- 坐标自愈：动作落地前用 UI 层级核对目标"还在不在"（文本相似度 0.4 + 位置 0.5 加权），小漂移直接修正坐标
- 失败分型喂回：shifted / occupied / disappeared 三类结构化失败进执行事件（见 [[预执行安全网与执行事件]]）
- 公开基准说话：AndroidWorld（Google Research，116 个跨 20 个真实 App 的任务）是这一领域的标准考场
