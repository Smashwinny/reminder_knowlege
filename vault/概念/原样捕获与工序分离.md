# 原样捕获与工序分离

**一句话定义**：捕获（capture）时刻只做保真记录——原话逐字落盘、禁止 AI 总结润色；一切加工（整理/提炼/归档）推迟到另一个人工或 AI 的工序里做。

**属于领域**：知识管理 / 捕获管道设计。

**通俗理解**（比喻/例子，讲完落回术语）：像考古现场——出土瞬间只做拍照封存，不许当场"修复"陶罐；修复是实验室里另一道工序。落回术语：随记机器人的规则"正文原样保留空格标点换行、不修正错字、只另生成一个短标题"，就是捕获工序的完整契约；"记录的摩擦 ↓，表达欲存活率 ↑"是它的产品学动机。

**为什么原样是硬要求**：
1. 原话是思考的化石——犹豫、跳跃、"没想清楚"本身就是信息，润色会把它们抹掉（AI 润色 = 有损压缩）
2. 原样才可校验——脚本可以做"复读校验"（写入 == 发出，逐字节比对）；一旦允许改写，正确性只能靠人眼
3. 捕获瞬间是丢信息的高危时刻，加工介入越早，损耗越大

**与已有概念的关联**：
- 相关：[[原子笔记与双链]]（先保真原子记录、后结构化加工，同一哲学的上游环节）
- 相关：[[个人记忆流水线]]、[[事实与判断分离]]（"记录不加工 / 加工不掺记录"是同一分工思想）
- 相关：[[提示注入]]（"只保存不执行"让捕获 Agent 对恶意内容天然免疫）
- 相关：[[证据优先质检ProofOverClaims]]（保真原始证据先于结论）

## WeChatBridge：源归档保留与后续处理边界（2026-10-06）

[[项目笔记/wechat_bridge]] 补充用户主动分享的文件入口：集合账本引用原 ZIP，转换文本/Markdown 与模型解释作为后续派生物。保留归档支持回看，但不证明微信全部聊天已完整导出，或后续解析没有损失。已有实验仅用两条虚构中文消息与 64 字节 sample.bin，后者不是图片，没有真实媒体渲染证据。

上文“只保存不执行”带来“天然免疫提示注入”的说法应收窄：捕获阶段避免执行内容可降低风险；同一资料之后交给模型读取时，仍需保持指令/数据边界、最小权限和敏感行动检查。保真不是授权，也不代表测试过完整注入防护。旧正文原样保留，追加说明用于限定其适用范围。

主动分享与 [[项目笔记/wechat_hermes_notebot]] 的常驻消息捕获是不同入口；后续发给目标 AI 应用也不能沿用“全程数据不离机”的总承诺。关联 [[提示注入]]、[[产物留痕与状态外置]]、[[本地优先与文件监听]]。
