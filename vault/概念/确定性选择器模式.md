# 确定性选择器模式

**一句话定义**：不让 LLM 直接做最终决定（打总分），而是让它只输出分类特征（布尔/枚举"票"），由 Python 用确定性逻辑（AND、计数、阈值）组合出决定信号的工程纪律。

**属于领域**：AI / LLM 应用（LLM 工程）

**通俗理解**：LLM 当裁判有个病态：让直接打 0-10 分，它几乎什么都给 7-8 分（flat-band），阈值形同虚设。像让评委只举牌"通过/不通过/弃权"再数牌，而不是写散文评语——牌是离散的，数牌是确定的，结果可复现可测试。all-agentic-architectures 库里 13/35 个架构用此模式（CRAG 给文档判相关/模糊/无关三档、Constitutional AI 逐条宪法 pass/fail 再 AND），另 9 个架构设计上天然免疫。

**与已有概念的关联**：
- 直接呼应：[[事实与判断分离]]（LLM 只出研判材料，代码下最终决定）、[[确定性脚本]]（决定信号可测）
- 应用处：[[推理反思架构族]]（LLMJudge）、[[RAG架构谱系]]（CRAG/Self-RAG 的文档取舍）
- 对立面：让 LLM 自由打分/自由路由的"LLM-as-Scorer 裸用"
