# 对抗辩论式决策架构

**一句话定义**：让立场对立的 LLM 角色（多/空、激进/保守/中性）围绕同一份材料轮流反驳，由计数器控制轮数、路由器控制发言顺序，最后由管理者综合双方论点拍板——用结构性对抗压单 Agent 的过度自信。

**属于领域**：AI Agent 决策架构

**通俗理解**：不是"开会各说各话"，是"法庭辩论"——正方说完反方必须接招，接不上就输。工程实现没有魔法：共享状态里放 `debate_state`（count 计数 + latest_speaker），条件边路由器按"谁刚说完→谁接"轮转，`count ≥ N×rounds` 就交给 manager。TradingAgents 实测（max_debate_rounds=1）：Bull 先手→Bear→Bull→Research Manager；风险段 Trader 固定先咨询 Aggressive，再 Conservative→Neutral→Portfolio Manager（3×rounds）。两段辩论分工明确：多空辩**方向**（该不该做），风险三方辩**下行**（做了会怎么死）。

**为什么有效**：单 Agent 一个 prompt 问"能不能买"，模型倾向给自信答案；辩论把"唱反调"从可选项变成必经工序，反方论点必须被记录在案，manager 的综合报告因此可审计。
