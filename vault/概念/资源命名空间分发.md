# 资源命名空间分发

**一句话定义**：团队 AI 资产仓库里用 `skills/<namespace>/` 这类子目录做隔离，成员按 Roles（角色）、Tags（标签）、Sources（订阅源）、Projects（项目）四个正交维度只领取与自己相关的 namespace，且**活跃 namespace 中的同名条目会整体替换根目录条目**（不合并）。

**属于领域**：AI 工程 / 团队协作工具链（teamai-cli 分发策略层）

**通俗理解**（比喻/例子，讲完落回术语）：像公司食堂的餐线——根目录是大众窗口，`skills/frontend/` 是前端专窗：你挂了 frontend 角色就多打一份前端菜，没挂的人打不到。替换语义是关键：`rules/checkout/code-style.md`（项目专窗）会**整份顶掉** `rules/code-style.md`（大众窗口），避免两种规范同时加载打架；想让大家都能改的部分放根目录，项目要覆盖的也放根目录版做兜底——官方口诀是"**需要被覆盖的共享内容放根目录，而不是放每个角色都会激活的 namespace**"。两个活跃 namespace 撞名时 pull 直接报错停机，宁可不更新也不静默二选一。

**实测要点**：
- namespace 必须是单个路径片段，同一类型下不允许仅大小写差异；资源成为目录名
- push 时落点由 `manifest/roles.yaml` 决定：无终端可交互（CI/hook）时以退出码 2 停止并要求 `--role <ns>`，绝不静默退回共享根目录（那会发给所有人）
- Tags 过滤 skills/rules 的订阅；Sources 可订阅其他团队或公共 skill 仓库，pull 时自动带上
