# 快照限定 Ref 与严格重识别

**一句话定义**：把元素编号绑定到产生它的快照，写成 `@<snapshot_id>:e<N>`；动作前必须证明原快照、目标会话与唯一元素身份仍然匹配，遇到裸编号、未知快照、歧义、不完整证据或过期身份就拒绝，而不是猜一个控件执行。

**属于领域**：AI Agent / 工具寻址 / 动作安全。

**通俗理解**（比喻/例子，讲完落回术语）：裸 `@e1` 像只说“第一排第一个人”，换一批观众就可能指错；`@s8f3k2p9:e1` 像同时写明场次和座位。界面变化后还要重新核对，而不是拿旧票进场。严格重识别把“找不到足够证据”当作停止条件。

**源码锚点**：固定提交的 `ref_token.rs` 依次要求 `@` 前缀、`:e` 分隔、合法快照 ID 和本地元素编号；`ref_capture_proof.rs` 要求完整窗口观察与唯一身份匹配。安全实验对这些源码标记做了静态断言，**没有**把 `click @e1` 当作无桌面实验：Linux 的权限探测先于 ref 校验，可能访问 AT-SPI 总线。

**与已有概念的关联**：
- [[无障碍树语义桌面自动化]]：树提供语义候选，快照限定 ref 提供带上下文的动作地址。
- [[预执行安全网与执行事件]]：都在动作前核对目标；本条特别约束快照、身份唯一性与未知证据。
- [[证据状态机]]：Known、Absent、Unknown 不可合并，缺失或不可读不能当作已匹配。
