# 上下文预算与战略压缩

**一句话定义**：把上下文窗口当预算来管理——给每样占用（系统提示、工具描述、MCP、规则、历史）记账，并在**逻辑断点**主动压缩，而不是等 95% 时被自动压缩腰斩。

**属于领域**：AI 工具生态 / 编程智能体

**通俗理解**：200k 窗口像一个背包，工具描述和 MCP 是一出生就塞进去的砖头（每个 MCP 服务器的工具描述常驻消耗 token，全开会把可用窗口压到 ~70k）；战略压缩是"到一个章节结束时自己整理背包"，自动压缩则是"背包爆了被人倒出来抖一抖"——后者会把关键变量名、文件路径抖丢。

**ECC 的实操数字**（harness 代管预算）：
| 手段 | 默认 | 推荐效果 |
|---|---|---|
| `model` 路由 | opus | sonnet 打底（~60% 成本降，80% 任务够用），opus 只留给架构级难题 |
| `MAX_THINKING_TOKENS` | 31,999 | 10,000（隐藏思考成本 ~70% 降） |
| `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` | 95% | 50%（早压缩，长会话质量更好） |
| MCP 数量 | 不限 | <10 个/项目，活跃工具 <80 个（[[工具目录膨胀]]） |

**何时压缩 / 何时千万别**：调研完动手前、里程碑完成时、调试失败换路前→压缩；实现中途→千万别（会丢变量名和半成品状态）。
