### 领域：AI 工具生态
- [[MCP协议]] — AI 连接外部工具的开放标准，M×N → M+N；底层 [[MCP服务器]] 与 [[stdio与流式HTTP传输]]

- [[JSON-RPC与stdio传输]] — JSON-RPC 2.0 三种消息 + stdio 通道纪律（stdout 即协议）
- [[工具调用生命周期]] — 发现→决策→调用→执行→返回；与 [[LLM工具调用]] 互为协议侧/框架侧
- [[M×N集成问题]] — 协议之所以存在的经济学：M×N 定制对接 → M+N
- [[提示注入]] — 藏在数据里的恶意指令；Gate + 最小授权 + 审计三防
- [[分层按需加载]] — 小入口常驻 + 大主体待命：Agent Skill 装下一整个学科的架构前提（nihaixia 实测入口仅占 2.71%）

- [[提示词权威边界]] — 宪法管审美原文禁改、军规管物流只准追加：防 AI 提示词漂移的结构性方案 + 消毒输出纪律
- [[能力层与后端路由]] — 不新写功能，管"选型/安装/体检/路由"：每平台有序后端列表，第一个真实可用者当选，接入换代只调顺序（Agent Reach）
- [[健康探测三态]] — which() 不能证明能跑：missing / broken / timeout 三态探测 + 自动修复处方
- [[统一数据网关]] — Master Key 一站式聚合 28+ 平台数据（AgentKey/tikhub），[[能力层与后端路由]] 的商业化镜像
- [[OAuth资源发现]] — RFC 9728：401 + WWW-Authenticate 元数据引导自动拿凭证，远程 MCP 免贴 Key 接入的前提

概念主线：**流水线拆解复杂任务 → 各 Pass 之间设 Gate → Gate 依赖确定性裁判 → AI 借此自我纠错 → 产出程序化 Three.js 模型**；AI 工具生态主线：**MCP 协议标准化工具接口 → 框架（LangChain/CrewAI）管编排 → 服务器管能力复用**

### 领域：分布式系统 / 后端架构
概念主线：**单机到瓶颈 → 负载均衡水平扩展 → 缓存救数据库 → 消息队列异步削峰 → 数据库分片 → CAP/一致性决定每个副本的行为 → 延迟数与估算法是判断一切瓶颈的标尺**

- [[系统设计与可扩展性]] — 顶层规划 + 压力×10 时加机器能否撑住；利用率 80% 是隐形红线
- [[负载均衡与反向代理]] — 服务器前面的"领班"：分发流量 + 健康检查踢除坏节点
- [[CAP理论]] — P 必选，真正的选择是 CP 还是 AP
- [[一致性模式]] — 强/最终/弱：改完头像朋友几秒后才看到，就是最终一致
- [[关系型数据库与NoSQL]] — 拿不准就用 RDBMS；NoSQL 是规模逼出来的针对性武器
- [[缓存]] — 命中率 95% 把 DB 利用率从 1000% 拉回 50%，数据库的生命线
- [[消息队列与异步削峰]] — 水库式削峰填谷；用户拿到"已受理"而非"已办完"
- [[延迟数与估算法]] — 内存比磁盘快 100 倍；30 秒心算系统量级

- [[RAG检索增强生成]] 见上"AI / LLM 应用"分区（本批与 Qdrant 侧合并互链）

### 领域：AI / 本地推理（2026-10-01 新增，来自 ollama）
- [[本地推理引擎]] — 自家厨房 vs 叫外卖：权重载入显存→调度→逐 token 生成；Ollama = CLI + server + 推理子进程
- [[量化与GGUF]] — 权重有损压缩（FP16→Q4 体积 1/4），消费级显卡跑大模型的前提；与 [[向量量化]] 同族不同对象
- [[KV缓存与上下文]] — 显存账单 = 权重（固定）+ KV 缓存（随上下文线性涨）+ 缓冲
- [[内容寻址与镜像分层]] — 文件按 sha256 存、manifest 清单组装：Docker 镜像与 Ollama 模型库同构
- [[LLM采样与温度]] — temperature=保守/发疯旋钮，seed=骰子序列；GPU 上温度 0 也非绝对确定

概念主线：**[[量化与GGUF]] 让模型小到装得下 → [[本地推理引擎]] 把权重搬进显存 → [[KV缓存与上下文]] 决定能"回看"多长 → [[LLM采样与温度]] 控制输出性格（低温+固定种子=[[确定性脚本]] 的 AI 版） → 模型库本身是 [[内容寻址与镜像分层]] 结构**
