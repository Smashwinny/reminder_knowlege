按领域分区，概念间用 `[[双链]]` 关联。新概念若与已有概念是同一事物，合并进旧笔记并加别名。

- [[零依赖编程]] — 只用标准库，随处可跑

### 领域：AI 工具生态
- [[MCP协议]] — AI 连接外部工具的开放标准，M×N → M+N；底层 [[MCP服务器]] 与 [[stdio与流式HTTP传输]]
- [[MCP服务器]] — Tools/Resources/Prompts 三能力；一条命令装进 Claude，三步自造
- [[stdio与流式HTTP传输]] — 本地子进程 vs 远程 URL，对应 🏠/☁️
- [[MCP模型上下文协议]] — 同一协议的并行批次笔记（与 [[MCP协议]] 互链）；报文层见 [[JSON-RPC与stdio传输]]
- [[JSON-RPC与stdio传输]] — JSON-RPC 2.0 三种消息 + stdio 通道纪律（stdout 即协议）
- [[工具调用生命周期]] — 发现→决策→调用→执行→返回；与 [[LLM工具调用]] 互为协议侧/框架侧
- [[M×N集成问题]] — 协议之所以存在的经济学：M×N 定制对接 → M+N
- [[提示注入]] — 藏在数据里的恶意指令；Gate + 最小授权 + 审计三防

概念主线：**流水线拆解复杂任务 → 各 Pass 之间设 Gate → Gate 依赖确定性裁判 → AI 借此自我纠错 → 产出程序化 Three.js 模型**；AI 工具生态主线：**MCP 协议标准化工具接口 → 框架（LangChain/CrewAI）管编排 → 服务器管能力复用**

### 领域：AI / LLM 应用
- [[ChatModel与消息类型]] — 统一模型接口（万能转接头）+ 4 种消息角色（System/Human/AI/Tool）
- [[LLM工具调用]] — LLM 只"点菜"（输出 JSON），框架"炒菜"（真正执行函数）
- [[Agent循环]] — 模型↔工具自动循环直到任务完成，错误回流即自纠
- [[RAG检索增强生成]] — 开卷考试：先检索相关段落再回答（Embedding 语义坐标 + VectorStore）
- [[提示词模板]] — 带变量槽位的提示词对象，组装过程确定可测
- [[LangGraph与Agent编排]] — 状态图引擎：节点+边+全局状态，Agent 循环只是最简单的两站环线
- [[共享状态与Reducer]] — 共享白板：节点进全量快照、写回增量；Reducer 管并行写入合并
- [[Checkpoint存档与持久执行]] — 每步一快照，崩了从存档续跑不重花钱；thread_id 一人一档
- [[人机协同Interrupt]] — "暂停等人"= 存档+退出，Command(resume) 带答案唤醒
- [[Agent中间件]] — 插进 Agent 循环的钩子：摘要记忆、人工审批、隐私抹除
- [[多智能体协作]] — 角色分工+互查的 AI 小组（crewAI 的 Crew）；对照 [[LangGraph与Agent编排]]（组队默认 vs 流程图默认）
- [[角色提示]] — role/goal/backstory 三件套发岗位说明书，改一个字符串换一个人格
- [[AI智能体Agent]] — LLM 大脑 + 工具手脚 + 自主循环的"总纲"笔记，串起上面所有概念
- [[智能体框架]] — 管循环/注册/存储的脚手架：agno / crewAI / LangGraph / ADK 概念互通
- [[AgentSkills技能包]] — 给编程智能体装的方法论包（SKILL.md 格式），与 Tool/MCP 三分天下
- [[能力运行时]] — 多功能共享同一个 Agent 循环：功能 = 可插拔的"能力"插件包（DeepTutor 的 agent-native 架构）
- [[三层记忆]] — L1 原始轨迹 → L2 界面摘要 → L3 用户画像，LLM 逐层压缩、可回溯可编辑的长期记忆
- [[子智能体咨询]] — 把本机 Claude Code 等 CLI 包装成 consult_subagent 工具：主 Agent 决定问什么，管家真跑真查

概念主线：**ChatModel 统一接口 → LLM"点菜"框架执行（工具调用） → 错误回流模型自纠（Agent 循环 ≈ [[质检Gate与自我纠错循环]] 的 LLM 版） → LangGraph 状态图保证可控 → middleware 插槽扩展**

### 领域：分布式系统 / 后端架构
概念主线：**单机到瓶颈 → 负载均衡水平扩展 → 缓存救数据库 → 消息队列异步削峰 → 数据库分片 → CAP/一致性决定每个副本的行为 → 延迟数与估算法是判断一切瓶颈的标尺**

- [[系统设计与可扩展性]] — 顶层规划 + 压力×10 时加机器能否撑住；利用率 80% 是隐形红线
- [[负载均衡与反向代理]] — 服务器前面的"领班"：分发流量 + 健康检查踢除坏节点
- [[CAP理论]] — P 必选，真正的选择是 CP 还是 AP
- [[一致性模式]] — 强/最终/弱：改完头像朋友几秒后才看到，就是最终一致
- [[关系型数据库与NoSQL]] — 拿不准就用 RDBMS；NoSQL 是规模逼出来的针对性武器
- [[缓存]] — 命中率 95% 把 DB 利用率从 1000% 拉回 50%，数据库的生命线
- [[消息队列与异步削峰]] — 水库式削峰填谷；用户拿到"已受理"而非"已办完"
- [[延迟数与估算法]] — 内存比磁盘快 100 倍；30 秒心算系统量级

### 领域：AI / 检索（2026-10-01 新增，来自 Qdrant）
- [[向量与Embedding]] — 文本/图片 → 意义空间的坐标（512 维数字串）
- [[余弦相似度]] — 比方向不比长短的"像不像"打分函数
- [[向量数据库]] — 按"谁最像"检索的数据库；Collection/Point/Payload；选型对比
- [[HNSW近似最近邻索引]] — 高速→省道→小巷的分层图索引，亿级毫秒检索
- [[向量量化]] — float32→int8/1bit，把 200GB 压成 50GB 的存储魔法
- [[RAG检索增强生成]] 见上"AI / LLM 应用"分区（本批与 Qdrant 侧合并互链）

概念主线：**文本经 [[向量与Embedding]] 变坐标 → 存入 [[向量数据库]] → 检索靠 [[HNSW近似最近邻索引]] + [[余弦相似度]] → 规模化靠 [[向量量化]] → 最终服务于 [[RAG检索增强生成]]（ollama 跑模型 + langchain 编排 + Qdrant 存知识）**
