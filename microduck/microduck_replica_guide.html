1策略每 20ms 看到的 61 维观测向量里装了什么？契约核心

策略网络是只认固定格式表格的"会计"：61 列一列都不能错位。布局已被源码 duck-control/src/obs.rs 的注释原文证实：

索引宽内容坑
0..33躯干陀螺仪角速度 (rad/s)—
3..63重力投影单位向量模长必须=1
6..2014关节位置 − home pose嘴部不在内！
20..3414关节速度 (rad/s)同上
34..4814上一时刻原始动作缩放前
48..6113命令块：vx/vy/vyaw + 头部4目标 + 身体6位姿见下
命令块三个暗坑（obs.rs 注释原话级警告，复刻者最容易栽）：
① body 块顺序是 z, roll, pitch，不是 z, pitch, roll；
② body x/y/yaw 恒为零——训练里没绑定，全零是名义编码不是占位符，槽位不可删；
③ 头部目标是喂进观测的命令，不能再加到策略输出上——双重叠加会把头掰弯两次。

目标公式：target = home_pose + action_scale × action；ONNX 要求输入 [1,61] 输出 [1,14]，观测归一化器必须烘进 ONNX 图（手工 .pt 转 ONNX 会漏掉归一化），推理前先 warm-up。

2index-9 陷阱：一行代码怎么毁一只鸭？本次实验实锤

运行时目标数组是 15 槽（含嘴），策略输出只有 14 维（不含嘴）。线序与 ID 表（duck-ipc-proto/model.rs 源码原值）：

段关节Dynamixel ID
左腿 ×5hip_yaw/roll/pitch, knee, ankle20–24
头颈 ×4neck_pitch, head_pitch/yaw/roll30–33
嘴 ×1mouth（线序第 9 槽，策略不驱动）34
右腿 ×5hip_yaw/roll/pitch, knee, ankle10–14
IMU 桥imu_to_dxl v2 从设备200
图 1：index-9 陷阱。本篇实验用真实源码常量复现：naive 直拷使 15 槽中 2 段（嘴+右腿全部）错位
✅ 实验结论（contract_check.py 步骤 4）：把 action[9]=0.5rad 直拷进目标数组，嘴部（ID 34）会收到 +28.6° 的右髋 yaw 命令；正确映射（跳过 index 9）嘴槽为 0。源码里那句 if slot < MOUTH_INDEX { slot } else { slot + 1 } 就是复刻最不能出错的一行代码。
3标称 5V 的舵机，为什么训练时电压随机到 6.5~8.2V？域随机化实证

市售 XL330-M288 规格书写 3.7–6.0V（推荐 5V），但训练代码 microduck_constants.py 里明晃晃写着 vin_range=(6.5, 8.2)、运行时以 6.6V 空电/8.2V 满电判断。矛盾吗？

不矛盾——这是域随机化的教科书案例：训练时故意让电池电压在宽区间随机（还叠加负载压降 vin_drop_gain），策略就学会"电压怎么漂都能走"。文章作者也诚实标注：这一电压适配未经实物验证，复刻者不要把"5V 舵机 + 默认运行时"当成已验证方案。

连带推论（文章原话级警示）：结构若从 ~800g 涨到 1.2kg，就是另一套动力学系统——必须更新 MJCF 重训，不能只调大 action_scale 硬扛。

哪些硬件变化必须重训？

换舵机型号/减速比、回差变化、通信延迟变化、增重或质心移动、腿长/足底/摩擦变化、IMU 安装角变化、控制频率变化、增益/滤波变化、电池电压范围变化。正确流程：测新硬件 → 更新 MJCF → 辨识执行器 → 更新域随机化 → smoke test → 重训 → 导出 → CPU 复演 → 真机扶持测试。

5动手实验：复刻契约对拍（27/27 全 PASS，无硬件纯源码）

实验思想：文章说的每一条契约，都去两个官方仓库的真实源码里找原文，再写程序交叉对拍。脚本 microduck/exercise/contract_check.py（Python 3.14 + numpy），六步：

1
解析运行端源码：正则抽取 duck-ipc-proto/src/lib.rs 的 15 关节线序、model.rs 的 ID 表/MOUTH_INDEX/home pose。✅ 线序 [左腿5|头颈4|嘴|右腿5]、ID 20-24/30-33/34/10-14、IMU=200、1Mbps，与文章逐条一致
2
home pose 两端对拍：训练端 HOME_FRAME（regex 通配）解析后展开成 14 关节，与运行端 DEFAULT_POSITION 逐值比较。✅ 14/14 全等（如 left_hip_pitch 两端均 −0.4579）；嘴在训练端无 home（策略不驱动）
3
61 维观测拼装：按 obs.rs 布局用 Python 复现（含 joint_of 跳嘴映射、body 块 z,roll,pitch 顺序、x/y/yaw 恒零）。✅ 形状 (61,)、分块 3+3+14+14+14+13、重力单位向量模长=1、两个暗坑的编码均与源码一致
4
index-9 陷阱复现：action[9]=0.5 直拷 vs 跳嘴映射。✅ naive 版嘴槽 +28.6°（右髋命令误入嘴）、正确版嘴槽 0、右腿整体后移一槽——2 个槽不同
5
编码器换算：q = 2π·raw/4096 − π。✅ raw=2048→0、raw=0→−π、raw=4095→距 +π 一个量化格（≈0.088°）
6
ONNX 契约常量：直接 import publish/manifest.py（纯 stdlib）。✅ OBS_LEN=61、ACTION_LEN=14、control_hz=50、固定文件名 policy.onnx、7 个策略槽位
✅ 预期结果（真实输出末行）：结果: 27 PASS / 0 FAIL，退出码 0。完整输出存 exercise/run_output.txt

诚实限制：无真机，本实验验证的是"契约层"（源码常量与映射逻辑）；机械装配、上电、实机行走不在覆盖范围。文章中五处关键论断（61 维布局/ID 表/MOUTH_INDEX/home pose/vin_range）全部在源码中找到原文对应。
