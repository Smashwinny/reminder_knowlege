Q1

OpenArm 到底是什么？开源了哪些东西？

一句话：一套 7 自由度、按人体比例（160~165cm 人群）设计的开源机械臂，东京机器人公司 enactic 把从 CAD 图纸到电机固件到控制代码的全部家底都放上了 GitHub，整机约 $6,500、双臂 14-DOF 约 $13,000，负载约 6kg。

它不是"一个仓库"，而是 1 个门户 + 9 个子仓库的家族（实测盘点见实验①）：

子仓库装的是什么许可证
openarm_hardwareCAD 图纸（STEP 全装配/STL 可打印）+ BOM + 接线图（实体放 Google Drive，GitHub Releases 镜像）CERN-OHL-S v2
openarm_canC++17 CAN 总线电机控制库（达妙电机）Apache-2.0
openarm_mujocoMuJoCo 模型 v0.3/v1/v2 + 浏览器 WASM 版Apache-2.0
openarm_descriptionURDF/xacro 机器人描述（ROS 用）Apache-2.0
openarm_ros2 / openarm_isaac_labROS2 集成 / Isaac Lab 训练环境Apache-2.0
openarm_teleop主从遥操作（单边/双边控制）Apache-2.0
openarm_dataset / dora-openarm数据采集（LeRobot 格式）/ Dora 数据流节点Apache-2.0

还有个理念产品 OpenArm Cell：统一背景、光照、相机的标准化评测台，让全球研究者的数据在同一条生产线上产出。

Q2

为什么叫具身智能的"Linux 时刻"？

类比两条历史：1991 年 Linux 把只有大厂玩得起的 Unix 服务器系统搬上每个人的电脑； 2005 年 RepRap 把工业 3D 打印机拆成.self 复制的开源套件。共同点：

硬件被开源降维成"平民基建"后，竞争的赛道才转移到算法和数据上——这就是"时刻"的含义。

Q3

QDD 准直驱是什么？为什么"高反驱"= 安全？

QDD（Quasi-Direct Drive，准直驱）：电机几乎不经大减速比齿轮箱、直接驱动关节（小比减速或皮带一级）。 对比传统工业臂的大减速比谐波箱：

反驱性（Backdrivability）= 你从输出端施力，电机端会被带着转。反驱越好，电机绕组切割磁感线产生的反电动势就天然把碰撞力"报"给控制器——不需要额外六维力传感器就获得全身触觉。这就是 OpenArm 能"用手拖拽示教"的物理根基。

类比：[[智能舵机与菊花链总线]] 里的舵机是"内置减速箱的哑巴+工号报数"；QDD 电机反过来，减掉减速箱换取力觉透明。

Q4

重力补偿是怎么让机械臂"失重"的？

高反驱是把双刃剑：断电的 QDD 手臂会被自己的重量拖着塌下去。我的仿真实验A实测（MuJoCo，v1 模型，总质量 5.39kg）： 力矩全零 2 秒，肩关节 joint2 从 0° 掉了 100.1°，峰值角速度 7.64 rad/s。

解法 = 重力补偿（Gravity Compensation）前馈：按当前位姿，用动力学模型算出"每个关节恰好抵住自重所需的力矩 τg"，先发给电机。 剩下的才是人手/算法要出的力——于是手臂摸起来像失重的漂浮状态，拖拽示教毫不费力。

实验B 实测对照：竖直伸展位（重力矩最大的位姿）保持 3 秒——纯 PD 反馈 joint2 残差 0.051°、joint6 残差 0.135°；加上重力补偿前馈后 7 个关节误差全部归零（改善 100%）。前馈管"已知"，反馈管"意外"，这就是控制里的黄金搭档。

Q5

主从遥操作：单边 vs 双边（力反馈）差在哪？

OpenArm 用一台同款手臂当主控手柄（Leader Arm），与从臂（Follower）1:1 跟随，leader 侧控制环跑 500Hz。

单边（unilateral）：从臂抄主臂角度，抓没抓到东西，人手毫无感觉。双边（bilateral）：从臂每个关节受到的外力矩，经同样"高反驱"的主臂转成真实的推拉感——捏鸡蛋的力度感直接回到你掌心。正因主从臂是同一套 QDD 硬件，力才"透得回来"；这也解释了为什么主臂叫 KER（Kinematic EXO-frame Replica，外骨骼式复刻架）架构。

teleop 仓库里正是三个控制器文件：gravity_compasation / unilateral_control / bilateral_control（C++，500Hz 定时线程）。

Q6

一条 CAN 线怎么指挥 7 个电机？MIT 帧的 8 字节里藏了什么？

OpenArm 每个关节一颗达妙（Damiao）QDD 电机，全部挂在一条 CAN 总线上（2 线差分，[[智能舵机与菊花链总线]] 的"一根线串一串"思想，只是协议换成汽车级的 CAN）。控制库 openarm_can 支持 13 种达妙型号、4 种控制模式（MIT / POS_VEL / VEL / POS_FORCE）。

最核心的是 MIT 模式（源自 MIT 猎豹机器人约定）：一条 8 字节帧塞下 5 个控制量——

实验③我把它用 Python 逐位复刻并与手算对照：q=1.0rad → 0x8A3D 完全一致，1000 组随机值编解码往返误差全部 ≤ 半个分辨率（0.00019 rad）。所谓"电机协议"不过是一张定点压缩的位排布表——拆开就不再神秘。

9 种错误码（过压/欠压/过流/过热/失联/过载…）藏在反馈帧 D0 高 4 位，电机指示灯就靠它闪。

Q7

7 自由度怎么布局？为什么不是 6 个？

人臂就是 7 DOF：肩 3 + 肘 1 + 腕 3。OpenArm 的 MJCF 实测关节表（含限位）：

关节轴限位类比人体
joint1Z（竖直）-80° ~ +200°肩：内外旋
joint2X-100° ~ +100°肩：前后摆
joint3Z±90°肩：侧摆
joint4Y0° ~ +140°肘
joint5~7Z/X/Y±90° / ±45° / ±90°腕：3 轴球窝
finger×2slide（平移）0 ~ 44mm平行夹指（equality 耦合同步）

为什么 7 > 6？6 个自由度只够把末端摆到"任意位置+任意姿态"，但 7 DOF 多出一个冗余自由度：末端定住不动，手臂还能在内部"换姿势"（自运动）——绕开桌腿、避开障碍、让肘更贴近身体，像人手肘不动也能拧钥匙一样。代价是逆运动学从"唯一解"变成"无穷解"，要靠优化挑最舒服的那个（见 [[逆运动学IK与CCD迭代]]）。

链条与 [[前向运动学FK与四元数链]] 完全同构：7 个 hinge + 2 个 slide 手指沿运动链折叠，实验②里我摆出 joint2=90°+joint4=90° 的抓取姿，末端位移 683mm，与模型几何吻合。

Q8

MuJoCo 模型文件里，机械臂长什么样？

openarm_mujoco 提供 v0.3 / v1 / v2 三代 MJCF + 浏览器 WASM 版。v1 单臂实测：nq=9, nv=9, 执行器 8 个, 刚体 10 个, 总质量 5.390kg, dt=2ms。文件结构四件套：

default → 类"CSS"：class="motor" 统一 damping=0.25, frictionloss=0.02 worldbody → link1→…→link7→hand→finger×2 严格嵌套（[[Three.js与场景图]] 同款父子树） tendon → 固定滑绳 0.5×finger1 + 0.5×finger2 equality → 把两根手指焊成"同步开合"约束 actuator → 8 个 motor（joint2 特例 ctrlrange=±12，注释：克服全伸展重力）

两个值得学的细节：① 手指不是双执行器——1 个执行器 + equality 约束让两指镜像同步，省钱又天然同步； ② visual 与 collision 网格分离（视觉用精细 OBJ、碰撞用粗包络 STL），渲染好看、碰撞便宜——所有物理引擎的通用手法。

实验②离屏渲染出机械臂结构剪影（exercise/ex2_render.png）；断电实验证明这个模型"物理是活的"：不给力矩它就诚实地塌下去。

Q9

遥操作采下来的数据长什么样？（LeRobot 格式）

模仿学习的"燃料"就是遥操作数据。openarm_dataset 采用 Hugging Face LeRobot v2.1/v3.0 格式（parquet + 视频）。官方自带的测试数据实测（实验④）：

episodes: 2 条（1 成功 1 失败——失败数据也留档！） 观测 7 键：arms/{right,left}/{qpos,qvel,qtorque} 各 (746, 8) + lifter/elevation 动作键： arms/{right,left}/qpos + lifter/elevation 列名： joint1..joint7 + gripper，时间戳精度到纳秒，帧间隔 4.0ms = 250Hz

三个要点：① 8 列 = 7 关节 + 夹爪，和 [[策略观测向量与动作契约]] 的"逐槽对齐"契约一模一样； ② 观测里带 qtorque（力矩）——这是 QDD 免费力传感器的红利，普通舵机臂想记都记不了； ③ 连"失败 episode"都保留，因为模仿学习恰恰需要负样本。

Q10

Sim-to-Real 路线：从 MuJoCo 到真机怎么走？

与 [[Sim2Real与MuJoCo仿真]]（microduck）同一条路，但 OpenArm 把"身体描述"标准化成公共基建：MJCF/URDF/Isaac 三格式同源维护，仿真里调好的策略，参数语义与真机 CAN 指令一一对应。

Q11

CERN-OHL-S 和 Apache-2.0 有什么区别？

Apache-2.0（软件仓库）CERN-OHL-S v2（硬件 CAD）
管的对象代码物理设计文件（STEP/STL/BOM）
传染性宽松：可闭源二进制分发强互惠（S=Strongly Reciprocal）：改了硬件设计并"对外分发"（卖/发）成品，设计文件也必须开源
类比MIT/GPL 之间的宽松派硬件界的 GPL
对你的意思随便改随便商用自用随意；想拿它做闭源商业臂？门都没有

这套"软件宽松 + 硬件强互惠"的双许可组合是开源硬件项目的标准操作：代码放开吸引生态，图纸用 OHL-S 防止白嫖成品闭源售卖。
