Q1

"邪修"到底是什么？省的是哪笔钱？

不是漏洞、不是外挂、不碰任何反代——它只是把一次开发任务的"想"和"干"两道工序拆开，分别记到两个账户的账本上。

一次"给产品降本"的任务 = 读数据 → 分析规划（贵）→ 写代码执行（相对便宜）。旧干法里规划交给 Codex 里的 GPT-6 Astra Ultra，正文原话："Ultra 规划一次就能烧掉 200 刀会员周额度的 10%"——最贵的推理钱花在了"看材料写方案"上。

邪修 = 规划这道工序挪到额度完全独立、每周白送 200 次的网页版 GPT-6 Pro，Codex 只剩下 4% 一次的执行钱。

Q2

为什么网页版 Pro 额度和 Codex 额度是分开的？

因为它们在产品里就是两个不同的产品面，各配一条配额管道：网页版 ChatGPT 的"Pro 对话"按次数计（每周重置）， 编码工具 Codex 按额度池计（也是每周重置）。订阅费一次买的是这两条管道的各自额度，互相不结转、不通兑。

订阅档位网页版 GPT-6 Pro 对话Codex 额度本方案眼中的价值
$100 / 月每周 50 次独立额度池规划次数少，个人项目够用
$200 / 月每周 200 次独立额度池正文场景：规划 60 次/周仍有余

大多数人的浪费：让 Codex 又想又干（规划也烧 Codex 账），网页版那 200 次 Pro 对话在旁边吃灰。

类比：健身房年卡里其实含两样东西——器械区（Codex）和私教课（网页版 Pro）。你以为卡只有器械区， 天天用最贵的私教器械自己练规划，私教课一节没上。

举例：想"降低 API 成本"。只看代码，AI 会说"加缓存吧"（理论正确）；看到生产数据发现 90% 成本来自 Ultra 规划调用，方案立刻变成"把规划挪走"（实际有效）；再看 PR 历史知道"这里曾经上过缓存又被撤了，因为 stale 数据出过事故"， 就不会再提同样的馊主意。缺任何一路，方案都可能在重蹈覆辙。

Q4

为什么 GPT Pro 看不到生产数据？插件底层是什么？

网页版 ChatGPT 天然是沙箱里的聊天员：它能看 GitHub 插件送来的代码和 PR，但服务器日志、线上数据库在你的机房里， 它的手够不着。痛点原话对比："代码告诉 AI 理论上怎么运行，生产数据告诉 AI 实际上怎么运行"——拿不到后者的规划只是猜。

破局点：网页版聊天模式可以挂插件，而插件的底层正是 MCP（模型上下文协议）——你自建一个 MCP Server 挂上去，GPT Pro 就多了一双伸进你生产环境的"只读的手"。

插件（MCP）Skill（技能包）
本质工具接口：一组可调用的函数方法论文件包：教 Agent 怎么做事的说明书
网页版 ChatGPT✅ 能挂（本方案的地基）❌ 不能调
对应已学概念[[MCP服务器]]、[[LLM工具调用]][[AgentSkills技能包]]

所以文章让 Codex 去"造"的不是 Skill 而是插件——载体选型由宿主能挂什么决定。

Q5

"只读、最小权限、可审计"分别怎么落实？

给 AI 开生产数据的口子，安全全压在这六个字上。每一词都有对应的工程手段（实验里逐一验证过）：

原则技术落点实验验证（真跑结果）
只读① SQLite file:...?mode=ro 驱动层物理只读
② SQL 关键词校验：只放行纯 SELECT		INSERT 被拒：attempt to write a
readonly database；三条写 SQL 全被应用层拦截
最小权限③ 工具目录只有 2 个白名单工具，没有任何写工具存在
④ 表名白名单（sqlite_master 也进不来）		write_everything → "未知工具"；
sqlite_master → "表不在白名单"
可审计⑤ 每个请求（含被拒的）追加写 JSONL 审计日志客户端 8 条请求 = 审计日志 8 行（拒 5），逐条对账
图3｜三道闸 + 一本账：即使前两闸被绕过，驱动层也写不进；无论成败都留痕

要点：安全要做成"多层闸门"而不是一句提示词——提示词可能被注入绕过， mode=ro 是数据库驱动层面的物理事实。

Q6

为什么必须接 OAuth（飞书）鉴权？

MCP Server 一旦挂到网页版，就是一个挂在公网、能读生产库的服务。正文里 Codex 主动提出"需要 OAuth 登录服务"， 而公司已有飞书认证中心，于是直接接飞书鉴权——只有作者本人的飞书账号登录后才能用。

  • 不做鉴权 = 生产库裸奔：任何知道 Server 地址的人（或被提示注入攻陷的会话）都能借它的工具读你的用户表、成本表。
  • 为什么用现成的飞书而不是自建账号体系：认证中心已管着"谁是谁"，复用 = 最小实现 + 权限天然与组织架构对齐。
  • 这与已学的 [[OAuth资源发现]]（RFC 9728 远程 MCP 免贴 Key）是同一命题的两端：那是客户端自动拿凭证，这是服务端用企业 IdP 把住门。
Q7

"添加到 Codex"按钮到底做了什么？

GPT Pro 推理约 40 分钟产出高质量方案后，不用下载 md 文档再手动喂给 Codex——点聊天窗口的 "添加到 Codex"，整段对话（含方案全文）作为上下文直接出现在 Codex 窗口。这是官方给"网页版 ⇄ 编码端"修的一条 上下文接力管道：规划现场的所有推理成果零损耗搬家。

图4｜"添加到 Codex"：规划上下文的一键接力管道（免下载-上传的手动搬运）

两个执行细节：① 执行 Prompt 是授权式的（"所有值得做的"）而不是逐条点名，把二次决策也交给 Codex； ② 推理等级开"高"——轻度档容易反复失败或不验证，省下的小钱会被重试烧回去。

Q12

我没有 $200 Pro 会员，这方法对我有什么用？

  • $100 档也适用：正文明说每周 50 次 Pro 对话同样能走这条路；实验算过 60 次/周的需求会不够， 但个人项目一周做不了 60 次大规划——次数够不够，取决于你把"规划"这件事的频次设计得多高。
  • 零成本也能学走两样：①"三视角喂料"（代码+生产数据+历史决策）是规划质量方法论，不花一分钱； ②"只读最小权限可审计"的 MCP Server 是通用基建，本实验 130 行 Python 就造出来了，挂给任何 Agent 都行。
  • 真正的可迁移资产是"分账思维"：下次要烧贵额度前先问一句——这道工序能不能记到另一本更便宜/免费的账上？ 能搬就搬，搬不了的才留在贵账户上干。

这个项目给我什么（能力清单）

  1. 会算额度账：拿到任何订阅，先画出它的额度管道图（几条池子、按什么计、多久重置、互不结转），再决定工序怎么摆。
  2. 会给 AI 开"生产数据只读口"：三道闸（工具白名单 / SQL 校验 / mode=ro）+ JSONL 审计，130 行 Python 可复制的模板（见实验）。
  3. 会跑"贵想便宜干"双账户工作流：规划在网页版挂 MCP+GitHub 插件完成 → 一键/文档接力 → 执行端只干不猜。
  4. 会用三视角喂料：让 AI 做方案前同时给代码（理论）、生产数据（实际）、决策历史（为什么），方案不再纸上谈兵。
  5. 会判安全边界：官方能力组合 = 安全；抹平计费边界的搬运 = 风控雷区。
  6. 能落地到自己的项目：AIHOT 式"降本分析"任务模板——先聚合成本数据（按模型/按端点），再让贵模型出方案，执行端统一上线。

坑与提醒

  • 规划别挪走执行：邪修只省"想"的钱，执行仍要 Codex 认真跑——推理等级开"高"，轻度档反复失败反而更烧。

  • 别碰三方桥接/反代：省的是小钱，赌的是账号——被风控了没有找回通道。
  • 文章数字会过期：10%/4%/200 次是 2026-09 时点该档位的数，学的是"分账思维"，数字要按当时最新价目重算。
