02 / 从疑问走进模型

Q01 原帖的主角到底是谁？不是猜一个20 FPS模型吗？

主角是 LingBot-Map。原帖正文不写模型名，但作者本人在两条回复中都给出 Robbyant/lingbot-map；因此身份有作者直接证据，而非根据视频外观或第三方回复猜测。原帖没有引用帖字段。其正文把因子图、IMU预积分当作定位领域的演进背景，不能据此说本模型使用IMU或LiDAR。[S1]

把“原帖说什么”“作者补了什么”“论文能证明什么”分成三层，可以避免把社区评论自动升级为模型事实。

Q02 单目SLAM以前真的“不可能”吗？

不应把作者个人经历写成整个领域的历史结论。PTAM在 2007年已有面向小型AR空间的实时相机跟踪与建图；其官网明确不需要预制地图或惯性传感器，并提示初始化要平移、不能只旋转。真正变化是工作范围、稠密度、学习先验与工程可用性，而不是“2026年前没有单目SLAM”。[S4]

传统稀疏地图不等于差，神经稠密点云也不自动等于可用于精密测量的地图；比较时先明确任务。

Q03 一台相机为什么不知道真实尺寸？

针孔投影为 u=fX/Z、v=fY/Z。将三维点和相机平移同时乘任意正数 s，投影不变，因此单目几何无法单独确定米制尺度。我们的200点数值实验把世界放大 3.7倍，最大像素变化仅5.68×10⁻¹⁴。学习模型可借数据先验输出尺度，但先验不是测量保证。[S2 §3.2；E2]

模型用初始anchor帧定义规范尺度；不要把“尺度一致”翻译成“每个点都准确到米”。真正米制应用还需已知尺寸、标定或可观测的多传感约束。

Q04 它输出什么，和3DGS或完整机器人SLAM有何不同？

论文的任务输出是每帧相机位姿与深度图，投影后得到点云。不是直接输出有材质网格，也不是直接训练一组可渲染高斯；想进入3DGS、网格化或导航还需后续处理。论文明确没有显式回环闭合；它是借鉴SLAM结构的前馈流式重建基础模型，不能把机器人定位、规划与安全栈都算成已完成。[S2 §3.1、§7]

与已有[[点图与前馈重建]]互链即可；本批新增的是其上下文结构与评测边界，不再重复写一套DUSt3R入门。

Q05 Anchor、局部窗、轨迹记忆分别负责什么？

Anchor保存初始若干帧完整信息，固定参考坐标和尺度；局部pose-reference窗保存最近帧的完整图像token，为重叠区域提供稠密几何；轨迹记忆只保留离开局部窗的每帧6个特殊token（相机1、register4、anchor1）。三者是功能分工，不是三份完全相同的历史缓存。[S2 §3.2；S3 aggregator/stream.py:151–177]

旧ABot-Recon笔记谈固定12帧；这里还保留压缩历史，所以不能直接照搬其严格O(1)状态结论。

Q06 “近乎常量内存”到底是不是O(1)？

按论文公式，T帧总上下文为 (n+k)M+6T，n为anchor数、k为窗口数、M为图像token数。6T仍随历史增长，所以Direct模式并非严格O(1)。我们的518×378、patch14账本取M=999、n=8、k=64：1万帧为131,928 token，10万帧变671,928。比全保留快很多不等于没有增长。[S2复杂度分析；E3]

这些是按公式实算的token数，不是模型实际显存。若要估显存还须层数、通道、dtype、缓存布局、激活与输出点云等，不能把token比直接写成端到端显存比。

Q07 长序列为什么要Direct与VO两种模式？

Direct持续累积三层上下文，不引入跨窗对齐；技术报告称约3000帧附近开始有泛化压力。更长视频用VO/windowed：窗口内重建、窗口间靠重叠区域做 Sim(3)（尺度+旋转+平移）对齐并重置状态。它可限制单窗口资源，但会叠加边界对齐误差；“万帧稳定”不是“无限距离零漂移”。[S2 §4.4；S3 gct_stream_window_v2.py:957–1058]

读取参数单位：window_size数的是缓存关键帧槽。README表格把keyframe_interval=10的命令解释成13，存在同步错误，应以固定源码和运行记录核对。

Q08 约20 FPS要什么条件？“前馈”难道不迭代吗？

论文表9给出518×378、k=64、n=8时 H800约20 FPS，RTX4090约12 FPS，都属于作者报告，不是本批实测。FlashInfer分页KV避免频繁搬移整个连续缓存；同等设置下论文报告SDPA基线约10.5 FPS。前馈不做测试时梯度优化或BA，但相机头仍可有迭代精化，README默认camera_num_iterations=4。[S2 §3.4、表9；S3 README:320–329]

公平测速要分预热/编译、解码、推理、可视化与输出落盘，记录帧数、分辨率、GPU与dtype，不能拿50ms网络耗时冒充完整系统20 FPS。

Q09 因子图具体在“算”什么？

节点是未知状态，边是观测约束；求和加权残差平方，让状态同时尽量满足所有测量。教学实验只估2D位置，残差为 rᵢⱼ=(pⱼ−pᵢ−zᵢⱼ)/σ，固定p₀消除平移自由度。此处残差线性，最小二乘一次就是精确Gauss–Newton步，不需假装做了复杂非线性SLAM。[S5 §IV；E4]

正确回环使61位姿合成轨迹RMSE从0.9681m降到0.04135m。它只说明这组含偏置测量在正确约束下得到改善；没有证明LingBot-Map使用因子图。

Q10 有回环是不是就一定更准确？

不。回环必须先确认“真的是同一地点”；错误匹配若被赋予高权重，会强迫整张地图变形。本实验把终点误标为[4,0]，RMSE反而从0.9681m恶化至 2.2964m，说明后端优化只能服从输入，不会自动识别真理。实际系统需几何验证、鲁棒核、离群值门控与退化检测。[E4]

这也是本项目与旧[[漂移与回环闭合]]笔记的新增差异：不再做“每圈直接清零”的理想演示，而加入错误约束负对照。

Q11 IMU预积分为什么能省计算，偏置又有多危险？

IMU高频数据先在关键帧间汇总为ΔR、Δv、Δp，再作为一条相对运动约束进入因子图；关键是对初始状态的解耦与偏置变化的Jacobian修正，并非只把采样“取平均”。一手论文在SO(3)上推导旋转、噪声传播与一阶偏置修正。本批仅做已去重力、姿态固定的一维直觉实验，不是完整VIO实现。[S5 §V–VI]

400个200Hz样本、2秒、加速度偏置0.05m/s²导致位置偏差0.10m，符合½bT²；已知偏置修正后Δp恢复0.8m。真实IMU还要时间同步、外参、重力和随机游走。

Q12 怎样判断它适不适合自己的场景？

先定目标：AR预览看连贯性，测量看米制误差，导航看失败恢复与时延上界。再选有真值的数据，固定时间同步和对齐协议，同时报告ATE/RPE、点云准确率/完整率、失败比例、运行时间和显存。论文ATE是在Sim(3)对齐后计算；对齐会消去整体尺度误差，故低ATE不自动证明绝对米制准确。[S2 §5.2]

本批CPU实验验证基础数值与复杂度边界；GPU模型、公开真实视频的模型推理、硬件在线导航都待验证。没有因为云端没有用户F盘而停工，也没有借用密钥或购买服务。

03 / 主实验：从投影到定位

在解压exercise ZIP后，进入exercise的上级目录。已有python3+numpy；独立环境可执行：python3 -m venv .venv && .venv/bin/pip install numpy==2.5.4，再用.venv/bin/python替换python3。所有数据均合成，无私密输入。

E1 环境与能力边界

目的：确认这次实验发生在哪，不把CPU仿真说成GPU网络前向。
python3 exercise/lab.py env
真实结果：Python3.13.5、NumPy2.5.4，NVIDIA设备0。
验证：核对JSON环境字段；设备0只说明当前未发现NVIDIA设备，不是对所有加速器的断言。

E2 尺度不可辨识

目的：把世界点与相机平移同乘3.7，验证投影不变。
python3 exercise/lab.py scale
真实结果：200点最大像素差5.6843×10⁻¹⁴。
验证：程序断言差值<1e-10；只验证理想针孔几何，没有图像跟踪。

E3 三层上下文账本

目的：按论文公式计算Direct模式token数量与增长率。
python3 exercise/lab.py context
真实结果：1万帧131,928；10万帧671,928；每帧增量6。
验证：断言增量=6且长序列数量增长；与全历史1万帧10,050,000作同口径对照。

03 / 主实验：对照比“全绿”重要

E4 因子图正负对照

目的：用相同里程计比较无回环、正确回环、错误回环。
python3 exercise/lab.py graph
真实结果：RMSE：0.96815→0.04135m（真）；→2.29638m（假）。
验证：固定seed7、p₀=0；正确比基线低且错误比基线高；正规方程残差4.21×10⁻¹¹。

E5 一维预积分与偏置

目的：汇总400个200Hz样本，并用已知偏置解析修正。
python3 exercise/lab.py imu
真实结果：真实Δp=0.8m；未修正0.9m；修正约0.8m。
验证：对照½aT²和aT；误差<1e-12。无SO(3)/噪声/协方差，不能称完整IMU预积分库。

E6 重放与结果保存

目的：再运行五个实验组，保存JSON和轨迹数组，便于核对。
python3 exercise/lab.py verify
真实结果：5个自写实验组通过；results.json与graph-data.npz落盘。
验证：不等于官方测试或独立审核；运行日志保留完整标准输出。
