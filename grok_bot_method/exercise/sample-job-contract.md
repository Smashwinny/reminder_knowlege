# 岗位契约示例：每日行业情报员（Grok Bot 方法实践）

> 实验产物：按《Grok Bot: How to Hire Your First AI Employee》的方法
> 为一个虚构岗位编写完整契约，并对照 xAI 官方 FAQ/Computers 文档做安全符合性检查。
> 日期：2026-10-27 ｜ 本契约是练习样例，未在 Grok Bot 上真实创建。

## 一、岗位契约（Job Contract）

- **岗位名称**：每日行业情报员
- **岗位职责（只列三条，可验收）**：
  1. 每天 08:00 前汇总指定 5 个信息源的头条，输出 ≤10 条中文摘要（每条 ≤80 字，附来源链接）；
  2. 将摘要写入共享盘 `/reports/daily/YYYY-MM-DD.md`，文件名固定；
  3. 发现与本公司产品直接相关的重大新闻时，在摘要顶部标 🔴 并在群消息里 @我。
- **不在职责内（红线）**：不回复任何外部私信；不在任何平台发布内容；不修改 `/reports` 以外的任何文件；遇到登录/验证码/付款页立即停下并请求人工接管。
- **输入**：5 个信息源 URL 清单（由雇主提供）；昨日摘要（供连续性参考）。
- **输出**：上述 Markdown 文件 + 群消息通知（仅 🔴 条目）。
- **失败定义**：漏掉任一信息源；摘要超 10 条或字数超标；未标 🔴 的重大新闻；碰了红线。

## 二、权限分层

| 层级 | 动作 | 默认姿态 |
|---|---|---|
| L0 自动 | 读网页、读共享盘、写 `/reports/daily/` | 直接放行 |
| L1 每日例行 | 定时触发本岗位 routine | 放行（每日 07:30 触发） |
| L2 先问 | 群消息 @人、打开任何登录态网站 | 每次询问 |
| L3 人工接管 | 密码 / 2FA / 验证码 / 付款 / 删除 | 永远计算机接管（computer takeover） |

## 三、验收流程（三次试运行 → 五次通过 → 扩大自主）

- **试运行 1-3**（人工旁站）：每天检查输出是否满足"岗位职责+失败定义"，记录偏差；
- **五次连续通过后**：L2 中"@人"降级为自动；**再五次通过**：考虑扩大到第二信息源组；
- **任何红线触发**：立即回退到试运行状态，重新计次；
- **60 天复核**：岗位职责是否漂移、信息源是否失效、摘要质量是否下降。

## 四、交接规则

- 岗位上下文写在 Bot 的 role context 里，另存 `/reports/ROLE.md` 一份（防角色上下文丢失）；
- 换 Bot 接手时：新 Bot 读本文件 + 最近 7 天摘要即上岗；
- 重要决策必须"查当前来源"而不是凭记忆（官方 FAQ 明确要求）。

## 五、安全符合性检查（对照官方文档）

| 检查项 | 官方要求（FAQ/Computers 实测原文） | 本契约 |
|---|---|---|
| 不以 Bot 当安全边界 | "Do not use separate Bots as a security boundary"（同账户共享一台云电脑：文件/浏览器会话/登录全共享） | ✅ 契约默认共享盘可互访，敏感文件不放共享盘 |
| 先问规则覆盖高危动作 | 官方建议收窄 send/publish/delete/purchase 的"Ask first" | ✅ L2/L3 全列出 |
| 登录/2FA/验证码 | 走 computer takeover | ✅ L3 明确 |
| routine 前先真任务试跑 | "Test a skill on a real one-time task before making it a routine" | ✅ 三次试运行在前 |
| 重大决策查当前来源 | FAQ 要求勿凭记忆 | ✅ 交接规则写入 |
| 屏幕≠隔离 | 每 Bot 各有屏幕但共享一台机器 | ✅ 权限分层不依赖屏幕隔离 |
