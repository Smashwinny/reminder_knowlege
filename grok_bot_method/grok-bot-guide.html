Grok Bot：把 AI 当"员工"雇，而不是当"聊天框"用

岗位契约 + 三次试运行 + 五次通过 + 权限分层——官方文档核实：同账户 Bot 共享一台云电脑，屏幕不是隔离边界

官方 FAQ/Computers 直读核验契约样例 6/6 符合

来源：@distortgeekin《Grok Bot: How to Hire Your First AI Employee》+ docs.x.ai 官方文档 ｜ 学习日期 2026-10-27

Q1

Grok Bot 是什么？和普通聊天有什么区别？

xAI 的常驻 AI 员工：它拥有一台持久的云电脑（文件、浏览器、登录态都留着），后台持续工作，能与其他 Bot 协作——关掉手机它也不停。

官方 FAQ 定义了它与"聊天"的三个本质差异：①有电脑（持久云主机，按用户分配）②能后台（routine 定时触发，关 App 不中断）③能协作（多 Bot 并行，文件和会话可交接）。这是从"问答工具"到"岗位载体"的形态变化。

最重要的一条官方警告：云电脑按用户分配、不按 Bot 分配——同账户所有 Bot 共享同一台机器的文件、浏览器会话和登录态。原文："Do not use separate Bots as a security boundary."（不要把不同 Bot 当成安全隔离。）每个 Bot 的"屏幕"只是视图，不是边界。
Q2

"雇 AI 员工"和普通用 Agent 的区别在哪？

区别在于"雇佣关系"的三个文件化：岗位职责写清楚、验收标准可检查、红线行为明令禁止。作者（@distortgeekin）的方法把"聊天"变成"雇佣"：

雇佣要素具体做法
岗位契约职责≤3条且每条可验收；写明"不在职责内"的红线；定义"什么算失败"
试用期三次试运行，人工旁站检查输出
转正条件五次连续通过→才扩大自主（不是一次通过就放权）
权限分层自动 / 每日例行 / 每次询问 / 永远人工接管 四级
交接岗位上下文落盘（ROLE.md），换 Bot 读文件即上岗

这和知识库 [[Agent指令文件AgentMd]]（员工守则）+ [[代码管边界提示词管判断]]（红线归代码）完全同构——只是载体从项目目录变成了云电脑上的常驻 Bot。

Q3

skill 和 routine 有什么区别？（官方定义）

skill 是"做事的方法"，routine 是"把方法排上班表"。官方 FAQ：skill 描述如何做某类任务；routine 把工作流指派给一个 Bot 并按时间表或事件触发。官方强调的顺序很关键：先把 skill 在真实一次性任务上试跑成功，再固化成 routine——未经真任务验证的方法直接自动化，等于把未知风险放大成每日定时风险。

Q4

权限应该怎么分层？（官方机制 + 作者分层）

层动作例子官方/作者姿态
L0 自动读网页、读共享盘、写指定目录直接放行
L1 例行每日定时触发的已验证 routine放行（但 skill 先真任务试跑）
L2 每次询问发消息@人、打开登录态网站、外发内容官方建议收窄"Ask first"规则覆盖 send/publish/delete/purchase
L3 永远接管密码 / 2FA / 验证码 / 付款官方机制：computer takeover，Bot 停下换人
官方还有一个细节：敏感动作是否暂停审批取决于"工具×动作风险×Auto-review 规则"三者；网站也可主动拦自动化或要求人工确认——所以连接器（connectors）优先于浏览器模拟。
Q5

共享电脑带来哪些安全真相？（官方 Computers 文档）

  • 一台托管电脑服务该成员的所有团队：任何团队 recreate/terminate 都影响它；
  • 持久盘：Bot/文件/登录在重建后保留；你自装的软件会被清掉（Team Setup Scripts 装的会还原）；
  • terminate ≠ 移除访问：终止只停当前工作，要真正收回权限还得移出团队 + IdP 撤销会话；
  • 30 天无使用的休眠机会被自动终止（Enterprise 可选开关，默认关、无宽限）；
  • 删除类操作要键入 DELETE 确认、全量进审计日志、每团队同时只允许一个操作。

实践推论：敏感文件别放共享盘；不同信任级别的"员工"应该分账户（而不是分 Bot）。

Q6

"三次试运行、五次通过"科学吗？

它不是统计学，是纪律工程：用小额重复样本换信任累积，用明确回退条件防止渐进失控。三次试运行抓的是"能不能稳定做对"；五次连续通过防的是"偶尔对一次就放权"；红线触发即回退重计，防止信任只升不降。对照官方"skill 先真任务试跑再变 routine"，尺度不同（一次性 vs 连续五次）但方向一致：信任只能挣，不能默认。

Q8

这套方法离开 Grok Bot 还能用吗？

完全能——四件套与载体无关。对任何常驻 Agent（本机 Claude Code、OpenClaw、Easel 之类）：写岗位契约（≤3条可验收职责+红线）、小样本试运行、连续通过才放权、红线即回退。本指南实验部分产出了一个通用契约样例（每日行业情报员），六项安全对照全部通过，可直接改用到你自己的 Agent 上。
