01

这到底是什么项目，学它要学会什么？

先说清：证据型知识库，是把一项主张、它的来源和适用条件放在一起的资料集合。这里学习的是它的组织方法与可追溯性。

HowToLiveBetter 的中文标题是《高性价比人生指南》。README 是目录和规则，book/ 保存分节条目，docs/ 保存长文、交叉引用和核实记录。固定版本 README 写正文有 34 节；本实验只解析其中第 4 节的 18 个条目，并深查第 3、6、7 条，不声称逐一验证全书。

具体例子 你想知道“异步沟通更好”从哪来。先找第 4 节，再读第 6 条全部字段，最后看来源和备注。最终产物应是一张带证据边界的阅读卡，而不是直接取消任何会议。

读到一个建议，只是追溯开始

依据：S1 L67–100、L296–308；S2 L52–60

02

没有这种结构时，我们容易丢掉什么？

先说清：上下文，是一个结论成立时附带的人群、场景、比较对象、时间和例外；原子主张，是可以单独问“证据是什么”的最小陈述。

只摘标题会把行动建议和研究结果混在一起。条目用成本、说人话、收益、证据等级、来源、备注六个字段保留上下文，但字段不是自动可信的容器：“收益”里也可能含作者推演。先完整读取，再拆成原子主张。

具体例子 第 6 条的收益栏转述会议研究，又写“省下的时间，等于你砍掉的会议时长本身”。后一句是时间账的简化表述，没自动扣除替代沟通耗时。本次脚本初稿曾把整个收益栏归为经验性断言，作者自查后拆开并保留两次运行日志。

按句辨认证据身份，不能按栏目整包背书

依据：S2 L52–59；实验日志首次与修订复跑

03

A 级证据是不是“已经证实而且适合我”？

先说清：证据等级是作者的来源标签。荟萃分析合并多项研究；队列长期观察一群人；随机试验随机分组后比较。因果指因素改变导致结果改变；适用性指研究条件能否迁移到当前情境。

仓库 A/B/C 有自己的定义。A 包括有数字的荟萃分析、大型队列和随机试验；README 另说明法律政策类 A 指引到原始文件。A 并不保证因果，更不能自动证明适合某个人。B 可以是单项或小样本研究；C 包括作者经验与没有直接研究文献的做法。

具体例子 阅读卡要把“仓库标 A”“研究设计是什么”“本次读到哪一层”“能否迁移到当前情境”分成四项。即使标签为 A，只看到文献标识符 DOI 也只能确认存在一个来源入口，不能替它升级为全文核验。

等级标签、因果强度、个人适用性分别回答

依据：S1 L172–186

04

“证据强”与“性价比高”为什么要分开？

先说清：性价比判断，是把成本与收益放入一套取舍规则后的排序；口径，是计量对象和单位，例如时间与金钱。

README 明确说，性价比档是作者判断，按书中标准本身只算 C 级。它和证据等级是两个轴。成本标签涉及钱、时间和毅力，收益又有量级。不同口径不能合成一个无单位总分；仓库明确不把寿命、时间精力、钱与人身自由互相折算。

具体例子 两条资料都给出研究链接，不表示它们值得同样优先处理。先限定同一问题和同一口径，再展示作者标签及依据。本实验没有运行 index.html 的排序代码，也没有自行复刻其算法，所以不生成“最值得做”的榜单。

可靠程度不替你做价值取舍

依据：S1 L155–200；S4 第4步

05

怎样保证明天还能找到今天读的那一条？

先说清：固定版本，是用不可变的提交编号定位仓库快照；SHA-256 是对文件字节生成的内容指纹；溯源记录，是谁在何时从哪里取得什么内容的记录。

main 分支会变化，所以链接必须落到完整 commit。再保留文件相对路径、行号、抓取时间、文件 SHA-256 和 Git blob（Git保存文件内容的对象）。哈希能检测字节是否改变，却不能证明文字正确。条号也可能因插入条目而变化，应同时保留标题与版本。

具体例子 本次固定提交 bc149af3a02e721f0e3d03a673a0ec64fca765c4，抓取于 2026-10-05 UTC。第 6 条在第 4 节 L52–60，来源在 L58，备注在 L59。练习 ZIP 附固定源快照；离线重跑仍可核对字节，不依赖未来的 main。

版本、路径、行号和内容指纹一起留

依据：S1–S3；练习 manifest.json

06

从条目追到 DOI，就算把证据核实了吗？

先说清：DOI 是文献的持久标识符。元数据是题名、作者、年份等描述；摘要是压缩说明；全文才含完整方法、结果和限制。它们的可读程度不同。

主链是 README → 完整条目 → 来源 DOI → 核实记录 → 原始出版来源。内部交叉引用用于导航，不能代替外部研究。主实验验证前四个节点的真实连接，六个 DOI 都能在对应核实记录里找到；脚本本身没有联网读取论文。仓库核实记录是作者当时做过什么的记录，不是本次已经复核的证明。

具体例子 外源补充检查中，DOI/出版页面直接打开受限，出版方 ScienceDirect 的搜索返回可读摘要和元数据。PubMed 定向搜索也返回条目 6 对应摘要。它们只算搜索可见摘要层，不写成直接开页成功或已读全文。

追到哪里，就报告到哪里

依据：S2 L58、L67；S3 L47–66；外源访问日志

07

怎样把事实断言和作者判断分开？

先说清：事实断言，是可以接受外部证据检验的陈述，不等于已证实事实；作者判断，是从证据向行动、取舍或解释迈出的推理。

至少分四层：仓库里确有这段文字；仓库转述某研究发现；作者基于它提出建议；建议对某个读者有效。第一层可以靠本次读取确认，后面每层都需要额外证据。脚本可找明显标记，但无标记不能证明没有判断；最终仍要逐句阅读。

具体例子 第 6 条有两个 DOI，这是可复核的仓库事实。“会议数量与疲劳相关”是仓库转述的研究断言。“改用文字异步沟通”是作者推论，备注明确说明没有直接比较。某团队一定因此省时，则在本次证据之外。

“出处是真的”与“建议被证明”之间仍有距离

依据：S2 L52–59；实验结果 separation

08

数字读起来很精确，为什么还要留条件？

先说清：百分点是两个百分比直接相减；相对变化是差值除以原来的数。二者分母不同。净收益还需要扣除替代方案的成本。

先辨认数字测量的对象、样本、单位、对照和场景，再考虑算术。第 4 条转述某研究的 29.3% 与 60.0%，简单相减是 30.7 个百分点，不是“提高 30.7%”。这一算式只处理仓库所报数值，既不重新证明研究，也不预测读者的提升。

具体例子 第 6 条即使少开一个 30 分钟的会，是否净省 30 分钟仍要知道写作、阅读、来回澄清的耗时。这里的 30 分钟仅为教学假设，不是仓库实测结果；本实验不让任何团队改变沟通方式。

保留分母与条件，精确算术不能弥补证据缺口

依据：S2 L34–41、L52–59

09

资料没写清楚时，怎样“有用地不知道”？

先说清：弃权是证据不足时不输出所问结论，同时说明缺口、已知部分和补证路径。ABSTAIN表示弃权，null表示没有数值；未知不自动变成零或否。

第 7 条备注说具体百分比没核到原文。询问“拆任务一定节省多少百分比”时，合格输出是 value=null，并说明样本只支持方向性转述，不能补造比例。条目找不到、来源缺失、文件哈希不匹配，也应分别报告不同失败原因。

具体例子 真实测试得到 ABSTAIN，缺失的第 999 条得到 UNKNOWN_ENTRY，内存中删去来源字段得到 UNKNOWN_SOURCE，追加字节的负向对照被 SHA256_MISMATCH 拒绝。这些对照用于测防线，主样本仍来自真实文件。

未知有原因，下一步才有方向

依据：S2 L61–68；实验 controls

10

核实记录与正文冲突时，该相信谁？

先说清：时间漂移，是不同文件在不同时间更新后留下的差异；对账是把差异定位并补齐更新依据，而不是强行选择一个看起来更权威的版本。

本次发现第 3 条正文出现 4.11 场，而同一提交里的较旧核实记录仍说具体场次未确认、没有写数字。这是可证明的记录不一致；它不能单独证明 4.11 错误，也不能证明后来已经读到原论文。应标记待补证，查更晚的核实记录或原始来源，保留过程。

具体例子 阅读卡写“正文有值；旧核实记录未确认；本次没有完成调和”。不要写“已经验证”，也不要把旧记录删掉。本项目的 skill 文件同样只是学习对象，本轮没有安装、执行或把其中流程扩大为现实行动权限。

把缺口暴露出来，比补一个顺耳答案更可靠

依据：S2 L25–32；S3 L10–13；S4

11

怎样接到已有知识，而不是另造一堆重复笔记？

先说清：概念查重，是判断新内容与已有概念是同一概念、相关概念还是新增概念。笔记存在只能证明资料已记录，不能证明读者已经掌握。

本轮检索公开索引的394条元数据，全文读取5篇固定版本笔记：事实与判断分离、证据状态机、置信度门控与弃权、证据优先质检、信号非证据。已保存知识记录在本轮列表快照中为空；这不代表本机没有知识。已有概念可简要回顾，把篇幅留给本项目新增的双轴分离、可读层级和跨文件漂移。

具体例子 把“查到来源”与“核实结论”分开，可关联证据状态机；没核实的比例不回答，可关联弃权。但这些是方法类比，不能把A/B/C等同于可信概率或既有状态。本次仅准备入库提案，本机最新笔记仍待回迁查重。

关联已有材料，保留待本机核对

依据：知识笔记中的逐项查重表与固定版本链接

12

怎样证明这次真的跑过，而非只写了流程？

先说清：可复现实验，是同样的输入和规则能重建关键结果，并保留命令、输出、环境、失败条件和限制；独立审核是由不同执行者实际核对材料。

六步只读实验在固定仓库真实文件上运行，保留首轮、修订复跑和分步重跑。输入哈希验证、6 个 DOI 定位、判断隔离、未知弃权、负向对照、只读不变性共 11 类校验通过。通过范围仅是这条追溯流程，不能扩成“全书正确”“源论文全读过”或“用户已经学会”。

具体例子 练习 ZIP 中运行 Python 脚本可得到 JSON 证据卡与标准输出。报告中的 HTML 浏览器预览、HTML 转 PDF 路线未验证成功，不重试已受阻路线；PDF 由Python的PDF生成库 ReportLab 直接生成并逐页渲染。是否通过独立审核以第六份审核日志为准。

运行证据与结论范围必须一起交付

依据：实验日志；练习 ZIP；独立审核日志

练习与自检答案

  1. 给第6条制作四层阅读卡

    至少写出仓库事实、研究断言、作者推论、适用性未知各一项；同时指出收益栏最后一句的算账假设

  2. 回答“第7条到底节省多少百分比”

    答案不能包含编造比例；写出 ABSTAIN、null、备注行号68及下一步查原研究的计划

  3. 解释第3条的4.11差异

    说明正文与旧核实记录不同；不要判定数字错误，也不要声称已读全文

  4. 把一条来源链接升级为证据卡

    记录commit、文件、行号、DOI、当前可读层级与尚未解决的问题；区分索引摘要和出版全文

  5. 识别两种“通过”

    解释为什么11类校验通过不等于所有知识主张为真；明确人工分层和独立审核仍必要

  6. 提出一次安全迁移

    选你愿意复查的低风险资料条目，只设计读证据流程，不做健康、法律或金融个人决策，不改现实设置

能正确解释证据缺口，才算练习达标；完成记录由你确认，不由材料替你宣告。
