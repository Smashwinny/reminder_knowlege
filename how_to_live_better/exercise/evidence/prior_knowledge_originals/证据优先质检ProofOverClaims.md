# 证据优先质检（Proof over Claims）

**一句话定义**：AI 自主干活的验收标准必须是"亲眼看到产物在运行"，而不是"编译/构建通过"——用无头引擎截图、实机录像等运行时证据驱动下一轮迭代。

**属于领域**：AI 智能体的自动化验收（autonomous agent delivery）。

**通俗理解**：装修验收不能只看"建材都是合格品"（编译通过），必须开着灯、开着水管走一遍（跑起来看画面）——水管在墙里漏水，建材清单上一个红叉都没有。Godogen 把这条写进运行时清单的 Delivery 章节，作为铁律：`Judge progress from the running game, never from a clean build`；收工时 AI 还要自己回看 15~20 秒实机录像才准宣布完成。

**为什么必须"画面优先"**：存在大量**静默失败**——场景节点被序列化器悄悄丢掉、材质没贴上、物理没生效，这些在编译结果里全是 0 error。只有运行时证据（截图/录像/控制台输出）能暴露它们。质检闭环：跑起来 → 截图/录像 → AI 看画面找缺陷 → 回去修 → 再跑，直到"看到它好玩"。

**与已有概念的关联**：
- 裁判升级版：[[质检Gate与自我纠错循环]]——Gate 用**确定性脚本**当裁判（参数校验、编译），Proof over Claims 用**视觉模型/看录像**当裁判，覆盖"编译器管不了"的维度
- 感知来源：[[Agent循环]]——截图/录像就是智能体的"眼睛"，把运行时画面作为感知输入回灌决策
- 工程手段：Godot 用 `--write-movie --fixed-fps 30` 确定性录像（450 帧=15 秒，可复现）；Babylon.js 直接给浏览器 URL 看直播
- PaperRoute 补强（2026-10）：证据还要**可定位**——别对对话框说"动作改自然点"（形容词=玄学，盲调实测修复率 19.5%），要自动抓取正/侧/后+黏土转面图后指着帧说话（"帽子第 3 帧没遮住头发"，推文口径改动成功率 70%，帧索引反馈实测 100%）；devlog 每个 checkpoint 挂截图+SHA-256，就是给下个会话的证据锚点（见 [[机制流与资产流隔离]]、[[混合模型分工流水线]]）
- 花叔《3D Vibe Coding》补强（2026-10-03）：证据要有**口径标签与独立通道数**——① 口径学：算子耗时 vs 端到端（16s vs 31s，混用把工期估少一半）、量出来的写 GiB 算出来的写 GB（看单位就知道数是量的还是算的）；② 输入用 SHA-256 锁死（"我记得是同一张图"和"两文件哈希逐位相同"证据等级差一个数量级）；③ 结论要三条独立通道互证（自写解析器 + Blender + 平台读数，"自说自话"的脚本不算证据）；④ **自己的文档也是待核实来源**（README 里 927 万 vs 927K 差十倍躺了两天，重测后推翻"必须重拓扑"整句话）；⑤ 宁可缺数不凑数（取不回的耗时那格就空着）；⑥ "量不出回归"≠"变快了"（见 [[先量后优化性能法]]）
