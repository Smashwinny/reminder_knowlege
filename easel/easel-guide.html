Q1

Easel 是什么？一句话能说清吗？

一个开源的社交媒体运营智能体：把"发现热点→策划选题→创作内容→多平台发布→数据归因"这条自媒体全流程交给 AI，产出的不是建议而是可以直接发布的图文/视频成品。

它由浙江大学 REAL Lab（联合北大 OpenDCAI Lab）开发，底层是 OpenClaw agent 底座，上挂 113 个内容技能（实测 skills 目录 114 个）和 账号画像系统，覆盖小红书、抖音、快手、知乎、B站、视频号、公众号七个平台。定位句：不是聊天顾问，是"能交出成品的 content workbench"。

Q2

为什么需要它？自媒体运营的痛点是什么？

自媒体是"高频率、多平台、重复盘"的苦力活：一个人运营一个号每天要经历找选题、写稿、做图、适配各平台格式、发布、看数据——而通用聊天 AI 只会"给建议"，最后动手还得是人。

Easel 的判断：自媒体流程高度模式化，恰是 Agent 最擅长接管的类型。它的增量不在某个单点技术，而在把整个工作流产品化：113 个技能覆盖从 SEO 检查到爆款复盘的每个工序，账号画像保证"同一个号风格稳定"，归因阶段把数据教训写回画像让输出越用越准。

与知识库已学的 [[AI热点长视频生产流水线]]（Simon 的 Skill 方案）对照：那是"单点 deep workflow"，Easel 是"全家桶 workbench"——选题、图文、多平台、复盘全部内置。
Q3

它是怎么做到的？核心机制拆解

① 账号画像（六维模板，实测存在）

每个账号一个目录 profiles/<name>/，实测模板含六个文件：

文件维度实测内容要点
identity.md定位账号是谁、做什么
style.md风格语言调性、视觉风格
audience.md受众读者画像
platforms.md平台各平台差异化策略
preferences.md偏好与红线要做的 / 不做的 / 合规底线三栏
memory.md长期记忆内容洞察 / 踩过的坑，带"不是每次做完任务都写"的更新纪律

② 技能分层（SKILL-SPEC 规范）

技能说明（SKILL.md frontmatter：name/description/layer）+ 按需参考资料 + 可执行脚本三层分离；layer 标注五段归属（discover/plan/create/publish/attribute）。产物统一落 outputs/<主题>/，决策层产物（创作简报）与执行层产物分开归档。

③ 发布安全闸门（本指南实测重点）

docs/SKILL-SPEC.md 规定：一切发布类脚本真发前必须过 content_guard.py 的 guard_or_die()：BLOCK 级（API key、内部 URL、env 真值）→ fail-closed 退出码 7；WARN 级（"AI 生成"字样、模型名）→ 只提醒不拦；显式 --allow-unsafe 才放行。

Q5

"自进化"是真的吗？归因写回到底怎么运作？

文章里的"自进化"需要祛魅：它不是模型权重在更新，而是"外部记忆 + 上下文适应"。

机制链条：发布后用 skill-publish-analytics 读数据 → skill-content-postmortem 做证据化复盘（实测其 SKILL.md 要求输入内容原文/平台/数据指标/发布时间/同期对照基线）→ 提炼出的规律写进画像 memory.md 的"内容洞察"，坑写进"踩过的坑" → 下次创作时画像作为上下文注入。模型本身一个参数都没变——这正是知识库 [[三层记忆]]/[[决策记忆结算反思闭环]] 的同类结构：经验沉淀在记忆层，不进权重层。

而且 memory.md 模板自带反膨胀纪律："此文件记录真正有价值的洞察，不是每次做完任务都写……不要堆流水账。"——比很多商业产品的记忆系统克制。

Q8

边界与风险是什么？

  • 不是装上就能跑：需要 Python 3.10+、Node 24.16+（25.x 与 26.0 明确不兼容）、OpenClaw、LLM key、Playwright/Chromium；FFmpeg 缺失时音视频技能降级；
  • Windows 全链路兼容"进行中"：官方自述 Windows 原生安装可用但完整链路仍在完善；
  • 发布是真实账号行为：登录态在你自己的社媒账号上，发错内容是真发错——content_guard 是最后一道闸，但不是免死金牌；
  • 小红书明确提示"可能检测自动化"：README 建议小红书人工预览确认后手动发布；
  • 文章陈述 ≠ 实测："一个月星数增长""爆款原因分析"是文章说法，本实验未核对；七平台文档支持 ≠ 每平台都已稳定发布成功；
  • 归因准确性未验证：复盘质量取决于数据读取与 LLM 分析，没有客观基准。
Q9

这类"自媒体全家桶 Agent"值不值得跟进？

值得研究架构，谨慎托付账号。

值得学：①画像即配置——把"账号是谁"从 prompt 里抽出来变成文件资产，换号即换目录；②闸门模式——发布类操作统一过确定性安全检查，AI 措辞只提醒、真敏感必拦，分级设计非常成熟；③记忆纪律——"不是每次做完任务都写"反膨胀设计。

谨慎用：社媒账号是稀缺资产（封禁成本高），发布链路建议长期保持"AI 草稿 + 人工点发"，把 Easel 用在发现/策划/创作/归因四段，发布段只做预检。

Q10

实际怎么装、怎么用？

# 安装（Linux/macOS/Windows PowerShell）
git clone https://github.com/ZJU-REAL/Easel && cd Easel
bash setup.sh          # 或 Windows: .\setup.ps1
# 安装器建隔离 easel profile，不动 ~/.openclaw

# 配置：web UI（localhost:7860）里填 LLM key（Anthropic 或 OpenAI 兼容）

# 日常
easel doctor           # 体检（读 outputs/_install/last-install.json）
easel web              # 打开工作台
easel chat             # 命令行对话
嵌入 API 可选：不配时"显式使用关键词记忆检索"，不会偷偷反复调 chat 端点的 embedding——这种"降级显式化"设计值得抄。
★

这个项目给我什么能力？

  1. 给自己的账号建画像资产：六维模板直接可抄，任何内容工作都能用"定位/风格/受众/平台/红线/记忆"描述清楚一个账号；
  2. 抄发布安全闸门设计：content_guard 的 BLOCK/WARN 分级 + exit 7 fail-closed + 显式绕过，可平移到任何"AI 出站内容"管道；
  3. 抄记忆更新纪律："有价值的洞察才写、不堆流水账"——给自己的 vault/记忆系统立规矩；
  4. 证据化复盘模板：skill-content-postmortem 的输入契约（指标+基线对照）可用于任何"事后归因"场景；
  5. 五段工作流分工：发现/策划/创作/发布/归因的工序切分，可直接映射到自己的内容生产流水线。

一页总结

  • 它是自媒体全流程 Agent 工作台：浙大 REAL Lab 出品，OpenClaw + 113 技能 + 七平台；
  • 画像六维是核心资产：一个账号一套 Markdown，偏好红线合规底线分层，记忆有反膨胀纪律；
  • 发布闸门实测有效：BLOCK 必拦 exit 7 / WARN 提醒 / 显式绕过——可平移的设计；
  • "自进化"=记忆写回非权重更新：归因复盘进 memory.md，越用越准但模型不变；
  • 建议用法：发现/策划/创作/归因交给它，发布保持人工点发。
