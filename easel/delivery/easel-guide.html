01
问题 01 / 定位与问题

Easel 到底替创作者整理了什么

Easel 把创作上下文、技能和文件产物组织成内容工作台。

项目的目标链路。图中的外部创作、发布与复盘能力并未在本次实验中运行。

先给出定义

内容工作台是围绕选题、制作、管理和发布组织工具的应用。Easel 的 README 把它定位为面向社交媒体创作者的开源工作台，借助 OpenClaw 执行工作。OpenClaw 是运行智能体会话和工具的宿主，本次只阅读其在项目中的接口，不启动它。

用一个具体场景理解

虚构的“周末科普小站”想写一条微博短文。普通聊天可以给出句子；工作台还需要知道受众是谁、稿件放在哪、哪版是成品、检查过哪些条件，以及后来是否真的发布。后面的问题将沿这条线展开。

本指南选择的小切口

本次用自写虚构画像与中文短文，调用固定版本的真实本地组件。它能让你观察文件、索引和校验行为；这不是模型生成内容，也不是“发现到归因”的整套实跑。

自测：得到一段好文案，就等于内容工作台已验证吗

参考回答：不等于。还要分别验证存储、元数据、检查与外部效果；本次只覆盖指定本地组件。

02
问题 02 / 流程与执行者

五层工作流为何需要明确交接

分层描述工作步骤，不代表已经运行五个智能体。

发现和策划合并为一个图节点，实际概念仍是 discover、plan、produce、publish、attribute 五层。

五层是什么意思

发现寻找内容机会；策划确定主题、受众和结构；制作得到文案、图片或视频；发布把审核后的内容发到指定平台；归因分析表现并反馈下一轮。这里的层是职责分类，不是独立进程数量，也不是五个模型各自完成工作的证据。

交接不能只剩一句总结

创作简报 brief 是把受众、基调、必须保留和避免事项写清的文件。例如“给初学者讲番茄钟，避免承诺效率翻倍”。下游要读取简报和正文，而不能只凭“一篇效率稿已经做好”的一句话。

接回已有知识

已有“分镜表驱动生成”和“产物留痕与状态外置”可以复用。Easel 的增量是把层名、产物路径和摘要登记在同一个项目记录里。表格或摘要填满仍不等于成品可用。

自测：manifest 记录了 produce/done，就证明制作工具运行过吗

参考回答：不证明。记录可以被手工写入，要继续检查真实文件和执行日志。

问题 03 / 画像与记忆范围

六份画像文件怎样影响创作

Profile 描述创作背景，平台登录身份必须另行核实。

六份文件被分为三组展示；它们是内容上下文，不是账号凭证。

一个新对象先讲清

Profile 即画像，是有关账号定位、写作风格、受众、平台、偏好和记忆的上下文文件夹。persona.py 按 identity、style、audience、platforms、preferences、memory 的固定顺序读取非空 Markdown，其余 Markdown 再按文件名追加。

一组可观察的变化

例如可以给“周末科普小站”的 style 写上“短句，先例子后术语”，audience 写上“刚接触时间管理的人”。本次实际使用“纸页角落”虚构画像，核对文件修改和消息前缀；没有模型调用，就不能据此声称输出已经更符合这种风格。

画像记忆和真实身份分开

persona_prefix 会提示使用该画像目录下的 memory.md，避免把不同画像的账号知识混到全局记忆。这个提示是上下文安排，不是操作系统隔离。选中一个画像不会自动登录微博，也不会证明当前发布账号归属。

自测：profile_exists 返回真，能证明账号已经登录吗

参考回答：只能说明对应画像目录存在；登录状态和发布身份还需要平台侧证据。

问题 04 / 按需加载与配置

已有 Skill 为什么还需要提示词分层

把长期规则、路径和临时技能分开，能减少上下文混乱。

这是固定版本文档描述的 prompt stack；本次没有运行宿主加载过程。

提示词栈是什么

提示词栈就是按职责组合的多层说明。SOUL 管沟通人格与能力概览；AGENTS 管分工与编排；CONTEXT 提供项目路径；触发具体技能后再读 SKILL 和必要参考资料。它不是另一个生成模型。

沿用已学内容

“AgentSkills 技能包”已经讲过说明书、脚本和参考资料的差别。这里不重教概念，重点看 Easel 的接口：SKILL.md 的 name、description、layer 用于发现和分类，scripts 在执行时被调用，不能把脚本放在目录里等同于它运行过。

避免文档名称带来的错觉

例如发布检查清单的某处仍提到 meta.json，而总规范约定 .easel.json。面对这种文档漂移，要沿实际代码核对消费者读什么文件。教程不应为“看起来统一”的接口补造并不存在的保证。

参考回答：不足。加载、依赖、许可、服务权限和实际输入都可能影响可用性。

问题 05 / 目录与可接手性

为什么成品和中间文件要分开放

目录让人找得到文件，证据让人判断文件是否可用。

项目根存成品，assets 存草稿或素材；.easel.json 记录元数据，不复制全部正文。

产物与素材的区别

产物是用户最终要读、发或交付的文件；中间件是制作时需要但通常不直接交付的草稿、镜头或临时素材。Easel 约定一个具体主题一个目录，成品在目录根，assets 子目录保存中间件。

文件组织的例子

一个“番茄钟实验记录”目录可以包含 weibo-post.txt、brief.md、assets/draft.txt 和 .easel.json。这样复用时知道去哪里找正文，修改时也能区分成品和草稿；但目录整齐并不证明正文事实正确。

沿着已学概念加一层验证

已有“产物留痕与状态外置”解释了为何不要只靠会话记忆。本项目进一步要求消费者打开文件，检查存在性、类型和内容。把不存在的文件名写进 outputs 字段，登记程序仍可能成功。

自测：只有 outputs=["final.mp4"]，能证明视频可以播放吗

参考回答：不能。还需文件存在、可解码、内容和音画等检查；本次不生成或播放视频。

问题 06 / 薄索引与双状态域

一份 manifest 为什么有两种状态

项目的 draft/ready/published 与步骤的 done/failed 回答不同问题。

上下两条状态线独立；脚本允许记录这些词，并不自动完成对应现实动作。

manifest 是什么

Manifest 是描述项目及其产物的结构化清单。Easel 将标题、平台、体裁、成品列表等展示字段，与 steps 步骤数组写进 .easel.json。薄索引意味着只保留摘要和路径，全文仍在正文、简报和素材文件中。

两个状态域分别解释

项目 status 的 draft、ready、published 用于生命周期展示；每个步骤 status 的 done、failed 表达该次登记的执行情况。两者可以同时出现不同含义。meta 只更新本次传入的字段，列表字段给出后整体替换。

一个容易误判的例子

把项目 status 手动设为 published，只会改变文件里的字符串，不会向社交平台发帖。record 的原子写入通过临时文件加替换降低半文件风险，但它不是发布回执，也不提供全流程事务或并发合并保证。

自测：文件里写 published，能当作平台发布证据吗

参考回答：不能。需要实际发送日志、目标账号以及平台回执或可验证链接。

问题 07 / 失败与消费者检查

latest 取到最近一步就能继续吗

latest 取最后一条匹配记录，不保证那条记录成功。

这是字段与读取规则示意。下游必须读取 status，不可把 found=true 当成成功。

先定义消费者

消费者是读取上游产物并继续工作的程序或智能体。manifest latest 按可选 layer 筛选，然后返回最后一条记录；没有匹配记录时输出 found=false 并退出1。它没有自动过滤 failed 步骤。

用失败记录看差异

第一次策划完成后写 done；第二次修改因输入不足写 failed。此时 latest --layer plan 看到的是第二条。正确的下游应先停下来检查原因、可复用产物和授权，再决定恢复；不能忽略 failed 直接制作。

测试通过究竟指什么

负例是专门设计来触发拒绝、缺失或失败的输入。负例返回预期非零码，说明这条行为被观察到，不等于业务成功。本实验把上游自测入口与自写行为检查分开统计，避免把所有数字拼成“全套测试通过”。

自测：found=true 但 step.status=failed 应怎样理解

参考回答：找到了一条失败记录；是否能继续由消费者核实，不能直接把它当成功输入。

来源：latest 和记录状态 skills/shared/scripts/manifest.py

问题 08 / 启发式与元数据

素材索引为何可能认错平台

assets 的平台判断依赖路径规则，不会自动读取 .easel.json 的 platform。

两条信息来源不同；一致需要额外核对，不是内置自动同步。

启发式是什么意思

启发式是用简单规则作推断。assets.py 从相对路径和文件名识别平台，结合扩展名、关键词、日期和大小建立索引。规则便宜且确定，但它理解的是路径字符串，不能理解文案真正适合哪个平台。

一个会暴露差异的例子

把一份相同正文放在包含 weibo 的路径中，可能被标为 weibo；使用中性路径时可能变为 unknown。即使 .easel.json 里写 platform=微博，这个扫描器也不因此获得平台字段。标签与索引是另一组状态文件。

扫描也会写文件

scan 会生成或更新 outputs 根下的 INDEX.json，不能称作纯只读。search 依赖索引，并有相应扫描路径。实验只在练习目录内扫描、检索、打标签；不运行 archive 或 --apply 移动操作。

自测：搜索未返回稿件，最先检查什么

参考回答：检查索引是否更新、路径命名及筛选字段，不要先断言文件丢失或平台元数据无效。

问题 09 / 确定性计数与目标

字数为什么交给代码仍要说明口径

脚本给出可复现的计数，不等于复刻微博的实时计费或发布规则。

输入、口径、目标和容差共同决定结果；修改目标就可能改变通过状态。

计数口径先定义

口径是把什么算一个单位的约定。wordcount.py 的 social_count 把 CJK（中日韩表意文字区）字符、英文词、数字串、标点或符号相加，同时给出含空白字符数等指标。它是本地近似规则，不是本轮核实的微博官方实时标准。

为什么不要让模型自报字数

同一句中文夹有 AI、数字和标点，按英文词计数与按所有字符计数会不同。确定性脚本能让同一输入反复得到相同结果。严格目标必须明确 metric、target 和 tolerance；默认容差为5%，范围边界使用 round。

看见变化才学会检查

实验对自写短文的冗长版本与修订版本检查相同目标，观察 over 变为 ok。这不需要调用模型，也不修改发布平台。检查某个目标通过，只表示该口径的本地判定通过，不代表内容质量或发布可行性。

自测：social_count 通过，能证明微博一定接收吗

参考回答：不能。官方当前限制、账号状态、媒体规格与内容规则仍需分别核实。

来源：计数和目标校验实现 skills/shared/scripts/wordcount.py

问题 10 / 检查范围与退出码

内容扫描的 BLOCK 和 WARN 有何差别

扫描器只处理定义过的模式；没有阻塞命中不能保证内容全面安全。

本地阻塞函数在特定条件下可退出7；实验只调用本地组件，没有发送内容。

两个级别分别是什么

BLOCK 是密钥样式、内部地址或路径等阻塞类别；WARN 是模型名或 AI 表述等提醒类别。content_guard 结合正则模式和敏感环境值扫描文本，报告会对命中片段打码。这里的安全是限定范围的泄露检查。

为什么技术词不能一律禁止

技术科普本来可能需要写 OpenClaw 或“由AI生成”。固定版本将此类内容作为 WARN。提醒后应按真实用途与平台要求决定，不该为了消除警告而隐瞒必要的AI披露或误导读者。

实验与现实发布的边界

本地阻塞分支不会自行发布。真实秘密不能拿来做学习样本；实验只使用合成测试值，也不扫描个人 .env。事实、版权、广告声明、授权和平台规则不由这个函数全面覆盖。

自测：WARN 存在但函数返回，意味着可直接发布吗

参考回答：不意味着。它只说明该提醒不会在此函数中硬拦，仍需其他检查和发布授权。

问题 11 / 接口约定与实际调用

路径校验为什么必须显式调用

有一个校验函数，不等于所有写入入口都自动受它保护。

图表示 output_paths 的用途。manifest 当前实现没有自动调用它；实验由自建 harness 显式检查。

路径校验检查什么

output_paths.validate_output_path 会解析绝对路径，要求内容位于 outputs 下的具体主题目录，拒绝根目录散文件、泛化主题名和默认不允许的系统路径。resolve 将路径归一化并解析已有链接，但单次检查不等于完整操作系统沙箱。

把规范和实现分清

总规范要求新脚本写入前调用校验器；固定版本 manifest.py 的路径构造本身没有调用它。实验用自建 harness 显式连接检查与后续动作。Harness 是组织输入、调用与检查的测试程序；这段连接是教学新增，不能写成上游统一安全层。

一个有用的反例

outputs/test/post.txt 因主题名过于泛化可被拒绝；outputs/番茄钟观察/post.txt 则符合该命名约定。还要测试根目录与越界路径。通过这些样本只证明所测路径行为，不保证并发竞态、全部符号链接或所有调用点安全。

自测：路径被登记进 manifest，就说明校验器放行了吗

参考回答：不说明。需要实际调用证据；本次 harness 会单独记录路径检查。

问题 12 / 证据与下一步

怎样知道这次学到了哪一层

源码可读、组件可跑、宿主可用、平台发布是不同证据层。

本指南实际推进到固定版本的本地组件行为；右侧两层需要新的环境、授权和证据。

先锁定版本再讨论结果

源码提交 SHA 是锁定具体代码快照的标识。本次固定提交为 6c049ce 开头；pyproject.toml 写0.2.1，包内 __init__.py 写0.1.1，git describe 为 v0.2.1-79-g6c049ce。版本文本不一致时以完整SHA和文件指纹定位。

重复运行也要保留差异

同样输入、同样源码可以重放行为；时间戳、临时目录和文件修改时间可能变化。应该比较稳定字段和预期分支，不能承诺每次 JSON 都字节相同。原始失败、非零退出和恢复过程也要保留。

下一步需要什么证据

若以后要体验完整工作台，应再核对依赖、模型服务、OpenClaw、平台身份与许可，并为真实动作取得授权。本次未运行 CLI 主入口、Web 服务、全局同步 hook、模型生成、社媒登录或发布；根 LICENSE 为 Apache-2.0，不能据此认证所有第三方技能许可。

自测：本地组件实验成功后，最准确的总结是什么

参考回答：所列真实组件对这组虚构输入表现符合已记录预期；整套内容工作流和真实发布尚未验证。

项目文件与交接契约

五个用途

  1. 用虚构画像整理科普账号的受众、语气和红线，先明确创作输入
  2. 给一组自写短文加主题目录与薄索引，下一次可以按文件继续改
  3. 对中文短文作受控修改，练习区分超出、不足和达标
  4. 在纯合成样本上对比警告、阻塞与路径拒绝，学习校验边界
  5. 为未来的完整部署列出仍需验证的模型、宿主、账号与发布证据
一个主实验 / 先看边界

真正调用 Easel 的六个本地组件，观察拒绝到通过的变化。

真实运行了什么

主实验采用六个学习步骤：第1步运行含六个内部阶段的自建harness；后5步读取并验证真实产物。上游模块保持原字节，runpy（标准库的进程内脚本执行器）按日志argv执行；画像路径由harness指向虚构夹具。没有运行Easel主CLI、模型或发布器。

环境与依赖

Linux x86_64，Python 3.12.14，标准库。练习包带必要源码副本、Apache-2.0根许可和指纹清单；复放不需安装依赖。env -i移除继承凭据，进程内审计hook限制网络、子进程与越界写入；它不是操作系统沙箱，也没有安装全局hook。

怎样开始

将随附练习ZIP解压到一个新的空目录，在该目录打开Linux/POSIX终端，按后页6条命令操作。所有相对路径以解包根为准。不要在已有fixtures上重跑；每次复放都用新目录。后页命令均已原样执行，完整stdout/stderr见实验日志。
