01

终端里装了它，算力究竟在哪里？

CLI 是遥控器，真正运行代码的是 Colab 远程机器。

命令行界面（CLI）让你用文字命令操作服务。这个项目把申请会话、执行 Python、传文件和释放资源接到终端。安装它不会让本机凭空多出 GPU，也不代表账号一定拿得到某种加速器。

术语落地 运行时（runtime）是承载代码的远程执行环境；会话（session）把本地名字、后端分配和访问状态关联起来。

看一个场景 你在笔记本上编辑分析脚本，CLI 把代码送到远程内核；图表和文件还需按需要取回。本次只实测本地日志模块，没有申请远程机器。

先分清“在哪里发命令”和“在哪里算”，本次实验停留在本地。

依据：S1、S6。本页解释中的建议不等于本次已验证功能。

02

已有 Colab 网页，为什么还要 CLI？

把重复的手工操作，变成可检查的命令步骤。

网页适合交互探索；CLI 适合把本地文件、参数、执行与取回过程接进工作流。它也能给 AI 代理提供操作接口，但自动化程度不会扩大权限、额度或服务允许的用途。是否适合长期无人值守，还要看认证、配额、失败处理和释放证据。

术语落地 工作流是有输入、步骤、输出与失败分支的一组操作。自动化只是减少重复点击，不是可靠性证明。

看一个场景 同一个脚本换三个参数时，固定版本和记录每次输出比凭记忆重做更可靠。先在本地学会留存证据，再考虑经过授权的远程运行。

复用“工具调用生命周期”：发出请求之后，还要判断成功与收尾。

依据：S1、S7。本页解释中的建议不等于本次已验证功能。

03

new、exec、run 各负责哪一段？

new 申请，exec 使用已有会话，run 把一次任务串起来。

new 申请运行时并记住会话；exec 把代码送入所选会话；stop 释放会话。run 则为脚本申请新会话、传递参数、执行并尝试收尾。--keep 会跳过自动释放，必须另行管理。程序的 finally 收尾设计，并不能证明每次网络故障后资源都已释放。

术语落地 生命周期指资源从申请到使用再到释放的全过程；幂等是重复操作仍能得到可预测结果，本次没有验证远程操作的幂等性。

看一个场景 一次性图片处理可用单次任务思路；需要多次交互调试则复用会话。选择前先确定失败时如何查状态、保结果、停资源。

源码显示 run 有 finally 清理路径；本次没有进行远程释放验证。

依据：S1、S7。本页解释中的建议不等于本次已验证功能。

04

脚本、Notebook、REPL 和 console 怎么选？

Python 内核与终端 shell 是两条不同的执行通道。

exec 支持本地 Python 文件、Notebook 和标准输入；REPL 是逐条输入 Python 的交互循环。console 提供远程终端 shell，绕过 Jupyter 内核。TTY 表示交互式终端，管道输入不是 TTY，因此结束输入和退出行为需要单独处理。

术语落地 内核（kernel）执行 Notebook 的代码单元；shell 解释系统命令。两者共享机器并不等于使用相同协议或语法。

看一个场景 导出器给 source=piped 且不以 ! 开头的代码加 %%bash。但管道输入的 Python REPL 也使用 piped 标记，存在被误当 shell 的风险，重跑前必须检查。

piped 是来源标签，不是可靠语言识别；不要直接重跑导出的单元。

依据：S6、S9、S13。本页解释中的建议不等于本次已验证功能。

05

本地文件、远程文件与下载结果是什么关系？

传代码与传数据是两件事；远程成功不等于本地已保存。

本地脚本可以被读取后发送给内核，不必先作为文件上传。脚本引用的数据文件却仍须在远程可见的位置准备好。upload、download 与远程文件管理负责另一条数据通路。运行时可能被回收，关键输出应按授权取回并检查大小、格式或摘要。

术语落地 数据面负责实际字节与结果；控制面负责申请、选择、停止等指令。沿用这个区分，可以减少“命令成功但文件没到手”的误判。

看一个场景 日志里写着 download，并不能证明某份真实模型已下载。本次使用明确标为虚构的文件事件，只验证日志表示与格式转换。

历史事件是操作记录；真实文件是否存在需要独立证据。

依据：S1、S8。本页解释中的建议不等于本次已验证功能。

06

默认认证是 ADC 还是 OAuth2？

这个固定版本里，代码默认 OAuth2；README 写成 ADC。

OAuth2 是让应用获得用户授权的机制；ADC 是 Google 库寻找应用默认凭据的约定。固定提交的 cli.py 与 common.py 都选择 OAUTH2，README 的默认 adc 描述与之冲突。学习时应保留差异，部署前检查实际版本的帮助和源码，不把文档一句话当运行事实。

术语落地 认证回答“你是谁”，授权回答“可以做什么”。工具存在、账号登录和服务权益是不同层次。

看一个场景 一个看似查询信息的命令也可能刷新凭据或访问网络。本实验直接导入日志与导出模块，并用进程内网络阻断，不触发任何 Google 登录。

截至本次固定提交可定位到具体文件；不能外推到所有未来版本。

依据：S1、S3、S4。本页解释中的建议不等于本次已验证功能。

07

只加 --config，就把实验完全隔离了吗？

--config 只改会话状态文件，其他路径仍可能跟着 HOME。

common.py 的会话存储接受 config_path，但历史记录器与设置存储分别使用默认路径；日志路径也独立处理。因此另指定 sessions.json 不足以隔离所有本地状态。本次在项目内安排 HOME、缓存和临时目录，并绕开整套 CLI 启动与认证入口。

术语落地 隔离边界要由实际路径与访问行为证明。进程内 socket 阻断能拦住测试进程的联网尝试，不等于操作系统级安全沙箱。

看一个场景 换一本“会话账本”，不等于把“历史档案”和“设置抽屉”也搬走。若导入模块时就计算 HOME，必须在导入前设好进程环境。

实验设置只作用于项目与当前进程，没有修改全局配置。

依据：S4、S8、S3。本页解释中的建议不等于本次已验证功能。

08

JSONL 历史为什么值得保留？

一行一个事件，让机器可以重新读取完整结构。

JSONL 每行保存一个可独立解析的 JSON 值；这里每行是事件对象。HistoryLogger 追加 timestamp、event_type 和事件数据，按会话保存。get_history 逐行读回，list_sessions 列出有日志的会话。它不是不可篡改审计系统，缺失或损坏记录仍要检查。

术语落地 事件（event）描述某个时刻发生的动作及相关数据；历史快照记录事实的表示，不能代替执行本身。

看一个场景 把“代码是什么”和“输出是什么”写进 execution 事件，随后能导出教学 Notebook。人工写入一个成功输出，只能证明导出能力，不能证明计算真的发生。

本实验的输入是合成事件，实际执行的是上游日志代码。

依据：S8、S11。本页解释中的建议不等于本次已验证功能。

09

导出 ipynb、Markdown、TXT 会丢什么？

格式方便程度不同，保留的信息也不同。

JSONL 导出逐事件保存结构；ipynb 把部分事件变成代码或说明单元。Markdown 着重代码与 text 输出；TXT 对 execution 主要写代码。导出器还会把含 text 的输出统一写成 stdout，并忽略部分事件类型。因此可读版不是完整原始记录的替代品。

术语落地 序列化把结构变成可保存的字节；投影只选择原数据的一部分。Notebook 和 Markdown 在这里更接近面向阅读的投影。

看一个场景 当输出没有 text/data 且 output_type=error 时，错误会映射到 Notebook；Markdown 可能漏掉这些详情。原始 JSONL 应与可读报告一起保存。

漂亮的报告不是无损备份，导出之后还要比较关键字段。

依据：S9。本页解释中的建议不等于本次已验证功能。

没有登录 Google，怎样做一次真实实验？

运行真实本地模块，明确把远程服务留在验证范围之外。

程序可拆成多层。HistoryLogger 和 converter 的本地路径，可以用固定上游源码、可控输入和独立断言运行。网络阻断与项目内目录减少意外触达账号的风险。这样能真实验证这条管线，却不能证明会话申请、GPU、计费或某篇帖文的运行结论。

术语落地 测试替身是替代外部系统的受控对象；合成夹具是专门设计的输入。这里没有改写 logger 或 converter，只把输入标为合成数据。

看一个场景 同一输入分别导出四种格式，再用 nbformat 校验 Notebook 结构，检查 shell 包装、错误输出与事件数量。这比只截一张“运行成功”图更可复核。

真实代码执行与真实云端执行必须分别举证。

Google One 的 200 CCUs 能直接等于免费 GPU 吗？

实验结果与边界

  • 通过不等于没有缺点：测试确认了元数据可覆盖、损坏 JSONL 报错，以及导出器的已有信息损失；没有修改上游代码修复这些行为。
