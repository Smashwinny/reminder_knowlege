Q1

Higgsfield 是什么？这次公告新在哪？

AI 视频/图像生成平台（模型有 Soul、Nano Banana Pro、Seedance、Kling、Veo）。这次公告的新意：视频生成能力接入了 ChatGPT/Codex 形态——既有结构化通路（CLI/MCP），也有 Computer Use 形式的 GUI 操作。公告是维护者宣称，能验证的是官方文档里可读的契约。

Q2

三条通路怎么选？（决策矩阵）

通路谁用适合边界
CLI + Skillscoding agent（Claude Code/OpenClaw 等）批量、可编排npm 安装+浏览器登录
MCPchat agent对话内迭代账号认证，无 API key
Computer UseGUI 操作复杂一次性界面流Windows 需目标应用可见
关键边界：CLI 调用成功 ≠ GUI 完整复现；两者是不同证据。"在 Codex 里能用"有三种完全不同的技术含义，复现前先说清是哪一种。
Q3

费用与责任：官方原文级的三条红线

  • 同一积分池：CLI/MCP/网页同账号同费率——批量=成本放大器，先小额验证；
  • Unlimited/免费生成不适用：help 页原话 "don't apply to either"；
  • Developer Terms：agent 经你账号生成的内容由你负责——agent 闯祸算你的。

另有一个同名陷阱：CLI Skills 与 Supercomputer 内置 Skill 是两个同名不同体的系统，不可互换。

Q4

异步生成：会轮询，但具体状态值未公开

2026-11-22 当前 CLI 页明确“生成是异步的，agent 会轮询完成并返回结果”；帮助页说明产出落 Assets。两页仍未给出任务状态枚举、任务 ID 查询命令或完整状态机。因此不能继续写“异步完全未文档化”，也不能把 PixStag 五态冒充 Higgsfield 状态。

本地 `route_contract.py` 只验证通用五态、预算熔断与三通路证据差异，8 项测试通过；真实 Higgsfield 任务仍需授权账号回读。

Q7

给批量场景的费控设计

① 先 1 条小额验证（积分单价+质量+Assets 落点）
② 批量=小步验证：示例每批 ≤5 条，批间人工抽查（阈值不是官方建议）
③ 自定义余额熔断线：本地示例 500 点；真实阈值按账号价格与预算另算
④ 内容责任：合规过滤（肖像/版权/平台规则）前置到 brief
Q8

"full access"话术破译

营销里的 full access 指"功能可用"，不指"免费/无限/免责"。三问拆穿：扣什么（积分池）？上限多少（Unlimited 不适用）？谁负责（Developer Terms 你负责）。本案例三问都有官方答案，其他产品套用同样三问。

Q9

账号制 vs API key 制（顺带的分辨）

Higgsfield 的 CLI/MCP 走账号登录与积分；另一款 Higgsfield API 才是 key 制开发者产品。账号登录、API key 只是不同认证形态，权限大小仍取决于产品 scope、账号和配置，不能简单说哪一种天然更安全。这里应记录 agent 行为、积分消耗与内容责任，并保护会话。
