①
LangGraph 到底是什么？一句话能说清吗？

官方原话："Low-level orchestration framework for building stateful agents"——构建有状态智能体的底层编排框架。翻译成人话：

LangGraph = 一块共享白板(State) + 一张节点路线图(Graph) + 一台存档机(Checkpointer)

你把干活的人（Node 节点，就是普通 Python 函数）画在路线图上，他们围着同一块白板排队干活，图负责决定"下一个谁上"，存档机负责每走一步就拍快照，断了能续。

图 = 节点（函数）+ 边（顺序/条件）+ 一块一路流转的共享白板

关键认知：节点里想调大模型就调，不想调也完全可以。LangGraph 编排的是"任意 Python 函数"，大模型只是最常见住客。这也是本指南实验敢不接 API key 就能跑的原因。

②
没有 LangGraph 之前，人们怎么写 LLM 应用？痛点在哪？

2023 年大家写 Agent 基本是"while 循环 + if 堆成山"：在一个大函数里手写循环，让模型反复"思考→调工具→把结果塞回 prompt"。代码长这样：

while True: reply = llm(messages) # 问模型 if "调用搜索" in reply: ... # 手写判断 if 用户不满意的次数 > 3: break # 手写退出 # ……几百行 if/else 之后，没人敢动这段代码

四个要命的痛点：

痛点具体惨状LangGraph 的解法
状态没处放对话历史、中间结果散落在闭包变量里集中到 State 白板，由框架管理
循环写死想加一步"人工审批"要重写半个函数加个节点 + 条件边即可
断掉全完跑到第 20 步进程挂了，从头再来（再花钱调 API）Checkpointer 每步存档，断点续跑
没法画、没法查流程只存在于 if/else 缝隙里图结构一目了然，还能打印成流程图
历史小故事：LangChain 团队做着做着发现，复杂的 Agent 应用真正需要的不是"更多组件"，而是一个能把控制流显式画出来的引擎——于是 2024 年初从 LangChain 里拆出了 LangGraph。如今 Klarna、Replit、Uber 都用它跑生产级 Agent。
③
"状态图"和我熟悉的"流水线 + 质检 Gate"是什么关系？

好消息：你已经懂了 80%。知识库里的 [[构建流水线与Pass]] 和 [[质检Gate与自我纠错循环]] 说的正是这件事——复杂工作拆成顺序阶段，阶段之间设检查站。LangGraph 就是这个思想的工业化引擎版：

你已学的概念LangGraph 对应物增强点
流水线 / PassGraph + Node边可以是条件边，能分叉、能回头
各 Pass 传递的中间产物State 共享状态不是"传来传去"，而是所有人读写同一块白板
质检 Gate + 返工循环Conditional Edge循环是图的一等公民，画得出、存得了档
确定性脚本当裁判节点函数本身裁判也可以是真 LLM，反正都只是节点
上：传统流水线，单向不可回头；下：LangGraph 状态图，"打回重写"就是一条普通的边
④
共享白板 State 是怎么工作的？节点之间怎么传数据？

State 就是一个 TypedDict（带字段类型说明的字典）。它的流转规则只有一条：

每个节点收到"整块白板的快照"，干完活只把自己改动的字段部分覆盖回去

class State(TypedDict): draft: str # 字段就是白板上的格子 score: int def writer(state): return {"draft": "新草稿"} # 只写 draft 格子，score 不动
节点的输入输出协议：进 = 全量快照，出 = 部分增量

这个"进全量、出增量"的设计，让任何节点都不用关心别的节点内部怎么干活——节点之间彻底解耦，增删节点不用改别人的代码。

⑤
什么是 Reducer？两个节点都想写同一格白板怎么办？

默认规则是"后写的覆盖先写的"。但想象两条分支并行执行后要汇合：一个往 messages 格子里写了"搜索结果"，另一个写了"计算结果"——覆盖谁？LangGraph 的答案叫 Reducer 归约器：

在字段上声明"合并规则"，冲突就不叫冲突，叫"合并"

import operator from typing import Annotated, TypedDict class State(TypedDict): # Annotated 第二个参数就是 reducer：用 + 号合并 messages: Annotated[list, operator.add] # 新旧两表拼接 score: int # 没写 reducer = 默认覆盖
并行分支汇合时，Reducer 决定怎么合：默认覆盖，声明 operator.add 则拼接
为什么重要：后面学 multi_agent（多智能体）时，几个 Agent 并行写同一份对话历史，全靠 Annotated[list, operator.add] 保证不互相覆盖。这是 LangGraph 面试出现率最高的细节之一。
⑥
条件边怎么实现"打回重写"的循环？

普通边 add_edge("A","B") 是死板的"A 完了必定到 B"。要"看情况走人"，用 Conditional Edge 条件边：

def gate(state) -> str: # 一个纯粹的裁判函数 return "END" if state["score"] >= 80 else "writer" g.add_conditional_edges("reviewer", gate, {"writer": "writer", "END": END})

裁判函数读白板 → 返回一个字符串 → 按映射表跳到对应节点。裁判就是普通函数，所以测试它 = 测试一个纯函数，不用跑大模型——这正是知识库 [[确定性脚本]] 思想的翻版：把"决策"从业务代码里拎出来变成可单测的小函数。

"打回重写"不是什么特殊机制，就是一条画回上游的边

⚠️ 实战红lines：循环必须带退出条件（比如 attempts 计数或最大轮数），否则模型打分不给过就会无限打转烧钱。

⑦
Checkpointer 存档器是什么？"持久化/可恢复"具体指什么？

Checkpointer 干的事像游戏存档：图每执行完一个节点，就把整块白板拍一张快照存起来。编译时挂上即可：

from langgraph.checkpoint.memory import MemorySaver app = g.compile(checkpointer=MemorySaver()) # 内存存档（学习用） # 生产环境换成 SqliteSaver / PostgresSaver，代码一行不用改

官方管这叫 Durable Execution 持久执行：进程崩了、机器换了、隔了一天再跑，都能从最近一次快照原样恢复。这解决了 LLM 应用最贵的浪费——重跑 = 重新花钱调 API。

每步一快照：崩溃恢复点 = 最近一次快照，已完成的节点不重跑
⑧
thread_id 是什么？为什么一个图能同时服务很多用户？

挂了 Checkpointer 之后，每次调用都要带一个 config = {"configurable": {"thread_id": "..."}}。thread_id 就是存档槽位号：

同一个编译好的图 + 不同 thread_id = 互不干扰的多份存档。用户 A 的对话白板在槽 "user-A"，用户 B 在槽 "user-B"，各自续各自的命。

一份图代码，N 个独立存档槽——这就是"有状态服务"的底层原理

实验步骤 4 验证过的名场面：第二轮调用只传一个新烂稿，没传 attempts，图从存档里补齐 attempts=2 接着数——用户感知就是"这服务记得我"。

⑨
interrupt 人机协同：程序"暂停"了，进程去哪了？

在节点里调一句 interrupt(问题)，图就停在这一行，把问题抛给外面的人。魔法在于：

进程根本没有"卡住等待"——它正常退出了，状态躺在存档里。人可能一分钟后回复，也可能三天后。回复到达时，用 Command(resume=答案) 再 invoke 一次，图从暂停的那一行原样复活，连 interrupt() 的返回值就是人的答案。

def publisher(state): answer = interrupt({"question": "质检通过，是否发布？"}) # 图在此冻结 return {"approved": answer == "yes"} r1 = app.invoke(输入, cfg) # 跑到 interrupt 停下，r1 里带 __interrupt__ r2 = app.invoke(Command(resume="yes"), cfg) # 人审批后，从冻结点继续
"暂停"的真实实现 = 存档 + 退出；"恢复" = 带答案再 invoke 一次
场景：客服 Agent 想给客户退款 5000 元——超过权限了。这时 interrupt 出来问主管；主管在下班路上用手机点了同意；第二天早上 Agent 从冻结点复活继续执行。HITL（Human-in-the-Loop）不是"程序挂起等人"，而是"任务等待人"。
⑩
prebuilt 高层 API 和 StateGraph 底层 API，我该用哪个？

LangGraph 是个三层蛋糕：

层是什么适合谁
Deep Agents站在 LangGraph 之上的成品框架（会规划、会派子Agent、带文件系统）想要"开箱即用的深度研究Agent"
prebuilt
create_react_agent		一条命令生成"ReAct Agent"（模型+工具，思考→调工具→观察循环的通用配方）快速原型、标准聊天机器人
StateGraph
（本指南学的）		底层引擎：节点、边、条件边、Checkpointer、interrupt 全部亲手拼完全掌控流程的工作流——学习阶段必须从这里入门
越高越省事越受约束；越低越费事越自由。上层建筑全部由下层搭成

判断口诀：流程能用"模型自己决定下一步"描述 → prebuilt；流程有固定业务阶段和审批点 → 自己画 StateGraph。两者可混用：把 create_react_agent 做的 Agent 当作大图里的一个节点。

⑪
LangGraph 和 LangChain 什么关系？名字里都有 Lang？

同门师兄弟，分工完全不同：

LangChainLangGraph
定位组件超市：各家模型的统一接口、文档加载器、向量库适配……编排引擎：只管"流程怎么走、状态怎么存"
类比食材和厨具供应商后厨的动线设计
依赖方向LangGraph 可以完全脱离 LangChain 使用（本指南实验就是零 LangChain 模型调用）；反过来 LangChain 1.x 的 Agent 内部用 LangGraph 做引擎

顺带认全家族：LangSmith（配套的可观测/调试平台，看图执行的每一步 trace）、Deep Agents（上层成品）、LangGraph Platform（托管部署）。家族庞大但只有 LangGraph 引擎和 LangSmith 观测是日常开发绕不开的。

1搭最简图：白板 + 两个节点

怎么操作存为 exercise\step1_state_and_nodes.py，运行 PYTHONUTF8=1 python exercise/step1_state_and_nodes.py

from typing import TypedDict from langgraph.graph import StateGraph, START, END class State(TypedDict): draft: str; score: int # 白板上的两个格子 def writer(state) -> dict: # 节点=普通函数，返回增量 return {"draft": "LangGraph 是一个状态图编排框架。"} def reviewer(state) -> dict: return {"score": 85} g = StateGraph(State) # 建图，声明白板格式 g.add_node("writer", writer); g.add_node("reviewer", reviewer) g.add_edge(START, "writer"); g.add_edge("writer", "reviewer"); g.add_edge("reviewer", END) app = g.compile() # 编译成可执行应用 print(app.invoke({"draft": "", "score": 0}))

目的理解"节点=函数、边=顺序、白板一路传"。 实现了什么最小编排：两个函数被图串起来执行。

✅ 预期结果：最终白板: {'draft': 'LangGraph 是一个状态图编排框架。', 'score': 85}出现即成功——你返回的增量被合并进了最终白板。

6interrupt：质检过了，先等人审批再发布

怎么操作在发布节点里加 interrupt()，两次 invoke 完成暂停与唤醒（完整代码 exercise\step6_human_in_loop.py）：

from langgraph.types import interrupt, Command def publisher(state): answer = interrupt({"question": "质检通过，是否发布？"}) # 冻结点 return {"approved": answer == "yes"} r1 = app.invoke(初始白板, cfg) # 停在 interrupt，r1["__interrupt__"] 带问题 r2 = app.invoke(Command(resume="yes"), cfg) # 人点头，从冻结点复活

目的体验 LangGraph 招牌的 Human-in-the-Loop。 实现了什么图在 publisher 里冻结→等人→恢复，approved 依人的回答落定。

✅ 预期结果：返回: {'question': '文章质检通过，是否发布？', 'draft': '第2版草稿'} 最终白板: {'draft': '第2版草稿', 'score': 90, 'attempts': 2, 'approved': True}
