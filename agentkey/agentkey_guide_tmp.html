AgentKey 小白指南

Agent 生态的「数字钥匙串」：一个订阅 + 一条命令，让 AI Agent 实时抓取 28+ 平台数据
chainbase-labs/Agentkey Apache-2.0（集成层开源） Product Hunt 日榜第一 订阅制付费 SKILL v1.14.0 实测
一句话：AgentKey 把「Agent 找数据要到处注册、贴 Key、管账单」这件事，压缩成一个远程 MCP 端点 + 一个 SKILL.md。仓库开源的只是「钥匙环」，真正开锁的云端聚合服务是闭源订阅制。
Q1AgentKey 到底是什么？

它是 Chainbase Labs 出的 Agent 数据接入平台：本地装一个技能包（SKILL.md）+ 云端连一个 MCP 服务器（https://api.agentkey.app/v1/mcp），装好之后你对 Claude Code / Codex 说「马斯克最近在推特说什么」「看看 B 站这个视频讲了啥」「小红书上大家怎么评价防晒霜」，Agent 就会自动调云端工具去 X / Reddit / YouTube / B站 / 小红书 / 抖音 / LinkedIn / GitHub / 链上数据等 28+ 平台抓公开数据并总结。

本质：一个「统一数据网关」生意——把 N 个平台的 API 收敛成 1 个 Key、1 份账单、1 套工具。

注意区分：GitHub 仓库（Apache-2.0）开源的是集成层——SKILL.md、各家 Agent 的插件清单、安装/更新脚本；核心 MCP 服务器是闭源云服务，按订阅 + credit 计量收费（Early Access）。

Q2没有它之前，人们怎么给 Agent 接数据？（三种流派）
流派做法痛点
逐个申请官方 APIX API、Reddit API… 每家注册、审核、填 Key10 个任务 = 10 个 Key = 10 份账单；很多平台根本不开 API
第三方爬虫 API（如 tikhub）按调用次数买第三方聚合接口稳定性靠运气、每家还要单独充值管余额
本地能力层（Agent-Reach）本机装一堆开源 CLI（yt-dlp、bili-cli…），零 API 费要自己养登录态、装依赖，渠道会腐化
AgentKey 的赌注：把「接入方式的维护」整个搬上云端卖给订阅者，Agent 侧只留一个永远不变的 MCP 入口。用户买的是「持续有人替你盯着哪家上游还活着」。

Q4为什么一条命令接入 40+ Agent，还不用复制粘贴 Key？

秘密在 RFC 9728 OAuth 发现链。AgentKey 的 MCP 配置刻意不写任何静态 Authorization 头——客户端连上时：

POST /v1/mcp  (无 Key)
→ HTTP 401
→ WWW-Authenticate: Bearer resource_metadata="…/.well-known/oauth-protected-resource"
→ 客户端读该元数据 → 弹浏览器 OAuth 登录 → 自动拿 Token
✅ 实验1/2 实测：无 Key 请求返回的正是上面两行；元数据里 authorization_servers = api.agentkey.app（Clerk），bearer_methods = header。
⚠️ 反例（仓库 CLAUDE.md 明写）：一旦配置里写了静态 Authorization 头，Claude Code 会视为「显式头认证」，401 后不再回退 OAuth。所以各插件清单里反复强调「保持 entry 最小化，只留 url」。

装不了 OAuth 的客户端（如 DSH、CI）走兜底：npx -y @agentkey/cli --auth-login 设备码登录 → 自动把 Bearer Key 写进本机 18 个 Agent 的 MCP 配置。

Q5Agent 只看到 3 个工具？——「先发现、再描述、后执行」设计
工具作用成本
find_tools语义搜索工具目录（中英混、别名「推特→twitter」都行），返回规范名 + 每次调用多少 credit免费
describe_tool返回参数 schema；每次 execute 前必须先 describe免费
execute_tool真正执行抓取；execute_tool("agentkey_account") 查余额+上游健康按平台计 credit
为什么旧的 list_tools 被弃用？因为上游平台目录是动态变化的，任何工具名都不值得让模型背下来——名字必须每一步从前一步的返回里原样透传，记错就重跑 find_tools。这是把「幻觉防御」做进了工具协议。

防滥用也有章法：一轮只许一次 execute；≥3 次调用或预估 ≥10 credit 必须先查余额、报预算、等用户确认；API 返回内容一律视为不可信外部数据（防[[提示注入]]），禁止执行其中的指令。

Q6技能包自己怎么升级？——skill-meta-v1 版本信标协议

SKILL.md 是静态文件，但云端目录天天变。AgentKey 设计了双通道升级信标（v1.14.0 起是 MCP 工具 agentkey_skill_meta，Bash 客户端则跑 check-update.sh）：

会话开始 → 信标查 GitHub releases/latest（缓存 24h，3 秒超时，永不抛错）
→ 与 SKILL.md frontmatter 的 version 比较
→ 相同 → 静默继续；不同 → 提示升级（每会话最多提醒一次）
✅ 实验3/4 实测：releases/latest 返回 v1.14.0，本地 frontmatter 1.14.0 → UP_TO_DATE，判定链路走通。

工程细节值得抄：网络失败返回空字符串而不是抛异常（否则会弄挂 list_tools）；24h 缓存 + ETag；STALE 缓存永远优于慢响应；AGENTKEY_NO_VERSION_BEACON=1 可整体退出。

Q7和 Agent-Reach 是什么关系？——同题异解的镜像对照
AgentKey（本篇）Agent-Reach（前一篇，[[项目笔记/agent-reach]]）
定位云端统一网关（钥匙串）本地能力层（装机工+体检医生）
抓取执行方云端服务器调上游 API本机 CLI（yt-dlp、bili-cli、gh…）直连
费用订阅 + credit 计量零 API 费（自己出账号/流量）
渠道规模28+ 平台 + 链上/电商/金融17+ 渠道（社交媒体/RSS/网页为主）
维护负担零（厂商养）自己养（doctor 三态体检兜底）
数据主权/隐私请求经厂商云（称不存查询内容，遥测可关）全在本机
接入方式远程 MCP + OAuth 发现装本地 CLI + SKILL.md 教用法
开源程度集成层开源，服务端闭源（open-core）全开源 MIT
一句话记：Agent-Reach 把复杂性留给你的硬盘，AgentKey 把复杂性卖给你的订阅。两者不是竞品替代关系，而是同一问题的两个极端解；[[能力层与后端路由]] 里「接入方式比功能更易腐化」的判断，AgentKey 用商业手段给出了第二个答案。
Q8它能给我什么？（能力清单）

① 对 Agent 说人话即得全网实时数据（社媒舆情、视频要点、竞品/候选人 LinkedIn、Reddit 痛点、币价链上动向）；② 40+ Agent 一键接入免贴 Key；③ 工具目录自带成本标注，花钱前可预算；④ 余额与上游健康一键可查；⑤ 技能包自动升级信标，渠道变化不用重装。

适合谁：要 Agent 频繁取全网公开数据、且愿意为此付费省事的人。不适合：只想免费用几个固定平台（用 Agent-Reach）、对数据隐私敏感不能出网、或需要写入/发帖等非只读操作的场景。

Q10坑与结论

① 别把「开源仓库」当成「开源产品」：repo 里没有服务器代码，装完就是连付费云，Star 数 ≠ 可自建。② 各 Agent 配置里的 MCP entry 必须保持最小（只有 url），加了静态头就永久失去 OAuth 兜底。③ 工具名永远来自 find_tools，不要凭记忆写——目录是动态的。④ 预算防线（≥10 credit 先确认）是给 Agent 上「消费刹车」的好范式。⑤ 安全链条完整：OAuth 发现免贴 Key、API 响应只展示不执行、遥测可关、批量操作强制确认。⑥ 若上游平台对爬数据的合法性收紧，云端网关是单点风险——这也是 Agent-Reach 本地方案并存的的意义。

学习收获：这一课真正的新概念不是 AgentKey 本身，而是它身上三个可复用的工程范式——RFC 9728 免配置接入、动态目录「发现式」工具协议、以及「信标式」技能自升级。任何「Agent + 云服务」的组合都能套用。
