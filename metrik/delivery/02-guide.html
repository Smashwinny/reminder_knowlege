01

它到底在量什么：额度、Token 还是钱？

三个数字回答三个问题，不能拿一个推算另一个。

Metrik 是多种 AI 编程工具的桌面用量仪表盘。官方额度回答“套餐还允许用多少”；本地 Token 回答“日志里记录了多少处理量”；估算成本把处理量乘公开 API 价格，回答“按该价目约值多少”。后者不是订阅扣费或官方账单。

术语落地 Token 是模型处理文本的计量片段；quota（配额）是服务方给定的限制。两者没有通用换算率。

看一个例子 今天处理了 100 万 Token，不能据此断言周额度还剩 40%，也不能断言信用卡会扣某个金额。

三条证据线并列，缺哪条就承认哪条未知。

依据：S1、S2、S18

02

只显示一个百分比，为什么不总取最小值？

正常选排序最前的有效窗口；≤15% 才触发低余量接管。

窗口是一个计量周期，例如 5 小时、每周。bindingWindow 先排除不可用和已过重置点的窗口，再使用后端既定顺序。没有百分比窗口告急时返回第一项；有余量≤15%的窗口时，选其中最小者，同值保留较前者。函数本身不会重新按周期排序。

术语落地 主窗口选择是一条显示策略，不是对所有余量无条件求最小值；传入顺序是契约。

看一个例子 短周期 80%、每周 40% 时显示 80%；每周降到 15% 时改为 15%。README 的“取余量最低”不足以描述实际规则。

边界包含 15%；只对百分比窗口触发接管。

依据：S4、S5、S1

03

没有数据、数据陈旧、周期已结束，是一回事吗？

未知不是 0%；陈旧也不自动等于周期结束。

available=false 表示当前视图无可用读数。stale 表示读数可能不新鲜，但主窗口函数不会仅因 stale 就丢弃它。resetExpired 表示这条记录的重置时刻已过去，旧周期读数被排除。不要把旧读数当现在，也不要在缺失时自作主张补 100%。

术语落地 新鲜度说明证据有多新；周期有效性说明证据属于哪个计量周期。这是两条不同的判断轴。

看一个例子 旧读数仍是 22%，但尚未过重置点，可以带陈旧提示显示；若记录已跨过重置点，就不再当主读数。

本实验给定这些状态位，未运行后端计算状态的代码。

依据：S4、S6、S9

04

账户余额 10，为什么不能当成剩余 10%？

字段名相同，也可能装着不同的单位。

balance_cny、balance_usd 这类窗口是余额型。源码沿用 remainingPercent 字段装金额，不能按字段名就画成百分比。isBalanceWindow 识别 balance 前缀，余额不参加≤15%的告急筛选；若它恰是有效首项，仍可按正常路径选中。

术语落地 语义单位是数据契约的一部分。金额与比例不可直接比较；展示前必须看窗口类型。

看一个例子 短周期 80% 加余额 10 元，不能因为 10 比 80 小就让余额顶替；只有一个余额窗口时，仍应展示金额。

本次验证选择逻辑，不验证实际账户余额或货币格式界面。

依据：S4、S9、S2

05

累计 Token 连续出现，为什么不能逐行相加？

先辨清“累计计数器”与“本次增量”，再入账。

适配器把各工具不同的日志翻译成统一事件。Codex 提供累计计数，解析器先记首个快照，再计算各组成部分的正增量；不变的快照不产生新事件。分叉日志可能复制父会话历史，源码还有跳过继承前缀并维护差分基线的处理。

术语落地 差分是用相邻累计读数求本次增加量；快照是某时刻状态，事件是一次发生的事实。

看一个例子 100、130、130 三个累计读数不是 360。只谈这个简化计数器，首读 100 加后续 30，合计为 130。真实解析还处理事件身份和分叉。

这是源码解释与教学例子；Rust 日志解析本次未执行。

依据：S10、S2

06

同一条消息出现在两个文件，怎样避免算两遍？

文件路径说明“在哪里看见”，事件身份说明“发生了什么”。

账本将 usage_event（逻辑事件）与 event_observation（来源观察）分开。同一事实可以在多个文件中被观察；移动文件不应制造新用量。Claude 按提供方消息 ID 去重，渐进更新取各 Token 组成的最大值；请求、模型冲突会触发校验，不能任意合并。

术语落地 幂等去重指重复导入同一事实不改变累计量；它不等于把内容看起来相同的调用全部删除。

看一个例子 一个消息先记录输入 100、输出 20，稍后更新输出 35，不能把两行相加成输入 200、输出 55。两条真正不同消息也不能合并。

去重规则依来源而异；本次只做源码审阅，未运行账本事务。

依据：S12、S11、S2

07

缓存和推理 Token，怎样加才不会重算？

先归一组成，再求处理量；推理输出是输出的子项。

Metrik 的处理量口径是：未缓存输入 + 缓存读取 + 缓存写入 + 输出。不同提供方对 input 的定义可能不同，适配器负责翻译。reasoning_output 只保留为输出细节，不再加到总处理量。紧凑显示的 K/M/B 只是格式化，不改变这种统计口径。

术语落地 归一化是把不同来源映射到同一语义；缓存读取量不等于“没有计算”，也不等于与普通输入同价。

看一个例子 未缓存输入 100、缓存读 200、缓存写 50、输出 30，其中推理 10：处理量是 380，不是 390。该算例不是本次 Rust 执行结果。

后端组成归一化仅审阅；前端紧凑数字函数在实验中真实执行。

依据：S9、S2、S8

08

统计页有数字，就代表历史已经读全了吗？

统计区间、来源覆盖率和数据新鲜度要分别看。

当前引擎以固定 182 天视界解析，界面周期决定账本查询范围，不再跟随 Today/7/30 天扩扫。单次解析约 1500 毫秒预算，在文件间检查；未完工作留待回填。坏行、拒绝事件等影响质量，日统计按本地时区聚合。

术语落地 coverage 是已读取的范围；partial 是来源不完整；backfill 是补齐待处理历史，三者都不能解释为用量为零。

看一个例子 “数据不完整”不是还剩多少的比例；总量看起来合理也可能漏事件。比较两次统计前，先对齐区间、时区与来源质量。

本次不扫描任何个人日志，不验证真实来源覆盖率。

依据：S14、S2

09

用 Pi 发出的请求，为什么可能记在别的卡片？

运行工具、计费用途和项目归属，是三个不同维度。

Pi 等 harness（运行编排工具）可以连接多种提供方。上游按订阅或 API 路由归属用量，不能见到 Pi 文件就都算在 Pi 套餐下。项目归属则来自日志里的工作目录，再由查询层规则向项目根聚合；目录缺失或被隐藏的用量仍可能在总量中。

术语落地 归因是决定一条用量属于哪张卡片或哪个项目。工具名不自动等于账单主体。

看一个例子 Pi 走 ChatGPT 订阅的请求可归入 Codex 卡片；同一工具走直接 API 的请求仍可能留在 Pi。项目总表与全部用量差额要先查未归属项。

复用已有 BYOK 归因知识；具体路由规则仅源码审阅。

依据：S2、S15

10

同步“统计”会不会顺手同步原对话？

同步的是受约束的事件数据，不应把原始日志当交换文件。

上游设计用共享目录交换近 30 天统计事件，再在账本合并；不是直接同步正在使用的 SQLite 数据库。数据库不写提示词、回复、工具输出或凭据，但本地仍含会话、来源路径和项目目录等元数据。同步不导出项目目录；账号级 Cursor 用量不参加多设备同步。

术语落地 最小化数据是只传任务需要的字段；“没有正文”仍不等于“完全没有隐私”。

看一个例子 两台机器都能看到同一账号的 Cursor 仪表盘，把两份账号级结果当设备增量相加就会重复；因此上游将其排除。

同步与隐私字段为源码结论；本次未启用共享目录或真实同步。

依据：S13、S2、S3

11

小小的托盘数字，为什么也值得单独测试？

选择、舍入、陈旧提示和绘制可以分开验证。

trayBadgeSpec 取状态列表第一项，不是找全部 Agent 的最低值。百分比经四舍五入并钳制到 0–100，非有限值变不可用；提示文字保留 Agent 与陈旧状态。状态指纹含 Agent、数字和陈旧位。App.jsx 调用层先把余额映射为不可用，徽标函数本身不识别金额。画位图的函数需要浏览器画布。

术语落地 纯逻辑函数只靠输入返回输出，可在 Node 测试；canvas（画布）负责像素渲染，两者证据不同。

看一个例子 A 排第一且剩 80%，B 剩 5%，徽标仍选择 A。B 的低值不会自动抢到列表首位。999500 Token 紧凑显示为 1M，也不表示原始量精确等于百万。

实验执行纯逻辑与紧凑格式，不绘制托盘，不宣称 Windows 验收。

  • 重复窗口输入保留不变不等于用量事件去重。Rust 解析、Token 组成归一化、账本事务、后端时效派生仍只有源码审阅。
  • 历史原件在新目录解压后，按指南五条命令执行成功；公开整理未重跑，包内可执行代码、输入与输出保持原样。

  • 已知 JSONL 与折叠模型只作起点；新增重点是累计计数的差分、事件身份与来源观察分离。

  • 公开知识关联限于列出的已读资料；目录元数据不等于全文阅读，旧项目结论不替代本项目证据。
