Q1

CloddsBot 到底是个啥？

Claude + Odds（赔率）= Clodds。一句话：一个跑在自己电脑上的 AI 交易终端——你用聊天口吻下指令，它替你盯市场、找机会、下单、报风险。它不是一个"策略"，而是一个把「行情数据 + 交易所接口 + AI 大脑 + 风控引擎 + 聊天界面」打包在一起的操作台。

没有它之前：想在 Polymarket 和币安同时搬砖的人，得自己写爬虫、自己接 WebSocket、自己写风控、自己搭 Telegram 机器人——四套活儿。CloddsBot 把这四套活儿全做成了现成模块，还加了个能听懂人话的 AI 大脑（Claude）当总调度。

Q3

"不预测涨跌也能赚"是什么原理？预测市场是啥？

推文最反直觉的一句是"它根本不预测涨跌"。要理解这个，先懂预测市场（prediction market）：把一个未来事件（"BTC 一小时内会涨吗？"）变成一份二元合约——

  • 市场发行两种股份：YES 股和 NO 股，价格在 0~1 美元之间浮动；
  • 事件揭晓后，赢的那股固定赔 1.00 美元，输的那股归零；
  • 所以 YES 的价格 = 市场公认的该事件发生概率（YES 卖 0.65 刀 ≈ 大家认为 65% 会发生）。

Polymarket 是目前最大的加密预测市场，日成交量上亿刀。它有个天然特性：短期 BTC 涨跌盘（5 分钟 / 15 分钟 / 1 小时一轮）全天候滚动开盘——这就是机器人"晚上也不用睡"的原因：市场永远开着。

图2：二元合约的两股定价。两边价格之和被"必赔 1 美元"锚在 1.00 附近
关键转变：机器人不回答"会涨吗"，它只回答"两边的报价加起来是不是错位了"——判断题外包给了全市场的交易者，机器人只做算术题。这就是"不预测也能赚"的全部秘密（前提是机会真存在，见 Q6）。
Q4

为什么 YES 卖价 + NO 卖价 < 1 就稳赚？

这就是推文里机器人的核心打法，行话叫负风险套利（negative risk arbitrage）。逻辑是一道小学算术：

  • 同时买 1 股 YES（$0.48）+ 1 股 NO（$0.49），总成本 $0.97；
  • 事件揭晓必然二选一：赢的那股固定赔 $1.00；
  • 所以无论结果如何，你收 $1.00，稳赚 $0.03，约 3.1% 无风险收益。

同平台内出现这种错位叫负风险套利；同一个事件在 Polymarket 卖 YES、在 Kalshi 买 NO 出现错位，叫跨平台套利——CloddsBot 的 src/arbitrage/ 两种都扫，这正是"监控 Polymarket"那一块的真身。

repo 源码对应（src/arbitrage/index.ts） ArbitrageOpportunity { buyPrice, sellPrice, // 两腿价格 spread, spreadPct, // 价差与百分比 profitPer100, // 每 100 刀本金的理论利润 confidence, // 匹配置信度(0~1) isActive // 机会是否仍有效(转瞬即逝) }
但注意：理论稳赚 ≠ 真赚。三只手会伸过来：①手续费 ②下单滑点 ③资金占用期的事件风险（平台跑路/规则改）。所以工程上必须配"净边际过滤"（Q7）和风控（Q9）。先记住公式：净赚 = (1 − YES卖价 − NO卖价) − 手续费 − 滑点，下一节的实验就靠它。
Q5

机器人怎么知道"两个市场说的是同一件事"？

跨平台套利有个脏活：Polymarket 上写 "Will the Fed cut rates in October?"，Kalshi 上写 "Fed rate decision October meeting"，机器人得认出这是同一件事才能对冲。CloddsBot 的做法在 questionSimilarity() 函数里，意外地朴素：

// src/arbitrage/index.ts （真实源码，简化注释） function questionSimilarity(q1, q2) { const normalize = s => s.toLowerCase() // ① 全小写 .replace(标点, ' ') // ② 去标点 const words1 = new Set(normalize(q1)) // ③ 分词成集合 const words2 = new Set(normalize(q2)) const inter = [...words1].filter(x => words2.has(x)) // ④ 交集 return inter.size / union.size // ⑤ Jaccard 相似度 }

Jaccard 相似度 = 交集 ÷ 并集。上面两句分词后交集有 {fed, rate, october}，并集 9 词，相似度 0.33，超过阈值就列为"候选同事件"，再由 AI 大脑（Claude）做最终语义确认。确定性算法海选 + LLM 终审——和我们在 [[LLM裁判与自动评估]]、[[事实与判断分离]] 里学过的分工完全一致：便宜精确的先干粗活，贵而聪明的只干细活。

图3：市场配对流水线——纯文本相似度做粗筛，大模型做终审
工程亮点：粗筛必须便宜（每轮要扫上千个市场），终审才准花钱。把"贵而聪明"的调用次数压到 1% 以下，是所有 AI 应用省钱的同一招。
Q6

为什么实测扫不到套利机会？——地板被焊死在 1.001

我们照着 repo 的套利逻辑写了 Python 复刻版去扫 Polymarket 真实行情（实验 ex1，见实验节），结果 25 个最热门的市场里一个机会都没有——所有市场的 YES卖价 + NO卖价 全部落在 1.001 ~ 1.010。为什么？

  • Polymarket 价格最小变动单位（tick）是 $0.001；
  • 成百上千个做市机器人 7×24 挂单，一旦双边合计跌破 1.001，零点几秒内就被别人的机器人吃掉；
  • 所以留给我们的"地板"恰好是 1 × tick = 1.001——这个数字就是市场有效性的体温计。
图4：ex1 实测分布（12/25 市场成功取到双边报价，全部 ≥ 1.001）
这一课最值钱：推文里"睡一觉赚 280 刀"如果真发生过，赚的不是"捡钱"，是速度、门槛（tick）和费率之间的极限缝隙——拼的是服务器离交易所近、下单快。散户拿家用电脑 + 手动操作，处在食物链最底端。看见"无风险稳赚"四个字，先问 tick 和手续费。
Q7

跨交易所搬砖为什么不能闭眼搬？——净边际

第二块"监控 Binance"的打法是跨所搬砖：同一资产（如 BTC/USDT）在 A 所便宜 B 所贵，A 买 B 卖。但 repo 的 V2 套利文档（docs/V2_HFT_ARBITRAGE.md）第一原则就是净边际过滤（net-edge filter）：

净边际 = 毛价差 − 买入所手续费 − 卖出所手续费 − 滑点 − (资金到账延迟 × 波动率) repo 还额外惩罚：报价过期(stale-quote)、库存不足、延迟高的路径 —— 全部不过门槛直接拒绝出单

我们用 OKX 和 Kraken 的真实行情做了实测（实验 ex2）：两个大所的 BTC 毛价差只有 0.0007%~0.011%，而两腿 taker 手续费合计 0.36%——净边际 −0.36%，两个字：不干。这就是为什么 repo 里写"Rejects plans that fail minimum net-edge"——大多数"看起来有价差"的机会，死在手续费这道门。

图5：净边际瀑布——绿色（毛利）还没橙色（成本）长，必亏
联动已学：这正是 [[交易成本与鞭打效应]] 的又一实证——信号越密、交易越频繁，成本越是生死线。任何"搬砖"策略上市前，第一笔要算的账永远是手续费。
Q8

多跳套利怎么用算法找？——负环检测

repo 的 V2 还有个更炫的模块：多跳套利（multi-hop arbitrage）。不只比两个价格，而是在"货币兑换图"里找环路：BTC → USDT → ETH → BTC，绕一圈回来如果钱变多了，就是三角套利。经典算法两步：

  • 第一步：汇率取负对数变边权。把每一跳的汇率 r 乘上 (1−手续费)，取 w = −log(r×(1−fee))。这样"绕一圈的汇率乘积 > 1"就等价于"绕一圈的边权之和 < 0"——对数把乘法变加法；
  • 第二步：找负环。在带负权的图里找"边权和为负的回路"，标准算法是 Bellman-Ford（它能处理负权边，第 n 轮还在松弛就说明有负环）。

我们用 OKX 真实行情三元组（BTC/USDT、ETH/USDT、ETH/BTC）实测（实验 ex3）：两个方向的环扣掉每跳 0.1% 手续费后，边权和 +0.0030，资金乘数 0.997——绕一圈亏 0.3%，无套利。主流大所的三角缝隙同样被机器人抹平。

图6：ex3 实测的三元组环——两个方向边权和均为正，无套利
为什么这设计漂亮：把金融问题（哪个环赚钱）转成图论问题（有没有负环），就能用几十年打磨过的成熟算法一次扫全图。repo 还在此之上做延迟感知排序——同样无套利时优先选延迟低的路径，因为套利的本质是抢时间。
Q9

"风险太高直接不玩"具体怎么实现？——十道盘前检查

推文第三块"实时盯流动性，风险太高直接取消"，对应 repo 里最工程化的部分：src/risk/engine.ts 的 RiskEngine。每一笔单子下单前必须按顺序过 10 道检查，任一道拦截即否决：

#检查干嘛的（白话版）
1Kill switch 总闸一键停止交易开关有没有被拉下
2熔断器 circuit breaker连续亏损/异常行情时自动断电
3单笔上限这一单金额超没超上限
4敞口限额总持仓超没超上限
5日亏/回撤/集中度今天亏够数没有、是不是全押一个宝
6VaR 风险价值"95% 的情况下今天最多亏多少"超没超线
7波动率分档低/常/高/极端四档，极端档减仓到 25% 或直接停机
8Kelly 仓位按胜率赔率算"该押多大"，不批准只调大小

Kelly 公式一句话：押注比例 = 优势 ÷ 赔率。胜率 55%、赔率 1:1 时 Kelly 仓位 = (0.55−0.45)/1 = 10% 本金；实际工程用"半 Kelly"（再砍半）因为胜率估计本身有误差。repo 里 src/trading/kelly.ts 做的是动态 Kelly——用最近的滚动胜率实时调整，连击亏损时自动缩仓。

这个设计和我们已学的 [[护栏模式Guardrails]]、[[评分契约与护栏]] 一脉相承：AI 负责"挑哪个机会"，确定性代码负责"这笔单能不能出"——权力边界用架构焊死，不靠 AI 自觉。仓库的 tests/trading 里甚至有专门的 "shared pre-trade gate" 测试：风控减仓单可以超仓位上限，但 kill switch 谁也绕不过（我们实测 11/11 全过，见实验 ex4）。

记住分层：预测（AI，可以错）→ 定量（Kelly，公式算）→ 放行（10 道检查，一票否决）。三层里任何一层交给 AI 全权负责，都是事故。

Q11

121 个"技能包"是什么？和 Claude Code 技能什么关系？

CloddsBot 的功能扩展机制和我们已经在用的 SKILL.md 技能包（见 [[AgentSkills技能包]]）是同一套格式：一个文件夹 + 一个带 YAML frontmatter 的 markdown 说明文件，加载器自动发现、无需注册。README 自称 "Full backwards compatibility with OpenClaw-format SKILL.md files"——整个生态在合流。

Q12

x402 是什么新词？

仓库 topics 里有个陌生的词 x402：一个"机器对机器支付"的开放协议， resurrect 了 HTTP 402（Payment Required）这个几十年没用的状态码——API 被调用时可以直接回一句"付费 0.001 美元再试"，机器 A 用加密钱包当场付钱、当场拿到服务，不需要人刷卡、不需要注册账号。业内叫它"代理商务（agentic commerce）"：当 AI Agent 们开始互相买服务，就得有机器间的收银台。

CloddsBot 自称 "Agent commerce protocol for machine-to-machine payments"，设想是：你的机器人缺一条付费数据源，它自己发现、自己砍价、自己付款。这类协议还在早期，但方向值得知道：AI 的下一个基建不是更强的模型，而是"付钱的手"。

联想记忆：[[MCP协议]] 解决"Agent 怎么调工具"，x402 想解决"Agent 怎么为工具付费"。一个管握手，一个管收银。

Q14

我能拿它做什么？千万别做什么？

可以做的（零风险高收益）：

  • 把它当AI Agent 终端的参考架构读：网关/渠道适配/技能包/风控引擎的分层，搬到任何 Agent 项目都成立；
  • 跑它的单元测试学风控测试怎么写（kill switch 优先于一切）；
  • 用它的公开 API 思路（gamma + CLOB 都免钥只读）做行情分析、数据可视化、市场有效性研究；
  • 复刻套利检测器当教学工具——本指南实验就是范例，拿来改阈值、加市场、画图都行。

千万别做的（血泪忠告）：

  • ❌ 充真金白银跑实盘：200x 杠杆、链上钱包私钥交给一个 GitHub 项目，等于把银行卡密码贴朋友圈；
  • ❌ 买它 README 里的 meme 币（那是项目方的融资手段，不是投资机会）；
  • ❌ 相信"挂机睡觉赚钱"——所有 passive income 叙事在套利领域都意味着你在食物链底端（Q6/Q7/Q8 三连实测已证明：热门市场无缝隙，缝隙拼速度和费率）；
  • ❌ 在没有 10 道风控检查的情况下裸跑任何交易脚本。
一句话总结：这个仓库最值钱的产出不是利润，是一套可以直接抄的"AI + 交易"工程蓝图——蓝图免费，学费免交。

实验 ex1 · 复刻"监控 Polymarket"：负风险套利扫描器（主实验）
第 1 步 · 理解要复刻什么
目的：把 repo src/arbitrage/index.ts 的五步流水线（扫描→比价→算边际→打分→风控过滤）用 100 行 Python 复刻。
操作：读 repo 源码的 ArbitrageOpportunity 接口与 calculateArbitrage()，然后打开 exercise\ex1_poly_arb.py。
实现了什么： Polymarket gamma-api 拉热门市场 + CLOB 公开订单簿取双边最优卖价。
验证：脚本第一行输出"拉到 40 个活跃市场"。
第 2 步 · 运行扫描
操作：python ex1_poly_arb.py
目的：用真实行情算每个市场的 YES卖价+NO卖价。
实现了什么：12 个市场成功取到双边报价（其余因订单簿空的被跳过）。
验证（真实输出摘要）：
[1] 市场扫描: 拉到 40 个活跃市场, 其中二元市场 40 个 [2] 价格比较: 成功拿到 12 个市场的 YES/NO 双边最优卖价 [3] 风控过滤: 流动性>=5000$ 且 净边际>=0.005 且 边际<=0.15 -> 通过 0/12 Will Flávio Bolsonaro win… YES 0.570 NO 0.431 合计 1.001 毛边际 -0.001 Will the Fed increase… YES 0.005 NO 0.996 合计 1.001 毛边际 -0.001 2026 Balance of Power… YES 0.080 NO 0.930 合计 1.010 毛边际 -0.010
第 3 步 · 改参数再跑（可见成果）
操作：把 MIN_EDGE 从 0.005 改成 -0.02（故意放进负边际"机会"），重跑。
实现了什么：表格立刻出现一堆"合计 1.01"的假机会被排到前面——直观看到"没有风控过滤会怎样"。
验证：过滤行从"通过 0/12"变成"通过 12/12"，证明过滤逻辑在起作用。
第 4 步 · 解读
所有市场合计成本 ≥ 1.001 = tick 地板（Q6 结论）。✅ 预期结果：热门市场零套利机会——市场有效，"捡钱"不存在。
实测坑：gamma API 的 clobTokenIds 字段返回的是 JSON 字符串不是数组，直接 len() 永远等于 1，必须再 json.loads() 一次——我们第一版就栽在这，40 个市场全被过滤成 0 个。
实验 ex2 · 复刻"监控 Binance"：跨所净边际计算
操作与目的
python ex2_venue_edge.py —— 用 OKX 和 Kraken 公共行情算 BTC/USDT 跨所搬砖的净边际（Binance 公共 API 实测被地域限制 "restricted location"，本身就是个真实世界坑：交易所会按 IP 拒服务）。
验证（真实输出）：
OKX ask=84,432.6 bid=84,432.5 Kraken ask=84,433.2 bid=84,423.2 A: Kraken买 -> OKX卖 毛边际 -0.0008% 双taker费 0.3600% 净边际 -0.3608% 拒绝 B: OKX买 -> Kraken卖 毛边际 -0.0111% 双taker费 0.3600% 净边际 -0.3711% 拒绝 => 印证 repo 净边际过滤存在的意义: 大多数'看起来有价差'的机会过不了手续费这道门
✅ 预期结果：两大所毛价差 0.001% 量级 << 0.36% 双腿手续费，两个方向都被拒绝——"搬砖梦"被手续费当场击碎。
实验 ex3 · 多跳套利：负环检测
操作与目的
python ex3_multihop.py —— 拿 OKX 真实三元组（BTC/USDT、ETH/USDT、ETH/BTC）做 −log 边权 + Bellman-Ford 思想的负环检测。
验证（真实输出）：
BTC-USDT mid = 84,432.55 ETH-USDT mid = 2,657.59 ETH-BTC mid = 0.0315 环1 BTC->USDT->ETH->BTC 边权和=+0.003028 资金乘数=0.996977 无套利 环2 反向 BTC->ETH->USDT->BTC 边权和=+0.002975 资金乘数=0.997029 无套利 => 三角套利在主流大所早被机器人抹平
✅ 预期结果：扣每跳 0.1% 手续费后两个方向边权和均为正（绕一圈亏 0.3%）——图论算法正确工作，市场同样有效。
实测坑：第一版把环方向汇率写反（BTC→USDT 用了 1/价格），负环"满地都是"资金乘数 71 亿倍——套利检测器最危险的 bug 就是方向搞反后把必亏报成暴富。正确语义：rate = 换到的资产数 ÷ 换出的资产数。
