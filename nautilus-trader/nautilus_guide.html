Q1 量化交易和 NautilusTrader 是什么？

量化交易：把"什么时候买、买多少、什么时候卖"写成程序规则，让电脑代替人盯盘下单。人决定策略思想，机器负责纪律和执行速度。

NautilusTrader（鹦鹉螺交易者）是澳大利亚 Nautech Systems 开源的生产级算法交易平台：它把历史回测和实盘交易装进同一个事件驱动引擎里，覆盖外汇、股票、期货、期权、加密货币、甚至博彩交易所。

一句话：用 Rust 造的一台"交易发动机"，Python 当方向盘和仪表盘。

Q2 为什么底层用 Rust、策略用 Python？

交易软件有两个互相打架的要求：核心要快到极致且绝不崩溃（撮合、账本、风控），策略要改起来快（今天试均线、明天试机器学习）。

NautilusTrader 的解法是一分为二：

类比知识库里的"本地推理引擎"（ollama）：模型权重装载、调度这些重活在底层引擎，用户只跟 CLI 打交道。这里 Rust 负责"绝不能出错、绝不能卡"的部分，Python 负责"天天要改"的部分。整个系统甚至可以全部用 Rust 写，用于对延迟最敏感的场景。

Q3 回测是什么？"回测实盘同一套代码"为什么重要？

回测（backtest）= 拿历史行情数据"重放"一遍，看策略当时会怎么买卖、赚赔多少。是策略上实盘前的 rehearsal（彩排）。

传统量化工具最大的坑：回测写一套代码、实盘又写一套——彩排用的剧本和正式演出不是同一份，那彩排还有什么意义？两个系统行为有细微差异（撮合规则、费用、时序），策略一上实盘就变样。

同一份策略代码，接上回测引擎就是回测，接上交易所网关就是实盘。这就是推文里"回测与实盘共用同一套代码"的实际含义。

Q4 事件驱动架构是怎么回事？

NautilusTrader 不是"一次调用算一天"的批处理框架，而是事件驱动：行情、订单、成交全是带时间戳的事件，按时间顺序在一条总线上排队处理。

类比知识库里的"消息队列与异步削峰"：总线就是那个水库，事件就是水流；再类比"Agent 循环"，策略收到事件→做出反应→发出新事件，循环往复。事件驱动保证了回测和实盘的处理顺序完全一致，这是 Q3"同一套代码"能成立的地基。

Q5 tick、K线（bar）、QuoteTick 都是什么？

tick（跳价）：市场上每一次报价变动的最小记录。外汇里一条 QuoteTick 包含：时间戳、买一价（bid）、卖一价（ask）、买量、卖量。买一卖一之间的差价叫点差（spread），就是交易成本的一部分。

K线 / bar（柱状线）：把一堆 tick 按时间桶压缩：这一分钟的开盘价、最高价、最低价、收盘价（OHLC）。K线是 tick 的"摘要"。

实验里我们喂给引擎的是 tick（audusd-ticks.csv 约 10 万条），策略订阅的是 1-MINUTE-MID-INTERNAL K线——中间的聚合是引擎自动做的（INTERNAL 聚合器按 (买一+卖一)/2 合成 MID 价 K线）。

Q6 "纳秒级"时间戳到底意味着什么？

金融领域"谁先到谁成交"——两个事件相差几微秒，处理顺序不同，结果可能就不同。NautilusTrader 内部所有事件时间戳都是64 位整数纳秒（不是浮点秒），保证排序精确、不丢精度。

实验实测：第一条 tick 的时间戳是

first_ts_ns: 1580398089820000000
= 2020-01-30 15:28:09.820000000 UTC（共 10 亿分之一秒精度）

纳秒时间戳是"确定性回测"的前提：同一批数据，重跑一万次，结果一模一样。

Q7 撮合引擎和模拟交易所（SIM venue）是什么？

撮合引擎（matching engine）：真正交易所的心脏，负责把买卖订单按规则配对成交。回测时没有真实交易所，NautilusTrader 在你机器里内置了一个。

SIM venue（模拟交易所）：回测里你声明的一个"虚拟交易所"，可以配置：账户类型（现金/保证金）、持仓模式、初始资金、手续费模型、滑点模型。实验里我们建了一个：

engine.add_venue(
    venue=SIM,                          # 名字叫 SIM 的模拟交易所
    oms_type=OmsType.NETTING,           # 净额结算：同品种多空自动抵消
    account_type=AccountType.MARGIN,    # 保证金账户（可杠杆）
    base_currency=USD,
    starting_balances=[Money(1_000_000, USD)],  # 100万美元本金
    fee_model=MakerTakerFeeModel(...),  # 吃单/挂单费率模型
)

策略下的每个市价单，都由这个内置撮合引擎"假装交易所"即时成交并记账——就像学车时的模拟器，仪表全真，但不会真撞车。

Q8 EMA 均线交叉策略是怎么工作的？

EMA（指数移动平均线）：一种"越近的K线权重越大"的平均价，比简单均线更跟手。两条不同周期的 EMA 画在一起：

快线（周期短）从下向上穿越慢线 = 金叉 = 买入信号；从上向下穿越 = 死叉 = 卖出信号。这是量化界的"Hello World"策略：规则简单、人人能懂，但正因为简单，它本身没有赚钱优势——官方案例原文就叫它 "a teaching strategy and has no edge"。它的价值在于带你跑通全链路，顺便亲眼看看"交易越频繁，手续费吃掉越多利润"（见实验数据）。

Q9 NETTING 和 HEDGING 两种持仓模式有何不同？

同一个品种，先买 10 万又卖 10 万，账户里剩下什么？两种答案：

NETTING（净额结算）HEDGING（对冲/锁仓）
持仓结果两笔抵消，持仓归 0可同时持有 +10 万多单和 -10 万空单
像什么股票账户：买卖轧差部分外汇平台：锁仓功能
适合单策略单方向，账本简单多策略共用一个账户、需要锁仓对冲

实验用的是 OmsType.NETTING：策略每次金叉先平掉旧仓位再开新仓，引擎自动轧差，账本干净。官方 FX 教程用 HEDGING，因为外汇保证金实务里多空锁仓很常见。

Q10 点差、手续费、滑点如何影响回测？

回测盈亏 = 行情差价 − 三道真实成本：

我们的实验把三道成本都打开了：MID 价 K线意味着买卖按中间价成交（理想化），但 MakerTakerFeeModel 按合约自带的 0.00002 费率收手续费。实测：10/20 参数一天亏 526.82 美元，其中 227.82 是手续费——成本占亏损的 43%。回测不真实建模成本，等于给自己算命。

Q11 回测赚钱 = 实盘赚钱吗？

不等于！回测好看实盘翻车，是量化新手的第一课。常见死因：

陷阱说明
过拟合参数在历史数据上调到刚好赚钱，换个时间段就失效
前视偏差代码里不小心用了"未来"的信息（如用了收盘价做开盘决策）
成本低估没算滑点、手续费、点差，信号越频繁死得越惨
流动性幻觉回测假设单子总能按报价成交，实盘中大单会推动价格

NautilusTrader 的诚实之处：官方文档专门有一节 "Backtest and live differences"，明说回测无法完全复现实盘中的交易所行为、网络延迟、对账差异。它把回测引擎做得尽量真（真撮合、真账本、真费用），但不向你承诺"回测即实盘"——这正是工程素养的体现。

Q12 数据目录（catalog）和数据整形器（wrangler）是干嘛的？

量化项目 80% 的时间是洗数据。NautilusTrader 提供两件工具：

DataCatalog（数据目录）：把海量行情按 Apache Parquet 列式格式归档，配合 DataFusion 查询引擎用 SQL 快速检索（"给我 2020 年 1 月所有 AUD/USD 的 tick"），大规模回测时按需流式读取，不用全装内存。

DataWrangler（数据整形器）：把 pandas DataFrame"翻译"成 Nautilus 强类型对象的转换器。实验里就用了一行：

wrangler = QuoteTickDataWrangler(instrument=instrument)
ticks = wrangler.process(df)   # DataFrame → list[QuoteTick]（纳秒时间戳、强类型价格数量）

用知识库的话说：wrangler 是"报关口"，DataFrame 是散装货，QuoteTick 是报关后的标准集装箱，引擎只认集装箱。

Q14 想实盘接入真实交易所要做什么？

NautilusTrader 用模块化适配器（adapter）接入交易所：每个交易所一个适配器，负责该所的行情协议（WebSocket）和下单协议（REST/FIX）与 Nautilus 内部事件模型之间的双向翻译。

官方已维护币安、Bybit、OKX、dYdX、Interactive Brokers（盈透）等适配器；任何有 REST/WebSocket/FIX API 的交易所都能照模子写。实盘时策略代码一行不改，只是对面从 SIM 换成了真交易所——这就是 Q3 那个承诺的兑现方式。
