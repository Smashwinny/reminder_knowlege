Q1

这个项目是什么？一句话能说清吗？

一个"手绘风格配方仓库"：把 23 种手绘/插画风格各自整理成一段经过验证的提示词配方（recipe），Agent 或人按编号点菜，脚本从配方真源原样提取、填入你的主体内容，输出一条可直接喂给任何图像模型的完整 prompt。

项目明确不生图——它是"菜谱"不是"厨房"：输出模型无关的文本 prompt 或 JSON 调用包，执行交给用户自己的图像工具（Midjourney、Nano Banana、GPT Image 等均可）。

Q2

为什么需要它？没有它之前怎么画手绘风？

没有它之前，"画出手绘感"是纯试错玄学。同一个模型，你要描述"像 5 岁小孩用蜡笔画的、故意画得很丑、白纸质感"，来回抽卡几十次才偶尔蒙对；下次换个主体又得重来。社区的散装经验散落在小红书评论和论坛帖里，无法复用、无法传承。

这个仓库把每次成功的"咒语"固化成配方，核心贡献是三个"确定性"：

痛点配方的解法
每次重新组织语言配方正文是成品 prompt 本身，不是描述——提取即用
模型对"风格"理解漂移每套配方含负向"严禁"清单（如"严禁：均匀灰度滤镜、平滑渐变"）
经验口口相传会走样STYLES.md 是唯一真源，脚本机械提取，人改不了渲染路径

它本质是知识库 [[PromptAsCode提示词即代码]] 的社区实践：提示词从"聊天记录"升级为"版本化的代码资产"。

Q3

它是怎么做到的？架构是什么？

极简架构：一份"唯一真源"Markdown + 一个零依赖 Python 渲染器 + 别名路由表。

① STYLES.md —— 唯一真源

23 套配方全部以代码块形式存在这一个文件里，每套配方含正文 prompt + 槽位声明（【主体】【主色调】等）。所有工具（脚本 / SKILL.md / AGENTS.md）都从它提取，不存在第二份拷贝，杜绝"文档和实现不一致"。

② scripts/render_prompt.py —— 渲染器

零第三方依赖（只用标准库）。职责：解析 STYLES.md → 按编号/中文名/别名找到配方 → 检查必填槽位 → 填槽输出。实测 116 个别名全部可路由。

③ 槽位 fail-closed 机制

缺槽位时拒绝输出半成品 prompt，明确报"缺少占位符：主色调"。这是它与"字符串模板 replace"的本质区别：宁可报错也不交付残次咒语。

④ 分发层

Claude Code 把目录放进 ~/.claude/skills/、Codex 放 ~/.codex/skills/；Cursor/Gemini 用 AGENTS.md + PROTOCOL.md 指规则。参考锚图托管在 Cloudflare Pages，带 SHA-256 校验和本地缓存。

Q4

关键术语都是什么意思？

术语一句话解释
配方 (recipe)一段成品级 prompt 模板，含槽位，存于 STYLES.md 代码块
画风编号 / 别名每套配方的路由键：1~23 编号 + 中文名 + 英文别名共 116 个
槽位 / 占位符配方里的变量，如【主体】【主色调】【文字】，渲染时必填
负向清单（严禁段）配方尾部"严禁：照片写实、3D……"段，压住模型的默认倾向
锚图 (anchor)画风 3.1/19/20/22 需要的参考图，作为风格基准而非内容来源
JSON 调用包需锚图的画风输出结构化 JSON（含 content-source / style 锚点分工）
fail-closed缺槽位/未知画风时拒绝输出，报错指向具体缺失项
Q5

23 种画风都有什么？怎么选？

一张"风格光谱"：从极简到繁复、从单色到彩色、从平面到材质。

编号画风一句话气质特殊要求
1极简黑白线条漫画几笔画完一个故事—
2蜡笔儿童画5 岁小孩故意画"丑"—
3吉卜力水彩温柔通透动画水彩—
3.1吉卜力标题卡带准确标题字的标题画面需锚图+标题词
8写意水墨墨分五色、留白空灵—
9复古像素画8-bit 精灵图、棋盘抖动需主色调
13北欧剪纸对称镂空纸艺—
22朱红水墨转绘给照片换水墨魂需源图+锚图
23皮影彩染非遗皮影质感注明 DAAI 灵感来源
选择方式有三种：直接报编号（--style 9）、报中文名、报英文别名（--style ink-wash）。--list 输出全部菜单 JSON，--catalog 只读查询带选型说明。

Q7

实测：一条配方到底长什么样？

以水墨风（ink-wash）为例，本机真实渲染输出（节选）：

中国传统写意水墨画,画在生宣纸上,纯手绘毛笔笔触,不是数字插画、不是照片。
主体:一只鸟停在细枝上。
用墨:以黑墨为主,讲究"墨分五色"——焦、浓、重、淡、清并存……
留白:大量空白宣纸作为画面主体,疏可走马、密不透风……
点睛:画面一角一枚小小的朱红方形印章。
严禁:照片写实、3D、数字矢量、均匀灰度滤镜、平滑渐变……

观察配方的三段式结构：① 身份断言（"是……不是……"先立边界）→ ② 工艺细节（用墨/笔法/留白，给模型可执行的视觉词汇）→ ③ 严禁清单（压住模型的照片写实默认倾向）。这就是"为什么别人的提示词比你的管用"的全部秘密。

Q8

它的边界在哪？什么情况下不好用？

  • 不生图：它没有图像生成能力，输出要接你自己的工具；
  • 锚图依赖外网：画风 3.1/19/20/22 的参考图托管在 Cloudflare Pages，离线环境不可用；
  • 轻量化包可能落后 main：官方 hand-drawn-skill.zip（≤1MiB）明确注明"可能落后于 main 分支"；
  • README 与 About 描述不一致：侧边栏仍写"5 种画风"而实际 23 种——小项目常见的文档漂移，选用时以 STYLES.md 真源为准；
  • 风格覆盖面：目前以平面手绘/插画风为主，照片级写实、3D 渲染类风格不在射程内。
Q9

模型无关宣称可信吗？跨模型一致性怎么理解？

原始推文称它"跨 MJ/Nanobanana/GPT Image 模型一致性调试"，意为配方在多家图像模型上都抽卡验证过，输出文本 prompt 是模型无关的——但"同一 prompt 在不同模型出图效果一致"永远是程度问题，不是承诺。

工程上的真实含义是：配方把变量收敛到最小——正文固定（真源提取）、只剩主体/色调等少数槽位由你填。比"每个人自由发挥写 prompt"的一致性强得多，这是"社区配方"相对"个人咒语"的本质优势。实测蜡笔配方的英文开头甚至写了 "NOT made by an artist. It should look clumsy, messy, and 'bad' on purpose"——用身份否定句对抗模型"画得越好越对"的默认优化方向，是跨模型通用的技巧。

Q10

实际怎么装、怎么用？（含本机实测命令）

安装（Claude Code 路线）

git clone --depth 1 https://github.com/threerocks/hand-drawn-styles
# 把目录放进 ~/.claude/skills/hand-drawn-styles/

日常三条命令

# ① 自检（23 配方 / 116 别名 / 23 完整调用）
python scripts/check_skill.py

# ② 渲染 prompt（编号 / 中文名 / 别名均可）
python scripts/render_prompt.py --style ink-wash --subject "一只鸟停在细枝上" --aspect 3:4

# ③ 需槽位的配方用 --var 逐个填（缺了会 fail-closed 报错）
python scripts/render_prompt.py --style pixel-art --subject "一只猫在屋顶" --var 主色调=深蓝
本机实测全部通过：自检 pass；水墨/像素/蜡笔三套配方成功渲染；未知画风与缺槽位均被明确拒绝。详见 hand_drawn_styles\exercise\experiment-log.md。
