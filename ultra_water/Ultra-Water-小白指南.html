01 / 一帧海水，是按什么顺序做出来的？

渲染通道（pass）：把一项 GPU 工作画进指定目标；HDR：保留高亮范围的颜色缓冲。

这不是一个“加上水材质就结束”的示例。renderFrame(dt) 先取最近完成的水面查询，再推进漂浮物；接着更新漂浮物阴影、入水波纹、FFT 海浪与焦散，最后提交下一批水面查询。旧查询供当前物理使用，新查询留给之后的帧。

之后按顺序画平面反射（相机低于查询水面约 0.3 米时跳过）、不透明场景、水面；相机在水面下，或高出水面不足约 1.2 米时，再做水下合成，深潜时可以跳过近裁面水线判定，最后后处理。水面需要前面的场景颜色与深度才能表现折射；水下合成需要水面的正反面标签才能判断哪些像素在水下。先后次序本身就是数据依赖。

阅读时沿“谁写纹理 → 谁读纹理”追踪，而不是只沿场景树找对象。这里把你已有的 Three.js 场景图、先测后优化与证据优先作为基础，不再展开。

02 / 为什么要四级级联，而不是一张大波浪图？

FFT（快速傅里叶变换）：高效转换频域与空间域；本项目用 IFFT（逆变换）生成海面。级联（cascade）：按尺度分工的波段；图集（atlas）：把多层数据排进一张纹理。

源码固定四个周期长度：600、85、12、2.1 米，每层都是 256×256，纵向堆成 256×1024 图集。它们不是四个 FFT 计算阶段，也不是四层网格 LOD（细节层级）；每个级联负责一段波数范围，边界由下一层基频的六倍决定。

频域演化后，横向八级、纵向八级 Stockham IFFT（分阶段重排数据的逆变换）在 ping/pong 两个目标间交替读写，称为乒乓缓冲；MRT（多渲染目标，一次绘制写多份输出）把位移及导数打包计算。这里“级联数”和“变换阶段数”务必分开。

前三层贡献几何位移，第四层只贡献坡度，让细小纹理影响反光而不强迫网格追逐微波。mipmap（逐级缩小的纹理）按网格间距过滤位移，坡度二阶矩则用于粗糙度。四层索引在多处写死，并没有现成的“级联数”开关。

03 / JONSWAP 到底决定了海浪的什么？

频谱：能量如何分布到不同频率；JONSWAP：描述有主峰的风浪能量谱模型。风区长度（fetch）：风沿海面持续作用的距离；涌浪（swell）：与本地风浪分开描述的长周期波。

频谱决定“哪些频率强”，不是直接画出某个浪头。jonswapParams 用风速与风区长度求 alpha 和峰值角频率；jonswap 用峰值两侧不同的宽度，以及 gamma 的峰增强项，塑造能量曲线。提高 gamma 更像突出主峰，不等于整体抬高所有波浪。

初始化循环叠加两套谱：风浪与涌浪。方向分布通过余弦的 2s 次幂等表达式决定能量朝哪里散开；短波衰减抑制过细波段。最后乘高斯随机数，产生固定种子下的初始复振幅。

从角频率谱转到二维波数网格时，代码还乘 dω/dk、除以 k，再乘网格间隔平方；不是把一条谱曲线直接当高度贴图。要改变海况，先辨认在改总强度、主峰、方向还是细节衰减。

04 / 不同波长为什么走得不同？循环又意味着什么？

波数 k＝2π/波长；角频率 ω：相位每秒变化的弧度。色散关系：ω 与 k 的对应关系；相位：波在周期中的位置。

公共 GLSL 中统一使用 ω² = gk + (σ/ρ)k³。第一项是重力贡献，第二项是表面张力贡献；细波的后者更重要。不是只有第四层调用这条公式，只是第四层专门承担重力—毛细细节。相速度为 ω/k，因此不同尺度不会像一张整体平移的贴图那样同速。

演化时并不直接使用连续 ω：代码把它向下量化到 2π/300 的整数倍；时间按 300 秒取模，再把相位约化进一个周期。这样 FFT 的相位重复，并避免长时间累积导致单精度相位精度变差，但频率也有量化误差。

这个循环承诺只针对 FFT 相位，不是整段场景视频。泡沫有历史恢复，物理有状态；岸浪、噪声和表面时间也另走时钟。不能从“FFT 循环”推断漂浮物、泡沫及所有后处理都能无缝循环。

05 / 浪峰为什么变白，Jacobian 又是什么？

Jacobian（雅可比行列式）：局部坐标变形的面积比例；此处描述水平位移把海面挤紧还是拉开。λ 是水平尖锐位移的强度，不是波长。

组装通道算 J=(1+λDxx)(1+λDzz)−(λDxz)²。J 下降表示水平压缩增强；相比只用“高度很高就涂白”，它能更贴近尖锐浪峰处的破碎倾向。但它是视觉判据，不是气泡流体求解。

位移纹理的 alpha 存的是带恢复历史的 turbulence：min(J, prev + dt×recovery/max(J,0.5))。压缩发生时立即下降，之后按时间步恢复。表面再把前三层该值按水深加权，经过 bias/scale 阈值转换为泡沫量；不是直接把精确总位移的 Jacobian 重算一次。

最终白沫还叠加岸浪破碎、浅水接触等来源，使用花边/团块纹理、覆盖侵蚀和凹凸着色。恢复速度、几何尖锐度、着色阈值是不同控制项，别把纹理变白误解为真实空气被模拟出来了。

06 / 为何正看能见底，掠看却更像镜子？

菲涅耳（Fresnel）：界面反射比例随观察角变化；折射：光穿过介质界面时转向。Beer–Lambert 吸收：光随介质路程按指数衰减。

水面使用粗糙度（微小法线分散程度）感知的菲涅耳近似：F=F0+(F90−F0)(1−N·V)⁵，F0 固定为 0.02，F90 随粗糙度调整。掠看时反射增强，但这里并非粗糙远海也强行变成纯白镜面。N 是单位法线，V 是朝向相机的单位向量。

水上折射是屏幕空间近似：由法线偏移场景颜色采样坐标，用深度差估计穿水厚度。如果偏移采到了水面前的物体，就平滑回退，减轻物体边缘错误；颜色再按 T=exp(−吸收系数×厚度) 衰减并加入散射。它不是完整三维光线追踪。

反射组合天空立方体（六面环境纹理）和以海平面 y=0 镜像相机得到的平面反射，按粗糙度采样模糊层级。最后混合水体颜色和反射，再加太阳高光。图里的光线说明角度关系，实际水上折射实现仍是屏幕偏移。

07 / 海底的亮线是怎样聚出来的？

焦散（caustics）：折射光束汇聚形成的明暗纹；面积比铺点（splatting）：把源面积映到接收面，用面积缩放分配亮度。

焦散只读取 12 米级联的坡度，不是四层完整海面光线追踪。顶点把太阳方向按水的折射率折入水下，投到 1.5、4、10 米三个深度切片；减去平水面落点偏移，让纹理坐标对准入水点。

同样多的入射光落到更小区域就更亮。片元通过屏幕导数求原面积/落地面积，并用加法混合叠加重叠三角形。坡度用三次 B 样条平滑采样，目标使用 MSAA（多重采样抗锯齿），避免细光线断成点。

查询时按深度插值切片，深处增加模糊，最终作为直射太阳光倍率。理想构造意图是重分配能量、均值约一；但源码把面积倍率截到 16，落点也有边界夹取，故不能宣称实现了严格能量守恒。低太阳角尤其应检查这些近似。

08 / 相机半入水时，为何不能只加一层蓝雾？

Snell 窗：水下向上看时能透见水上世界的角度窗口；全内反射：超出临界角后光不能穿出水面。弯月线（meniscus）：此处指镜头水线附近的暗边效果。

水面是双面着色。背面分支折射天空、读取水上物体，并在 Snell 窗外近似反射深水颜色；临界角边缘按粗糙度柔化。它不是把整幅图统一调成青色。

水下合成先逐像素判断：水面 alpha 标签区分顶面与底面；看不到水面的地方，用 64×36 镜头近裁面水深图判定。这样浪冲过镜头时，同一帧中可以上半空气、下半水体，并在正反面交接处加暗水线。

水下路程产生指数消光与入散射。太阳光柱在半分辨率下沿视线做 24 个带抖动的单次散射采样，同时读取焦散与地形/漂浮物阴影，再按深度一致性放大合成。单次散射指只计算一次散射事件，不是完整多次散射体积输运。

09 / 箱子为什么会摇，而不只是跟着高度上下动？

浮力：排开水的重量产生的向上力；刚体：形状不变、可平移和旋转的物体；力矩 τ＝r×F：偏离质心的力引起转动。

每个漂浮物被描述成多个采样单元。单元位置与水高比较，得到浸没比例；浮力为 ρg×单元体积×浸没比例×倍率。在各单元施力，左右或前后受力不均就自动出现横摇和俯仰，而不是额外套一段摇摆动画。

阻力使用单元速度减局部水速度；水速度从多次查询得到的位移差估计，并被限幅，以免陡峭波前扫过时夸大粒子速度。积分以不大于约 1/240 秒的子步推进，单次输入 dt（帧时间间隔）还被限制。子步更细不意味着水面查询也变成同频新数据。

触底用地形高度弹簧及摩擦近似，转动惯量用实心盒近似。漂浮物入水可产生涟漪和飞溅，但没有物体间碰撞，也没有持续航行尾流；它是演示级波浪—刚体耦合，不是完整航海工程模拟器。

10 / GPU 上的海浪，CPU 怎样读而不卡住？

异步回读：提交 GPU 数据读取后不立刻等待，完成后再消费；PBO：像素缓冲对象；fence：标记 GPU 命令完成位置的同步栅栏。

WaterQuery 把待查询世界 xz 坐标装进纹理，画一个窄条目标，再调用 Three.js 的 readRenderTargetPixelsAsync。本应用没有手写 PBO/fence 回读实现；PBO 与 fence 是 README/注释对底层机制的说明，依赖实现应在依赖源码中另核。

查询着色器复用 waterAt：对水平尖锐位移做四次固定点反解，再采样高度。main 把容量设为 512（类默认是 256），最多允许两批在途；容量满会截断，已有两批时本次直接跳过，不是每帧保证交付。结果包含高度、水平位移、时间及布局标签。

11 / HUD、GPU 计时和不封顶循环，测的是同一件事吗？

vsync（垂直同步）：按显示刷新节奏调度；timer query：由 GPU 记录一段命令的耗时；disjoint：GPU 计时不连续、结果可能无效的状态。

普通循环用 requestAnimationFrame 调度，tick 限制 dt、更新控制器和相机，再画一帧。HUD 用时间窗口内的帧计数估算频率，它描述该调度模式下的吞吐，不等于显示器实际呈现了同样多张独立画面。

GpuTimer 使用可选的 EXT_disjoint_timer_query_webgl2 扩展，不可嵌套；新标签会先结束旧标签。它延后查询可用性，常规路径遇到 disjoint 不更新统计，结果按标签平滑。扩展缺失时这些分项不可用，不能拿 CPU 提交时间冒充 GPU 时间。

不封顶模式用 MessageChannel 连续调度，以 fence 将在途帧限制在三帧；隐藏标签页回到 rAF。按需基准则暂停普通循环，预热后批量渲染，等待 fence 确认完成再除以帧数，并读出分项。drain() 本身未重做 disjoint 检查，采证时仍应记录计时有效性。本次只执行一次该基准，原始UI报告及局限见实验页；未独立核查该批计时的disjoint状态，不能据此作性能保证。

12 / 这个项目的边界在哪里，什么不能据此宣称？

高度场（heightfield）：每个水平位置只对应一个表面高度，不能表达翻卷成管的多层水面；带限：只保留采样能表达的频率，避免走样。

岸浪不是把深海 FFT 一路推到沙滩。浅水处长涌浪淡出，烘焙的传播时间场接手；其浅水速度用 √(g×深度)，深度被夹在 0.3–14 米。一阶扫掠与模糊近似传播前沿，波高及水平挤压预算限制破碎形态，所以能倾斜却不会真正卷成浪管。

空间也有界：海面是随相机移动的极坐标网格，远处接平裙边；岸线图超出范围时按深水处理。FFT 纹理按各自周期重复，不等于物理无限且永不重复的大海；焦散只有三个深度切片，水上折射只知道当前屏幕数据。

明确未实现：持续航行尾流、漂浮物互撞、真实翻卷浪管（README 已列）。本次所读核心链路未找到完整体积流体求解，不能把它当工程预测器。WebGL2、浮点渲染目标及具体驱动支持要在目标机确认。本机安装、生产构建及 CPU 数值检查已完成，协调者观察到服务器启动和 Lagoon 渲染；这些都不能替代完整的 GPU 兼容性、长期稳定性或性能测试，本文不宣称稳定帧率或长期无漂移。
