Q2

它只是“背单词神器”，还是更大的工具箱？

词汇星图是 18 个 Skills + 4 个学习应用中的一员；本指南只深挖它及其直接依赖的建词、排程能力。

词汇星图自身包含项目页、词汇星图、词典页、背单词页、日历、收藏夹与单词页。直接相关的两个 Skill 是：

  • build-word-entry：采集限定词典证据、构造词条、维护关系。
  • schedule-ebbinghaus-plan：确定性 Python 排程，不让 Agent 手算整张日历。
重要边界：仓库附带考试词表文本，不等于自带完整释义词库。README 明确：学龄段目前只有动态“所有单词（测试）”，正式词表待用户提供；未建词只显示占位与候选关联，不猜释义。
Q3

总词库、项目、计划怎样各管一摊？

总词库存“知识”，项目存“我学哪些”，计划存“何时复习”；通过稳定 wordId 连接，而不是复制三份释义。

层主要落点职责
总词库dicts/a.jsonl … z.jsonl每行一份完整词条，按首字母分桶
项目projects/<id>/project.json项目名、词表、wordId 引用
熟悉度项目内 learning-state.json每项目独立 unfamiliar/seen/familiar
计划plans/<planId>.json日程、轮次、通过记录、乱序设置
跨项目favorites/ui-state收藏与界面状态

词条 ID 来自 NFKC 规范化、去首尾空白、空白折叠、casefold 后的 SHA-256 前 20 个十六进制字符，再加 w_。本实验实测 " WORD " 与 "word" 得到相同 ID。

Q4

“星图”里的点和线分别是什么？

点是词条、待建词、词形或派生词；线是同义/近义/反义/拼写相似关系。同族词靠分组聚拢，不画同族边。

  • 总览：当前项目词表、已发布词形/派生词和可见节点间关系。
  • 聚焦：先展示直接同族与关联邻居，可再展开其余节点。
  • 关系状态：正式关系实线；待核验候选用虚线。synonym_or_near_synonym 展示时归入近义，不偷偷改原数据。
  • 力学布局：弹簧、斥力、阻尼和同族间距共同决定位置；Alt+滚轮才缩放，防止普通滚动误触。
容量边界：首屏最多 500 个词条与占位节点；搜索、聚焦可访问其余词。布局漂亮不等于语义关系已被专家确认。
Q5

拼写相似为何用 LCS，而不是肉眼猜？

LCS 是“最长公共子序列”：允许跳过字符，但顺序不能乱；得分达到 0.75 才建立拼写相似关系。

公式：score = 2 × LCS(a,b) / (len(a)+len(b))。上游用整数不等式 8 × LCS ≥ 3 × (len(a)+len(b)) 判定，避免浮点边界误差。

词对LCS得分结果
quiet / quite40.800通过
cat / cut20.667不通过
planet / planeta60.923通过
别把“像”当“同族”：别名、屈折词形、已确认同族与派生词会被排除；后来确认同族时，还会清掉旧的拼写相似边。拼写边无需 Agent 逐对判断，也不绑到某个义项。
Q6

艾宾浩斯计划具体怎样排到每一天？

每天最多引入一个新批次；每个批次在首次学习后的 +1、+2、+4、+7、+15 天复习，复习批次数不限。

以 8 个 item、每天 3 个为例：批次为 [1,2,3] / [4,5,6] / [7,8]。D2 同时出现新 4–6 与复习 1–3；D4 复习 4–8。最后一项在第 18 天完成第五次预定复习。

本实验独立参考模型核对：8 个新词各出现一次，复习事件共 40 个，且每词恰好 5 次。

科学表述边界：上游明确说这些间隔是“本项目的排程约定”，不是唯一、普适的实验定律。它也不是 FSRS/Anki 那种按答题表现动态调参的算法；通过/重试记录不会自动改写未来的间隔。
Q7

葫芦背书法与艾宾浩斯差在哪？

葫芦法只排首次学习，用“当前页至少 80% 通过”控制能否前进；艾宾浩斯法把未来复习日也排进日历。

维度艾宾浩斯葫芦背书法
排程新学 + 预定复习仅首次学习
完成门槛当天末尾重试未通过词每页 ≥80% 才前进
下一轮手动开始手动开始
乱序稳定展示顺序；不改计划日程

5 词一页时，4/5=80% 通过，3/5=60% 不通过；门槛在源码里用 5×通过数 ≥ 4×页词数 做整数判断。修改项目、方法、开始日期或数量会重排并清空该计划所有轮次通过记录。

Q8

自动生成的词条为什么还要看证据？

因为“JSON 合法”只说明形状对，不说明释义对；项目把来源证据、AI 生成、脚本核验、Agent 审查分开记账。

  • 来源支持：具体页面定位与短证据摘要；不保存 Cookie、账号或密码。
  • automatic_passed：确定性脚本核对通过，不等于人工听过发音或认可所有语义。
  • agent_passed：本次内容审查通过；审查要绑定证据/候选摘要，不能拿旧判断复用。
  • pending：证据不足或待核验，仍可展示但必须带状态，不伪装成事实。
本次限制：没有运行外站采集，不声称 Cambridge/Oxford 等当前选择器可用；登录、验证码与质量复核必须暂停人工处理，不能绕过。
Q9

本地数据、并发与安全怎样被守住？

它是本机单用户架构：回环地址降低暴露面，revision 防止旧页面覆盖新状态，原子写入与 Schema 降低坏文件风险。

  • 进程边界：Vite 前端 127.0.0.1:5185，Python API 127.0.0.1:5186；不要直接打开 HTML。
  • 请求来源：有 Origin 时只接受本机回环 HTTP 来源，其他来源 403。它是基础防护，不是多用户身份系统。
  • 乐观并发：更新携带 expectedRevision；不匹配返回 409，而不是“最后写入赢”。
  • 可恢复性：原子写入、多分桶事务、状态机检查点；词条与索引冲突时暂停。
  • 稳定乱序：planId + 轮次 + 日期生成随机种子，刷新不改变当天顺序。
供应链提示：本次 npm ci 成功安装 70 包，但 npm 报告 2 个 high 漏洞。未执行 npm audit fix，避免未经测试升级锁定依赖；本机使用也应及时复核上游修复。
Q10

我能拿它做什么，又不该期待什么？

最适合“我有词表，想建可追溯词条、看关系、做本地复习”的学习工作流；不是开箱即用的权威全量词典。

六种具体用途

  1. 把考试/课文词表建成独立项目，保持原顺序并去重。
  2. 生成带词典来源、例句与核验状态的词条。
  3. 用星图集中辨析同族、同义、反义与易混拼写。
  4. 用项目熟悉度和跨项目收藏组织个人弱点。
  5. 建立多个艾宾浩斯或葫芦计划，在日历追踪。
  6. 把占位词交给可恢复的建词状态机，暂停后继续。
一句话上手：先建一个小项目（例如 8 个词），确认词条证据和图谱，再建每日 3 词的艾宾浩斯计划；别一上来导入几千个未建词。
