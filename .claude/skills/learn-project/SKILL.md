# 子项目学习方法（learn-project）

这是 F:\reminder 总仓库的**总体学习方法**。用户有 400+ 个小项目要逐个学习，本 skill 定义对每一个项目的标准学习流程。

## 第 0 步：项目分类路由

先快速浏览子项目目录（README、主要文件），判断类别：

| 类别 | 判断特征 | 处理方式 |
|---|---|---|
| **知识学习类** | 教程、论文复现、算法讲解、概念演示 | 走本 skill 完整流程 |
| **开源项目类** | 可克隆、可运行、有 README 的开源软件/库 | 走本 skill 完整流程 |
| **工具速用类** | 只是拿来用一次的工具/脚本 | 简化：跑通 → 写一页速用笔记入库，不出 PDF |
| **一次性报告类** | 用户临时要一份分析/报告（如 changeheadanddance） | 按报告需求直接产出，不强制入库流程 |

不确定类别时问用户。知识学习类和开源项目类继续往下走，两类流程相同，仅实验设计侧重不同（前者侧重"验证概念"，后者侧重"跑起来并改造它"）。

## 目录布局约定（必须遵守）

```
F:\reminder\
├── CLAUDE.md                    ← 总仓库说明
├── .claude\skills\learn-project\SKILL.md
├── vault\                       ← Obsidian 知识库（全部项目共用一个）
│   ├── 00-总览.md               ← MOC：概念地图 + 项目索引
│   ├── 概念\                    ← 一个概念一个笔记，跨项目复用合并
│   ├── 项目笔记\<项目名>.md
│   └── _templates\              ← 概念模板 / 项目笔记模板
└── <子项目名>\
    ├── repo\                    ← 克隆的上游代码（总仓库 .gitignore 掉，不提交）
    ├── <项目名>-小白指南.pdf     ← 学习成果（提交）
    ├── <项目名>-动手练习.pdf     ← 与指南合一或独立均可（提交）
    └── exercise\                ← 自己写的实验材料（提交；不要写进 repo\ 里）
```

克隆上游仓库时：`git clone <url> <子项目名>\repo`。若克隆下来才发现要放 repo\，把全部内容（含 .git）移进去。

## 第 1 步：读取知识储备

先读 `vault\00-总览.md` 和 `vault\概念\` 下的笔记，了解已掌握的概念。

- 疑问清单要**避开已掌握的概念**（或一句话带过+链接知识库），把篇幅留给新概念；
- 讲解新概念时，尽量**类比知识库里已有的概念**（例：已学过 Three.js 场景图，讲 ROS topic 就可类比）；
- 这就是"知识储备递增、概念关联合并"的机制。

## 第 2 步：快速摸底项目

读 README、目录结构、核心入口代码；能跑就实际跑一遍最小示例（记录环境坑：中文 Windows 默认 GBK，跑 Python 前先 `setx PYTHONUTF8 1`）。

## 第 3 步：列疑问清单

以"**工科毕业生第一次接触该项目**"的视角列 10~15 个疑问，从浅到深分层：

1. 这是什么？解决什么问题？（一句话能说清吗）
2. 为什么需要它？没有它之前人们怎么做？
3. 它是怎么做到的？（核心原理/架构）
4. 关键术语都是什么意思？
5. 它和我知道的 XX 有什么关系？
6. …

**用用户的已有知识库过滤**：已知概念不出现在疑问里。

## 第 4 步：逐条解答

每个疑问的回答必须至少运用以下三种方式中的一种，最好多种结合：

- **图文并茂**：画 SVG 示意图/流程图/对比表（HTML 内联 SVG，别用外部图片除非必要）；
- **举例说明**：具体、可感的例子，避免抽象描述；
- **讲故事**：用一个场景/人物/历史脉络把概念串起来。

写作红线：比喻要服务理解，讲完比喻必须落回术语本身；每个新术语第一次出现给一句话解释。

## 第 5 步：这个项目给我什么

单独一节列出：项目提供的能力清单 + 用户能用它干什么（3~6 个具体用途，结合用户水平）。

## 第 6 步：设计成就感实验

设计 **1 个主实验（3~7 步）**，要求：

- 小白可以**一步一步跟着做**；
- 每一步写清四件事：**怎么操作（完整命令，可复制）→ 目的是什么 → 实现了什么 → 怎么检测/验证成功**（给出期望的输出样例或截图描述）;
- 有中间可见的成果（改一个参数看到变化 > 只看跑通日志）；
- **所有命令必须实际执行验证过**才能写进 PDF，禁止想当然；
- 实验自建材料放 `<子项目名>\exercise\`，不要污染 `repo\`。

## 第 7 步：产出彩色 PDF

用 HTML → Edge 无头打印（这是用户全局偏好：色彩鲜艳、重点夸张）：

```powershell
# 1. 写 HTML（ASCII 临时文件名，中文文件名会让 file:// URL 失败）
# 2. 打印
msedge --headless --disable-gpu --no-pdf-header-footer --print-to-pdf="F:\reminder\tmp_out.pdf" "file:///F:/reminder/<ascii_name>.html"
# 3. 改回中文名
Rename-Item F:\reminder\tmp_out.pdf "<项目名>-小白指南.pdf"
```

HTML 设计要求：
- **高饱和鲜艳配色**（定义在 `:root` 色彩变量里）：明快的主色 + 对比强的强调色，禁止灰暗单调；
- 疑问即目录：每个疑问一张彩色卡片，编号大而夸张；
- **重点句用大号加粗 + 高亮底色**，关键数字/命令用代码块强调；
- 每个疑问配至少一张 SVG 示意图；
- 实验部分用分步卡片，验证标准用"✅ 预期结果"框突出；
- 页面 A4 友好（`@page` 边距、卡片 `break-inside: avoid`）。

产出位置：`<子项目名>\<项目名>-小白指南.pdf`（HTML 源文件一并保留在旁边）。

## 第 8 步：知识入库（Obsidian vault）

学习完成后，把知识沉淀进 `vault\`：

1. **概念笔记**：本项目引入的新概念，每个一条，写入 `vault\概念\<概念名>.md`，用模板；正文含：一句话定义 + 属于哪个领域 + 和已有概念的关联（`[[链接]]`）；
2. **概念合并**：如果新概念和已有笔记是同一事物（不同叫法），合并进旧笔记而不是新建，保留旧名做别名；如果只是相关，互相 `[[链接]]`；
3. **项目笔记**：`vault\项目笔记\<项目名>.md`——这个项目是什么、带来了哪些概念（链接）、实验做了什么、坑与结论；
4. **更新 MOC**：`vault\00-总览.md` 里更新概念地图和项目索引，保持知识库的秩序。

## 第 9 步：git 提交同步

在 `F:\reminder` 下：

```bash
git add <子项目名>/ vault/ .claude/ CLAUDE.md .gitignore
git commit -m "learn: <项目名> 小白指南 + 实验验证 + 知识入库"
git push
```

- 注意 `repo\` 已被 .gitignore 排除，不要提交克隆的上游代码；
- push 失败先 `git pull --rebase` 再试；认证问题则提示用户在终端交互登录。

## 已知环境坑（Windows 11 中文系统）

- 中文文件名 + `file://` URL → Edge 打印失败，一律先 ASCII 临时名再改名；
- 中文 Windows 默认 GBK → Python 项目先 `setx PYTHONUTF8 1`，否则测试套件大量假失败；
- 子项目如果是自带 `.git` 的克隆，其内部文件外层仓库跟踪不到 → 一切学习成果放子项目根目录或 `exercise\`，不放 `repo\`。
