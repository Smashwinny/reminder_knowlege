开胃故事：为什么叫"西洋镜"？

zoetrope 的中文名叫西洋镜（走马灯）：一串静止的画面快速转过，看起来就"动"了。 Claude Code 干活时，你的终端里只有唰唰滚动的文字；而在磁盘上，它其实一直在 一行一行地写"日志"。zoetrope 做的就是把这串静止的日志行快速"转"起来—— 让你亲眼看见一个会话如何分裂出子 agent、子 agent 又调了哪些工具， 就像看一场实况转播或赛后录像。作者是 furkankly，Rust 编写，MIT 协议，2026 年刚开源就收获了约 979 颗星。

疑问解答（每个疑问一张卡）

Q1

zoetrope 到底是什么？一句话说清

一个只读的小工具：把 Claude Code（或 Codex）的会话，实时画成一张"流动图"， 在终端里看，也可以在浏览器里看。它不做任何修改、不联网，纯粹是一台"监视器 + 录像机"： 会话正在跑时可以跟随直播，会话结束后可以倒带回放。 图上每个 agent 是一张卡片，卡片之间的连线表示"谁派生了谁"，卡片下的小徽章（chip）显示它在用什么工具。

Q2

为什么需要它？没有它之前人们怎么看 agent 在干嘛？

以前只有三种"土办法"：① 盯着终端看文字滚动，派生了子 agent 时只看到一句 Async agent launched，之后它在干嘛完全是黑箱；② 会话结束后去翻 ~/.claude/projects/ 里的 JSONL 日志——几千行 JSON，肉眼没法看； ③ 装各种需要联网上传日志的第三方面板（隐私堪忧）。 zoetrope 的答案：直接把日志文件"翻译"成一张会动的图，全程只读本机文件、零网络。 主实验里我们看到一段真实转录被折叠成 1 agent, 56 tool calls (50✓ 6✗)——一眼看完全貌。

Q3

数据从哪来？JSONL 会话转录是什么？

Claude Code 每开一个会话，就在 ~/.claude/projects/<项目路径编码>/ 下 建一个 JSONL 文件（每行一个独立 JSON 对象的日志文件）， 会话的每一步——你发的提示词、模型的思考、每次工具调用的开始/结果、派生子 agent 的记录—— 都追加一行进去。这个文件是官方内部格式、没有公开文档。 Codex 的对应物在 ~/.codex/sessions/，文件名以 rollout 开头。 zoetrope 把它当作 append-only 事件日志：只管往下读新行， 每行独立解析，坏一行就跳过，绝不致命。本机真实的转录路径例如：
C:\Users\Windows\.claude\projects\F--reminder\a3ffe5cf-0024-....jsonl

Q4

流动图上的节点、边、chip 分别是什么？

元素含义真实例子（实测输出）
agent 卡片一个智能体：主 agent / 子 agent / workflow 组● claude · ⚒ 5 · Workflow · active · 520 tok
边（箭头）Spawn：主 agent 通过 Agent/Task 工具派生子 agentmain → Explore / general-purpose ×2
工具 chip连续同名工具调用聚合成一枚计数徽章⚒ bash ×5、⚒ Grep 5.0s ✓、⚒ Bash 10s ✗
时间线底部可拖动的进度条，按"事件"而非墙钟时间索引空档被压缩，密集区被放大

chip 聚合是个贴心设计：agent 连读 20 个文件，不会闪过 20 枚 chip， 而是一枚 ⚒ read ×20 计数徽章在慢慢变大；只有连续 2.5 秒（RUN_GAP）没再有同名调用， 这枚 chip 才算"冷却"，下一次同名调用会开一枚新 chip。

Q5

"直播"和"时间旅行回放"是怎么实现的？

zoetrope 内部维护一条事件时间线和一个播放头（playhead）——和视频播放器一模一样： 回放就是播放头从头往前走；直播就是播放头钉在文件末尾追新行。 关键在于它区分了两台时钟（作者称之为全项目最重要的设计）：

内容时钟 content-time呈现时钟 presentation-time
是什么会话自己的时间戳（播放头的位置）你看了多久（真实秒表）
管什么状态：谁在运行、工具成没成功动画：镜头滑动、chip 余晖、蚂蚁线
暂停/拖动时永远可以问到"此刻为真"立即冻结，倒带不重播动画

把"事实"和"动画"分开，才可能做到往回拖动进度条时，图会真的"缩回"过去的样子， 而动画不会乱闪。默认回放速度 8 倍（--speed N 可调），长空闲被对数曲线压缩—— 5 分钟的等待仍比 5 秒的停顿显示得长，但不会让你干等。

怎么安装？基本命令有哪些？（本机实测版）

# Windows 无 Rust 工具链时的最简路径（本机采用，已验证）：
# 1. 从 GitHub Releases 下载 zoetrope-0.2.0-x86_64-pc-windows-msvc.zip，解压出 zoe.exe
F:\reminder\zoetrope\bin\zoe.exe --version        # → zoe 0.2.0

# 其他平台：
brew install furkankly/tap/zoetrope               # macOS / Linux
cargo install zoetrope                             # 有 Rust 工具链的话

# 日常使用（全部实测）：
zoe                                                # 跟随当前项目的直播会话
zoe <file.jsonl>                                   # 从头回放一段录像
zoe a3ffe5cf                                       # 按会话 id 前缀回放（不用记全 UUID）
zoe <file.jsonl> --follow                          # 打开时就钉在直播边缘
zoe <file.jsonl> --speed 20                        # 20 倍速回放
zoe inspect <file|id>                              # 无界面：直接打印会话树（脚本友好）

打开后的按键：space 播放/暂停 ｜ [ ] 上/下一个提示词时代 ｜ g 跳回直播 ｜ s 空档压缩开关 ｜ f 跟随镜头 ｜ ? 帮助 ｜ q 退出。

Q7

子 agent 几分钟不吭声，它怎么判断"还在干活"还是"挂了"？

这是整个项目最难、也最值得学的部分。转录里没有一个"子 agent 完成了"的事件。 作者踩过的坑被写进了架构文档：

❌ 陷阱一：主 agent 调 Agent 工具的返回值写的是 "Async agent launched successfully"——这是"派生回执"，不是"完成通知"。 早期版本把回执当完成，子 agent 卡片刚出生就标 Done，闪一下又活了（chip 闪烁 bug）。

❌ 陷阱二：子 agent 143 秒没输出，"安静判定"就宣布它 Done——结果它真正的工具错误报出来时， 图上已经把它当历史了。教训浓缩成一条原则：未完成的工具调用（pending tool_call）本身就是"还在干活"的铁证，优先级高于一切推测。

✅ 现在的三层判定：① 权威终止信号（task-notification / workflow journal result）→ 终态，锁死； ② 有 pending 工具调用 → 一定 Running；③ 都没有时才用"120 秒活跃窗口"启发式—— 而且是可逆的：一旦它又动了，状态立刻翻回 Running。

Q8

转录格式是官方私有的，官方一改它就崩吗？

格式确实没文档、随版本可能变。zoetrope 的对策是两层：

① 防御性解析：每一行 JSONL 独立解析，认不出的记录类型直接跳过—— 坏一行绝不拖垮整个会话，最多是图上少画一个元素；

② provider 边界：代码里有一条铁律——"provider 只陈述记录里写了什么，核心来推断没写出来的含义"。 Claude 格式的怪癖（比如"缺 is_error 字段 = 成功"）只允许写在 src/provider/claude/ 里， 且必须配一个用真实数据验证的测试夹具。想支持新工具（比如其他 agent CLI）？ 加一个 provider 目录即可，核心一行不改。识别格式时它看文件内容而不是看路径/扩展名—— 实验里 codex 的 rollout 文件被自动识别，无需任何参数。

Q9

"零网络"是什么意思？为什么反复强调？

会话转录里全是你的代码、提示词、甚至 API 相关上下文——交给一个联网的第三方面板等于把工作日志上传出去。 zoetrope 的承诺是可证明的零网络：依赖树里根本没有 HTTP 客户端， 就连异步运行时 tokio 都编译成不带 net 特性的版本； 任何人都能用 cargo tree 亲自验证"没有一条依赖通向网络"。 浏览器版同理：WASM 在你浏览器里解析本地文件，文件不上传。

Q10

终端里黑底白字怎么"画图"？同一个核心怎么跑进浏览器？

靠 Rust 的 TUI 框架 ratatui（在终端里用字符块画出卡片、边框、进度条的库）， 加上作者自研的图布局组件 rataflow。更有意思的是架构： 模型 / 时间线 / 渲染全部放在一个不做任何 I/O 的核心库里， 外面套两件"壳"——终端壳（native）和浏览器壳（编译成 WebAssembly，用 ratzilla 框架）。 所以浏览器版和终端版画出来的图是同一份代码。实测中我们 даже 在无终端环境下抓到了它渲染的 字符帧：● claude ⚒ 5 · Workflow、⚒ Grep 5.0s ✓、卡片间连线 ╭─┴─——这就是字符版"显卡"。

Q12

这个项目给我什么？（能力清单见下一节）

一句话总结它教给我们的三件"可迁移"的事： ① append-only 事件日志 + 折叠（fold）= 任意时刻状态可重建； ② 派生状态必须可逆、且永远不许覆盖真实记录； ③ 内容时钟与呈现时钟分离，才有可 scrub 的时间旅行。 这三条不止用于可视化——任何"从日志重建状态"的系统（监控面板、调试器、回放测试）都是同一套思路。

第五步：这个项目给我什么（能力清单）

1. 实时监督长任务
让 Claude Code 跑大活时，另开一个终端 zoe 直播看：哪个子 agent 卡住了、哪个工具反复失败，一眼可见。
2. 复盘历史会话
zoe inspect <id前缀> 秒出会话树：几个 agent、56 次调用、6 次编辑、哪里失败过——写复盘笔记的素材机。
3. 理解别人的 agent 工程
回放开源项目的会话录像，看别人怎么拆任务、怎么用子 agent，是学习 agent 编排的"比赛录像"。
4. 无界面脚本集成
zoe inspect 输出纯文本会话树，可以塞进脚本/CI 做会话统计（agent 数、失败工具数、token 量）。
5. 隐私安全分享
浏览器版零上传，或直接用仓库自带 demo.jsonl 给同事演示"我们的 agent 是怎么干活的"。
6. 学 Rust TUI 架构
ratatui + 自研 rataflow + no-IO 核心库 + WASM 双端，是"核心逻辑与呈现分离"的教科书式范例。

一页带走：zoetrope 教给我们的三件事

1. 事件日志是最高级的存档。 只追加、不可变、每行独立——从它出发可以重建任意时刻的状态（fold 折叠模型），倒带=重新折叠前缀。

2. 推断必须可逆，铁证优先于推测。 "没消息"不等于"完成了"：pending 工具调用是铁证，安静时长只是可逆推断——这个原则适用于一切监控/看板系统。

3. 事实与动画分两台钟。 状态读内容时钟（会话时间戳），动画走呈现时钟（真实秒表）——所以才能放心地拖动时间线"时间旅行"。
