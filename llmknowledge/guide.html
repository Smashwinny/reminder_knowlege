Q2
AI 智能体(Agent)到底是什么?和聊天机器人差在哪?
聊天机器人只会「说」,智能体会「说 + 做」:它能调用工具、查资料、执行动作,自己决定下一步干什么。

AI 智能体(Agent):以大语言模型为"大脑",配上工具当"手脚",再给一个自主循环让它"想了就做、做完再想"的程序。

🗣️ 比喻:聊天机器人像电话客服——你问它答,答完就挂,办不了任何实事。智能体像有手有脚的助理——你说"帮我订下周三的机票",它自己查航班、比价格、打开订票页面、下单,然后回来汇报。
落回术语:区别的本质是——聊天机器人的输出只有文字;智能体的输出可以是「工具调用请求」,由程序真正执行,再把结果喂回大脑继续决策。
智能体 = 大脑(LLM) + 手脚(工具 Tools) + 循环(自主决定做几步)

Q3
它是怎么「自己动手」的?—— 工具调用循环(全仓库的核心原理)
关键机制叫「工具调用 / Function Calling」:LLM 不执行代码,它只「点菜」(输出函数名+参数的 JSON),真正下厨的是框架;菜端回来,它再决定下一口吃什么。

工具调用(Function Calling):让 LLM 从一份"工具菜单"里选择"我要调哪个函数、传什么参数",由外部程序代为执行并把结果还给 LLM 的机制。

图3:工具调用循环 —— 本仓库所有 88 个示例的共同心脏

✅ 已实测验证(agno 3.0.11 + GLM-4.6):问"光一年走多少公里",日志清楚显示 calculator(expression=3e5 * 365 * 24 * 3600),然后 LLM 用返回值组织出「约 9.4608×10¹² 公里」;问"现在几点",它调用 now_time() 拿到真实时间。两问都没心算、没编时间——菜单机制生效了。

🔗 连接你的知识库:这个「生成→执行→检查→修正」的循环,和 [[质检Gate与自我纠错循环]] 是同族思想;每一步工具结果就是一次客观的 Gate 检查,LLM 据此决定继续还是收工。区别在于:Gate 循环的裁判是确定性脚本,这里的裁判是LLM 自己读结果后决策。

Q5
RAG 是什么?为什么「让 AI 读我的 PDF」不能直接把 PDF 塞给它?
RAG(检索增强生成)= 先从你的资料里「检索」出最相关的几段,再把这几段塞进提示词让 LLM「生成」答案。解决的是:资料太多塞不下 + 模型没见过你的私有资料。

直接塞整本 PDF 有三个问题:① 上下文窗口有限(模型一次能读的字数有上限);② 贵(按字数收费);③ 大海捞针(塞得越多,模型越容易漏掉关键句)。

嵌入(Embedding):把一段文字变成一串数字(向量),意思越相近的段落,向量越接近——于是"找相关段落"变成"找最近的向量"。

图4:RAG 两阶段 —— 建库一次,检索无数次
📚 比喻:让 LLM 直接读整本书,是逼它闭卷硬背;RAG 是考试前帮它做好一盒索引卡片,考到哪个知识点就抽出对应的卡片放它面前——它只需要读那几张卡片就能作答。落回术语:卡片盒=向量数据库,做卡片=Embedding 建库,抽卡片=Top-K 检索。

✅ 已实测源码(repo/rag_tutorials/rag_chain/app.py,199 行):Chroma 向量库 → db.as_retriever(k=5) → 提示词模板 → LLM → 输出,和图 4 一一对应。该区 24 个教程 = 这条链的无数种升级(检索质量自评、查不到就转网搜、多模态、带引用……)。

Q6
多智能体团队(Multi-Agent Team)为什么要「分工」?
一个智能体什么都管,指令会互相打架、工具越挂越多;拆成各管一摊的专员,再让一个「队长」汇总,效果和可维护性都更好。
🏥 比喻:去医院不会挂一个「全科包治百病」号,而是分诊台(Team)→ 各科专家(member agents)。每位专家只带自己科室的工具(化验单、CT 机),诊断更准;分诊台负责听你描述、决定叫哪些科、最后汇总病历。落回术语:member=有专属工具和指令的子智能体,Team=带汇总模型的编排器。

✅ 已实测源码(ai_finance_agent_team,约 60 行):web_agent(挂搜索引擎工具)+ finance_agent(挂股价工具)→ Team(members=[web_agent, finance_agent])。读股票分析问题时,队长自动拆分"查新闻"和"查股价"两路,再合并成报告。

Q7
MCP 是什么?为什么全网都在说?
MCP(Model Context Protocol,模型上下文协议)= AI 工具的「USB-C 接口标准」:工具做一次 MCP Server,所有支持 MCP 的智能体都能即插即用。

没有统一标准时:你有 M 个智能体、N 个工具(浏览器、GitHub、Notion……),最坏要写 M×N 套对接代码。有了 MCP,工具方实现一次 MCP Server,智能体方实现一次 MCP Client,变成 M+N。

图6:MCP 把 M×N 变成 M+N

仓库的 mcp_ai_agents/ 给了 6 个现成例子:自然语言开真浏览器、用嘴逛 GitHub 仓库、指挥 Notion。你现在用的 Claude Code 本身就是 MCP Client——这就是为什么"给 Claude 装个浏览器工具"只需要一行配置。

Q10
agno 框架是什么?为什么所有示例都用它?
智能体框架 = 脚手架:替你管「模型对接、工具注册、消息循环、会话存储」,你只写"用哪个脑、带哪些手、守什么规矩"三件事。

没有框架时,你要自己写:HTTP 调模型的代码、把工具清单翻译成 API 要的 JSON 格式、解析模型返回的"点菜单"、执行函数、把结果按格式塞回去、循环、存聊天记录……约 200 行样板代码。用 agno 只要 6 行:

from agno.agent import Agent agent = Agent( name="小助手", model=Claude(id="glm-4.6", ...), # ① 用哪个脑 tools=[now_time, calculator], # ② 带哪些手 instructions=["计算必须用工具"], # ③ 守什么规矩 )

agno 还自带 Team(多智能体编排)、SqliteDb(会话/记忆存储)、AgentOS(一键起服务)。同类框架还有 LangChain/LangGraph、CrewAI、AG2;仓库的"框架速成课"教 Google ADK 和 OpenAI Agents SDK——概念互通,换框架只是换语法。

图7:框架夹在「你的三行配置」和「模型 API」之间
Q11
「记忆(Memory)」是怎么回事?保存聊天记录不就是记忆吗?
聊天记录=本次对话的"工作记忆";记忆=跨会话提炼并记住的"用户画像与偏好"。前者每开新窗口就清零,后者写进数据库,下次见面还认识你。
🐟 比喻:只存聊天记录的助手像金鱼——这顿饭聊得再好,下次见面就不认识你了。有记忆的助手像带笔记本的老管家:服务完把你"不吃香菜、喜欢靠窗位"记进小本本(数据库),下次直接安排好。落回术语:短期记忆=上下文里的对话历史;长期记忆=框架从历史中提炼、存入 SqliteDb 等存储的结构化信息。

仓库写法就两行:db = SqliteDb(db_file="agents.db") + add_history_to_context=True——历史自动进库、自动带回上下文。memory 专区 6 个示例演示了"记住你的研究兴趣/旅行偏好/每人独立记忆"等玩法。

Q12
没有 OpenAI key,能用国产 / 本地模型跑这些示例吗?
能。三条路(本指南实测第一条):① 任何 Anthropic 兼容端点(如 GLM)→ agno 的 Claude 类 + 换 base_url;② OpenAI 兼容端点(DeepSeek/Qwen/硅基流动)→ agno 的 OpenAIChat 换 base_url;③ 完全本地 → Ollama + llama3.2/qwen,零 API key。
# 本指南实测通过:用 GLM 的 Anthropic 兼容端点跑 agno 智能体 from agno.models.anthropic import Claude model = Claude( id="glm-4.6", api_key=os.environ["ANTHROPIC_AUTH_TOKEN"], client_params={"base_url": os.environ["ANTHROPIC_BASE_URL"]}, )
⚠️ 实测踩坑记录(宝贵的三个)
① agno 3.x 接口变了:网上旧教程写 Claude(base_url=...) 会报 TypeError,3.x 要用 client_params={"base_url": ...};而仓库示例还是按 2.x 写的——跑仓库示例前先 pip 装兼容版本或按新 API 小改。
② 限流 429:GLM 接入点约每分钟 1 次请求,连续两次调用要 time.sleep(65),否则报 rate_limit_error 1302。
③ 中文 Windows 的 GBK:跑 Python 前先 setx PYTHONUTF8 1,否则中文输出乱码/假报错。

本地路线示例(仓库有大量 local_* 教程,零 key):Ollama(id="llama3.2")——先装 Ollama,再 ollama pull llama3.2(约 2GB),之后模型跑在你自己电脑上,不花钱、数据不出门。
