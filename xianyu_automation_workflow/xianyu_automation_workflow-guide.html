Q1这个方法一句话是什么？

在闲鱼卖"自动化脚本模板"，用 AI Coding 工具（Claude 出架构 + Codex 出代码）把交付成本压到十分之一，卖的不是代码而是"弄好之后你就不用再动手"。客户为省时间付钱，你靠模板复用吃规模。

文中关键洞察：闲鱼上真正好卖的不是高大上的 AI 工具，而是"土得掉渣、天天折磨人"的重复破事——抓数据导 Excel、订单算利润、图片批量改名加水印、多表合并做周报。

Q2六步工作流拆解

① 选品：闲鱼搜高频词

专挑收藏和咨询多的帖子——那是已被验证的需求。文中六类：网页抓取清洗推送 / 订单利润日报 / 图片批处理 / 小红书文案库 / Excel 周报 / 定时任务。

② 把客户原话翻译成一句 spec

"客户原话"是模糊的，一句明确的需求描述是后面所有 AI 工作的锚——这步省 5 分钟，后面省 5 小时。

③ Claude 角色：架构与异常处理

让 Claude 出完整架构、异常处理、定时逻辑、操作说明。异常处理先行：字段缺失怎么办、平台扣点怎么算，全在设计阶段定死。

④ Codex 角色：可运行代码 + 界面 + 安装包

生成 Python 脚本+简单 GUI+一键安装包。分工的本质：架构决策与代码实现分离，各自校对。

⑤ 本地跑通 + 30 秒演示视频

演示视频是成交开关——客户先看到"它真的在跑"，才愿意拍。

⑥ 模板复用：改三个参数十分钟出货

改数据源、改推送方式、改字段名——文中称三个月后真正从零写的单子不到三分之一。

Q3为什么 Claude 和 Codex 要分开用？

这是本工作流最有技术含量的决策：架构/异常处理与代码实现由不同模型生成，互相校验。Claude 出架构时被迫把边界情况想清楚（"扣点怎么算"不写明白，Codex 就会静默算错）；Codex 照架构实现时，架构的漏洞会立刻暴露为跑不通。单次"一句话需求直接生成"省的是分工时间，赔的是返工时间。

对应 vault 的 [[规划执行分账]]：规划与执行分开核对，AI 时代这个原则从"团队协作"变成"同一个人按两次 enter"。

Q4选品：为什么是"土需求"而不是"AI 工具"？

需求公式：高频 × 痛（天天折磨）× 可自动化 × 客户自己不会写。"解压玩具"式的一锤子买卖没有复购，而"每天睁眼就要算的订单利润"天天折磨人。闲鱼搜索量验证需求存在（收藏咨询多=预付意愿强），6 类清单全是"数据进、报告出"的形状——恰好是脚本最擅长的事。

Q5收入宣称祛魅：11 万/三个月可信吗？

按证据算账：文中称"成交记录、聊天记录、脚本日志甩脸上"，但这是叙述者转述、无可独立核实数字。即便属实，三个隐含成本被淡化：①获客成本——闲鱼咨询转化、同行抄袭定价内卷；②售后成本——客户环境千差万别，"一键安装包"在别人的 Windows 7/Excel 2010 上必然翻车；③平台风险——虚拟商品交易纠纷、10 账号矩阵式运营触碰平台规则。收入数字按"单方案例主张"处理（[[证据优先质检ProofOverClaims]]），方法可信度与收入可信度分开评。

Q6模板复用为什么能把成本压到 1/10？

软件复用的经典规律在副业场景的兑现：第一单把"加载→计算→渲染→推送"的骨架做出来，后面每单只改配置（数据源/推送/字段）。文中"从零写的不到三分之一"就是复用率的直接度量。本指南实验的"订单利润日报"模板正是这个骨架的最小实例（见 Q10）。

Q9这个项目给我什么（能力清单）

① AI 分工工作流：架构模型与代码模型分离互校，单次提示词时代终结。
② spec 前置：客户原话→一句明确需求，是所有 AI 交付的第一道工序。
③ 异常设计先行：把"会怎么坏"写在架构里，比写功能更值钱。
④ 需求四要素：高频×痛×可自动化×客户不会写 = 可卖脚本。
⑤ 模板骨架思维：加载→计算→渲染→推送，改配置即新单。
⑥ 祛魅双标：方法可信度与收入可信度分开评分。
