02

官方课程真正讲了哪些模块？

课程事实官方当前页标注中级、约 1 小时 47 分、9 个视频课与 6 个代码示例。转发版约 112 分钟，且字幕显示部分转场重复，故下面采用官方模块顺序而非网传时间戳。

学习主线不是“Prompt → Agent → Loop → Graph 的 2026 新理论”，而是：先手写 Agent 认识循环，再用 LangGraph 显式化状态与路由，最后加入检索、持久化、人类介入和多节点写作。

与已有知识衔接：State、Reducer、Checkpoint、Interrupt 已在 LangGraph 指南中学过，本指南不重复安装与 API 教学，集中追问“路由到 END 是否真的代表任务做对了”。
03

从零 Agent 的循环什么时候结束？

课程事实从零实现的 query(question, max_turns) 有两个出口：正则找不到 Action 就 return；否则执行工具，把 Observation 喂回模型；达到 max_turns 也会退出。

关键边界：“没有 Action”只说明模型没有再按格式请求工具，不等于答案正确；“达到 max_turns”只说明预算耗尽，更不等于完成。未知工具会抛异常，而不是被静默执行。

这把停止条件分成两个正交问题：控制流为什么结束与结果是否被验证。课程代码回答前者；后者需要另加评估 Gate。

04

换成 LangGraph 后，结束判断变聪明了吗？

课程事实核心结构是 StateGraph(AgentState)、llm 节点、action 节点和条件函数 exists_action。最新消息有 tool calls 就去 action，没有就去 END。

没有变聪明，只是变得显式、可测、可插拔。条件边仍然只判断“有没有工具调用”。这是好事：把简单路由与复杂质量评价分开，才能分别替换和测试。

State 细节：课程用 Annotated[Sequence[BaseMessage], operator.add] 让消息追加；节点返回增量，框架更新共享状态。普通边负责固定转移，条件边负责运行时路由。
05

Agentic Search 与普通搜索差在哪里？

课程事实普通搜索往往返回链接/摘要，Agent 还得抓网页、清 HTML、找相关段落。课程用 Tavily 演示把复杂问题拆成子查询、选择来源、提取与排序内容，返回更完整、结构化的机器输入。

对停止条件的启发是：“搜索工具返回了”不是“证据够了”。还要检查来源是否存在、是否支撑最终结论、格式是否符合下游契约。

本轮限制：没有申请 Tavily key，也没有把实时搜索结果当实验事实；实验中的来源字段是固定字符串，用来验证 Gate 逻辑，不证明联网检索质量。
06

Checkpoint 是“完成”还是“可恢复”？

课程事实课程把 checkpointer 传给 graph.compile，用 thread_id 区分会话；.stream() 发出节点更新，.astream_events() 可筛 on_chat_model_stream 逐 token 输出。

Checkpoint 是“保存当前事实”，不是“宣布任务成功”。stream 也只是把过程事件暴露出来，不自动判断质量。内存 SQLite 在 Notebook 重置后消失；生产持久性需要外部数据库。

停止语义必须分型：VERIFIED_SUCCESS 是终态；BUDGET_EXHAUSTED 是失败终态；WAITING_HUMAN 是暂停；CHECKPOINT_SAVED 只是可恢复记录。混成同一个 done 布尔值，就会谎报完成。
07

Human-in-the-loop 到底改变了什么？

课程事实在 compile 时设置 checkpointer 和 interrupt_before="action"，图会停在工具执行前。人可读 get_state、用 update_state 改工具参数，再以同一 thread 调 stream(None, config) 继续。

课程还演示历史快照、从旧 checkpoint “time travel”、编辑后形成分支，以及用 as_node="action" 人工补工具结果。本质是把执行权暂时从图转交给人，而不是让另一个 LLM 说声“我看行”。

工程价值：高风险动作前暂停、保留证据、允许修正与审计。暂停点应放在不可逆动作之前，而不是所有节点都打断人。
08

Essay Writer 的停止条件有没有 off-by-one？

课程事实它使用 revision_number 与 max_revisions。每次 generate 后计数加一，随后判断：revision_number > max_revisions → END，否则进入 reflect → research_critique → generate。

官方示例从 1 开始、上限为 2，结果是 2 次生成 + 1 次反思/检索修订。这里的 > 与计数初值共同定义边界；换成 >= 会少一轮。

更重要的问题：它只看修订次数，不看文章是否达标。END 可能意味着“预算用完”，并非“质量通过”。本实验的两个专门单测实测 (2,2)→reflect、(3,2)→end，防止把边界讲错。
09

结尾真正介绍的五种图结构是什么？

课程事实最后约四分钟是架构速览，不是“四十分钟完整图系统实战”。它把不同流程的信息流与控制权放在一起比较。

Multi-agent 与 Supervisor 的区别在状态和控制：前者围绕共享状态交接；后者由 supervisor 决定子 Agent 输入，子 Agent 可有独立状态。LATS 依赖历史状态回跳，因此 persistence 很重要。

选型纪律：不要为了“图工程”把确定性的合并、去重、排序也交给模型。先用最简流程；只有分支、回退、恢复或并行需求真实出现时，才增加图复杂度。

“自修改 Agent”与本课的边界在哪里？

宣传未证在约 1:30:15 的字幕中，讲师正在定义 Essay Writer 的修订计数；官方目录与结论都没有“Agent 修改并升级自己代码”的模块。因此不能把自修改能力记到这门课名下。

修改作文、修复当前文件，与改写系统自身的提示词/控制流/评估器不是同一风险级。后者属于已有知识库的 RRSI 正则化递归自我改进：需要隔离候选、泄漏审查、独立评估、版本化与回滚。

本实验仅验证一条安全边界：候选若写评估器或越出允许路径，立即 HARD_FAILURE，不进入“让它自己修修看”的循环。没有实现、也没有声称验证了真正的自修改 Agent。

生产循环需要哪几类停止出口？

本实验增量课程的“无 Action / END / max_turns / max_revisions / interrupt”不足以覆盖所有故障。本轮把出口拆成五类，并让每类都有可观察理由。

出口触发证据能否自动重试
验证成功Outcome 与 Trajectory 都通过不需要；交付结果
硬失败篡改评估器、越权路径、不可逆危险不能；先升级处理
停滞候选指纹与上一轮相同原策略不应原样重试
预算耗尽达到明确轮数/成本上限不能假装成功
等待人工interrupt / 审批需求这是暂停，不是终止

重点不是“停得越早越好”，而是停止理由必须机器可查、语义不混淆。停滞与硬失败是本实验额外增补，不应归到原课程。

怎样用五个病例验证 Gate 没被骗？

本实验增量固定候选让结果完全可复现。Gate 分开检查终态（日期、负责人、来源）与轨迹（允许路径、评估器完整性），并且忽略 claimed_done。

repair 第一轮返回三个具体错误 MISSING_DATE / MISSING_OWNER / MISSING_SOURCE，第二轮通过；stagnant 的候选 SHA-256 前缀连续两次都是 716787f7f710，所以在第 2 轮停滞退出；tamper 虽然答案字段齐全，仍因 EVALUATOR_TAMPERING 立即失败。

评估器也要被评估：一个病例只证明一个机制。5 个病例 + 9 个单测不能推出生产系统可靠，更不能推出“同模型同 Token 完成度倍增”；它们只证明这份小型运行时的既定行为。

这门课与实验真正给我什么

1. 审计已有循环
把“无工具调用”“达到上限”“质量通过”拆开，不再用一个 done 含糊收尾。
2. 设计可恢复的图
知道 checkpoint、thread、stream、interrupt 各管什么，不把暂停误报为失败或完成。
3. 写停止条件测试
直接钉住 > 与初值边界，避免升级代码时多一轮或少一轮。
4. 建双层 Gate
终态查交付物，轨迹查越权/成本/修复过程；模型自称完成不是证据。
5. 识别营销换壳
用官方目录 + 字幕时间点交叉核对，不把“自修改”“效率倍增”等宣传当学习成果。
6. 找到下一门课
若要研究真正自修改，应转到 RRSI 等独立材料，而不是继续在这段视频里寻找不存在的内容。
