# spider_turret（候选，未写入vault）

**这是什么**：作者宣称由单张概念图借助Gemini 4 Argon、bpy生成的机械3D展示；公开版本以GLB刚性节点层级加JS解析IK/步态/材质驱动。当前固定SHA `e5f92a8b99f2cbeef6a87ad12c142b0ccf34a99b`；不能据此证明原帖当时one-shot生成过程。

**查重范围**：知识库main `a8674777e18302b8804b137212b1396cbfe5a747` 的总览及img2threejs、3d_vibe_coding、blueprint_to_3d、程序化建模、图生3D资产管线、Three.js与场景图、逆运动学IK与CCD迭代；未发现本项目。复用既有笔记，不新增“场景图/图生3D/先量后优化”的同义条目。

**它给我什么能力**：GLB命名节点验收；刚性机械交互展示；解析腿IK与落脚目标原型；dt事件回归；AI作品证据拆分。

**实验记录**：
- GLB 340 nodes / 282 meshes / 0 skins / 0 animations，24个必要节点齐全；绑定不等于蒙皮。
- 上游6个状态用例；9rad/s标签FIRING_ACTIVE却尚无触发；合成20/30/60/120Hz在2秒计数33/36/35/35，非实测FPS。
- 101可达目标人工层级IK→真实Three.js FK最大残差4.1540741810552243e-16；不可达目标残差8.760841100617018。
- 600步合成推进支撑目标漂移0，未证实真实网格脚尖零滑动或物理平衡。

**坑与结论**：
- GLB导出器为Blender并不证明某次模型生成；无原始prompt/生成脚本时不编补流程。
- 注释terrain-aware与当前函数恒0并存；按实际执行逻辑描述能力。
- 乘dt不保证事件计数帧率无关；每update布尔事件可能吞次数。
- UI温度28+heat×760是视觉映射，不是热力学或硬件测量。

### 世界坐标落脚目标与摆动轨迹
**一句话定义**：支撑期锁世界坐标脚目标；摆动期依据相位向预测落点插值，再由IK追踪。
**属于领域**：三维动画/程序化步态。
**通俗理解**：站住的一只脚像钉在地上，只有抬起后才换“钉子”；IK触限可能让真实脚尖跟不上钉子。
**工程含义**：分开量目标漂移与实际末端残差。当前地形恒0、相位摆动占比0.42；不能宣称坡地或动力学稳定。
**关联**：[[逆运动学IK与CCD迭代]]、[[Three.js与场景图]]。

### 离散时间事件计数与阈值跨越
**一句话定义**：连续进度在离散update里跨过多个事件阈值时，输出布尔值会丢失次数，应明确事件数或时间戳语义。
**属于领域**：实时系统/游戏循环。
**通俗理解**：一帧里过了两道门，登记表若只记“过门了”，就少一次。
**工程含义**：固定输入总时长，扫dt做事件计数回归；把模拟Hz与实际FPS分开；同时检查加速阶段离散误差，不把所有差异都归因一处。
**关联**：[[先量后优化性能法]]、[[证据优先质检ProofOverClaims]]。

**必须保留的待验证**：单图生成链、真实prompt/成本/失败次数、浏览器WebGPU视觉/音频、GPU计时与FPS、真实GLB脚尖和坡地/物理平衡。本提案非独立审核，非任务勾选完成。
