## 新概念提案 1：浏览器敏感权限分层模型

- 一句话定义：摄像头、麦克风、定位等 Web 能力依次受安全上下文、Permissions Policy/iframe、浏览器站点权限和操作系统应用权限约束的多层授权模型。
- 领域：Web 安全 / 隐私工程。
- 核心点：点击链接不等于获得敏感权限；已有授权可能不重复提示；`getUserMedia` 成功后的轨道需要停止；Permissions API 查询不能代替用户撤权。
- 关联：[[WebRTC机器人应用]]（浏览器音视频能力的正当用途对照）、[[沙箱与审批正交]]、[[代码管边界提示词管判断]]。
- 来源：MDN getUserMedia、Geolocation API、Permissions API；本项目 Q1/Q2/Q9/Q10。

## 新概念提案 2：安全上下文信任边界

- 一句话定义：HTTPS、可信回环等条件只决定来源是否满足敏感 Web API 的安全上下文门槛，不证明页面内容、运营者或权限请求善意。
- 领域：Web 安全 / 身份与传输。
- 核心点：HTTPS 不等于网站可信；localhost/127.0.0.1 是开发例外而非恶意免疫区；回环服务仍需 Host/Origin、令牌和端口审计。
- 关联：[[本地MCP端点安全四道门]]（回环信任的请求侧加固）、[[OAuth资源发现]]（来源/元数据信任需独立核验）。
- 来源：MDN Secure Contexts；本项目 Q3 与真实回环实验。

## 新概念提案 3：权限社工与授权后回传

- 一句话定义：攻击者用功能伪装、紧迫话术、重复提示等使用户主动授权，再通过周期上传、第三方接收方和结果存储形成数据暴露的社工—技术复合链。
- 领域：社会工程防护 / 数据安全。
- 核心点：拒绝阻止本次敏感 API 调用，但不抹去页面访问和普通指纹事实；检测要看权限必要性、重复上传、第三方接收方与系统最近活动；响应按停止、撤权、证据、影响、报告、复盘推进。
- 关联：[[提示注入]]（都是数据/界面影响决策但载体不同，保持相关而不合并）、[[证据状态机]]（访问/授权/上传/下载/凭据不可混为完成状态）、[[证据优先质检ProofOverClaims]]（事实、mock 与外推边界分开）。
- 来源：CISA 社会工程与钓鱼建议、上游静态审计；本项目 Q4-Q8。
