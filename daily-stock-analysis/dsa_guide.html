Q2
没有它之前人们怎么做？它改变了什么？

Q4
数据从哪来？多数据源 fallback 怎么设计？

免费行情源（AkShare 爬东财等）随时可能限流、改接口、断网，所以 DSA 把 19 个 fetcher 做成同接口的适配器，按优先级排队，第一个成功的当选，失败的自动降级到下一个——这和知识库里 [[能力层与后端路由]]（每平台有序后端列表，第一个真实可用者当选）是同一个模式在金融数据上的落地。

图3：数据源优先级链 + 统一归一化 + 限速防封禁（akshare_fetcher 里带随机 User-Agent 和 sleep）

三个细节值得记住：① 每个 fetcher 都用子进程 + 超时强杀隔离（_akshare_call_with_timeout），防止爬虫库卡死主流程；② 列名归一化（_normalize_data）把不同源的中文列名统一成 open/close/high/low/volume；③ 新闻是另一条独立数据线（SerpAPI/Tavily/Bocha 等），失败不阻断行情分析，只在报告里如实标注"新闻缺失"。

Q5
技术指标是怎么算的？（可直接抄的公式）

核心在 src/stock_analyzer.py，全部用 pandas 十几行搞定，没有任何神秘黑箱：

# MA 均线：普通滚动平均
df['MA5']  = df['close'].rolling(5).mean()   # MA10/MA20/MA60 同理

# MACD(12,26,9)：EMA 是带"记忆衰减"的平均，近期价格权重更大
ema_fast = df['close'].ewm(span=12, adjust=False).mean()
ema_slow = df['close'].ewm(span=26, adjust=False).mean()
df['MACD_DIF'] = ema_fast - ema_slow              # 快线
df['MACD_DEA'] = df['MACD_DIF'].ewm(span=9, adjust=False).mean()  # 慢线(信号线)
df['MACD_BAR'] = (DIF - DEA) * 2                  # 柱状图(红绿柱)

# RSI(6/12/24)：Wilder's SMMA 口径（与主流行情软件一致）
gain = delta.where(delta > 0, 0);  loss = -delta.where(delta < 0, 0)
avg_gain = gain.ewm(alpha=1/period, adjust=False).mean()
avg_loss = loss.ewm(alpha=1/period, adjust=False).mean()
RSI = 100 - 100 / (1 + avg_gain/avg_loss)   # >70 超买, <30 超卖, NaN 填 50(中性)

关键口径细节：RSI 用 ewm(alpha=1/period)（Wilder 平滑）而不是简单平均——repo 里专门有测试 test_stock_analyzer_rsi.py 把 RSI_6/12/24 的期望值精确到小数点后 10 位钉死，还验证了报告模块和告警模块用的是同一公式，防止两处口径漂移。另一个细节：数据不足 60 根时 MA60 直接用 MA20 替代，避免长均线缺数报错。

Q6
规则信号怎么打分？"交易理念"如何变成代码？

作者的交易理念被翻译成 7 步确定性流水线（analyze()）：均线计算 → 趋势判断 → 乖离率 → 量能 → 支撑压力 → MACD → RSI → 生成信号。每步产出枚举状态，最后加权合成 0-100 信号评分 + 六态买入信号（强烈买入/买入/持有/观望/卖出/强烈卖出）。

理念（main.py 注释）代码实现实验实测
严进策略：不追高乖离率 = (Close−MA5)/MA5，>5% 不买；强势趋势放宽到 8%bull 形态乖离 1.8% → "价格贴近MA5，介入好时机"
趋势交易：只做多头排列MA5>MA10>MA20 且间距扩大 → STRONG_BULL(90分)；空头 → 减分合成空头K线 → 空头排列，强度25
效率优先：筹码集中量比、缩量回调加权量比 0.97 → 量能正常
买点偏好：回踩 MA5/MA10MA5/MA10 支撑判定 + 加分理由里出现"MA5支撑有效"

Q7
规则已经打分了，为什么还要 LLM？

规则引擎只看得懂 数字（K 线、指标），看不懂 文本（"董事长被调查"的公告、突发新闻、行业政策）。LLM 在 DSA 里干三件规则干不了的事：

① 多源综合 把指标结果 + 10 条新闻 + 公告 + 基本面捏进一个"上下文包"（analysis context pack），让模型通盘权衡；② 表达与解释 产出人类可读的决策仪表盘：核心结论、催化因素、风险警报、操作检查清单；③ 多轮策略问股 Web/Bot 里的对话式追问（"帮我用缠论看看这只"），由 src/agent/ 的 Agent 循环接手——这正是知识库里 [[Agent循环]] 的应用：模型点菜、工具执行（analyze_trend / get_daily_history 等）、循环到给出答案。

组合方式是典型的 "确定性代码打底 + LLM 提炼" 两段式：能算的绝不让模型猜（指标、评分、乖离率全是代码算好的事实），模型只负责事实之上的研判与表达。这比"把行情 JSON 直接扔给 LLM 问涨跌"的粗放做法可靠得多——事实与判断分离是这个项目最值得抄的架构决策。

Q8
LLM 输出不可靠怎么办？契约与护栏怎么设计？

金融场景最怕模型"嘴里跑火车"。DSA 的防线一套接一套：

防线做法
统一评分刻度decision-scale-v1（图4）：LLM 给的 sentiment_score 必须落进五档之一，代码用 decision_band_for_score() 强制归一，越界分直接丢弃（normalize_score 返回 None）
口径一致性守卫score≥60 但动作却是 hold/watch？必须在 guardrail_reason 写明降级原因，否则提取 DecisionSignal 时被强制对齐
JSON 修复模型输出的坏 JSON 用 json-repair 库自动修复后再解析
失败不阻断决策信号写入失败、新闻缺失都不影响主报告——主流程永远先保住"能交付"
可后验评估每个建议沉淀为 DecisionSignal 结构化记录（入场区间/止损/目标价/失效条件/过期时间），事后可统计命中率，evals/ 目录做 Agent 轨迹评估
诚实披露数据缺失、新闻为空都会在报告里明示（有专门测试 test_notification_empty_news_disclosure.py 盯着这件事）

这套"契约 + 护栏 + 可后验"三件套，适用于任何让 LLM 输出结构化决策的场景（不只是股票），与知识库 [[质检Gate与自我纠错循环]] 思路同源。

Q9
"15 种策略问股"是怎么回事？

strategies/ 目录下 15 个 YAML，每一个 = 一份发给 LLM 的"分析师岗位说明书" + 工具清单：均线金叉、缠论、波浪理论、龙头战法、情绪周期、事件驱动、成长质量、预期重估…… 用户在 Web 工作台问"用缠论分析 600519"，路由层按 aliases 命中策略，把对应 instructions 注入 Agent 的系统提示。

# strategies/ma_golden_cross.yaml（实验 D 实测解析）
name: ma_golden_cross          # 机器名
display_name: 均线金叉          # 展示名
category: trend                # 策略大类
core_rules: [1, 2, 3]          # 关联交易理念条款
required_tools:                # 声明该策略要用的工具(Agent按需调用)
  - get_daily_history
  - analyze_trend
aliases: ['均线金叉', '金叉']   # 意图路由关键词
market_regimes: [trending_up]  # 适用的市场状态
instructions: |                # 619 字符的判定标准说明书(发给LLM)
  主信号：MA5 在最近 3 个交易日内上穿 MA10 …
  量能确认：金叉日量比 > 1.2 为积极信号 …

精妙之处：YAML 里写的是"判定标准"而不是"答案"——均线金叉的数学判定由 analyze_trend 工具（也就是 Q5 的确定性代码）完成，LLM 只按说明书的逻辑组织证据下结论。策略 = 提示词工程 + 工具约束的组合包，这与知识库 [[AgentSkills技能包]] 是同一思想。

它和量化回测框架（如 nautilus-trader）的边界

别把 DSA 当成量化交易系统：DSA 是"每日研究助理"——生成建议与解释，不执行交易、不做策略回测优化；nautilus-trader 那类回测/实盘框架才是"策略引擎"——历史数据回放、撮合模拟、绩效归因。两者的交汇点是 DSA 的 DecisionSignal 资产（结构化建议记录）和内置的轻量回测模块——若要把 AI 建议变成可回测的策略，信号得先经过契约化（DSA 已做）再到回测框架验证（需另接）。一个是参谋，一个是演武场。
