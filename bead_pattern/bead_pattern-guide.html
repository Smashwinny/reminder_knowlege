Q2拼豆（perler beads）是什么？图纸长什么样？

拼豆 = 彩色塑料小管豆，排在带钉齿的豆板上组成像素画，覆烘焙纸用熨斗加热使豆面半熔粘连，就是一幅实体像素画。常见规格：豆板 29×29 钉（大图多块拼接）、常规豆径 5mm、全色卡 60+ 色。图纸 = 一张网格表：每格一个色块 + 色号符号 + 用量清单，玩家照格铺豆。

Q3核心算法是什么？一句话说清。

调色板量化（palette quantization）：把任意照片压到"少量固定颜色 + 低分辨率网格"，使每个格子都能用一颗实体豆子复现。三个子问题：① 压到多少格（降采样）；② 每格用哪个豆色（最近色匹配）；③ 怎么输出成人能照着做的图纸（网格 + 色号 + 用量）。

这和图像处理经典问题"GIF 时代 256 色量化"同源，只不过目标色板是豆子的实体颜色，且格子数极少（几百到几千，而不是几万像素），所以用最朴素的"逐格平均 + 最近色"就够好看。

Q4完整算法管线（本指南实测版）

步骤操作本实验实现
1. 解码读图像素。JPEG/PNG 需库；为了零依赖，实验用 PowerShell 把照片转 24 位 BMP 再解析read_bmp24() 131 行内手写 BMP 头解析
2. 降采样把照片切成 W×H 个格，每格取平均色（盒式滤波）downsample() 区域均值
3. 量化每格平均色映射到调色板中距离最近的豆色（RGB 欧氏距离）nearest_bead() 24 色入门板
4. 出图网格图纸：色块 + 符号 + 图例 + 用量统计render_html() + CSV 用量表
为什么够快：几千格 × 24 色 = 十万级距离计算，纯 Python 毫秒级；照片 945×2048 端到端 <1 秒。

大图拼接87×93（原帖商品标注）8k+ 颗 / 多天接近写真，定制高价区

宽度选择经验：人脸想辨认，脸部区域至少 20 格宽。算法上高度按比例自动算（H = W × 照片高宽比），否则人会变形。

Q6颜色怎么选？为什么图纸和照片有色差？

实体豆色是离散且有限的（常见全色卡 60+ 色），照片颜色是连续的百万色——量化必然有损。最近色匹配在 RGB 空间用欧氏距离，有两个已知偏差：① RGB 空间不符合人眼感知（人对绿色敏感、对蓝色迟钝），同距离下蓝色误差更显眼；② 暗部容易一团黑、亮部容易一片白（调色板覆盖不到）。

实践对策：肤色/发色区人工换色（图纸生成后肉眼校对几格）、深色照片先提亮（gamma 校正）、颜色紧张时减少网格尺寸反而比硬凑颜色更保真。

Q7"接单赚钱"现实吗？

按证据算账（截图属实，市场判断为推测）：闲鱼在售价 ¥49–99/单 = 图纸文件本身；成本侧豆子+豆板+熨制材料约 ¥20–40、工时 1–数天（视尺寸）。图纸自动生成后边际成本近零，真正成本是熨制人工。竞争侧：该关键词已有多个在售商品，入场门槛只是"会生成图纸"——本指南的算法公开且无壁垒。

结论：作为练手项目 + 赚点材料费可行；作为稳定收入不现实（无壁垒、平台压价、手工作品产能封顶）。帖子"怎么赚钱不用教了"是 hype，按 [[证据优先质检ProofOverClaims]] 处理。

Q9这个项目给我什么（能力清单）

① 调色板量化：把连续颜色映射到离散色板，GIF 时代老手艺的新场景。
