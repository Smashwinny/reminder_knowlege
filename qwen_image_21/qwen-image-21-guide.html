Q1

Qwen-Image-2.1 是什么？一句话能说清吗？

阿里 Qwen 家族的统一图像模型：文生图和图像编辑共用一条管道，原生支持 RGBA 透明背景生成与"透明图层编辑"，最高可喂 10 张参考图做局部修改（画圈/涂鸦/蒙版指定修改区域），并保留了人物身份。

规格亮点：32 层单流 DiT；最高分辨率 2048×2048（1:1）、2752×1536（16:9）、1536×2752（9:16）；强项是排版文字渲染、人像打光、材质质感。官方示例用法是 QwenImage21Pipeline + BF16 + CUDA，显存紧张时开 enable_model_cpu_offload()。

Q2

为什么要云端部署？本地跑不行吗？

因为这套管道的真实体格（实测 31.76GB 权重）远超消费级显卡容量，而"7B"的宣传数字会让人严重低估预算。

环境可行性代价
本地 24GB（4090/3090）⚠️ 可跑但须 CPU offload出图慢（权重反复换入换出）
本地 48GB+（A6000/双卡）✅ 全量装载硬件数万元
云端按量（AutoDL 等）✅ 开机即用1.6~2.5 元/小时 + 生命周期管理
官方 API 调用✅ 零部署按张计费（本指南未核价）

云端部署的真实卖点不是"便宜"，而是把一次性资本开支（买卡）变成运营开支（租卡）；但运营开支有个陷阱——见 Q6 的计费机制。

Q3

"7B"到底指什么？全模型多大？（本指南实测）

通过 HuggingFace 官方 tree API 逐个分片查询（原始回执存 qwen_image_21\exercise\）：

组件分片实测大小推算参数量（BF16）
text_encoder4 个 safetensors17.54 GB≈8.7B（模型卡从不宣传）
transformer（视觉生成器）2 个 safetensors14.23 GB≈7.1B ✅ 与"7B"自洽
VAE1 个文件数百 MB 级—
权重合计≈31.8 GB全管道 ≈16B 参数
营销文常见误导：拿"7B"推算"显存 14GB 够了"。真相：模型卡的 7B 只是视觉组件；磁盘和显存预算都要按 32GB 权重计——这还没算激活值、缓存和输出。
Q4

显存到底要多少？24GB 能不能跑？

裸装必爆；CPU offload 能跑，但"31 秒出图"之类的数字别当真。

  • BF16 权重全量驻留显存 ≈ 63.5 GiB 量级（31.76GB 按 2 字节/参数换算 + 激活只会更多）；
  • 24GB 卡唯一出路是官方示例的 enable_model_cpu_offload()：当前活跃组件驻留 GPU、其余留内存，需要时换入换出——峰值显存可压到 24GB 内，但每次切换都花时间；
  • 原帖"32GB 保证不爆显存"：仅 offload 前提下成立；裸装 32GB 同样不够；
  • 想舒服全量装载：48GB（A6000/魔改 4090 类）或双卡环境。
这与知识库 [[KV缓存与上下文]] 的"显存账单"思维同构：权重是固定账，激活/离屏是浮动账——算预算两项都要列。
Q5

许可允许商用吗？

默认不允许。Qwen Research License 把标准授权限定于"非商业研究或评估"，商业用途需向阿里单独申请许可。

原帖"无需授权许可"的说法与官方 LICENSE 直接矛盾。HF 页面 license 标签也只标 "other"。

用途是否可用
个人学习、研究、评测✅ 标准授权覆盖
自媒体配图（有收益）⚠️ 灰色地带，建议按商用对待
商业产品/客户交付❌ 需单独商业许可
营销文最爱省去的恰恰是这段。部署前先想清楚用途——免费的是研究许可，不是商业许可。
Q6

云端计费怎么算？钱会从哪里漏走？

AutoDL 官方计费规则（文档直读）：

  • 按量实例从开机到关机持续计费，与你的 Python 是否在跑无关；
  • 默认 50GB 免费本地数据盘；付费扩容的磁盘关机后仍计费；
  • 无卡模式（仅 CPU）便宜，适合下载权重/装环境。

实测权重 31.76GB → 50GB 免费盘刚好够用但余量紧张（pip 缓存、模型缓存、输出图会吃空间）。

价格行情（2026-10 检索）：AutoDL 4090 约 1.61–2.50 元/小时，原帖"1.58 元/小时"是特定时刻个案。算账：每天玩 2 小时约 4 元；忘关机一天 = 约 48 元——费用大头是生命周期管理不是单价。

Q7

部署代码本身要注意什么？

  • 依赖版本：官方要求 torch>=2.4.0、transformers>=5.17、git 版 diffusers、accelerate——版本错配是云端部署第一大坑，装完先记 pip freeze；
  • Pipeline 类：官方示例用 QwenImage21Pipeline，原帖通用 DiffusionPipeline + torch.accelerator 临时替代类的写法未经验证，建议照官方走；
  • 镜像源：国内云主机 HF 下载慢，模型卡同时挂了 ModelScope 同名模型——国内优先 ModelScope；
  • 验收口径：首跑用普通物体或文字海报，记录依赖版本/显存峰值/输出通道（RGBA?)/生成时间/实际费用——五项留痕才能复现（[[证据优先质检ProofOverClaims]]）。

实验：不租 GPU 把部署账单算清楚（约 15 分钟，零花费）

步骤 1 ｜ 查型号与许可。 
curl -s https://huggingface.co/api/models/Qwen/Qwen-Image-2.1 | python -m json.tool | grep -i license
✅ 预期结果：license=other（Qwen Research License）；标准授权限非商业研究/评估。
步骤 2 ｜ 查分片体积。 
curl -s https://huggingface.co/api/models/Qwen/Qwen-Image-2.1/tree/main/text_encoder
curl -s https://huggingface.co/api/models/Qwen/Qwen-Image-2.1/tree/main/transformer
✅ 预期结果（本机实测）：text_encoder 17.54GB + transformer 14.23GB = 31.76GB。
步骤 3 ｜ 算显存账。BF16 权重全量驻留 ≈ 63.5 GiB 量级；24GB 卡必须 CPU offload；32GB 裸装不够。
✅ 预期结果：得出"7B≠全模型"的结论。
步骤 4 ｜ 算费用账。50GB 免费盘装 31.76GB 权重余量紧张；4090 时租行情 1.61–2.50 元；忘关机一天≈48 元。
✅ 预期结果：明确"生命周期管理 > 单价"。
实验结论：四笔账（版本/磁盘/显存/费用+许可）全部用官方 API 真实回执算清。原始数据存 qwen_image_21\exercise\。未租用实例/未下载权重（如实声明）。

一页总结

  • "7B"只是视觉组件：全管道实测 31.76GB 权重，磁盘显存都按 32GB 预算；
  • 24GB 能跑靠 offload：速度换空间，"保证不爆"都是有条件真；
  • 许可默认非商用：研究免费、商用需单独授权——营销文"无需许可"不可信；
