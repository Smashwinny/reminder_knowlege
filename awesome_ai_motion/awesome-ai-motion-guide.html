Q1

这个项目是什么？一句话能说清吗？

一个"AI 动效作品编目库"：把散落在 X 上的优秀 AI 生成动效/视频作品收集起来，逐条核对来源、提取提示词、标注使用的模型和验证状态，形成可检索、可分级的参考资料库。

注意三个"不是"：不是 1728 套可运行代码；不是 1728 篇教程；不是 转载授权库（来源链接 ≠ 授权，MIT 只覆盖仓库原创脚本）。它的价值是编目与分级方法本身。

Q2

为什么需要编目？直接收藏帖子不行吗？

AI 动效正处于"作品爆炸、经验失传"阶段：每天都有神作刷屏，但两周后没人记得它用的什么模型、提示词是什么、有没有水分。散装收藏的三个死穴：

  • 不可检索：收藏夹只有标题，无法按"模型/技法/时长/验证状态"过滤；
  • 不可信：截图可能是摆拍，"我用某模型做的"可能是蹭热度——没有核对记录；
  • 不可传承：作者删帖就没了；提示词藏在评论区，没人提取。

编目库把每条作品变成一条结构化记录（作者/来源/模型+证据引文/媒体/提示词状态/验证四字段），这就是知识库 [[原子笔记与双链]] 在"AI 作品"领域的落地。

Q3

它的编目体系是怎么设计的？（实测数据）

主数据 data/cases.json 共 1728 条（本机实测解析），每条 17 个字段，核心是四层验证：

验证字段含义实测命中率
videoAttachmentConfirmed原帖确实带视频附件1728 / 100%
authorClaimConfirmed作者"用什么模型做的"主张经原文核对1696 / 98.1%
independentlyReproduced编目者独立复现成功0 / 0%（诚实照写）
fullReview完整人工复核0 / 0%（诚实照写）

提示词三态状态机：original 244（原帖公开）/ brief 233（简介级）/ unknown 1251——"有简介"不等于"拿到原提示词"，三级分明。

阶段流水线：discovery（发现池）1635 → catalogued（已编目）61 →（未来 fullReview）。

这套四级验证正是知识库 [[证据状态机]] 的兄弟实现：它把"信源说"和"我复现"彻底分开，0 复现就标 0，不用"编目完成"冒充"验证完成"。

Q5

原帖说的"让 Codex 多轮学习/强化学习"是真的吗？

不是。文章给的步骤是"读案例→提炼规律→用参考上下文"——这是提示词工程与上下文学习，没有训练数据、没有训练运行、没有权重更新。

正确的理解方式：这个仓库是给 Agent 的"风格语料库"——把 AGENTS.md 指向它，Agent 创作前先检索同类作品的提示词与技法（接 [[RAG检索增强生成]] / [[第二大脑LLMWiki]] 模式）。声称"强化学习"是传播中的夸大。

Q7

作为动效学习资源，它怎么用价值最大？

  1. 按模型过滤：案例带 model 字段（最新一批 311 个全是 Claude Opus 5.5 案例）——想看某模型的能力边界，直接检索；
  2. 只信 original 级提示词：244 条可放心复用；brief/unknown 级当灵感不当配方；
  3. 把证据引文当教学：model 字段带 evidenceQuote（作者原话），学习"作者如何描述自己的做法"；
  4. 喂给自己的 Agent：AGENTS.md 指向 cases/ 目录，Agent 创作前检索参考（"先查库再动手"）。
Q8

边界与风险是什么？

  • 0 条独立复现：编目可信到"原帖确实存在这个作品"，但"作品真的由所称模型做出"只有作者主张+原文核对，没有技术复现；
  • 来源链接 ≠ 授权：引用要回原文看作者声明；MIT 只管仓库原创脚本；
  • README 数字滞后：以 data/cases.json 为准；
  • 偏动效/演示向：叙事长片、商业广告类案例占比小；
  • 更新极快：clone 要常拉新，否则你的"1728"很快又过时。
Q9

这类"awesome 编目"项目通用的学习价值在哪？

它的真正资产不是 1728 条记录，而是四条可复制的编目纪律：

  • 每条记录必有来源与核对时间戳（sourceReadAt）；
  • 作者主张与独立验证分字段存放，永不混装；
  • 提示词分三态（原文/简介/未知），不拿简介冒充原文；
  • 承认 0 复现——可信度声明写在数据里而不是宣传里。

给自己的任何"收藏夹/知识库"项目立这四条规矩，可信度立刻超过 90% 的同类仓库。
