03 一个 MCP 代理如何减少目录体积？

把完整工具 schema 从常驻上下文移到按需发现，模型先搜索再取得具体工具定义。本实验造 100 条工具目录与一个小代理 JSON 比字节；这不是 tokenizer 测量，更不等于真实任务总 token 节省比例。

对照本项来源清单、相关查重笔记与实验日志；合成例不是原作者实测。

05 / 从概念走到边界

07 上下文压缩是不是 ZIP 无损压缩？

通常不是。摘要删改信息，可能丢禁止事项、当前目标和未决问题；累积处理十亿 token 不等于单次窗口十亿 token。官方 Pi 文档的 summary 要含 Goal、Constraints、Progress、Decisions、Next Steps，近期消息另保留。

对照本项来源清单、相关查重笔记与实验日志；合成例不是原作者实测。

08 压缩与缓存有什么不同？

压缩减少后续上下文；缓存复用连续相同前缀的计算。摘要替换旧历史会改变前缀，从变化位置之后通常需重算，未变系统/工具部分仍可能复用。当前官方触发与恢复时序比旧译文更复杂，应固定版本说明。

对照本项来源清单、相关查重笔记与实验日志；合成例不是原作者实测。

09 结构化追问怎样才有用？

问题应短、选项互斥或明确多选，允许“其他”补充，展示默认的风险；不能用问题卡伪造用户批准。原项目至少两选项。本次只验证 JSON 结构，不实际弹 UI，不替用户回答。

对照本项来源清单、相关查重笔记与实验日志；合成例不是原作者实测。
