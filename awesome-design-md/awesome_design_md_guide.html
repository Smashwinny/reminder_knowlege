Q1它是什么？"一键复刻大厂 UI"复刻的到底是什么？

抖音热梗说的"让你一键复刻大厂 UI 的开源项目"，就是这个 VoltAgent/awesome-design-md。它复刻的不是某个网站的代码，而是大厂网站的 "设计基因"——设计系统（Design System）。

一句话定义：把知名网站（Vercel、Notion、Linear、Stripe…共 73 个）的视觉规则——颜色、字体、间距、圆角、按钮长什么样——提炼成一份人话写的 Markdown 文档（DESIGN.md），你拷进自己的项目，AI 编程工具读了它，生成的 UI 就自动"长得很像那家大厂"。

📐 DESIGN.md 这个标准从哪来？

这是 Google Stitch（Google 的 AI UI 设计工具）提出的概念：AGENTS.md 告诉 AI"项目怎么建"，DESIGN.md 告诉 AI"项目该长什么样"。它就是纯文本 Markdown，不需要 Figma 导出、不需要 JSON 工具链——因为 Markdown 恰恰是 LLM 读得最好的格式。本仓库把这个理念做成了"现成大餐"：替你分析好 73 家网站，每家写成一份 DESIGN.md。

文件谁读它定义什么类比
AGENTS.md编程 Agent项目怎么构建、代码规范施工图纸
DESIGN.md设计 Agent / AI 编程工具界面长什么样、什么气质装修样板间的说明书

Q2没有它之前，人们怎么让 AI 做"好看的 UI"？

😭 旧方法三宗罪

① 截图让 AI 猜：贴一张 Vercel 官网截图说"照这个做"。AI 看图只能猜个大概，颜色取不准（截图压缩失真）、字号间距全是目测。
② Figma 导出 + 设计令牌工具链：专业但重——要会 Figma、要配 Style Dictionary 之类工具把 token 转成 CSS，个人开发者玩不动。
③ 每次口头描述："简约风、深色、有质感"——每句话 AI 理解都不同，十个页面生成十种风格。核心病根：审美规范没有一份确定的、AI 可读的"合同"。

DESIGN.md 的解法：把"合同"写成文本。颜色精确到 #5e6ad2，字号精确到 56px / 字重600 / 字距-1.8px，连"薰衣草紫只许用在 CTA 不许当装饰"这种纪律都写得明明白白。从"AI 猜审美"变成"AI 照合同施工"。

Q3核心原理：一份 Markdown 怎么管住 AI？

秘密是"结构化 token（机器读）+ 散文规则（AI 读）"双层结构。每份 DESIGN.md = YAML frontmatter（给程序解析的色值/字号表）+ Markdown 正文（给 AI 理解的设计原则和组件规范）。

🔑 为什么偏偏是 Markdown？

LLM 的母语就是文本。JSON 要转义、Figma 要插件，而 Markdown 零解析成本、diff 友好、人机共读——你改一行色值，AI 下次生成立刻跟着变。这是"把设计系统民主化"：过去只有大厂设计团队维护得起 design token，现在拷贝一个文件就拥有 Vercel 级规范。

Q5解剖一份规范：Linear 是怎么写的

拿 design-md/linear.app/DESIGN.md（548 行）开刀。它的自我介绍：近黑画布 #010102（全收藏最深）、浅灰文字、薰衣草紫 #5e6ad2 是唯一的彩色强调——只许出现在品牌标、焦点环和关键 CTA，绝不许当装饰。

色板（frontmatter 精确值）
primary#5e6ad2 hover#828fff canvas#010102 panel#0f1011 ink#f7f8f8 ok#27a644
字号阶梯（共 14 级）
层级规格
display-xl80px / 600 / 字距-3px
display-lg56px / 600 / 字距-1.8px
headline28px / 600 / 字距-0.6px
body16px / 400 / 行高1.5
button14px / 510 / 内边距 8×14px

📋 组件规范长这样（节选原文翻译）

button-primary：底色 {colors.primary} + 白字，按钮字 {typography.button}，内边距 8px×14px，圆角 {rounded.md}；悬停变亮紫、按下变深紫。
button-secondary：炭色面板底 + 细线边框，用于"Sign in"这类次要动作。
看点：每条规范都引用 token 名而不是裸值——改一处 token，全站按钮跟着变。这正是大厂 design token 思想的"穷人版平替"。

Q6动手实验：同一份文案，两套规范，气质立变（实测）

实验材料在 awesome-design-md\exercise\，全部命令 Windows 11 实跑。

1
操作：python -X utf8 exp1_parse_tokens.py　目的：验证"纯文本规范=机器可读"的声称。
实现：正则解析全部 frontmatter。✅ 预期结果：64/74 (86%) 解析成功，1491 个色值 token，平均 14.2 个字号层级；10 份老格式无 frontmatter 被点名。
2
操作：通读 repo\design-md\linear.app\DESIGN.md 与 notion\DESIGN.md，摘出色板/字号/按钮/圆角规范。
✅ 预期结果：Linear=近黑+单强调色；Notion=白底+深蓝主视觉带+紫 pill CTA+粉彩卡。
3
操作：手写 page_linear.html——每个 CSS 值都取自 Linear 规范（canvas #010102、panel #0f1011、主按钮 8×14 圆角6、负字距大标题）。
✅ 预期结果：页面一打开就是"Linear 味"：克制、精密、暗黑。
4
操作：同一产品文案写 page_notion.html——严格换用 Notion 规范（深蓝 #0a1530 主视觉带、便签圆点、#5645d4 胶囊按钮、粉彩特性卡）。
✅ 预期结果：同一段话，气质完全不同——证明"规范决定气质"。
5
操作：msedge --headless --screenshot=shot_linear.png file:///…page_linear.html（notion 同理）实拍取证。
✅ 预期结果：两张 PNG 如下，肉眼对比立见分晓。
▲ 按 Linear 规范：近黑画布，唯一紫色强调
▲ 按 Notion 规范：深蓝主视觉带 + 粉彩卡
✅ 实验结论：同一文案、同一布局骨架，只换一份 DESIGN.md，产物气质天差地别——"设计规范是一份可执行、可拷贝、可交接的资产"坐实。

Q7能力清单：我能用它干什么？

🎁 5 个立刻能上手的用途

① 给 AI 编程工具"装审美"：把想要的 DESIGN.md 拷到项目根目录，对 Cursor/Claude Code 说"按这个规范做登录页"，从此生成的页面不再杂风格。
② 快速仿站练手：想学 Vercel 的极简风？照着 frontmatter 的精确值手写一页（就像本指南实验），比看截图猜快 10 倍。
③ 产品原型瞬间"变大牌"：个人项目套 Stripe/Linear 规范，演示可信度暴涨。
④ 学设计系统的免费教材：74 份规范=74 份大厂设计课，看它们如何定义色阶、字阶、组件纪律。
⑤ 做自己的 DESIGN.md：拿一份当模板，改成自己的品牌规范，让 AI 稳定复现你的风格。

Q8坑与边界 + 和已学概念的关系

⚠️ 四个坑
① 字体拿不来：规范里的 "Linear Display"、"Airbnb Cereal" 是商业字体，本地没有就会回退到 Inter/系统字体——复刻的是"规则"不是"字体文件"。
② 86% vs 14%：10 份老格式（tesla/spotify 等）没有结构化 frontmatter，脚本解析不了，AI 也只能读散文，精度打折。
③ 复刻≠替代原创：套大厂规范做商业产品可能有品牌调性雷同甚至商标观感问题，练手学习最合适。
④ 越界检查：规范管"长什么样"，不管"对不对"——生成后仍要人工验收（呼应 [[证据优先质检ProofOverClaims]]）。

🔗 知识库关联

• [[规格书先行SpecDriven]]：DESIGN.md 就是"审美版规格书"——把主观审美翻译成客观可查的数值合同，同一思想在 UI 领域的落地。
• [[提示词权威边界]]：规范 = 给 AI 的"设计宪法"，禁止即改：防止 AI 生成过程中的风格漂移。
