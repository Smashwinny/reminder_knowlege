🎯
它是什么？
workout-guide 是一个"动作插画素材库 + 查询工具包"：302 个健身动作，每个动作 3 帧（起-中-止）统一风格的 SVG 线稿插画，打包成框架无关的 TypeScript npm 包，再配一个可搜索的在线画廊。做健身 App 最贵的不是代码，是几百张风格统一的动作图——这个项目把这块成本直接归零。
Q1
为什么需要它？没有它之前人们怎么做？
健身 App（Keep、 workout-cool、Hevy 这类）每个训练动作都要配图。自己做的三条老路：
老路代价
请插画师画 300+ 张动作图数千到上万元，周期以月计，风格难统一
扒 Everkinetic 等老数据集的 PNG风格陈旧不统一、无结构化元数据、License 模糊
用照片/视频版权风险大、体积大、深浅主题难适配
workout-guide 的答案：开源 + 统一矢量风格 + 结构化元数据 + 明确双许可，一次解决四个痛点。
Q2
302 个动作哪来的？和 Everkinetic 什么关系？
作者 Bryl Lim 在Everkinetic（一个老牌开源动作数据集，CC BY-SA 4.0）基础上二次创作：把老图重绘成统一风格线稿、补画大量新动作、补齐中间帧。实测 manifest：906 帧中 76 帧带 Everkinetic 上游溯源标注（记录来源 URL + 改动说明），其余为作者新绘。这是开源二创的教科书操作：逐帧写清"从哪来、改了什么"，CC BY-SA 的署名-相同方式共享义务落到了每个文件。
图2-1 二创链：继承 CC BY-SA 4.0，逐帧 attribution 记来源与改动

Q4
manifest.json 数据结构长什么样？
一个 302 元素的数组，每条动作记录：
{ "id": "exercise-bench-press", "slug": "bench-press", "name": "Bench Press", "exerciseType": "weight_reps", // 5 种：weight_reps/bodyweight_reps/duration/distance_duration/assisted_bodyweight "equipment": "Barbell", // 17 种器械 "primaryMuscle": "Chest", // 20 个主肌群；secondaryMuscles 还有协同肌 "isStretch": false, "frames": [ { "index": 1, "path": "assets/bench-press/frame-1.svg", "width": 512, "height": 512, "attribution": { creator, license: "CC BY-SA 4.0", source: { name:"Everkinetic", url, changes:"Rasterized…vector-traced" } } }, …共3帧 ] }
实测分布：器械 Bodyweight 111 / Dumbbell 45 / Machine 35 / Barbell 29；肌群 Core 45 / Glutes 38 / Quads 35 / Chest 26。每帧自带宽高和出处——数据即合同，App 端不用猜。
Q5
为什么每动作只有 3 帧？3 帧够吗？
动作示范的目的是看清轨迹，不是以假乱真。起势→中程→止点 3 帧恰好覆盖：起点教摆位、中程教轨迹、止点教收缩。对比方案：视频几十 MB、GIF 数 MB、3 帧 SVG 总共约 7KB/动作。循环播放时 1→2→3→2→1 的"钟摆式"循环就自然连贯（本指南实验 4 的图鉴就是这么做的，CSS 十几行搞定）。
图5-1 三帧法：最小帧数覆盖完整动作语义
Q6
双许可（MIT + CC BY-SA 4.0）怎么理解？商用要注意什么？
一个仓库两套许可，按"内容类型"划界：
部分许可你能干什么义务
代码 / 文档（src、scripts、site）MIT随便用、改、闭源商用保留版权声明
插画资产（assets/ 全部 906 帧）CC BY-SA 4.0免费商用署名（标注 Bryl Lim / workout-guide）+ 相同方式共享（你若修改分发这些图，修改版也得 CC BY-SA 4.0）
⚠️ 实操要点：App 里用原版图 = 署名即可（放"关于"页）；改了图再分发，改的部分也必须开源同许可。npm 包的 license 字段特意写成 "SEE LICENSE IN LICENSES.md" 逼使用户看两份许可。溯源链上游 Everkinetic 也是 CC BY-SA 4.0，许可兼容不冲突。
Q7
图片怎么到用户手机上？CDN 分发链路是什么？
getAssetUrl('push-up', 1) 默认返回：
https://cdn.jsdelivr.net/npm/@bryllim/workout-guide@1.0.0/assets/push-up/frame-1.png
npm 包本身就是"CDN 源"：jsDelivr 自动镜像 npm 上的任何包并提供全球边缘缓存——不花一分钱基础设施，App 换 URL 版本号即灰度升级（@1.0.0→@latest）。也可以 {baseUrl:'https://myapp.com/assets/'} 指向自托管。三个真实坑（实验全部踩到）：
坑1：发布版 manifest 帧路径是 .png 不是 .svg——仓库里 svg+png 双份（svg 2.3MB 是矢量源，png 兼容兜底），npm 包只发 manifest 引用的 PNG； 坑2：{baseUrl} 会拼出 assets/assets/ 双前缀——frame.path 自带 assets/ 前缀，baseUrl 应指向包根而不是 assets 目录； 坑3：SVG 是白色线稿+透明底，放在白色背景上直接"隐身"——官方画廊是深色主题，自建 UI 必须给深色容器（或改 fill）。
Q8
"框架无关的 npm 包"是怎么做到的？
三招：① 预构建 dist（发布时带好 index.js ESM + index.cjs CJS + index.d.ts 类型，装了就能用，不需要用户配构建器）；② package.json exports 双入口（. 主入口、./manifest.json、./assets/* 直取原始资产）；③ 零运行时依赖——不绑 React/Vue，输出纯数据对象。React 直接 getAssetUrl 放 <img src>，React Native 用 require() 静态图，Vue/原生 JS 同理。实测 npm install 后 Node ESM 直接 import 成功（实验 3）。
图8-1 一包多端：预构建 + exports + 零依赖 = 框架无关
Q9
搜索为什么大小写、重音、符号都打不倒它？
秘密在 normalizeSearchText 的归一化管道，实测 "Café & Lunge!" → "cafe and lunge"：
toLowerCase() // 大小写统一 .normalize('NFD') + 去组合重音符 // café → cafe（把 é 拆成 e + ́ 再删掉） .replace(/&/g,' and ') // 符号转词：& 就是 and .replace(/[^a-z0-9]+/g,' ') // 其余符号→空格 .trim() + 空格折叠 // 多空格合一
查询和被查字段走同一个归一化函数再比较——"规范化后比相等/包含"，比上搜索引擎轻一个数量级，302 条本地内存过滤瞬间完成。多词查询用"每个 token 都须命中"（AND 语义）。
Q10
906 张图 + manifest 怎么保证不出现坏数据？
仓库 scripts/ 里有 validate-catalog.mjs 校验脚本 + npm run check 总门，理念就是知识库里学过的质检 Gate 与自我纠错循环：目录导入→校验→过门才能合并。我照着这个思路自己写了零依赖质检脚本（实验 1），7 项检查全过：
✅ 302 动作 = manifest 记录数；✅ 906 帧记录 = 906 个磁盘 SVG（账实相符）；✅ 每帧 512×512；✅ 文件头含 <svg>；✅ 每帧 attribution 带 CC BY-SA 4.0；✅ 每动作恰好 3 帧；✅ slug 无重复。→ 质检 0 异常
数据集项目的可信度不靠宣传靠对账：声明数、文件数、字段值三方一致才算数。
Q11
它和同类项目什么关系？什么时候选它？
项目形态选它的场景
workout-guide插画库 + 查询包（302 动作）要风格统一的活动插画、要自建 UI、要轻量
yuhonas/free-exercise-db纯 JSON 数据集（800+ 动作）+ 英文说明要文字说明/属性，图不讲究
GitHub topic: workout 数据集1300+ 动作 GIF 数据要海量但接受 GIF 体积与风格混杂
Snouzy/workout-cool完整健身平台（产品）要现成 App 而非素材
一句话：要"图"选 workout-guide，要"字"选 free-exercise-db，要"现成产品"选 workout-cool。
Q12
我怎么用它做一个健身 App 的最小动作页？
四步（全部真实跑通，见下一节）：npm 装包 → searchExercises 按肌群/器械筛动作 → getAssetUrl 拿图（或本地 assets）→ 三帧 CSS 动画轮播。实验 4 产出的 exercise_gallery.html 就是零框架的最小完整示例：302 卡片 + 筛选 + 悬停播放，共 139KB。
