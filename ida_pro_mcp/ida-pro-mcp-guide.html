Q2

IDA、IDAPython、IDA Domain、MCP、Nexus 各管什么？

它们不是五个同义名词，而是“分析引擎 → 查询语言 → 共享数据库 → AI 协议”的不同层。

层职责一个具体动作
IDA Pro / idalib / idat加载二进制、自动分析、维护 IDB，提供反汇编/反编译基础。识别 main 的范围和指令。
IDAPython SDKIDA 自带 Python 接口，底层、覆盖广。idautils.Functions()。
IDA Domain位于 SDK 之上的领域化 Python API，让函数、指令、xrefs 成为一等对象。db.functions.get_all()。
IDA Nexus进程发现、数据库共享、worker、租约和 Python 执行。给当前客户端一个数据库句柄。
IDA MCP把 Nexus 能力包装成模型可调用的 MCP 工具，并记录语义追踪。tools/call execute_python。
MCP 不替代 IDA；它把模型请求适配到已有分析能力。
Q3

为什么官方只有六个 MCP 工具？

官方选择“窄协议入口 + 通用 Python 查询”，不是给每个逆向动作都造一个按钮。

工具作用只读标注 / 风险提示
open_database打开可执行文件或现有 IDB，选择当前目标。未标只读；可能创建 worker 与数据库。
execute_python在当前数据库运行 IDAPython / Domain 查询或修改。未标只读；可重命名、写注释、改类型、patch bytes。
reference查询 Domain API 名称、签名与示例。readOnlyHint=true。
list_databases列出 GUI / headless 数据库实例。readOnlyHint=true。
save_database把重命名、注释、类型和补丁持久化。未标只读；写磁盘。
close_database释放当前 MCP 会话的句柄与租约。未标只读；影响 worker 生命周期，不直接关闭 GUI。

典型顺序是 open_database → reference → execute_python → close_database。execute_python 的文档明确要求先查 reference，不要猜 API 形状。函数枚举、反编译、xrefs 等能力都在 Python 查询层，而不是独立 MCP 工具名。

六工具是当前提交中的真实协议面，不套用社区项目的工具清单。
Q4

一次分析请求怎样到达 IDB？

模型只发出 JSON-RPC 请求；真正查询发生在持有数据库租约的 worker 或 GUI 中。

  1. 宿主通过 stdio 或 Streamable HTTP 连接 IDA MCP。
  2. open_database 让 Nexus 附加 GUI 数据库，或启动 idalib/idat worker。
  3. execute_python 先解析一次目标实例，等待初始自动分析，再执行查询；变量可在这个客户端租约的命名空间里持续存在。
  4. 工具调用与结果用 call_id 配对写入 schema-1 JSONL 语义追踪；dashboard 和 logs 可继续检查。
  5. 取消时，MCP 发送请求拥有的 Nexus 取消操作；已经可能产生修改的失败请求不会被盲目重试。
协议传输、数据库生命周期、查询执行、语义追踪是四件不同的事。
Q5

怎样查询函数与反汇编？

先拿到函数对象，再读 start_ea、名称、反汇编或伪代码；不要把地址与函数对象混为一谈。

官方迁移指南给出的核心对应关系：

传统 IDAPythonIDA Domain意义
idautils.Functions()db.functions.get_all()枚举函数对象
idaapi.get_func(ea)db.functions.get_at(ea)按地址定位函数
idaapi.get_func_name(ea)db.functions.get_name(f)读名称
idc.GetDisasm(ea)db.instructions.get_disassembly(insn)读一条反汇编
def run(db):
    for func in db.functions.get_all():
        name = db.functions.get_name(func)
        if name == "authorize":
            print(hex(func.start_ea))
            for line in db.functions.get_disassembly(func):
                print(line)
            # 实机有 Hex-Rays 时还可读取：
            # pseudocode = db.functions.get_pseudocode(func)
Domain API 常返回 None 而不是旧的哨兵值；字节、名称、上一个 head 等查询都要先处理空结果。它仍保留部分 SDK 类型，并不等于完全替代 IDAPython。
本实验只实现只读子集；伪代码示例来自官方文档，未在本机反编译。
Q6

调用关系和 xrefs 怎样变成图？

xref 是“从哪个地址引用到哪个地址”的记录；把直接 call 边连起来，才得到调用图的一部分。

对本实验每个目标函数 f，查询 db.xrefs.calls_to_ea(f.start_ea)。每条 xref 的 from_ea 是 call 指令地址，再用 db.functions.get_at(from_ea) 找到调用者。这样比只看函数名多了一层可复核定位。

for xref in db.xrefs.calls_to_ea(target.start_ea):
    caller = db.functions.get_at(xref.from_ea)
    insn = db.instructions.get_at(xref.from_ea)
    print(caller, hex(xref.from_ea),
          db.instructions.get_disassembly(insn))

实测图：main → authorize → check → mix，同时 authorize → mix。它是直接静态调用边集合，不说明每个边在每次运行都会执行，也不证明参数数据流。

4 条直接静态调用边，全部来自自编译二进制的 Objdump 文本。
Q7

怎样让结论可回溯，而不是“听起来很专业”？

一条合格结论至少要带：输入哈希、适用范围、调用边、call 地址、原始指令。

本次查询脚本不是只打印“AI 认为 authorize 很重要”，而是输出结构化 conclusion.evidence。如果四条必要边缺一条，supported 就为 false，实验直接失败。

authorize->check @ 0x401499: call 401471 <_check> authorize->mix @ 0x4014b2: call 401460 <_mix> check->mix @ 0x40147d: call 401460 <_mix> main->authorize @ 0x4014ef: call 40148d <_authorize>

本次自编译文件 SHA-256 为 b1b330389e3c5b2c9d744167f1f0887797893d8dd66f4aed4fe8da38ac193560。重编译可能因 PE 时间戳改变哈希，所以重跑时以新日志为准，不能拿旧哈希套新文件。

证据优先不是否定 AI，而是让 AI 的每句话有回到二进制的路。
Q8

GUI、headless 与租约怎样共存？

close 的本义是“释放我这一份租约”，不是“把别人正在用的 IDA 关掉”。

GUI 插件让 Nexus 发现已经打开的数据库。没有 GUI 插件时仍可 headless：worker 使用 MCP 服务端 Python 的 idalib；装上插件后，headless worker 可进入 idat 与 IDA 自己的 Python 环境，并可按明确请求使用 GUI。

每个 MCP 进程持有独立租约。关闭一个句柄不会关闭 GUI 或其他客户端的租约；最后一份 managed-worker 租约消失时，Nexus 才负责保存和关闭 worker。save_database 是显式保存，close_database 返回 final_lease 与 idb_path。

租约是共享分析的边界；本次本地桩只模拟返回形状，未验证 Nexus 实机。
Q9

安装、安全和版本有哪些硬门槛？

“MCP 源码 MIT”不等于“IDA 免费”，也不等于“可以把任意样本交给模型”。

  • 官方要求：IDA 9.4+、idalib、Python 3.11+；Git 与 uv 在 PATH。插件清单同样声明 idaVersions >=9.4。
  • 安装入口：官方 README 推荐 uvx ida-hcli mcp install 或 hcli；GUI 插件与多个 Agent 宿主插件另有安装方式。
  • 传输：本机优先 stdio。源码对非 loopback HTTP 明确警告：没有内建认证时，execute_python 可能暴露给网络。
  • 权限：execute_python 可修改 IDB、patch bytes；提示词说“只读”不会改变工具能力。使用自己的小程序、最小权限和审计日志。
  • 版本差：社区 mrexodia 项目当前要求与工具面不同，不能照搬其安装前提、工具名或会话语义到官方项目。
本机常见安装路径未发现 IDA，uv 也不在 PATH。因此没有执行官方安装命令、没有启动官方 MCP/Nexus、没有加载外部二进制。以下文档命令只作未来实机参考，未在本次验证：
uvx ida-hcli mcp install
本次学习只跨越“自编译输入 + 本地桩 + 静态证据”的安全范围。

主实验：从自编译程序到 4 条地址证据

步骤 1：进入独立项目目录

操作：

cd F:\reminder\ida_pro_mcp

目的：把自建源码、反汇编、日志与上游 repo 隔离。实现：后续只在 exercise 写实验产物。

预期结果：当前目录存在 exercise/demo.c、查询脚本和本地桩。

步骤 2：一键编译、运行、反汇编并完成 MCP 查询

操作：

python -I exercise/run_experiment.py

目的：用 GCC 编译 demo.c，只运行这个自编译程序；再用 Objdump 生成真实汇编，启动限制输入的本地 MCP stdio 教学桩。

实现：脚本依次完成 initialize、tools/list、list/open/reference/execute/close；查询脚本收集函数、xrefs 与证据，缺任一边立即断言失败。

预期结果：出现 input=7 decision=1 token=66、input=27 decision=0 token=0、4 条 EVIDENCE 和最终 PASS。Objdump 原文写入 exercise/disassembly.txt。

步骤 3：独立回读结果和协议追踪

操作：

python -I -c "import json; d=json.load(open('exercise/analysis_result.json', encoding='utf-8')); r=[json.loads(x) for x in open('exercise/mcp_trace.jsonl', encoding='utf-8')]; print('supported=', d['conclusion']['supported'], 'evidence=', len(d['conclusion']['evidence']), 'calls=', sum(x['event']=='tool_call' for x in r), 'results=', sum(x['event']=='tool_result' for x in r))"

目的：不依赖终端印象，重新读取 JSON 与 JSONL。实现：核对结论状态、证据数和工具调用配对。

预期结果：supported= True evidence= 4 calls= 5 results= 5。
完整限制：本地桩只接受固定二进制、Objdump 文本与固定查询脚本哈希；它不是通用安全沙箱，也不是官方服务器。实验没有运行未知二进制，没有针对第三方目标，没有验证 IDA/idalib、Hex-Rays 反编译、自动分析、Nexus 租约或原帖所称“又快又准”。
