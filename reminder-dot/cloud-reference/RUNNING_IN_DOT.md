## 分类、领取与第 0–7 步

- 初步阶段每轮最多五条，用网站既有 claim/renew/release，保存来源、具体判断、已有知识关联、下一步。learning / non_learning / duplicate / needs_review / blocked / non_link 分别记录。无法读正文、已有知识或缺环境不等于非学习。
- 只处理获准列表中来源已核实且可领取的 learning，以当前 sourceHash / reportId 绑定 full 领取。保留唯一 owner、续约和同任务/链接/项目串行规则。过期 owner 不抢占；本轮不增加并行度或另建学习队列。
- 云端使用独立工作目录，沿用现有项目英文目录名，上游源码在 repo，自建实验在 exercise。目录不是 Windows 文件夹映射。
- 第 1 步先读取实际 Git main 的 `vault/00-总览.md` 和相关概念/项目笔记，记录基线 commit 与实际查重范围。尚未推送的 Windows 手改笔记不在云端范围，回迁保留冲突，不声称已读。
- 摸底项目，列 10–15 个由浅到深的疑问，图文、例子或故事解答，列能力与 3–6 个用途；保留关键来源、版本和边界。
- 真正运行 3–7 步主实验，逐步记录命令、目的、结果及验证方法；保留真实日志、练习材料和未验收范围。未运行的结果不能填已执行。
- 生成鲜艳彩色 HTML/A4 PDF并逐页视觉检查。Windows 的 Edge/PowerShell 用实际云端等价工具替代并留证据；HTML未加载、PDF未检查或原生集成未运行都必须明确，不能当作通过。

## 第 8 步：直接合并 GitHub 的 Obsidian vault

1. Dot 协调者从当前 main 读取相关知识文件；相同概念合并并保留别名，相关概念建立 `[[链接]]`，保留原文和其他项目增补。
2. 写概念笔记、`vault/项目笔记/<项目名>.md` 并更新 `vault/00-总览.md`。项目笔记包含能力、实际实验、坑、适用边界及已有概念联系；只有 knowledge_notes 提案不算入库。
3. 学习 worker 只交所属项目和入库提案；唯一 Dot 协调者写共享 vault/Git。已有 full 的积压仅补第 8/9 步，不重跑学习，不重领 full，不覆写不可变报告；先核对来源、原件指纹和原 owner 交接。

## 独立验收与第 9 步：直接 GitHub 提交/推送

- 真实独立审核者查看全部 PDF 页、实验实证、来源、最终知识合并和隐私；记录实际执行者及意见，不以改名自审或若干布尔值代替独立审核。
- 只发布该项目的已审核学习成果和相关 vault 文件。排除原记录/分类、账号/列表/任务/报告ID、私有回执、运行库、凭据、repo、依赖和缓存。公开学习文件亦须检查是否夹带私密原文。
- GitHub 对象接口可按明确字节清单创建 blob（PDF/ZIP使用 base64）、tree、commit 后非强制更新 ref；或使用已授权的等价 git。所有提交绑定刚读取的 main 基线，禁止强推、全仓 add、跳过 hooks、自动 rebase/reset 共享工作区。
- 基线变化则重读相关知识并重新合并/审核，保留候选 commit，不能覆盖远端新成果。请求超时先回读现有 commit/ref，再决定重试，防止重复计数。
- 提交后回读实际 main 的 commit、文件清单与字节指纹；确认包含 PDF/HTML/练习、真实日志、项目笔记和 MOC 后才记 Git 已推送。记录确切 commit URL、文件及哈希，不把 API 接受请求当作完成。

## 单项上传受阻后的持续规则（2026-10-06）

- 用户确认的后续同类处理方式：停止被拒动作，保留该项成果和 Git 待发布；将被拒上传的文件完整内容通过本人已连接、已确认归属的邮件账户私发本人既有通知邮箱，供本人手动阅读和备份，然后串行继续下一条已授权且可独立执行的任务。不得以一条受阻暂停整批，不扩大票据或增加 worker。
- 附件优先原文件或含完整文件的 ZIP，列明文件名、大小、SHA256、拒绝原因和真实阶段状态。摘要、截图、临时链接不能代替文件备份，不附凭据或无关私密原记录。既有邮件工具不支持附件时可以发送完整文本正文，但准确标记附件受阻和文件备份限制，不接入未经授权的新邮件服务。
- 按项目、被拒动作、文件版本哈希及拒绝原因去重，保留真实邮件发送回执；已成功发送的同版本不重复发。既有用途和收件范围不变沿用本人授权；确有外部平台本人确认要求或邮件失败时保留待邮件备份，并继续后续独立任务。
- 邮件发送不等于 Git 发布、用户已阅读或 Windows 已备份；本人手动阅读备份不授予新的公开上传权限。后续仍正常接受各项审批，不重试被拒动作或换工具绕过。
- 恢复受阻项目时重新读取实际 main、当前来源及原件指纹，查重合并并重新审核受影响的最终文件，禁止使用旧 vault 候选覆盖后续更新。保持唯一协调者串行、旧 owner 保护、真实学习/审核门槛和本人任务勾选。
