Q1

这四个资源分别管什么？

资源角色一句话
getdesign.md视觉规范参考设计参考站，给 AI 立审美标杆
libraries.dev局部组件复制 prompt 接入现成组件（主要面向 React）
impeccable审查修改1 skill/24 命令/62 条确定性规则，专抓"AI 味"
OpenDesign持续设计工作流设计工作空间，接你自己的 agent 长期迭代

组合拳的逻辑：规范定方向（getdesign.md）→ 组件提效率（libraries.dev）→ 审查保底线（impeccable）→ 工作流管长期（OpenDesign）。四者解决的是不同环节的问题，缺了审查环节，前两个只会让"丑得更快"。

Q2

为什么 AI 生成的 UI"一眼假"？

每个模型都被同一批 SaaS 模板喂过，跳过规范引导就输出同一套"AI 味"：万物皆 Inter、紫到蓝渐变、卡片套卡片、彩底灰字、标题上方一个圆角图标砖。impeccable 的 README 把这些 tells 列为靶子，并用 62 条确定性规则（不需要 LLM、不需要 API key）逐个抓。

Q3

impeccable 的 62 条规则是真的吗？（源码核实）

克隆仓库（@ d34c87e，4422 文件）静态阅读：

  • 规则引擎 crates/core/src/checks/rules.rs（2969 行），规则 ID 真实可查：ai-color-palette（紫色相 260-310° 判定/Tailwind from-purple 模式）、low-contrast、gradient-text、gray-on-color、side-tab 等；
  • PRODUCT.md 带 schema 版本注释，实测含 Platform/Users/Purpose/Positioning；
  • 引擎是 Rust workspace（core 规则 + wasm 浏览器扩展），二进制不随仓库分发。
本班边界：构建外部 Rust 引擎被权限层合理拒绝，故未跑官方二进制；以下实验用自写迷你检测器复刻概念。

写一个故意堆满 AI 味的示例页（Inter/紫蓝渐变/#999 灰字/嵌套卡片/图标砖），自写检测器实测输出：

检测完成：6 条 AI 味命中
 - Inter 万能字体 / 紫蓝紫渐变 / 灰色辅助文字 #999
 - 卡片套卡片 / 圆角图标砖+渐变底

低对比度用 WCAG 亮度公式实算 2.85:1——"灰字看不清"从审美吐槽变成可机检数字。这正是 [[设计令牌DesignToken]]"主观审美变可校验数字"的路线。

Q5

PRODUCT.md 和 DESIGN.md 为什么要分开？

产品事实（给谁用/解决什么/红线）是稳定层，视觉方向（这轮用什么风格）是易变层；混在一个文件里，改配色就会污染定位。impeccable 的 init 流程先落 PRODUCT.md（访谈式收集 durable truth），DESIGN.md 按 surface 再生成。这与知识库 [[DESIGN.md规范文档]]+[[事实与判断分离]] 完全同构——该仓库自己就带着 schema 版本注释（product-schema 1）和过期字段告警机制。

Q7

四个资源要一起装吗？

不要。分类阶段建议即本指南立场：先限定一个页面一个框架，保留相同文案与交互目标，逐个引入资源比较变化（响应式/对比度/操作反馈），再决定主工具。四个同时装只会把变量搞乱——对照实验纪律 [[规格书先行SpecDriven]]。

Q8

边界与风险

  • 库代码免费 ≠ 模型调用/服务目录免费；
  • 命令和规则随版本变化（本指南核对的命令集以 @d34c87e 为准）；
  • 审美结论是作者经验；62 条规则抓"AI 味"不抓"丑得有个性"；
  • 官方引擎需构建或下载二进制（本班因权限未跑）。
