0 · 这本书是什么：一句话与来龙去脉

一句话：它是 Agent 领域的《设计模式》教科书——就像 1994 年 GoF 把面向对象编程里反复出现的解法命名成"单例、观察者、工厂"一样，Google 高级工程师 Antonio Gulli 把构建 AI Agent 时反复出现的 21 种结构解法逐一命名、画图、配代码。

三个硬核事实：

  • 整本开源免费：PDF（实际 482 页）+ 配套 notebooks 全部公开，GitHub 镜像仓库 850+ star，另有中文翻译版《智能体设计模式》；
  • 每个模式都有可运行代码：50+ 个 notebook，横跨 LangChain/LangGraph、CrewAI、Google ADK 三套框架——同一模式三画布对照；
  • Google 官方背书：Google Cloud 官方架构文档《Choose a design pattern for your agentic AI system》直接引用这本书的模式分类。
📌 版权与依赖提示：书免费开源，但 notebook 全部依赖 OPENAI_API_KEY 或 GOOGLE_API_KEY（Gemini / GPT / Vertex AI），跑原版 notebook 需自备 Key。本指南实验用"确定性 FakeLLM"离线复现模式骨架，模式代码一行不改即可换成真模型。

疑问 2 · Level 0~3 复杂度分级是什么？我的项目在第几级？

Level 0 = 裸 LLM（只会背训练数据，问它昨天新闻必瞎编）→ Level 1 = 接上工具（对应模式 5/14）→ Level 2 = 会规划会反思（模式 4/6/8/17）→ Level 3 = 多 Agent 协作系统（模式 7/15/21）。这本书的模式地图就是一条"升级路线图"：想从 Level 1 升 Level 2，就补反思+规划+记忆三个模式。

疑问 3 · 提示链和我已会的 Agent 循环，本质区别是什么？

知识库里已有 [[Agent循环]]（模型↔工具自动转圈到任务完成）。提示链是它的反面兄弟：不给自主权。

提示链 Prompt Chaining（Ch1）Agent 循环（已有概念）
控制流人写死的固定流水线，站与站顺序执行模型自己决定下一步，循环到完成
交接物站间 JSON 契约，类型固定可断言自然语言 + 工具调用结果
确定性高：每站可单测，坏在哪一站立刻知道低：路径不可预测，调试靠 trace
适用流程稳定、步骤明确的任务（翻译→摘要→审校）开放式任务（"帮我调研 X"）

选型法则：能用提示链解决就别上 Agent 循环——确定性高、省 token、可测试；只有步骤本身需要模型临场决定时才升级为循环。

疑问 4 · 路由模式：分诊台是怎么搭的？

路由（Ch2）= 前面放一个轻量分类器，后面挂 N 个专科工位。每条输入只走一条路——省 token、且每条路可独立测试。书中三画布实现：LangGraph 用条件边（知识库 [[LangGraph与Agent编排]] 已学）、CrewAI 用 hierarchical 流程、ADK 用 agent transfer。

与已有概念的连接：[[技能路由器与授权硬门]] 是路由模式的"技能选择"特例；[[能力层与后端路由]] 是"后端选择"特例。书的贡献是给出通用命名 + 三框架对照实现——模式一旦命名，就能跨项目复用。

疑问 5 · 并行化的三种形态：切片、投票、总裁

形态做法生活类比典型场景
Sectioning 切片任务切成独立子块并行，结果拼接教材分章多人同写长文分节摘要、多文件审查
Voting 投票同一任务跑 N 遍，取多数/最优三位评委独立打分降低幻觉、提高判断可靠性
Governing 总裁多视角并行给意见，一个总裁合成各部门汇报，总裁拍板多维度审稿：事实+文风+安全

Voting 的本质是花 3 倍 token 买确定性——与 [[LLM采样与温度]] 的知识呼应：温度>0 的模型单次输出有随机性，多次投票用冗余换稳定。Governing 则是 [[多智能体协作]] 的最轻量前身：不用完整 Crew，一个 ThreadPoolExecutor 就够（见实验模式 3）。

疑问 6 · 反思循环：为什么必须有两个停止条件？

只有"分数达标才停"一个条件 → 碰上永远不合格的任务就无限烧钱；只有"最多 N 轮"一个条件 → N 轮后拿到的可能是没达标的半成品且无人知晓。两个一起才是安全设计：阈值管质量，轮数上限管成本。

知识库对照：反思模式就是 [[质检Gate与自我纠错循环]] 的 LLM 生成侧版本——Gate 的"打分器必须确定性"在真模型场景松动了（LLM 当批评家本身也有随机性），所以书里 Ch19 干脆再加一层 LLM-as-a-Judge 的评估来校准批评家自己。

疑问 8 · 护栏模式和提示注入防线是什么关系？

护栏（Ch18）是输入侧 + 输出侧的双重安检门：

  • 输入护栏：敏感词过滤、注入检测、权限校验——对接已有 [[提示注入]] 三防；
  • 输出护栏：Pydantic schema 校验、工具名白名单、置信度封顶——对接 [[Agent输出协议契约]] 的"协议门拒收坏结果"；
  • LLM 当护栏：再放一个模型当安检员读输出找违规——快但自身有漏报，所以确定性校验永远在 LLM 护栏外面包一层（代码校验是底线，模型校验是补充）。

已有 [[评分契约与护栏]] 是护栏模式在金融评分域的实例；书把它升格为通用安全模式，和评估（Ch19）、人在回路（Ch13）组成"安全三件套"。

疑问 9 · LLM-as-a-Judge 自动评估怎么工作？可信吗？

Ch19 的核心：写一份评分 rubric（评分细则）喂给一个强模型，让它按细则给被测 Agent 的输出打分——相当于雇了一个不知疲倦的外部裁判。书中示例是法律综述质量 rubric：论据是否可溯源、结构是否完整、术语是否准确，逐项打分。

可信度三定律（书上+社区共识）：

  • 细则质量 > 裁判模型强度：rubric 模糊，GPT-4o 级裁判也打糊涂分；
  • 裁判不能只评自家：同家族模型自评有偏，最好跨家族交叉；
  • 人抽检不可省：定期抽样人工比对，防裁判漂移——就是 [[证据优先质检ProofOverClaims]] 的"看实机画面"精神。

⚡ 动手实验：FakeLLM 离线复现 5 大模式（已真跑通过）

实验目标：用纯 Python + 确定性 FakeLLM 一次跑通书中 5 个代表性模式（提示链 / 路由 / 并行化 / 反思 / 护栏），验证每个模式的控制流和停止条件。环境：Python 3.14 + pydantic，零 API 依赖，可无限次重复，结果完全一致。

1进入实验目录并运行
cd F:\reminder\agentic-design-patterns\exercise
set PYTHONUTF8=1 && python patterns_playground.py
目的：跑通五模式流水线。✅ 预期：连续输出五个模式区块，最后一行 ALL 5 PATTERNS PASSED。
2看模式 1 提示链输出：输入 "Agent Memory Routing"，三站依次产出 {"keywords":[…]} → {outline:[…]} → {trends:[…]}，末行断言 trend_name=="agent" 通过。✅ 预期：三站 JSON 形状逐站变化但全程合法——固定流水线的可断言性。
3看模式 3 并行化输出：三个 Critic（事实核查/文风审查/安全审查）在 ThreadPoolExecutor 里真并发，总裁一次合成。✅ 预期：三条 critic 意见全部出现（"投诉率为0不可信"、"绝对化表述"、"放行"）。
4看模式 4 反思循环输出：文案三轮打磨，4 分→7 分→9 分，第 3 轮达标 early-stop（省下 2 轮调用）。✅ 预期：逐轮分数递增并提前停机。
5看模式 5 护栏输出（最有含金量）：越权工具名 delete_db 被白名单正则拒收；置信度 1.7 被 Field(ge=0,le=1) 拒收；第三次合法调用放行。✅ 预期：两次 ⛔ 拒收 + 一次 ✅ 放行——坏输出根本进不了执行层，且拒收理由（ValidationError 文本）可直接回流给模型重试。
6改造玩：把 THRESHOLD=8 改成 11 再跑——反思循环打不到阈值，改由最大轮数保险丝兜底止损。亲手体会"两个停止条件缺一不可"。
✔ 实测结果：5 个模式全部 PASS，重复运行输出完全一致（确定性验证）；真实运行完整输出存于 exercise\run_output.txt。
