03 / 新手疑问 1—2

01Pi-Purge 究竟改变哪一层？

【源码证实】它是 Pi 扩展，不是新模型、代理网关或 MCP 服务。入口注册 session_start、before_agent_start 和 /purge 命令；在每轮模型启动前返回一个 systemPrompt 字符串。它没有接管 provider，也没有授予文件/工具权限。扩展“可以改文字”不等于模型一定照做。

04 / 新手疑问 3—4

03不输入命令时真的完全没有作用吗？

【源码证实】enabled 初值 false；before_agent_start 在关闭时返回 undefined，不覆盖提示词。【我实际运行过（云端隔离环境）】两份扩展的默认关闭检查均通过。但 session_start 无条件调用 reload()：若已选外部 source，即使关闭仍会读该文件。因此 README 的“不读盘”不能扩大到整个关闭期间。

[S2] [S12]

04strict 会保留项目规则与工具吗？

【源码证实】strict 只返回自定义正文及格式化 cwd；原宿主提示中的 AGENTS.md、skills 文本、工具使用说明和其他扩展先前注入的内容都会被丢弃。【我实际运行过（云端隔离环境）】项目/工具文字确实不见了；没有执行任何工具。API tools schema 是另一通道，文字消失不证明工具被禁用，更不是安全沙箱。

05 / 新手疑问 5—6

05replace 是“智能理解后删段落”吗？

【源码证实】不是。它用精确的身份句、文档起止字符串寻找边界。身份句从命中位置删到该行结尾，文档需首尾都命中才删。两段相互独立，并非整体原子操作。【我实际运行过（云端隔离环境）】合成部分匹配场景中身份被删而文档保留；旧版生成提示匹配两段，当前版两段都不匹配。

[S2] [S9] [S10]

06append 是把自定义内容放末尾吗？

【源码证实】名称容易误导：所有模式都把 body 放在最前面，append 的精确组合是 body + 两换行 + 原始宿主提示。原帖“追加”只能理解为增加内容，不是顺序定义。【我实际运行过（云端隔离环境）】输出以原提示结尾，且长度增加，断言通过；未测这种顺序对模型回答的影响。

06 / 新手疑问 7—8

07“会话独立”是否所有变量都会归零？

【源码证实】session_start 只重置 enabled 和 lastCut，再 reload；mode、source 是模块顶层变量，未被重置。【我实际运行过（云端隔离环境）】append 模式跨 session_start 仍保留，开关会关闭；同一模块注册两套扩展时开关状态共享。这是隔离边界反例，不是声称常规 CLI 一定并发串会话。不同进程的内存仍各自独立。

[S2] [S3]

08status 与 reload 能当验收依据吗？

【源码证实】lastCut 只在 strict/replace 更新，append 不清空。【我实际运行过（云端隔离环境）】先 replace 后 append，status 仍显示上轮已切除；README 列出的 /purge reload 实际落入“未知子命令”。status 是辅助观测，不是完整请求记录。要重读已改文件，可重新 source 同路径或 on（本次未操作真实用户配置）。
