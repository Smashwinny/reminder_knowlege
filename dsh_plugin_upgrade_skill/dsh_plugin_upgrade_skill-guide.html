Q1这个仓库是什么？

一句话：教 AI 帮你升级 DSH（DeepSeek Harness）插件的 skill 集合——DSH 是"所有功能都以插件形式存在"的 AI 运行框架，每次发新版老插件可能直接启动不了；本仓库把已知坑整理成 AI 读得懂的升级手册（195 张卡），让 Claude Code / Codex / Gemini 帮你迁移，并用公开 benchmark 检验做没做对。社区共建，与 DeepSeek 官方无隶属。

Q2它解决的真痛是什么？

"插件化架构"的代价：宿主（harness）升级 → 插件 ABI/接口/机制变化 → 老插件启动即挂。传统解法是人啃 release notes 逐版迁移，痛苦且易漏。本项目的洞察：这些坑是重复性知识——"什么坏了、为什么坏、怎么修"可以预先写成卡片，agent 迁移时按需检索执行。卡的对象从"人"换成"AI"，文档结构随之改变（见 Q6）。

Q3195 张升级卡是什么结构？

卡片按"版本走廊"组织：每个版本跳变一个文件（references/v*.md，YAML frontmatter 带 from/to/cardCount/status/verifiedAt），卡按前缀编号（如 DSH-0.1.2-A2-01）。覆盖表在 README 如实标注每段状态：✅ 完成 / 📝 草稿（内测快照对齐待上游复核）——草稿段明确标出，不吹完成度。本机校验：20 个文件 cardCount 求和 = 195，与徽章精确一致。

Q411 个 skill 怎么分工？

skill职责
plugin-workflow统一入口：选择与编排其他 skill
plugin-upgrade / dsh-upgrade-audit查升级：目标版本有哪些破坏性变更
plugin-write / plugin-heavy-dep写插件 / 接入重依赖
plugin-test / plugin-runtime-debug测插件 / 运行时故障排查
plugin-release / plugin-fleet-sweep发布 / 宿主升级后整批巡检已装插件
dsh-benchmark-case把升级经验提取成考题（反哺 benchmark）
generic-migration不含 DSH 专有知识的通用迁移方法论——对照实验控制组
工程亮点：设了一个"通用迁移"控制组 skill——用对照实验量化"DSH 专有知识"本身的贡献，这是学术严谨性进入社区 skill 仓库的标志。

Q5benchmark + 论文是怎么做的？

63 道自动判分考题（README 口径 22 静态诊断 + 14 混合 + 27 实操，含 dsh-web 与 dsh-data-agent 两次真实迁移），挂 skill vs 不挂 skill 对照跑多个模型，论文《Evaluating Agent Skills for Version-Specific Plugin Migration》（arXiv:2609.30120）公开从原始回答、逐条评分到跨模型复评的全部证据链，可复算。这是"skill 有没有用"从口号变成可证伪命题的完整样本。

Q6一张卡的解剖（AI 可读性从哪来）

以 DSH-0.1.2-A2-01 为例，每张卡固定字段：Type（breaking/fix）· Applies to（哪些插件会踩）· Touchpoints（触点编号）· Action level（required-if-hit 等分级）· Symptoms（坏了长什么样）· 修复动作。链接到上游 compare 页与 release notes 溯源。写给人看的文档问"是什么"，写给 AI 执行的卡必须问"怎么识别、命中了没有、下一步做什么"——字段设计即人机分工设计。本机校验：抽样卡 4/4 关键字段命中。

Q7与 huashu-art-motion 的配方卡同构

两个仓库是同一范式的不同领域实例：huashu = 35 张艺术风格配方卡（渲染器+母题+转场），dsh-upgrade = 195 张版本坑升级卡（症状+修复+验证）。共同点：把专家踩坑经验结构化成 AI 可检索可执行的卡片库 + 让 agent 按场景取用 + 用独立评测证明有效。vault 新概念「经验卡知识库」可收这一模式（见知识提案）。

Q8边界与祛魅

① 适用面窄：只覆盖 DSH 一个框架的版本走廊，离了 DSH 只剩 generic-migration 控制组；② 论文分数是特定模型+特定任务的口径，不等于你的迁移一定 98 分；③ 0.1.7-rc.1→rc.2 段未成卡（README 自己标注）；④ 卡片知识会随上游发版过期，需要社区持续回流——它自己也承认"长期还是得靠更少破坏性变更+兼容层"；⑤ 本机校验发现 benchmark 实为 65 题（静态 24）比徽章 63 多 2 道——宣称保守低估，诚实方向反了也无妨，但说明徽章没及时更新。

Q9这个项目给我什么（能力清单）

① 版本迁移知识产品化：坑→卡片→agent 执行，三方结构比文档强在可检索可验证。
② 卡片字段设计：Symptoms/Applies to/Action level = AI 可执行性的三要素。
③ 对照实验思维：控制组 skill 量化专有知识贡献，可复算证据链。
④ 覆盖表诚实标注：草稿/完成分段标，信任从精确开始。
⑤ 插件 ABI 意识：宿主升级是插件化架构的结构性成本，不是意外。
⑥ 经验回流闭环：benchmark-case skill 把新坑反哺成考题，知识库自进化。
