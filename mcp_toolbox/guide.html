这个项目给我什么

5 项能力

  1. 连接多种数据源
    通过各类型 source 复用数据库连接；具体支持字段和权限须按版本、数据库检查。
  2. 提供预置与专用工具
    开发时探索表结构；运行时用固定 SQL 与类型化参数表达业务操作。
  3. 按应用组织工具
    把需要一起加载的工具归为 toolset，减少客户端无关能力与上下文负担。
  4. 接入身份与权限机制
    按工具验证身份或绑定可信身份参数；配合数据库权限，不能由描述文字替代。
  5. 记录运行与诊断信号
    支持连接管理、日志和 OpenTelemetry；真正的采集、保留与脱敏还需配置。

4 个具体用途

  1. 练习数据库助手
    用虚构酒店表测试 MCP 列表、参数绑定和错误处理，不需要大模型或真实账号。
  2. 做固定业务查询
    把“查订单状态”“统计当日库存”做成小而清楚的工具，并由可信身份限定数据。
  3. 辅助开发探索
    在隔离测试库中查看表与查询数据，通用 SQL 操作保留人工监督。
  4. 复用工具服务
    让不同 MCP 客户端或 Toolbox SDK 使用同一套经过测试的业务工具。
01

它是数据库，还是让 AI 使用数据库的接线员？

Toolbox 是工具服务器；真正存数据、执行 SQL 的仍是数据库。

想象客服助手收到“查一下上海的酒店”。模型理解需求，客户端发出工具调用，Toolbox 把已配置的查询交给数据库，再把结果传回。它不是大模型，也不会凭空知道你的表结构。项目把数据库连接、工具定义和调用接口集中起来，减少每个助手重复造接线代码。

术语落地 MCP（Model Context Protocol，模型上下文协议）约定客户端与工具服务器如何交换能力和请求；SQL 是关系数据库的查询语言。

看一个场景 例子：输入城市只是参数，酒店表和结果来自数据库，不是模型“记住”的答案。

需求被翻译为工具调用；结果沿原路返回。

依据：S1。本页解释中的建议不等于本次已验证功能。

02

我学过 MCP 了，为什么还要学 Toolbox？

MCP 是接口约定，Toolbox 是实现数据库工具的一套具体软件。

把 MCP 类比成插座规格，Toolbox 是有多种数据库插口的设备。会用 MCP 客户端，不等于已经定义好数据库查询。本项目提供两条入口：开发时使用预置通用工具探索数据；应用运行时提供围绕业务设计的自定义工具。两者风险和可控范围不同。

术语落地 预置工具是项目打包好的通用能力；自定义工具是你用配置写明用途、参数和执行逻辑的能力。

看一个场景 例子：开发者可以探索表结构；面向客户的助手通常只需“按订单号查状态”，不必获得任意 SQL。

已有 MCP 概念只复用，不把协议与产品混成一个词。

依据：S1。本页解释中的建议不等于本次已验证功能。

03

Source、Tool、Toolset 到底各管什么？

Source 连哪里，Tool 做什么，Toolset 一次加载哪些工具。

Source（数据源）保存数据库类型和连接信息；Tool（工具）定义可调用操作；Toolset（工具集）把工具按用途分组。比如酒店数据库是一个 source，按城市查询是一个 tool，客服常用查询放进一个 toolset。分组让客户端少看无关工具，但分组本身不能代替权限。

术语落地 配置是服务器启动时读取的结构化说明。固定文档将 toolset 视为仅含工具的 group（组）；旧配置仍兼容，但 description 等字段有例外，应核对版本。

看一个场景 例子：同一个数据库可被多个工具复用，同一个查询工具也可出现在不同工具集中。

连接、动作、打包分层，修改时才知道该动哪一层。

依据：S1、S5。本页解释中的建议不等于本次已验证功能。

04

参数绑定为什么比拼接 SQL 更稳妥？

把输入当作值传进去，不让输入变成 SQL 结构。

sqlite-sql 的普通参数按顺序绑定到问号占位符。城市名即使含引号，也应作为城市值处理，而不是拼成新的 WHERE 条件。类型检查还能提前发现把整数传进字符串参数的错误。参数化减少值注入风险，却不能替你决定谁有权查这行数据。

术语落地 占位符是 SQL 中等待填入“值”的位置；参数绑定由驱动传递值。templateParameters 则先替换 SQL 文本，作用不同，风险也更高。

看一个场景 例子：WHERE city = ? 可以绑定城市；不能靠 ? 动态替换表名。表名需求应优先改为固定工具或受控映射。

值进入指定槽位；不把用户文本直接当查询代码。

依据：S3。本页解释中的建议不等于本次已验证功能。

05

能直接执行任意 SQL，为什么还要写专用工具？

通用 SQL 很灵活；专用工具更容易定义、检查和限制业务范围。

sqlite-execute-sql 接收一段 SQL，适合有人监督的开发探索。sqlite-sql 则把语句固定在配置里，只开放必要参数。固定语句更便于审阅、测试和限定返回字段，但仍可能是一条写语句。工具名字叫“查询”或描述写“安全”都不构成限制。

术语落地 最小权限是只授予任务必要的能力；它必须落实在可用工具、认证授权和数据库权限等实际机制中。

看一个场景 例子：客服只需要订单状态，不应默认能列出整张客户表。官方 SQLite 通用 SQL 文档明确提醒其不适用于生产代理。

按场景收窄输入面，再检查数据库底层权限。

依据：S4、S3。本页解释中的建议不等于本次已验证功能。

06

把写工具从列表隐藏，等于禁止写入了吗？

工具清单是可发现范围；写入权限是另一道需要实测的边界。

toolset 让某个客户端加载一组工具，减少干扰和误调用。判断安全边界时，还要问：服务器是否仍注册其他工具？其他入口能否调用？数据库连接是否允许写？本实验会比较工具列表与实际调用结果，而不是看到菜单变短就宣布数据库只读。

术语落地 发现（discovery）是询问有哪些工具；调用（invocation）是请求执行某个工具。清单里的提示不是数据库的授权判决。

看一个场景 例子：菜单没有“修改价格”不等于厨房没有这道操作。要用受控写入测试与数据前后对照确认边界。

分别收集三层证据，不能用第一层替代第三层。

依据：S5、S6。本页解释中的建议不等于本次已验证功能。

07

readOnly、readOnlyHint、SQLite mode=ro 是同一件事吗？

不是。提示、Toolbox 功能和数据库连接方式属于不同层。

readOnlyHint 是给客户端的行为注解，不是权限证明。部分受支持数据源的 readOnly 功能会配合底层限制、工具裁剪和注解；当前文档矩阵列出 Cloud SQL PostgreSQL、Cloud SQL MySQL、AlloyDB PostgreSQL 和 BigQuery。SQLite 源没有这个 readOnly 配置字段，源码中的 IsReadOnly 返回 false。

术语落地 SQLite URI 的 mode=ro 表示该数据库文件以只读方式打开。本实验利用驱动接受的 URI，实测对该文件的写入失败；这不等于验证了上述云数据库机制。

看一个场景 例子：实验保留写工具并真正调用它。预期写失败、数据不变；不会使用 SQL 关键词过滤器充当安全边界。

SQLite 只读文件连接不自动证明工具被裁剪或注解正确。

依据：S6、S8。本页解释中的建议不等于本次已验证功能。

08

登录成功，为什么也未必能读所有数据？

身份验证说明“你是谁”；授权还要回答“你能做什么”。

Toolbox 可按工具检查令牌，也可把身份声明绑定到参数；数据库自身还可通过账号权限限制访问。应用应避免让模型随意填写他人的用户编号，再把它当可信身份。跨用户、跨租户的数据隔离必须在可信层校验，不能只写进提示词。

术语落地 认证是核实身份；授权是决定允许的动作和数据范围。OIDC 是传递身份信息的标准；claim 是令牌中经验证的身份字段。

看一个场景 例子：用户 A 的订单工具应使用可信身份限定 A 的记录。即使请求参数写成 B，也不应扩大到 B 的订单。该身份流程本次没有配置或验证。

本实验仅用虚构数据，不访问账号、令牌或真实客户数据。

依据：S7。本页解释中的建议不等于本次已验证功能。

09

stdio 和 HTTP 只是启动方式不同吗？

它们也是不同的连接方式和部署边界。

stdio 用进程的标准输入输出传递 MCP 消息，常见于本地客户端启动工具服务器；HTTP 通过网络端点连接，更适合独立部署但需要考虑暴露范围、认证和网络保护。本实验通过 stdio 启动官方二进制，不监听端口，不修改任何 MCP 客户端的全局配置。

术语落地 传输层是消息在客户端与服务器之间走的通道。JSON-RPC 是本实验 MCP 请求使用的消息格式，带有方法名、参数和请求编号。

看一个场景 例子：脚本发送 tools/list，再发送 tools/call，并把实际响应记入日志。无需模型或付费 API 也能测试这个协议环节。

真实工具服务器运行；模型规划质量不在本次测试范围内。

依据：S9、S1。本页解释中的建议不等于本次已验证功能。

10

看到“调用成功”，怎样知道到底发生了什么？

同时看响应、错误和数据库状态，才有完整证据链。

只看进程退出码会漏掉协议内的工具错误。测试应记录请求目标、参数、结果和错误，再比较数据前后状态。Toolbox 支持 OpenTelemetry 的链路与指标，但部署采集器和外部后端是另一项工作。本次只保留项目内测试日志，不向遥测服务发送数据。

术语落地 可观测性是通过日志、指标和链路了解系统运行；审计记录用于回溯“谁在何时做了什么”。测试日志不等于生产审计体系。

看一个场景 例子：本次主库读到 2 行、写调用返回只读错误、再次读取仍为 2 行，三份证据比“安全测试通过”一句话更可信。日志应避免记录令牌与真实敏感字段。

成功读取、预期拒绝、反例对照都应留下记录。

依据：S1、S10。本页解释中的建议不等于本次已验证功能。

11

我只改了一行配置，结果为什么变了？

配置也是可执行行为的一部分，需要版本、校验和回归测试。

Toolbox 可动态重载配置，因此改 source 或 statement 可能直接改变工具行为。实验固定官方二进制版本、文件 SHA-256 和运行配置，避免“昨天的文档配今天的程序”。源码 HEAD 与发布版本分开记录；遇到字段不识别，应核对该版本支持范围，不可静默删掉限制继续运行。

术语落地 版本固定是使用明确的版本或提交；SHA-256 是文件指纹，用于确认字节是否一致。它本身不证明文件来自可信发布者。

看一个场景 例子：SQLite 源写入 readOnly: true 若被拒绝，正确结论是“该字段不受支持”，不是“只读已打开”。本实验会保留真实报错证据。

官方渠道、文件指纹、实际行为是互补证据。

依据：S1、S8。本页解释中的建议不等于本次已验证功能。

12

做完这次实验，可以直接连生产数据库了吗？

先把小实验变成清楚的验收清单，再决定部署。

本次只证明固定版本在虚构 SQLite 文件上的特定行为。生产环境还要验证目标数据库权限、租户隔离、返回数据最小化、认证、超时与资源限制、敏感日志处理和回滚方案。即使一个写操作被拒绝，也不能推断所有文件、所有数据库或所有工具都安全。

术语落地 威胁模型是列清楚要保护的资产、可能的攻击路径和信任边界；回归测试是在改动后重复检查原有保证。

看一个场景 下一步：用脱敏测试库和真正的最小权限账号，补上越权、写入、超时、错误响应测试。只有授权和验收都明确后才考虑真实环境。

把结论带着适用范围一起迁移，避免小实验被放大。

依据：S6、S7。本页解释中的建议不等于本次已验证功能。

  • 预置 sqlite/sqlite_database_tools 实际列出 execute_sql 与 list_tables；主库返回 apples=4、pears=7，共 2 行，总量 11。execute_sql 的 readOnlyHint 仍为 false。
  • INSERT、UPDATE、DELETE、CREATE TABLE，以及 PRAGMA query_only=OFF 后尝试 INSERT 的组合均返回工具错误；原始文本含 attempt to write a readonly database (8)。随后读取成功，主库 SHA-256 前后相同。
  • 固定 SQL 的 name=? 查询返回 apples；SQL 外观输入仅作为值，返回空结果；整数参数触发类型错误。调用未配置工具返回 -32602 和 tool does not exist，不是身份鉴权证明。
  • 可写独立对照故意标 readOnlyHint=true，INSERT 仍成功，另一数据库连接确认记录从 2 行变为 3 行。SQLite source 的 readOnly:true 则启动失败，报 unknown field。
  • 本次没有测试云数据库 readOnly、OAuth、HTTP 入口、租户隔离或所有 SQL 副作用。BigQuery protected 模式在文档中允许会话临时写入，不能概括为绝对零副作用。
