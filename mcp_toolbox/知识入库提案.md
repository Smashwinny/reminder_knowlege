# MCP Toolbox 知识笔记与入库提案

## 一句话结论

Toolbox 是把数据源、工具和工具集合连接到 MCP 客户端的服务器。工具注解、工具暴露范围与数据库执行权限是三个不同层次，必须分别取证。本次真正运行官方二进制，不把自写测试驱动冒充上游项目。

## 已实际验证的项目实验

- 预置 sqlite/sqlite_database_tools 实际列出 execute_sql 与 list_tables；主库返回 apples=4、pears=7，共 2 行，总量 11。execute_sql 的 readOnlyHint 仍为 false。
- INSERT、UPDATE、DELETE、CREATE TABLE，以及 PRAGMA query_only=OFF 后尝试 INSERT 的组合均返回工具错误；原始文本含 attempt to write a readonly database (8)。随后读取成功，主库 SHA-256 前后相同。
- 固定 SQL 的 name=? 查询返回 apples；SQL 外观输入仅作为值，返回空结果；整数参数触发类型错误。调用未配置工具返回 -32602 和 tool does not exist，不是身份鉴权证明。
- 可写独立对照故意标 readOnlyHint=true，INSERT 仍成功，另一数据库连接确认记录从 2 行变为 3 行。SQLite source 的 readOnly:true 则启动失败，报 unknown field。
- 本次没有测试云数据库 readOnly、OAuth、HTTP 入口、租户隔离或所有 SQL 副作用。BigQuery protected 模式在文档中允许会话临时写入，不能概括为绝对零副作用。

## 三项增量 优先合并而非新建同义词

### 工具注解与强制执行分离

一句话定义：readOnlyHint等注解描述预期行为，实际操作是否获准由可信执行机制决定。

领域：AI工具安全。建议补充 [[代码管边界提示词管判断]] 和 [[MCP协议]]，互链 [[只读闸门三原则]]。

实证：同一个官方工具执行器，错误标注readOnlyHint=true而连接可写虚构数据库时，INSERT真的持久化。反过来，预置execute_sql仍显示readOnlyHint=false，mode=ro主库却真的拒绝写入。因此两层信息既可能不一致，也不能互相替代。

官方MCP规范：https://modelcontextprotocol.io/specification/2025-06-18/schema#toolannotations

### 适配器级只读能力矩阵

一句话定义：只读能力按引擎、来源适配器、连接模式、工具类型和版本逐项记录验证。

领域：数据库接入与权限。建议补充 [[只读闸门三原则]]，关联 [[关系型数据库与NoSQL]]。

静态观察：固定源码SQLite配置没有readOnly字段，IsReadOnly()始终false；database字符串传给sql.Open。实际运行通过URI mode=ro打开主库，五次写操作失败，文件哈希不变；加readOnly:true则启动报unknown field。不能从其他数据库相同字段名反推SQLite支持。

官方只读文档矩阵列Cloud SQL PostgreSQL、Cloud SQL MySQL、AlloyDB PostgreSQL和BigQuery；不是通用PostgreSQL或SQLite名单。BigQuery protected允许临时会话数据写入，不能据readOnlyHint推断普遍“零副作用”。云数据库机制这次只做源码/文档学习，没有实际连接验证。

### 工具暴露范围与数据权限分层

一句话定义：工具集组织可发现能力；数据库授权、参数范围和执行约束控制能接触的数据与操作。

领域：最小权限与MCP。建议补充 [[只读闸门三原则]]，关联 [[本地MCP端点安全四道门]]。

实证：预置toolset实际列两个工具；自定义配置只注册lookup_item，未配置execute_sql调用返回-32602未知工具。这个错误证明的是未注册，不是用户身份或命名HTTP端点的授权。文档默认无名加载toolset会加载服务器全部工具；客户端自行选小集合不能单独建立数据库权限。

源码细节：通用ShouldSuppress要求source.IsReadOnly为真，再对明确readOnlyHint=false的工具做抑制；未标注工具只警告。不能简写为“所有可能写的工具都消失”。

## 项目笔记提案

- 项目：MCP Toolbox for Databases，旧名Gen AI Toolbox
- 能力：多数据源连接、预置与自定义工具、工具集合、身份机制、可观测性
- 主要关联：[[MCP协议]]、[[只读闸门三原则]]、[[代码管边界提示词管判断]]
- 实验：真实官方程序+虚构SQLite主库，MCP stdio，读成功/写拒绝/参数绑定/可写负对照/未知配置错误
- 关键坑：主分支与发布版分开；参数化不等于只读；提示注解不等于权限；SQLite mode=ro不等于Toolbox readOnly；未知工具不等于身份鉴权
