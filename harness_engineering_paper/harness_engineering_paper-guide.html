Q2什么是 harness？什么不是？

论文定义：Agent = 模型 + harness——harness 是把 LLM 耦合到世界的运行时：循环、工具、上下文管理、安全控制、编排、扩展面。这个学科 2026 年初被命名（Anthropic 的 effective-agents 系列是其实证前奏）。关键边界：harness 不 benchmark 也不排名——它回答"怎么建的"，不回答"哪个更强"。

Q4"双缺席"——论文最炸的两个发现

① 无 agentic 框架：约 400 万行代码里，没有任何 agent runtime 导入 LangChain/LangGraph/AutoGen 等通用框架——连 Gemini CLI 都不用 Google 自家的。全靠手写 async 循环。② 无向量代码检索：没有一个系统用向量嵌入检索代码——全部是确定性检索：ripgrep、tree-sitter、glob、自动发现的 Markdown 上下文文件。两个缺席在三次语料扩充后依然成立。

为什么重要：这与"RAG 一切"的主流叙事正面相撞。生产级 Agent 的答案是：代码检索用确定性工具（grep 系）因为精确；agent 骨架手写因为框架的抽象不适合循环的本质。

Q5地板很低：100 行的 Mini-SWE-Agent

存在证明：Mini-SWE-Agent 用约 100 行实现全部七子系统——一个 while 循环、一个模板、一个工具、一个消息列表、两个限制、无编排、结构化类型作为全部扩展故事——SWE-bench Verified 成绩与体积大三个数量级的系统同区间。地板与生产系统的差距不在任务完成，而在安全、恢复、成本管理、扩展性、平台面。论文第 16 节甚至给出 90 行最小可行 harness 供复制特化。

Q6扩展标准之争：SKILL.md 赢了 MCP？

采用率：SKILL.md 技能 9/11 领先 MCP 8/11；ACP 协议进入 6 个系统并获得第三个角色——harness 托管（OpenHands 把 Claude Code/Codex/Gemini CLI 当可互换后端跑）。技能生态长出了注册表、信任分级、以及语料中第一批 agent 写给 agent 的技能。论文判断："Skills versus MCP: the tie has broken"——平局已破，技能是声明式程序，延迟加载是主导模式。

Q7平台转向：CLI 正在变成框架

论文第 14 节的论题：harness 与框架正在合并。四个信号：① 技能成为声明式程序；② hooks/事件总线成为扩展基底；③ 工具与工作流的边界消失；④ harness 成为服务面（ACP 托管）。配套经济学：市场、切换成本、企业治理。这意味着"用哪个框架"的问题正在被"用哪个 harness"吞掉——因为 harness 自己长成了框架。

Q9这个项目给我什么（能力清单）

① 七子系统解剖眼：看任何 Agent 先找七个位置，缺位也是位置。
② 最小/最大光谱思维：每部件都有极简与极繁解，选型=在光谱上定位。
③ 双缺席判断力：框架与向量检索的缺席是实证事实，不是品味。
④ 安全即架构：Codex 四层栈证明安全不是提示词是运行时层。
⑤ 平台化嗅觉：harness 吞框架，扩展面=生态入口。
⑥ 方法论纪律：不 benchmark 只解剖——描述性研究的价值样本。
