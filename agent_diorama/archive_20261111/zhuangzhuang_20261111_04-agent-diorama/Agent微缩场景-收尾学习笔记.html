01

原帖首先解决什么，而不是先解决什么？

把分散的任务定义与运行入口做成可理解的全局视图，而不是证明动画能提高生产率。作者明确称初版只接少量任务；“两天”“舒服”是作者自述，不是本轮性能或可用性测试。

依据：原帖 / 固定相关仓库 / 官方文档；详见sources.md

02

厂区、产线、包裹分别是什么？

项目是厂区；长期任务定义是产线/机器；每次真实执行是包裹。定义与实例必须分开：一条产线今天能发出多个包裹，重试也不应无意变成多个业务任务。本轮只有映射草案，未写运行代码。

依据：原帖 / 固定相关仓库 / 官方文档；详见sources.md

03

Webhook中台为什么居中？

原帖用分拣大厅表示接收、路由与状态分发，Agent是执行者。后续开源中台文档也区分事件、规则、事项、一轮和回执；它们不能被一个“任务”字段混成同一对象。实际飞书/Agent链路本轮未连接。

依据：原帖 / 固定相关仓库 / 官方文档；详见sources.md

04

动画位置能直接表示百分比进度吗？

不能自动推出。包裹移动到一半只说明视觉插值；若没有真实进度事件，不应显示业务完成50%。更安全的是明确阶段（排队/运行/待确认/完成），同时显示最后证据时间。这里只提出设计要求，未测试实现。

依据：原帖 / 固定相关仓库 / 官方文档；详见sources.md

05

失败、未知和待人工处理怎么显示？

不能只用红绿，也不能把Agent进程退出当业务成功。应有文字、形状或固定异常区，待决定任务比正常运转动画更突出。W3C要求颜色不能是唯一的信息通道；本轮未做屏幕阅读器或完整WCAG验收。

依据：原帖 / 固定相关仓库 / 官方文档；详见sources.md

06

重复和乱序事件要怎样进入场景？

后续中台协议规定同一来源同一id只记录一次；快照带seq，事件流从after=seq衔接。本自编草案尚无归约器，不能借用上游的去重保证；尤其不能让晚到的运行事件覆盖已完成状态。

依据：原帖 / 固定相关仓库 / 官方文档；详见sources.md

08

后续真接中台时，界面是否天然只读？

不是。协议把状态读取、回答、取消等请求列为不同能力。一个监控画面不应顺带获得启动、取消或批准权限。本轮没有安装中台、读取密钥或连接真实服务，也没有执行源码里的发布/日程建议。

依据：原帖 / 固定相关仓库 / 官方文档；详见sources.md

09

昼夜与天气属于业务状态吗？

它们是环境层，不应改变任务是否成功。场景可夜间变暗，但错误标记和正文仍需清晰；天气失效应标未知/陈旧，而不是持续假装实时。暂停环境动画也不应被误认为取消任务。前端联动尚未实现。

依据：原帖 / 固定相关仓库 / 官方文档；详见sources.md

依据：原帖 / 固定相关仓库 / 官方文档；详见sources.md

11

氛围动画和免费接口有哪些边界？

W3C建议自动移动/更新提供暂停、停止或隐藏控制；本轮只读文档，未实现控制。Open-Meteo免费API限定非商业用途并有限流，数据需署名；源码许可与数据许可不是同一层，不意味着无限免费商用。

依据：原帖 / 固定相关仓库 / 官方文档；详见sources.md
