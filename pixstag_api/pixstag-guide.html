PixStag 视频 API：异步任务、多模态输入与按秒计费

Q1

PixStag 是什么？一句话能说清吗？

一个视频生成服务的 API 层：把"对话做视频"翻译成标准异步接口——创建任务拿 task_id，轮询状态，成功后取回视频 URL 和按秒计费的 usage 账单。底层是多模型（MiniMax-H3、即梦 Seedance 2/2.5），前端体验只是包装。

对开发者的意义：它是"AI 视频服务"的标准形态样本——异步五态 + 多模态 content 数组 + 按秒对账。学通这一个，其他家的视频 API（可灵、Runway、Vidu）大同小异。

Q2

异步任务五态是什么？为什么要异步？

视频生成动辄几十秒到几分钟，HTTP 请求不可能干等。所以契约是：创建即返回 task_id，之后由你轮询（或 webhook 推送）查状态：

状态含义客户端动作
queued排队中继续等
running生成中继续等
succeeded成功取 content.url 与 usage 对账
failed失败读 error.code/message，决定重试
cancelled已取消释放，不计成功

这是知识库 [[任务票据与状态外置]]/[[可逆派生状态]] 的标准应用："排队中≠完成"，pending 是铁证、回执不是完成。

Q3

多模态 content 数组怎么组织？

content 是一个带"角色"的多模态数组——每个元素声明 type（text/image_url/audio_url/video_url）+ 可选 role（这个角色字段就是一致性控制的关键）。

role用途
first_frame图生视频的首帧（单图无 role 默认就是它）
last_frame尾帧，必须与 first_frame 配对做"首尾帧生成"
reference_image / reference_video / reference_audio多模态参考（角色长相/风格/音色）
文档明确：所有场景都要求非空 text（≤5000 字）。所以"不用自己想提示词"只是产品层替你写了——底层提示词永远存在，而且 text 的质量仍影响结果。这呼应 [[PromptAsCode提示词即代码]]：提示词不会消失，只会被托管。
Q4

按秒计费怎么对账？

成功响应带 usage 对象：total_seconds / input_seconds / output_seconds / input_image_count / input_audio_seconds + token 计数。对账纪律：请求时长 × 单价 必须等于账单秒数，不符即拒付复核（[[付费调用回执与预算熔断]]）。

另有三个账外因素：①积分有效期（user/me 返回 credit_valid_time，充值的积分会过期）；②失败重试也烧钱（failed 后重试 = 新一轮计费）；③分辨率/模型档位不同价——"1 块钱做视频"是特定时长+档位+优惠的个案。

Q5

本指南实测了什么？

① 真实只读探针：GET /api/v2/user/me（无 token）
   → HTTP 401: login fail ... (1004)   ✅ 错误契约与文档一致

② 本地模拟状态机：queued→running→succeeded，3 轮轮询到终态 ✅

③ 用量对账：请求 6s vs 计费 6s → ✅；篡改 8s → ❌ 拒付 ✅
如实声明：POST 创建真实生成任务是付费写操作，需本人授权，本班未执行（被权限层正确拦截）；生成质量/速度/真实账单未验证。全部脚本见 pixstag_api\exercise\。

Q7

接入到自己视频流水线的最小设计

# ① 任务创建：POST /video_generation（非空 text + role 化的多模态数组）
# ② 轮询或 callback_url webhook（最多 3 次推送，须回 SUCCESS）
# ③ 终态处理：succeeded → 对账 usage；failed → error.code 分类重试
# ④ 账单：记录每次 total_seconds，与 credit 余额/有效期联动熔断
Q8

宣称可信度核查

说法核实
对话即可制作、多模态输入✅ 文档确认（但底层仍需非空 text）
异步任务 + 状态查询✅ 文档确认（五态 + webhook）
按秒用量✅ usage 字段确认（文档未列每秒单价）
"只花一块钱""20 万播放"⚠️ 个案陈述，价格随时长/模型/分辨率变化，未实测
速度/质量最优⚠️ 服务商陈述，无独立测量
Q9

这类"API 中间层"值不值得学？

值得——它是"模型时代的产品化标准层"。单一模型 API 会直接过时，聚合层（多模型路由 + 统一异步契约 + 统一计费）有迁移价值。学它的接口设计比学某个按钮位置长寿得多。
