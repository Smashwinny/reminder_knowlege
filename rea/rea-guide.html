Q1

REA 是什么？一句话能说清吗？

REA 是一个"逆向工程工具的总调度台"：它本身不做逆向，而是把 Ghidra、Hopper、IDA、JADX 等专业逆向工具统一包装成一个 MCP 服务器 + 命令行，让 AI 编程 Agent（Claude Code、Codex、Cursor……）能够直接"审问"一个闭源程序：你是怎么工作的？

典型场景：你在某个 App 里看到一个好用的功能，想知道它的实现原理。过去要自己拖进反编译器啃几天；现在你对 Agent 说"用 REA 看看这个功能怎么实现的"，Agent 会自己调用工具链、收集证据、给出带出处结论的分析报告。

关键认知：REA 是路由层不是引擎。就像电梯调度系统本身不载客，它决定哪部电梯（哪个逆向引擎）去接哪个乘客（哪类分析目标）。官方原话："One MCP for reverse engineering across binaries, applications, and runtime behavior."
Q2

为什么需要它？没有它之前人们怎么做逆向？

逆向工程历来是"专家手艺"：工具贵、学习曲线陡、全程手动。传统流程是把二进制拖进反编译器，人肉阅读伪代码，在几千个函数里大海捞针。分析一个小功能可能要几天，而且结论全靠专家脑子记，无法复查、无法复现、容易幻觉（"我觉得这个函数是干这个的"）。

REA 带来的变化有三层：

维度没有 REA有了 REA
谁操作工具逆向工程师手动点 GUIAI Agent 通过 MCP 工具调用自动操作
结论形式专家口头/文档描述结构化 Evidence（证据包），每条结论带文件哈希+行列号
可信度"专家说如此"，无法机检三态标签 SEEN/INFERRED/UNKNOWN，机器可审计

还有一个更根本的驱动力：M×N 集成问题。AI Agent 有十几种（Claude Code/Codex/Cursor/Gemini…），逆向工具有十几种（Ghidra/Hopper/IDA/JADX…），两两对接是 M×N 的组合爆炸。MCP 协议把它收敛成 M+N——这正是知识库里 [[MCP协议]] 笔记讲过的经济学，REA 是它在逆向工程域的落地。

Q3

它是怎么做到的？核心架构是什么？

三层架构：MCP 工具接口层 → 证据框架层 → 分析引擎适配层。

① MCP 工具接口层（对上）

REA 向 Agent 暴露一百多个细粒度工具（本机实测 --help 列出上百个命令，如 analyze、decompile、analyze-javascript-application、capture-browser-scenario）。Agent 通过 MCP 协议（stdio 或 HTTP）发现和调用它们。一条命令即可注册：npx rea-agents setup。

② 证据框架层（核心，REA 的灵魂）

每一次分析产出一份 Evidence Bundle（证据包）：JSON 结构，包含被分析物的 SHA-256 指纹、每个结论的源码行列号、局限性和未知项清单。这让它和"AI 口嗨分析"彻底区分——结论可回溯、可机检、可比较（compare 系列命令支持两份证据包 diff）。

③ 分析引擎适配层（对下）

按目标类型路由到不同引擎：原生二进制→Hopper/Ghidra/IDA（三选一即可）；APK→JADX；JS/Electron/.NET→内置静态分析（不需要任何外部引擎）；固件→Binwalk；网页→Chrome 家族浏览器；抓包→HAR/TShark。运行时检测哪些引擎可用（rea doctor），不可用的给出修复指引。

Q5

三态证据框架到底重要在哪？

这是 REA 与"让 AI 直接读反编译代码"的本质区别：它逼 AI 诚实。

LLM 最大的风险是幻觉——分析二进制时它可能"自信地"编出一个不存在的函数调用。REA 的 Tri-State Evidence Framework 规定每条结论必须打三个标签之一：

  • SEEN 在工件里直接观测到的事实（如：字符串 ctrl+shift+k 出现在 main.js 第 5 行）——附 source-range 坐标，任何人都能复查；
  • INFERRED 从 SEEN 证据推导出来的（如：该字符串被传给 globalShortcut.register，推测是快捷键）——允许错，但血缘清晰；
  • UNKNOWN 无法确定的（如：运行时这个快捷键是否真的注册了）——不猜，如实记账。

本机实测（见动手实验）：对一个 4 文件样本做分析，产出 162 个节点、105 条关系，同时诚实记录 63 条 unknowns，limitations 里明确写着"运行时注册、可达性仍未被证明"。这和知识库里 [[证据优先质检ProofOverClaims]]（验收看跑起来的画面不看宣称）完全是同一套哲学：证据分层 + 局限性亮出来。

Q6

它和知识库里已有的概念是什么关系？

REA 不是全新物种，它是好几条已学概念线的交汇点：

已有概念REA 中的体现
[[MCP协议]] / [[MCP服务器]]REA 就是一个超大型 MCP 服务器（100+ 工具），M×N→M+N 的标准战例
[[工具目录膨胀]]反向教材：工具极多但按域拆分（analyze / capture / compare / decompile…），且支持 --llms 输出 LLM 可读清单压缩上下文
[[能力层与后端路由]]（agent-reach）同构：每个分析目标有有序后端列表，第一个可用者当选；doctor 就是"健康探测三态"的满配版（missing / broken / timeout）
[[证据优先质检ProofOverClaims]]三态证据框架 = 该哲学在逆向域的强制执行：没有证据链的结论不允许出现
[[提示注入]] 防线被分析对象是不可信输入，REA 把分析放在本地沙箱、以 inert 方式解析（"JS 和 HTML 按惰性文本解析，从不执行"）
agent-reach / artemis（安卓 GUI Agent）同域项目：REA 也覆盖安卓 APK 分析与 adb 设备取证，可与这两个项目的笔记互链
学习定位：REA = "把 MCP 协议 + 能力路由 + 证据纪律"这三件已学武器，在逆向工程这个高难度领域打的组合拳。学它主要学架构思想，不是学逆向本身。

它能分析哪些目标？需要什么条件？

目标类型后端引擎是否需要外部工具

入门建议：从 JS/Electron 路径开始——零外部依赖、分析本地目录、免费、且足以体验完整证据框架。本机实验正是这条路。

Q8

法律与安全边界在哪？

红线：只对授权目标做逆向。REA 仓库自带 DISCLAIMER，明确建议仅用于授权目标、互操作性研究或安全研究。商业引擎（IDA/Hopper/JEB）必须合法持有许可。分析行为发生在本地，代码不外传——这是隐私优势，但不改变合法性责任。

另一个有趣的真实细节：多家技术媒体报道，部分大模型（如 Claude Opus 5.5）会在逆向分析中途因安全策略拒绝继续，而 DeepSeek、Kimi 等模型则无此问题。这不是 REA 的缺陷，而是"用 AI 做安全研究"时的现实约束：模型自身的安全护栏也是流水线的一环，选模型时要考虑这一点。

防御性用途同样明确：检查自家软件是否被植入后门、审计供应链、学习优秀软件的架构思路（"学大厂代码思路"），都是项目点名的合法场景。

它的爆发为什么这么快？有没有水分？

REA 于 2026 年 10 月初爆发：star 数从 10 月 7 日的不足 1 万飙到 10 月 20 日的 34 万+，成为 GitHub 史上增长最快的仓库之一（本指南写作时已达 39.5 万★）。

为什么会爆？三点共振：

  • 时机：AI Agent 普及后，"让 Agent 替我逆向"是自然涌现的刚需；
  • 架构正确：不重复造引擎，只做路由+证据层——轻、稳、能借力所有成熟工具；
  • 故事好讲："逆向工程一切"一句话就能传播。

水分也要心里有数：媒体报道指出部分演示案例有夸张成分；34 万 star 里有大量"先 star 再说"的围观群众；深度原生分析依然依赖你本地装好专业引擎——REA 降低的是门槛，不是取消专业技能。

Q10

实际怎么装、怎么用？（含本机实测的坑）

安装（三选一）

# 方式一：给 Agent 注册（推荐）
npx rea-agents setup

# 方式二：一次性 CLI
npx -y rea-agents@latest <command> --json

# 方式三：全局安装
npm install --global rea-agents

硬性要求：Node.js 22.23.4+ / 24.22.1+ / 26.12.1+（注意是补丁版本级的要求！）

本机实测坑 1：本机 Node v24.21.0 差一个小版本，npm ci 直接拒绝（engine 检查），需 npm ci --force。doctor 也会把它标为 missing_dependency 并要求升级。
本机实测坑 2：从 git 源码构建时，Windows 原生控件（native/windows/build/ 两个文件）不在仓库里，JS 应用分析会报 capability_unavailable；官方错误文案即修复说明书——从 rea-agents@6.8.0 的 npm tarball 里把两个文件拷回来即可。

日常使用闭环

rea doctor                                  # ① 体检：17 项检查
rea analyze-javascript-application <路径>    # ② 免引擎分析 JS/Electron
rea inspect <目标>                           # ③ 带证据的概览
rea decompile --procedure <名>              # ④ 反编译单个函数
rea compare <证据A> <证据B>                 # ⑤ 版本对比（找改动）

所有分析在本机完成，产出的证据包（Evidence Bundle）就是可存档、可 diff、可审计的分析资产。

★

这个项目给我什么能力？（我能用它干什么）

  1. 挖 App 隐藏功能：想知道一个软件藏着什么快捷键/调试入口/暗门，让 Agent 跑一遍静态分析，证据带行列号；
  2. 查可疑软件有没有后门：供应链审计场景——拿到二进制先看它到底会做什么网络/进程行为；
  3. 学习优秀软件的实现思路：看到一个交互效果，逆向它的 JS bundle 学架构（合法边界内的互操作性研究）；
  4. 给自己的软件做"红队体检"：发布前用 REA 自查敏感字符串、硬编码密钥暴露面；
  5. 版本升级 diff：两个版本各出一份证据包，rea compare 自动找出行为变化（补丁分析）；
  6. 安卓应用分析入门：APK 丢给 JADX 路径，配合 agent-reach / artemis 的安卓知识形成组合拳。

实验：自己埋谜题，让 REA 来解（约 15 分钟）

为了验证 REA 的真实能力，我自己写了一个带隐藏功能的模拟 Electron 应用（日记 App 外壳），埋入 3 处谜题，再完全不读源码地用 REA 分析，看它能否挖出来。

步骤 1 ｜ 准备样本。创建 4 个文件：main.js（主进程，埋谜题）、renderer.js、renderer.html、package.json。埋入：① 隐藏快捷键 ctrl+shift+k 解锁会员；② checkLicense() 假装联网验证实际永远 true；③ 主进程与渲染进程间的 IPC 通道 license:unlocked。
✅ 预期结果：exercise\sample-app\ 下 4 个文件就位，能看懂每个谜题在哪几行。
步骤 2 ｜ 构建 REA（源码路线）。 
git clone --depth 1 https://github.com/morluto/rea repo
npm ci --force          # 本机 Node 24.21.0 差补丁版本，需 --force
npm run compile         # build:cached 不编译 TS，必须 compile
node scripts/rea.mjs --version   # → 6.8.0
✅ 预期结果：版本号正常输出。若报 "compiled runtime is missing"，说明漏了 compile 这步。
步骤 3 ｜ 体检与修复。 
node scripts/rea.mjs doctor
node scripts/rea.mjs analyze-javascript-app ..\exercise\sample-app --detail summary --evidence_output ..\exercise\evidence\run1
✅ 预期结果：doctor 报 healthy:false（Node 版本 + 缺引擎，正常现象）。分析若报 capability_unavailable 指向缺 Windows 原生控件 → 从 npm tarball 恢复 native/windows/build/ 两个文件后重跑成功。
步骤 4 ｜ 验证挖出全部谜题。在 309 KB 证据包 JSON 中检索，与埋入清单逐项对照：
✅ 预期结果（本机真实输出）：① 节点 label="ctrl+shift+k"，定位 main.js 第 5 行 ✅；② 函数节点 checkLicense，定位 main.js 第 7 行 ✅；③ 事件名 license:unlocked 在主进程（发送）与 renderer.js 第 18 行（接收）各出现一次，双向端点都对上 ✅。共 162 节点 / 105 关系 / 63 条 unknowns 如实记账。
步骤 5 ｜ 读局限性，感受三态证据。打开证据包 limitations 字段，原文写道："Electron relationships are derived from inert syntax; runtime registration ... remain unproven"。
✅ 预期结果：明确意识到——REA 证明了"代码里写了注册快捷键"，但诚实地声明"运行时是否真的生效仍是 UNKNOWN"。这正是它比"AI 直接读代码给结论"强的地方：不编造确定性。
实验结论：免商业引擎即可完成 JS/Electron 静态分析；自埋 3 谜题全部命中且证据可回溯；63 条未知项与局限性如实记录，三态证据框架真实有效。完整日志见 rea\exercise\experiment-log.md。
