Q01 这篇讲的是破解万能遥控器吗？

不是。原文是作者自有设备的交互重做案例，电视借助 ADB，补光灯和相机则要分别研究连接方式。原帖没有公开完整适配代码、包名和可复刻固件，因此不能从案例推导任何电视都能去广告。

Q02 ADB 到底有哪三端？

电脑上的命令客户端把请求送给电脑上的 ADB server，后者再与设备中的 adbd 通信。客户端到 server 的协议，不等于设备蓝牙或相机网络协议；本练习只编码前一段，不连接端口或设备。

Q03 为什么知道电视 IP 还不够？

设备需要开放对应调试能力，并由设备持有人确认授权。官方文档明确 USB 调试的 RSA 授权；无线调试还受系统版本、配对和同网段限制。这里没有开启调试、扫描局域网或改变安全设置。

Q04 主机请求为什么有四个字符的前缀？

AOSP 的 OVERVIEW.TXT 说明请求先发四字节 ASCII 十六进制长度，再发负载。实跑 host:devices-l 是 14 字节，所以前缀是 000e，不是根据搜索摘要抄来的 000d；编码后按实际字节数复核。

Q05 列表显示 device 是否就能开会？

不能。官方文档指出 device 状态不保证 Android 已完全启动。需要分别确认系统启动、遥控输入、投屏和信号切换；网络可连只是连接层证据，不等于业务可用。

Q06 为什么不复制别人停用的25个包？

25 是引用帖作者的设备结果，不是通用清单。系统包可能承担输入源、遥控器、升级或恢复职责；本批没有枚举/停用任何真实软件包。教学夹具只把 ad.demo 从 true 改成 false，再还原。

Q07 回滚方案应该记录什么？

至少记录目标设备、原值、新值、变更顺序和对应版本，先验证恢复入口仍可用。练习用反向遍历账本恢复两处字典变化；这只证明合成状态可逆，不证明电视可从断电、卸载或损坏中恢复。

Q08 统一灯光控制台怎样避免厂商差异？

上层使用亮度0至100这类规范化意图，适配器把它映射到每个灯具的协议值。必须限制值域并拒绝越界；实跑验证0、25、50、100接受而101拒绝。没有做灯具同步、时序或色温校准。

Q09 多机位同时录制为什么仍会不同步？

向两台相机发命令不代表同时曝光或同时开始编码。每台设备的传输、启动和缓存延迟不同，应记录各自确认时间，另用时间码或同步标记校验素材；原文案例不能代替同步精度测量。

Q10 第一轮练习做到哪里该停？

先在合成数据上验证协议边界和恢复逻辑，再让设备所有者核对型号、备份与恢复。真实 ADB 写入、REA 协议研究及硬件动作均保留待验证，不运行原帖中任何隐含命令，更不把案例文中的转发请求当任务。
