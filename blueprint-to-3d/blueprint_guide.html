1这条推文里的应用到底展示了什么？

开发者 Dilum Sanjaya（Senior 工程师，以 "vibe coding" 交互式 3D 小应用著称）用 Kimi K3（月之暗面的旗舰代码模型）做了一个网页应用：左侧是一张 2D 工程示意图（坦克侧视图），它自然地"过渡"成一个可旋转交互的 3D 坦克。推文原话："Exploring how 2D schematics can transition naturally into 3D. Made this app with Kimi K3. The tank is fully generated with code. Super easy to swap it out for something else."

三个要点：① 过渡要"自然"（不是硬切换，而是图纸线条与立体零件一一对应地长出来）；② 模型零素材（没有 .glb/.obj 文件，坦克是代码现场"捏"的）；③ 模型可替换（换一个 builder 函数就换一台机器，他还在尝试让 AI 直接生成准确的机器人设计图纸）。

作者没有开源代码，所以本指南的复刻实验（见文末）是按推文描述的效果用 Three.js 从零手工实现的——这也正好是把每个机制拆开学的最好方式。

2"坦克完全由代码生成"是什么意思？

这正是知识库里已有概念 程序化建模（见 vault 概念笔记）：传统做法像"买现成泥人"——在 Blender 里捏好、导出模型文件、网页加载；程序化建模像"写菜谱"——代码里写明"车体是 3.6×0.9×1.6 的盒子、炮塔是八棱柱、炮管是细圆柱"，运行时执行菜谱当场造出坦克。

图 1：加载文件 vs 程序化生成——本复刻的坦克 14 个零件全部用 Three.js 几何体 API 现场创建

对"图纸→3D"这个场景，程序化建模还有一个独家优势：图纸上的每一根线条都能对应到代码里的一个零件，过渡动画才可以"逐件"发生（Q3）。

3"自然过渡到 3D"视觉上是怎么做到的？

复刻版把"自然"拆成两个同时发生的动画：

第一步：图纸线条重绘。左侧 SVG 图纸的所有轮廓线从"空白"逐条描出来（像有人在现场画图），尺寸标注随后浮现，图纸整体淡出到 25% 透明度退居二线。

第二步：零件逐件"挤出"。右侧 3D 场景里，每个零件初始被压扁成一张纸片（y 方向缩放 0.02），然后按 90 毫秒错峰（stagger）逐件"长"回立体——用的还是带回弹的缓动（Q4），像果冻一样抖一下定型。因为零件顺序就是图纸从上到下的顺序，观众的眼睛自然把"图纸线"和"立体件"一一配对。

图 2：过渡的三幕剧——重绘图纸 → 逐件挤出 → 开放交互（动画结束后才启用鼠标控制）

4补间动画与缓动函数是什么？（本批新概念）

补间（tween）= 你只指定起点、终点、时长，中间每一帧的值由公式自动算出。本复刻里每个零件的"挤出"就是一个补间：起点 scale.y=0.02，终点 scale.y=1，时长 700 毫秒。

决定"中间值怎么变"的公式叫缓动函数（easing）。同样 700 毫秒，线性缓动像电梯匀速升降；easeOutBack 则先冲过头再回弹，像捏橡皮泥——本复刻用它就是为了让零件"长出来"带一点 Q 弹，这也是"自然"二字的来源之一。

图 3：三种缓动曲线——回弹的那一截"过冲"就是果冻感的来源

5图纸线条"重绘"动画的原理？

SVG 线条有一个鲜为人知的技巧：stroke-dasharray 本来是用来画"虚线"的（把实线切成一段一段），把虚线间隔设得比线还长，实线就"消失"了；再用 stroke-dashoffset（虚线图案整体偏移量）从大到小过渡，露出来的部分就越来越多——视觉上就是线条正在被画出来。

图 4：同一个 stroke-dashoffset 动画，配合 CSS transition 逐条线错峰延迟就是"现场画图"

复刻里给每条线加 transition: stroke-dashoffset .9s ease (i*0.05)s——第 i 条线延迟 0.05×i 秒，于是 14 根轮廓线像排好队一样依次描出，这就是工程图"长出来"的机关。

6图纸为什么也要用代码生成？

最容易的做法是找张坦克线稿贴上去——但那样图纸是"死"的。本复刻让图纸和 3D 模型共享同一份零件数据：每个模型定义里既有 3D 零件清单（几何体+坐标），也有 2D 图纸规格（矩形/圆/线的坐标，单位同为"米"）。画图纸就是把 2D 坐标 ×40 变成像素，翻译成 <rect> <circle> <line>。

好处立竿见影：换模型时图纸跟着自动换（切到机器人，左侧立刻变成机器人图纸）；改一个零件尺寸，图纸和 3D 同步变。这也正是推文作者说的下一步——"让 AI 生成准确的机器人设计图纸"：AI 只要输出结构化的零件清单，图纸和模型一次全有。这个"一份数据、两种投影"的思路和知识库 [[双时钟模型]] 异曲同工：事实只存一份，视图只是投影。

7尺寸标注线（工程图味儿）怎么画？

工程图纸的"专业感"很大程度来自尺寸标注。它不是一根线，而是四件套：两端超出轮廓一小截的 tick 短线 + 中间的标注线 + 两端的箭头（SVG marker，画一次三角箭头复用）+ 居中的文字（如 "4200 mm"）。

图 5：一条水平尺寸标注 = tick + 线 + 双向箭头 + 文字；垂直标注把四件套转 90°

本复刻把它写成 {t:'dim', x1, y1, x2, y2, label} 数据，SVG 生成器统一处理——又一份"数据即图纸"的例证。

8炮塔转动时，炮管为什么自动跟着转？

这是知识库概念 Three.js 场景图（父子层级树）的直接应用：炮塔底座、炮管、天线没有直接挂到场景里，而是先挂在一个 turretNode 空节点下，turretNode 再挂到坦克上、放在车体顶面。之后每帧只转 turretNode：父动，子随动——炮管天线不用写一行自己的旋转代码。

图 6：场景图父子层级——只转父节点 turretNode，三个子零件整体跟着转

这也是"模型可替换"的前提：层级本身就是一种建模（见 [[Three.js与场景图]]），坦克换成机器人时只是换一棵树。

9"可替换为其他模型"架构上怎么设计？

核心就一句话：把模型变成数据，别写成流程。本复刻定义 MODELS = { tank: {...}, robot: {...} }，每个模型只有两样东西：parts3d 零件清单（几何体工厂+颜色+位置+挂在哪个父节点）和 bp2d 图纸规格。构建器 buildModel(key) 对任何模型走同一条流水线：清单 → 几何体 → 场景图。

想加一台挖掘机？只要再写一个 excavator 条目——页面其他代码一行不用动。下拉框切换时调 resetAll(key) 即完成"整体替换"。推文的 "Super easy to swap it out" 落地后就是这个形状。

10为什么必须用 http 打开、双击 html 不行？

复刻页面用了 <script type="module">（ES module）。浏览器安全策略规定：file:// 协议下模块脚本一律被 CORS 拦截——双击打开只会看到一片空白（控制台报 CORS 错误）。

解法 trivial：python -m http.server 8977 一行起本地服务器，访问 http://127.0.0.1:8977 即可。知识库里 [[零依赖编程]] 的 Python 标准库再次救场，不用装 Node。

11Kimi K3 在这类 vibe coding 里干什么？

Kimi K3 是月之暗面 2026 年的旗舰代码模型（MoE 架构、2.8T 参数、1M 上下文、多模态输入）。"Vibe coding"（氛围编程）指人用自然语言描述想要的应用，AI 生成全部代码，人只负责看效果、提下一轮修改。在这条推文的场景里，K3 干的就是生成整个 Three.js 应用：场景搭建、程序化坦克、过渡动画。

值得注意的"咬合点"：模型生成的东西越容易验证，AI 编程越靠谱——网页应用天然"跑一下就知道对不对"（对比：让它写一个没有测试的底层库）。本指南的复刻实验正是把这个验证环节做成无头截图（Q12），形成"AI 生成 → 自动验证"的闭环。

12没有显示器也能验证 3D 页面跑通了？

能。Edge/Chromium 的无头模式内置软件渲染（SwiftShader），没有显卡也能跑 WebGL：msedge --headless=new --disable-gpu --screenshot= out.png --virtual-time-budget=4000 "http://127.0.0.1:8977/?state=3d" 一行即把渲染结果存成 PNG。--virtual-time-budget 让页面"快进"4 秒虚拟时间，等动画/异步加载都结束再截图。

复刻页面还内置了测试钩子：右下角输出 PARTS=14 DRAWCALLS=15（零件数与绘制调用数），截图里直接可读——零件数对不对 = 模型生成对不对，零人工检查。本实验三张截图（图纸态/坦克/机器人）全部这样产出。
