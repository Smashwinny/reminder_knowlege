02 / 疑问即目录

01 这个 Anatomy 到底是什么？

官方仓库把它写成一个 Agent Skill：给 Claude Code 用，也兼容 Antigravity、OpenCode、Codex 和 MiniMax Code。你用一句话点名要解释的概念，代理就发明一台能运转的等轴测装置，并画成可交互的 SVG / HTML / React 图。它是 MIT 开源技能，不是单独售卖的配音视频产品。

依据：S3, S4

02 原帖实际写了什么？

数字生命卡兹克的长文介绍了这个技能，举了机械表、劳斯莱斯 Trent 970、显卡、TCP 三次握手和刹车等例子；并指出门外汉看纯动画仍可能看不懂，于是用 Opus 5.5 再生成带讲解和配音的视频，最后对照 Karpathy 的四种学习形式。这些效果、耗时和额度都是作者经验。本次没有观看文中视频，不把画面写成事实。

依据：S1

04 “物体本身就是解释”是什么意思？

SKILL.md 和官网都把 The object is the explanation 写成第一条规则：不要画方框和箭头，而要发明一台真正能运转、其运动就是概念本身的装置。例如“一个 GPU 上下文服务多块画布”被映射成打印头拜访 16 个井的龙门绘图仪；官网把 TCP 握手映射为两站之间的邮筒索道（mail ropeway）。

04 / 疑问即目录

05 官方输出是网页，还是配音视频？

官方产物是独立 HTML、内嵌样式的 SVG，或 React / Next.js 组件；可加 WebGL，3D 模式仍标为测试；还可以从同一模型打印 A4 海报、图纸或讲义。SKILL.md、README 和官网都没有把配音科普视频写成技能功能。带讲解的视频是原帖作者在交互动画之上的延伸，也对应 Karpathy 最看好的形式，但那条工作流仍待验证。

依据：S3, S4, S5, S1

06 怎样安装？需要密钥吗？

官方安装命令是 npx skills add wheresryan22/anatomy，也可以 git clone 或下载 ZIP，放到对应代理的 skills 目录。README 写明不需要 API 密钥，也不需要 npm install 工具包。本次没有做全局安装，只用已复制的 kit，在本地把官方 dial-indicator 示例重建成浅色页。

08 为什么纯动画对门外汉可能不够？

这是原帖作者的观察，不是官方缺陷声明。他写：精致机械动画对已有基础的人很直观，但对零件名称、作用和计时原理一无所知的人，即使对着技能自带的文字讲解也会费劲。因此他主张在旁边增加讲解：这是什么、正在发生什么、为什么、有什么用。

06 / 疑问即目录

09 额度和“一个半小时”能当实测吗？

不能。原帖称 5 分钟 TCP 视频大约消耗 200 美元 Claude Max 周额度的 1%，Opus 5.5 Ultra 大约 1.5 小时。这些没有公开账单，本次也没有调用付费模型。可以对照的是官方自己公布的主动耗时：机械表 1 小时 54 分。官网把“细节需要时间，所以我宁愿展示真实数字，而不是猜测”写成作者立场。官方图耗时不等于原帖视频耗时。

依据：S1, S5

10 Karpathy 的四种形式怎么对照？

被引用的长帖（2026-10-02 08:37 CST，UTC+8）建议：用 ASD-STE100 这类受控英文写得更清楚、直接画图、做可交互 HTML，以及他最看好的定制讲解视频。Anatomy 的官方主产物对应第三种；原帖额外做的配音视频对应第四种。原帖也强调四种形式并不互相替代：文字便于查阅，图展示关系，网页可动手探索，视频按顺序讲过程。

依据：S2, S1

08 / 能力、实验、来源与诚实边界

可以用来做什么（非产品效果承诺）

  • 按需请代理做交互原理图，先自己动手摸结构，而不是只收藏别人做好的视频。
  • 按学习阶段在文字、示意图、交互网页和讲解视频之间切换，不默认某一种最好。
  • 用官方 audit、capture，或至少用键盘和读数做验收，而不只看画面是否精致。
  • 把 AI 讲解当草稿，对照 RFC 等一手规范核对状态与序号；给门外汉补旁白。

实验目录：/workspace/reminder-batch-2026-11-11/item-4-anatomy。完整命令与输出见 experiment-log.md。

步骤 1 · 重建官方拨针量表。目的：确认 kit 能在本地重建浅色示例页。
cd exercise/upstream/examples/dial-indicator && node build.mjs --light
真实结果：写出 136,489 字节的 dial-indicator-light.html，SHA-256 为 bc1810e340d916a25cc1749589b44096b7e41970f22fa7fce569bbefc0613093，与该提交原始文件一致。验证：大小与哈希相同。

步骤 2 · 无头浏览器驱动官方示例。目的：在禁止外网、降低动态效果时，用键盘改量块读数。
PYTHONPATH=../vendor python3 exercise/check.py browser && python3 exercise/check.py verify
真实结果：Home / ArrowLeft / End 得到 18.0、14.0、10.0 px；342 条路径；无脚本错误，无 HTTP。三幅姿态图不同。验证：退出码 0，6 项 PASS。不是机械精度或教学法审计。

步骤 3 · 运行 RFC 793 图 6 纯模型。目的：不打开浏览器、不调用模型，核对状态和序号。
python3 exercise/tcp_model.py
真实结果：14 项断言通过。SYN 占用序号，ACK=101 确认 SEQ=100；第 2 步 A 已 ESTABLISHED、B 仍 SYN-RECEIVED；ACK 不占用序号空间。验证：assertions=14 failed=0。

步骤 4 · 无头浏览器驱动教学页。目的：手写邮筒索道页与纯模型读数一致。
PYTHONPATH=../vendor python3 exercise/lab.py tcp
真实结果：四步读数完全一致；无脚本错误，无 HTTP。验证：tcp-results.json 里 errors 与 network_attempts 都是空列表。

步骤 5 · 核对不对称状态与截图。目的：第 2 步教学要点被真实渲染，且起止画面不同。
PYTHONPATH=../vendor python3 exercise/lab.py verify-tcp
真实结果：第 2 步为 ESTABLISHED / SYN-RECEIVED；tcp-step-0.png 与 tcp-step-3.png 有像素差异。验证：退出码 0。

步骤 6 · 留下源文件指纹。目的：给官方构建脚本、kit、重建页和教学模型留下哈希。
python3 exercise/lab.py hash
真实结果：build.mjs e4eaa2…8990d；iso-kit.mjs 6d3ecc…04018；浅色页 bc1810…13093；tcp_model.py d75b90…cd9fb；tcp-handshake.html caf9a3…42bdb。验证：同样输入再重建，官方浅色页哈希不变。
