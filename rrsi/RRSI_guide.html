让 AI 针对失败的检查重写 agent 的系统提示词——Google Research 的做法，以及它防翻车的四道闸门

0 | 这条推文说了什么（溯源）

起点是 X 用户 @N01ennn 的高赞转发（7 万+浏览）："Google 工程师讲了如何让 AI 针对失败的检查重写 agent 的系统提示词——失败检查变成下一个修复任务，回归套件盯着这次修复破坏了什么。" 顺着引用链追到底，本体是两篇 2026 年的工作：

RRSI = Regularized Recursive Self-Improvement of Agent Harnesses：把 agent 的"挽具"（系统提示词、控制流、工具、记忆、上下文管理）当作可进化对象，让 LLM 在一个评估驱动的循环里反复改写自己的 harness。14 位作者，代码开源在 google-research 组织下。

1 | 十二问解答（疑问即目录）

Q1"让 AI 重写系统提示词"到底是个什么流程？
一句话：把系统提示词当源代码，把评估集当测试套件，跑一个"改提示词→跑测试→只留变强版本"的进化循环。Google 的代码里每轮分两步——算法 1（提案侧）：分析当前失败轨迹 → 按预算起草候选 → 泄漏审查；算法 2（选择侧）：整套评估 → 四道闸门筛选 → 赢家上岗。落选候选连同分数、理由全部记进 history.jsonl，下轮提案时喂回给模型——被证伪的假设不会被重提。
Q2不搞正则化，直接进化会怎么翻车？
论文的实验发现：无正则化的 RSI 会把训练题背下来——进化集分数大涨（最高 +14.1 分），换一套没见过的题分数就地蒸发。本指南的迷你复现实验（见实验二模式三）完美复刻了这种翻车：写死答案爬到进化集满分，留出的回归套件得分全程为 0，token 成本反而是诚实版的 2.6 倍。所以 RRSI 的全部精髓不在"进化"，而在"正则化"——四道闸门（Q5~Q8）。
Q3什么是 harness？进化它和"调 prompt"差在哪？
harness = 模型外面的一切运行环境（见知识库 [[AgentHarness智能体挽具]]）。RRSI 的可编辑组件集 K 有 9 类：prompt / control_flow / config / output_plumbing / context_mgmt / client_tool / skill / memory / subagent。提示词爬山法只调"配方里的一句话"，RRSI 连配方、锅、灶台、进货渠道一起换——但约束只加在"搜索怎么走"上，不限制"挽具最终能长什么样"（开放编辑空间）。
Q4一轮进化循环里发生哪 7 步？
对应源码 rrsi/loop.py 的 Run.round(t)，README 有逐条"论文公式→代码位置"映射表。
Q5编辑预算为什么要"余弦退火"？
公式：b_t = ceil( b_min + (b_max-b_min)·½(1+cos(πt/T)) )。开局允许一个候选捆绑多处协同编辑（反正离最优远，怎么改都是往上走），临近收尾每轮只许改一处——因为每处编辑都要能单独归因"是它带来涨分"。官方单测第一条就锁这个公式。
实测 budget_table(T=10, 1..4) → 4,4,4,4,3,3,3,2,2,2（实验一第 1 段）
Q6噪声地板 delta——先承认"打分是有抖动的"
同一 harness 跑两次分数都不一样（模型采样有随机性）。比历史最高 S* 还低 delta 以内的"涨分"一律当作噪声不算数：admissible ⟺ S' ≥ S* − delta。delta 不拍脑袋：用 calibrate.py 对基线评估做 bootstrap 自助重采样估计出噪声带。这是防"自我安慰式改进"的第一闸。
Q7成本规则：涨分必须付得起 token 账
两条分支：真涨分（ΔS>delta）时，成本涨幅要 ≤ 预算 β₀ + β₁·ΔS——涨得多才许花得多；带内微涨时改用整形分 w_s·ΔS − w_c·ΔC + w_n·ν > 0，其中 ν=触及"从没被采纳过的结构组件"的数量，只作带内平局打破，鼓励探索新机制但不许抢真涨分的位。实测 E 候选 ΔS=+0.20 但 ΔC=+8.60 > 预算 8.10，被一票否决（实验一第 2 段）。最终版本比无正则进化省 30% 策略 token。
Q8Critic 六条拒绝规则都在防什么？
Critic 在评估花钱之前读 diff，专抓"作弊/退化/自杀式"编辑：①泄漏/任务特化——diff 里出现任务名、实体名、任务专属魔数（试金石：这条改动放到另一套题上还成立吗？）；②退化——声称加了机制其实是死代码，或删了安全机制没补；③评分器作弊——偷读判分逻辑、硬编码阈值；④未申报捆绑——夹带申报清单外的私货；⑤运行时记忆泄漏——跨 trial 持久化任务专属数据（这是背题不是改进）；⑥无界工作——没有退出条件的"继续改进"循环。拒绝意见回灌提案者修一轮（bounded repair），修不好就丢弃且不许再提。
Q9组件标签怎么防"谎报军情"？
提案者要给每条编辑申报改的是哪类组件，但申报不算数，diff 里必须有证据：text_only() 发现所有改动行都是字符串字面量/注释 → 一律判 prompt；结构性组件（tool/skill/memory/subagent）各有正则信号（如 skills/、register_tool、.remember(）。把控制流改动谎报成"探索新组件"骗探索槽？重标回真实类型，探索槽作废。实测四种谎报全部被纠正（实验一第 3 段）。
Q10候选为什么放进 git worktree？
每个候选在 evolve/<domain> 分支上开自己的 worktree 和分支起草，审查、评估、提交都在自己树上进行；采纳就 fast-forward，现任 harness 永远是一个 commit——出问题可回滚、可 diff、可审计。这正是知识库 [[GitWorktree并行隔离]] 思想的教科书用法。
Q11每条编辑的"功劳"怎么算？卡住了怎么办？
归因：提案者要预言每条编辑影响哪些题，事后对照逐题分数算 predicted_hit 命中率，还要列出"没预料到的回归题"——连月累积成提案者的"信用分"。停滞检测：近 w 轮涨幅 ≤ delta 就拉响停滯旗标，下轮强制留出"reserved 探索槽"去碰从没试过的组件。剪枝：近期收益为负的机制，连着它在任的代码一起交还提案者移除。推文说的"回归套件盯着这次修复破坏了什么"在这层落到代码：每轮记录 unpredicted_regressions。
Q12引用链另一半：graph / loop / harness 三层工程是什么？
arXiv 2609.00050（推文转发的 X 长文的原型论文）把 agent 工程分三层：graph engineering 管长流程怎么走（带验证门控的步骤转移）、loop engineering 管失败了怎么爬起来（有界的诊断→修复→重试→复验）、harness engineering 管零信任执行（身份、授权、隔离、运行时护栏）。RRSI 是第四维：让 harness 自己变强的"元循环"——三层是造车，RRSI 是让车自己升级（见知识库 [[图环挽具三层工程]]）。

4 | 一句话带走 + 三个坑

把系统提示词当代码：有测试（评估集）、有回归套件（留出集）、有 code review（Critic）、有性能预算（成本规则）、有 git（worktree 候选）——"提示词工程"到这一步正式成为"提示词软件工程"。
坑1 · 只看进化集分数
没有留出回归套件的"自动优化"都是在鼓励背题。任何 prompt 自动优化先建留出集。
坑2 · 分数抖动当真涨
不校准噪声带 delta 就接受"+0.01"，进化环会围绕噪声原地打转甚至错误采纳。
坑3 · 大胆捆绑式重写
一次改十处的"大优化"无法归因也无法回滚——退火预算的本质是可归因性。
