```markdown
# MCP（Model Context Protocol）

**一句话**：Anthropic 提出的开放协议，统一规定 AI 应用如何发现、描述和调用外部工具与数据源。
**领域**：agent 工具生态 / 协议标准。

要点：server 注册工具（名字+描述+zod 参数 schema），client 握手→listTools→callTool；
传输层有 stdio（本地子进程管道，适合桌面客户端）与 HTTP/SSE（适合远程共享）两种。
把"N 个客户端 × M 个工具"的适配问题变成统一插座。

**关联**：[[12306_mcp]]、[[agent-harness]]、[[agent-engineering]] 等项目均涉及工具接入；
zod 参数校验对应输入侧的证据守门。
```

```markdown
# 网页接口包装为工具

**一句话**：把无公开 API 的网站网页后端接口，包装成 AI 可调用的标准工具的通用方法论。
**领域**：agent 工具开发。来源：[[12306_mcp]] 项目（也可参照 WeChatBridge 等）。

四件套：
1. 动态路径探测——目标站接口路径会变，启动时先请求 init 页探测现行路径；
2. Cookie/会话预处理——先取会话凭证再调查询接口；
3. 输入翻译——LLM 说"北京"，内部查索引表转站点代码；
4. 输出翻译——把密麻字段格式化成自然语言结论（余票/价格/时刻）。

**关联**：[[MCP模型上下文协议]]（承载协议）、[[证据优先质检ProofOverClaims]]
（包装≠背书，网页数据时效与稳定性有限）。
```

```markdown
# 工具分层依赖模式

**一句话**：数据查询类工具分"基础层（查地址/翻译）+核心层（办正事）"两层，核心层依赖基础层产出。
**领域**：agent 工具设计。来源：[[12306_mcp]] 八个工具的分层。

动机：LLM 不会背内部代码（车站 telecode、数据库 ID），必须先调基础工具把自然语言
翻译成系统标识，再调核心工具；同时每层独立可测。
例：get-station-code-of-citys("北京")→BJP，再 get-tickets(BJP→SHH)。

**关联**：[[MCP模型上下文协议]]；与 [[agent-harness]] 等项目的工具注册同构，注意查重复合并。
```
