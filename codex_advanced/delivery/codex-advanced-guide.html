01

进阶到底要看懂哪几层

先辨认执行位置和协议层，再讨论模型

Codex 不只是一个模型名。客户端是你操作的界面；运行时负责会话、工具和执行；模型完成推理。Cloud 是托管任务环境，App Server 是把 Codex 能力接入自有客户端的协议接口。它们处在不同层。

把问题拆成“谁发请求、在哪执行、谁来推理、怎样授权”。例如同一个模型名出现在配置和目录中，仍不能回答代码在哪里运行、账户能否访问。本次只验证两份公开 schema 的数据结构。

依据 Codex Cloud · App Server 协议

02

订阅登录和 API 是一回事吗

登录路线影响用量归属，不能推导无限或免费

认证是确认“你是谁”。官方提供 ChatGPT 登录和 API key 等认证路线；ChatGPT 登录使用订阅相关的 Codex 访问，API key 路线使用 API 的用量计费。具体可用性、限制及组织策略要单独核查。

OAuth 是授权客户端取得一定访问权限的机制，不是把订阅变成通用免费 API。官方面向开源或本地托管应用提供明确授权的 ChatGPT 登录集成，但有支持范围和安全要求。本实验没有登录、读取令牌或发起计费请求。

依据 登录方式与计费边界 · ChatGPT 登录集成

03

Cloud 和远程客户端差在哪里

远程连接是一条通道，Cloud 是一种执行安排

Cloud 任务由托管环境处理，官方文档说明使用 Cloud 需要 ChatGPT 登录。远程客户端则描述界面与 Codex 运行时之间的连接关系；它不自动把运行时变成 Cloud，也不自动提供订阅或额外权限。

可以把界面理解为遥控器，把运行环境理解为工作台。遥控器在别处，不会改变工作台的文件、网络或账户规则。判断数据会去哪里，应核对真正的运行主机、传输边界与认证方式，不能只看 UI。

依据 Codex Cloud · App Server 协议 · 登录方式与计费边界

04

为什么能登录还可能不能调用

身份、权限、模型资格和费用要分别举证

授权是决定“允许做什么”；模型资格是账户或组织能否使用某个模型；计费归属说明用量记到哪里。它们与认证相关，却不是同一个事实。一个成功登录记录不能同时证明另外三项。

排查时逐层问：身份是否有效？这项操作是否被允许？这个账户是否有目标模型资格？走的是哪条用量路线？本包的离线通过结果只回答字段形状，不替代以上任何一层，也不提供绕过限制的方法。

依据 登录方式与计费边界 · 高级配置 · App Server 协议

05

配置为什么写了却没有生效

先看来源、优先级与信任，再看字段拼写

配置叠加是将多个来源合成为最终设置。来源包括命令行覆盖、项目层、profile 文件、用户配置等；这里不枚举完整优先级。项目层还受目录层级与信任约束。一个 TOML 文件能解析，只证明文本语法成立。

因此要分三次检查：TOML 能否解析；解析后的对象是否符合版本对应的 schema；真正加载时该来源是否被采用并允许覆盖。本实验只做前两项，不读取或写入真实配置，更不声称看到最终生效配置。

依据 配置基础 · 高级配置 · 固定版 ConfigToml schema

06

Provider 字段为什么也会误导

配置路由描述不等于真实服务能力

Provider 是模型服务的连接描述，可能包含服务地址、协议形式与认证相关配置。requires_openai_auth=false 也不表示无需认证。结构合规只说明字段被 schema 接受，不能证明端点可达、协议兼容、凭证有效或模型可用。

2026-10-05 核查的官方高级配置明确说明：model_provider 与 model_providers 属于用户级配置，项目级 .codex/config.toml 中这些键会被忽略。这个结论来自文档，不是本次运行时测试；不要用项目文件的 schema 通过反驳它。

依据 高级配置 · 固定版 ConfigToml schema

07

沙箱和审批到底管什么

沙箱限定能做的事，审批决定何时询问

沙箱是对执行环境的技术限制，例如文件写入和网络范围；审批策略规定哪些动作要等待同意。两者是独立维度，减少询问不会凭空扩大环境能力。组织策略或上层系统还可以施加更严格的约束。

旧配置示例也要看日期。2026-10-05 核查的官方文档把 untrusted 审批策略标为已退役；固定版 schema 中仍有相关枚举，并不使其成为当前推荐。我们的样例用于形状测试，没有修改任何沙箱、审批或全局设置。

依据 高级配置 · 固定版 ConfigToml schema

08

Thread Turn Item 怎么串起来

用对象层级理解会话，用事件理解进展

在 App Server 中，Thread 表示会话容器；Turn 是一次用户输入触发的处理轮次；Item 是该轮中的输入、输出或执行记录。JSON-RPC 是请求与响应使用的方法、参数和标识约定。

请求用 id 对应响应中的 result 或 error；通知没有 id。一次轮次可以产生多条 item 与通知，收到一条消息不代表全部完成。官方 App Server 的 JSON-RPC 2.0 消息省略 jsonrpc 头。本次只校验合成请求，没有发包或创建会话。

依据 App Server 协议 · 固定版 ClientRequest schema

09

请求格式对就能直接发送吗

格式合规不代表生命周期合规

生命周期是协议规定的先后状态。官方基本流程为 initialize 请求及响应，再发 initialized 通知；随后 thread/start 建会话，turn/start 开始一轮，最后检查 turn/completed 的状态与结果。顺序与终态需要运行时证据。

我们故意使用不存在的合成标识，展示“能通过 schema”与“真实对象存在”互不等价。校验器是静态检查者，不维护服务端会话状态。测试成功的含义是反例符合预期，而不是后端执行成功。

依据 App Server 协议 · 固定版 ClientRequest schema

10

model list 能证明模型权限吗

目录里能看见，与账户能使用是两份证据

model/list 是 App Server 的模型目录查询方法。目录可以帮助客户端展示模型和选项，但目录条目不是一次授权判决，更不是成功推理或费用证明。本次连这个目录接口都没有调用。

一个合成模型名可能是合法字符串，因此通过 schema。要证明真实可用，需在明确授权的环境与账户里核对官方可用性，并用符合权限与预算的操作验证；本指南不把这种在线验证伪装成本次离线结果。

依据 App Server 协议 · 登录方式与计费边界 · ChatGPT 登录集成

11

JSON Schema 到底证明什么

它验证契约的形状，不替运行时做决定

JSON Schema 是描述数据结构规则的标准；Draft-07 是这次两份官方 schema 声明的规范版本。校验器检查类型、必填键、枚举和分支等规则。TOML 先被解析为对象，再接受 ConfigToml schema 校验。

我们分别使用合法、非法与“形状合法但语义未知”的合成样例，观察通过和错误路径。真正的进阶点是划清证明边界：schema 的成功不是配置已采用、请求已执行、模型已授权或费用为零。

依据 固定版 ConfigToml schema · 固定版 ClientRequest schema

依据 固定版 ConfigToml schema · 固定版 ClientRequest schema · 上游 Apache 2.0 许可

五项能力

  1. 拆分产品与执行边界：先问客户端、运行时和模型各在哪一层，避免把“远程”和“Cloud”混成一种能力
  2. 核对身份和用量路线：分别记录认证、操作权限、模型资格和计费归属，不从订阅名称推断免费或无限
  3. 审查配置的实际含义：区分文本解析、schema 接受、来源生效和运行结果，发现旧示例与新文档的差异
  4. 阅读协议对象与状态：辨认 Thread、Turn、Item 与初始化流程，区分请求格式和服务端生命周期
  5. 设计可复验反例：把合法、非法和语义未知样例放进同一套离线验证，给每项结论标上证据边界

五个具体用途

  1. 审阅一份 Codex 配置教程：标出过期审批示例、错误配置层级与缺失的版本信息
  2. 设计自有客户端的接入评审：先画握手与会话状态，再讨论 UI 和消息展示
  3. 排查“名字写对却调用不了”：把字段错误、加载规则、账户资格与计费路线分开查
  4. 给自动化流水线增加配置预检：在接触真实账户之前，先离线阻止明显类型与枚举错误
  5. 整理知识库：把 schema 契约与既有证据状态、边界控制知识关联，避免重复新建概念

这些用途从阅读、设计与离线检查开始。真实连接、凭证配置、模型请求和费用相关动作，仍需对应环境、权限和明确授权。

怎样解释结果

正例

25 项样例全部符合预期，其中 8 项被接受。配置空对象、合成 Provider 以及部分协议请求形状可以通过；这是本地校验器的判断，没有被真实运行时采用。

反例

14 项被 schema 拒绝，另有 3 项在 JSON/TOML 解析阶段报错。数字模型名、字符串布尔值、未知枚举、缺失必填项和坏文本可定位到不同错误层。

语义陷阱

协议测试接受了合成模型名和不存在的 threadId，还接受了本包测试的额外 envelope/ClientInfo 字段；配置测试则拒绝未知字段。结果不能推广为全局兼容规则，也不能证明服务、权限或模型可用。
