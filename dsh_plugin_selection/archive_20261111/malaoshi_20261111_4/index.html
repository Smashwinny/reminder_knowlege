【源码证实】rewind 的说明是同一会话内移除目标消息及之后上下文/界面记录，并回填目标输入；源日志保留回退标记。文件侧跟踪写工具，在写入前留备份，不依赖 Git。因此它不等于分支回滚、全仓备份或任意时刻磁盘快照。源码格式检查通过也不能证明真实宿主能恢复全部编辑。

五个用途，四条不越界规则

用途 1：低成本试错

用一次性仓库和公开小文件练习“对话回退/文件恢复/分支恢复”三个验收点；先有 Git，不用正式项目测试逆操作。

用途 2：解释消耗

按请求分组、区分缓存桶和长上下文费率；看板帮助定位消耗，不以预算提醒替代硬限额，不以 API 等价值替代订阅账单。

用途 3：统一审查入口

需要独立子上下文时看 Micheng；需要 Git/SVN 预览与明确范围时评估 feng，但商业用途先处理其许可证授权。两者都要人工核对报告引用与测试证据。

用途 4：复用架构图资产

复用既有 archify 教程/IR，把新知识限定在 DSH provider、实际 Skill 来源与三坐标版本；不因为包更新就认定图已重验。

用途 5：建立团队候选卡

卡片字段固定为痛点、owner、npm 身份、SHA、宿主、许可证、权限、真实实验与未测项。只提交本地学习候选，不自动替团队部署或发布。

四条边界：不拿热门当安全；不拿文档当实测；不拿组件当端到端；不拿“源码公开”当无限商业许可。以上用途是建议，不是本次部署结果。
