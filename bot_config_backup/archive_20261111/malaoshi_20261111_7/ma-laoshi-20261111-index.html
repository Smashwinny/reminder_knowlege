04 为什么 fine-grained 比 classic 收敛？

【源码证实（官方文档）】fine-grained 可限定一个资源所有者、指定仓库及细化权限；不能超过本人已有权限，还可能等待组织审批。classic 的实际能力也受 scope/组织策略限制，“任何 classic 都碰所有仓库”过度简化。本研究不创建任何 token。

证据：GitHub token 文档 S3。本例代码路径 exercise/ma-laoshi-20261111-backup.py。

05 Contents 读写是否万能？

【源码证实（官方文档）】Contents write 包含 read，普通内容推送以此为最小方向，但不等于全部 GitHub 功能；workflows 是单独权限。组织政策、分支规则和审批仍可能阻断。【未验证】真实仓库的权限最小集合需在获授权环境验收。

证据：S3 的 Permissions 与 Repository permissions。本例代码路径 exercise/ma-laoshi-20261111-backup.py。

06 为什么新仓库不勾 README？

【作者说法】作者推荐空仓库。【源码证实】Git init 建立未含提交的初始分支；空远端可避免首次推送遇到双方不同根历史。README 不是安全威胁，也不是永远不能存在；已有提交应正常对齐历史，不能随意 force。

证据：S1/S2；Git git-init.txt:17–23、44–47。本例代码路径 exercise/ma-laoshi-20261111-backup.py。
