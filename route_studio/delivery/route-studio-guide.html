01

一条路线到底流经哪些层

路线数据、数学采样、设备效果，是三层不同证据。

Route Studio 是本地路线编辑与授权设备定位测试工具。路线草稿先保存点的顺序；运动模块按时间算出测试位置；适配器才负责与设备通信。编辑路线不会自动改变设备位置。

本次把第三层完全留在静态阅读范围。真正运行的是固定版 gpx.py 与 motion.py，输入全是原点附近的自建 TEST_ONLY 数据。

依据 Route Studio README · GPX 解析与地理计算 · 路线契约与 Motion 状态

02

GPX 导入成功就一定能用吗

文件能读、点能取、路线能走，要分别验收。

GPX 是存放地理点的 XML 格式。trkpt 表示轨迹点，rtept 表示路线点；它们不是同一个标签。gpx.load_points 只收 trkpt，Web 的导入实现另有 rtept 支持。

因此 README 的整体能力不能直接当作每个函数的承诺。我们的文件只有无时间戳的 trkpt；解析后还要交给 route_points，检查数量和总长度。

依据 GPX 解析与地理计算 · Web 入口静态审读 · Route Studio README

03

坐标数字为什么最容易接错

每个边界都写清字段、顺序、单位和含义。

Point 用 latitude、longitude；route_points 收 lat、lng。纬度是南北， 经度是东西，数值单位为度。距离函数内部换成弧度，输出才是米；速度先由 km/h 除以 3.6 变成 m/s。

例如纬度 0、经度 0.001 是本练习的合成点。不要凭数组的第一项猜坐标顺序，也不要把“0.001 度”直接当作“0.001 米”。这次不采用真实人的位置。

依据 GPX 解析与地理计算 · 路线契约与 Motion 状态

04

哪些输入必须挡在入口外

有限数、范围、节点数、非退化，缺一不可。

有限数指不是 NaN 或无穷。route_points 要求列表有 2 至 10000 个节点、纬度在 -85 至 85、经度在 -180 至 180，总长度至少 0.1 米。同一点重复两次仍可能不构成有效路线。

gpx.load_points 的纬度范围则是 -90 至 90，且只要求至少一个 trkpt。这是两个层次的契约差异，不是“GPX 已通过所以后面必过”。

依据 GPX 解析与地理计算 · 路线契约与 Motion 状态

05

地图上的直线有多长

本版算球面距离；不沿道路，也不取屏幕像素。

distance_meters 用半正矢公式，按半径 6371000 米的球体计算两点大圆距离。总长度是相邻点距离相加；路口、建筑、道路可达性都不在这个函数里。

已有笔记中的 Web 墨卡托是显示投影。它的像素长度不能直接替代地表米数。原点附近经度相差 0.001 度约为 111.195 米，适合本次小范围单元测试。

依据 GPX 解析与地理计算 · Route Studio README

06

两点之间的中间点怎么算

距离用球面公式；插值却是经纬度线性插值。

插值就是用比例选中间值。interpolate 会把 fraction 限制在 0 到 1，再分别线性混合纬度和经度；0 是起点，0.5 是数值中点，1 是终点。结果不带原输入的时间戳。

这个方法在本练习的小范围合成路线里容易核对，却不是完整的大圆插值器。跨日期变更线、长距离和极区都需要额外设计与证据，不能从本次结果外推。

依据 GPX 解析与地理计算 · 路线契约与 Motion 状态

07

速度怎样变成路线进度

推进靠传入的 dt；纯计算不会自己等一秒。

dt 表示本次推进的秒数。关闭两种波动后，每次新增距离为 speed_kmh / 3.6 × dt。Motion 再用累计距离寻找所在路段，算出局部比例并插值。

例如 3.6 km/h 就是 1 m/s，推进 10 秒应增加 10 米。这里的秒是实验传入的逻辑时间；函数耗时和设备延迟是另外的量。advance 自身不校验 dt；调用方仍须保证它是有限非负数。

依据 路线契约与 Motion 状态

08

到终点后为何还有状态要查

位置正确不够，distance、elapsed、laps、done 也要一致。

非循环时，累计距离被限制到总长度，返回 done=True。循环时，超过一圈的部分用取余留作新进度，laps 累加整圈数。elapsed 则继续累计逻辑时间。

重复一遍相同输入，要拿到相同状态序列。测试还要刻意越过终点，不能只看路线中间几个点；跳过零长路段和拒绝整条退化路线是两件事。

依据 路线契约与 Motion 状态

09

假设备为什么仍可能有副作用

桩替掉一个调用，并不保证整个对象没有副作用。

这是已有 StubSeam 概念的一次具体反例：PlaybackController 构造时会启动后台设备发现线程。即使传入 FakeDevice，也不能据此宣称没有设备探测。

本练习不导入 playback、web 或任何设备适配器，只导入 gpx 与 motion。运行器还核查模块加载范围。隔离边界要放在副作用之前，不能等线程启动后再解释。

依据 回放控制器静态审读 · GPX 解析与地理计算 · 路线契约与 Motion 状态

10

已发送位置算手机实测吗

计算出、成功发送、设备读回、现实运动，逐级分开。

README 说明页面橙色标记默认展示最近成功发送的模拟位置，并不是手机读回的真实 GPS。发送成功只能说明这一层调用完成，不能证明其他 App 接受了同一坐标。

本次只达到纯计算层。源码声明的真机接口、模拟标记、融合定位和清理行为均未实机验证；坐标流也不构成人体运动、步数、姿态或 GNSS 观测的证明。

依据 Route Studio README

11

清空和停止为什么要分开

草稿、已载入路线、运行状态、设备状态不是一份数据。

静态审读显示：编辑页清空草稿、停止并清除模拟、清空已载入路线、断开连接有不同作用。部分操作保留路线，部分请求设备清理；设备清理失败时也可能保留数据供重试。

可用已有“可逆派生状态”和“状态外置”理解这个设计。纯数学实验只检查内存里的 Motion 状态，不执行这些按钮，不把源码中的清理分支写成清理已成功。

怎样把结论做成可复验证据

固定版本、固定输入、明确边界、保留原始输出。

练习固定到完整提交哈希；先验证两个模块的 SHA-256，再执行自建测试。输出中保留断言总数、分步摘要和数值结果，失败必须返回非零退出码，不能把“文件已生成”当作实验成功。

五项能力

  1. 路线编辑与导入：项目能力，静态核对：布设节点、编辑草稿、GPX 导入；不同入口标签契约要分开看。
  2. 路线几何与验证：本次执行：范围、有限数、非退化长度、球面距离与局部插值。
  3. 按逻辑时间推进：本次执行：零波动下的速度换算、累计距离、终点限制和循环圈数。
  4. 授权设备的定位测试：项目声明与代码存在，未运行：平台适配器、接口能力和发送结果各有边界。
  5. 会话与操作状态管理：静态核对：草稿、路线、进度、连接和清理分开；实际恢复与清理未验证。

五个具体用途

  1. 给自有地图项目做输入回归测试，挡住 NaN、越界值和整条零长度路线。
  2. 给路径动画核对米、秒、km/h 的换算，定位“走快了 3.6 倍”一类单位错误。
  3. 给路线导入器写契约对照，明确 trkpt、rtept 与各层纬度范围。
  4. 为状态栏设计证据标签，明确“计算值”“已发送值”和“读回值”应如何展示。
  5. 设计未来授权集成测试的验收清单，逐项记录平台能力、失败清理和状态恢复。
