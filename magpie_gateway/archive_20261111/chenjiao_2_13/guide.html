02 / 从概念走到边界

01 本地模型网关解决什么问题？

多个 Agent 各有不同 base URL、模型名和请求格式，网关提供一个稳定入口再路由到提供方。它节省配置重复，不会凭空增加授权、订阅额度或模型能力，也不使不兼容工具语义自动正确。

对照本项来源清单、相关查重笔记与实验日志；合成例不是原作者实测。

02 OpenAI 兼容就能完全通用吗？

不能。Chat、Responses、Anthropic Messages 与 Gemini 的工具调用、流式事件、推理字段和多模态能力不同。README 声称做协议转换，但兼容性要对目标场景实测。本次 mock 只发 JSON，不测试真实模型、流式和工具调用。

03 / 从概念走到边界

03 控制面与数据面怎样分开？

提供方/账号/路由组属于控制面，请求与响应属于数据面，Web 面板管理权又不同于网关调用权。官方固定访问密钥 MAGPIE_WEB_KEY 面向 Web，不应假设它与每个 gateway key 或上游凭据等价。

对照本项来源清单、相关查重笔记与实验日志；合成例不是原作者实测。

04 为什么本次不直接运行 Magpie？

README 写明会读取 CLI 登录文件和系统钥匙串做订阅发现，还可能改 Agent 配置。用户明确禁止真实密钥与安全设置变更，因此用自编 loopback 桩验证路由思想。未安装 Magpie，不需要先关闭其发现设置，也没有更改现有工具。

04 / 从概念走到边界

05 127.0.0.1 是否足够安全？

只是限制监听接口，仍需考虑本机其他进程、反向代理、Origin、Host、管理页面与数据接口。Docker 发布端口的 peer 可能是桥接地址，官方文档也要求使用有效网关密钥。本次只绑定随机环回端口，且服务结束即关闭。

对照本项来源清单、相关查重笔记与实验日志；合成例不是原作者实测。

06 429 后怎样安全切换？

本教学客户端最多尝试两个本地端点：第一个返回 429，第二个返回 200，并记录实际次数。真实网关还应尊重重置时刻、预算、会话粘性和错误类型；不能用轮换账号规避服务条款，也不把限流当余额耗尽。

05 / 从概念走到边界

07 401 为什么不应无脑重试？

认证失败通常需要核对配置与授权，不宜把错误密钥反复发送。教学策略在 401 后立即停，第二桩零请求。Magpie 官方会对多种状态管理账号休息/路由，不能用本例断言其具体实现；本例仅展示一种保守客户端规则。

对照本项来源清单、相关查重笔记与实验日志；合成例不是原作者实测。

08 预算只记 token 够不够？

不够，还需区分输入/输出、缓存、推理、单价、估计与真实账单。脚本只做 100 个合成 token 预算的串行预留，40+50 放行、30 拒绝；不测试真实计费、并发保留或供应商额度。
