Q1

Archify 到底是什么？一句话说清

你把一句话需求（或一个真实仓库）丢给 AI 编程助手，Archify 让它产出一张能点、能搜、能走路径、能导出 PNG/SVG 的交互式图——不是一张死图片，而是一个自包含 HTML 小应用。

它的本体不是传统软件，而是一个 Agent Skill：一个 SKILL.md 说明书 + 一套本地 CLI 校验工具。AI 读完说明书，按规范写一份 JSON，再用 CLI 渲染成交互 HTML。没有服务器、没有账号、没有联网依赖，全部发生在你本机。

Q2

为什么能拿 76k stars？它踩中了什么痛点

画架构图的老三样各有硬伤，Archify 用"AI 生成 + 程序校验"一次全绕开：

工具怎么画痛点
draw.io / Visio手动拖拽慢；系统一改图就烂；无法跟着代码走
Mermaid写文本代码生成样式丑、布局失控、只有静态图不能交互
直接让 AI 画 SVGAI 自由发挥会撒谎：画布外溢出、线穿节点、画出代码里不存在的调用
ArchifyAI 按严格 schema 写 JSON → CLI 校验 → 真浏览器检查美观可控 + 事实可查 + 产物可交互

本质洞见：不让 LLM 自由画坐标，而是让它填一张有类型约束的表，几何由确定性渲染器算——这正是"约束式生成"战胜"自由式生成"的活教材。

Q3

"Agent Skill"形态怎么工作？为什么不用装服务

SKILL.md 只有 107 行，是一个给 AI 看的作业指导书：先选图类型 → 按路由读对应 schema 和示例 → 直接写候选 JSON → 跑 finalize。AI 能力（理解需求、读代码）和程序能力（几何计算、校验）在此分工：

安装也只是一句话：npx skills add tt-a1i/archify -g——把技能包注册给 Claude Code / Cursor / Codex CLI，之后对话里说"用 Archify 画一下……"即可。

Q4

五种图类型：typed JSON（JSON-IR）长什么样

类型用在哪核心字段
architecture系统组件 / 云拓扑 / 安全边界nodes(带 type 语义) + relationships + boundaries
workflow流程 / 审批 / CI-CD / 工具调用lanes(泳道) + nodes + edges（本指南实验用它）
sequenceAPI 调用链 / 请求生命周期participants + messages(带 y 坐标) + activations
dataflow管道 / ETL / 血缘sources → transforms → consumers
lifecycle状态机 / 重试 / 终态states + transitions

关键设计：节点的 type 不是形状而是语义——只能是 frontend / backend / database / cloud / security / messagebus / external 七种（实验 2 实测：填 process 直接被 schema 拒绝）。渲染器按语义上色、定形状、定图例，所以每张图风格一致、颜色即含义。

Q5

finalize 四道门禁：为什么图能"保证不烂"

源码实证（bin/finalize.mjs 第 21 行）：四个阶段是常量 FINALIZE_STAGES = ['validate','deliver','check','browser-check']，全过才发"通过回执"。browser-check 会真的启动 Chrome/Edge 无头渲染产物，不是模拟。AI 的稿件被当成"候选（candidate）"，程序才是终审法官。

Q6

产物是"自包含交互 HTML"——读者能玩什么

  • 缩放分级显示：100% 以下自动降为地图模式，175% 以上露出全部细节（Reading Depth）；
  • Node Finder 搜索：按标签或 ID 找节点并聚焦；Semantic Passport：点节点弹出它的上下游事实卡 + 可复制深链；
  • Route Probe 路径探测：选两个端点，高亮真实有向路径（拒绝几何脑补）；Reach：看某节点的全部上下游可达集；
  • 导出：PNG / JPEG / 双主题 SVG / 带描边动画的 WebM，还有 Route / Reach 分享卡；
  • trace 动画：可选的请求流动画，静态永远是兜底（尊重 prefers-reduced-motion）。

实验 1 实测：官方示例各 744 KB，外部 script/link/img 引用 0 个——发微信、传内网、离线双击全能开，查看方无需装任何东西。

Q7

画真实仓库的图，怎么保证 AI 不撒谎

这是 archify 最"工程狠"的部分（references/repository-authoring.md）：

  • 钉死身份：图必须记录 git rev-parse HEAD 的 40 位 commit SHA + 凭证剥离的 origin URL，写进 meta.repository；
  • 证据锚定：每条"谁调用谁"的关系都要附源码位置（sourceReferences），校验器对照该 commit 的字节验证，工作区未提交的改动不算数；
  • 语义检查：candidate 里可写 semanticChecks（"缓存只在 miss 后才出现"这类断言），交付时逐条核对；
  • 诚实边界：只画读到的切片，禁止为了图好看补一条"看起来该有"的线。

一句话：图和代码之间有据可查，职责声明不构成 I/O 证据——"maintains tasks" 这种注释不能证明真的直接读写文件。

Q9

和自己已知概念怎么连？

  • vs Mermaid：Mermaid 是"文本→静态SVG"，布局算法黑盒不可控；archify 是"类型化 JSON→校验→交互 HTML"，AI 只填内容不碰几何；
  • vs MCP 工具（知识库已有概念）：MCP 给 AI 调用外部能力，Skill 给 AI 注入作业指导书——archify 两者都不占，纯提示词+本地CLI，零服务零账号；
  • vs 让 LLM 直接画 SVG（本仓库 PDF 流水线现状）：LLM 画图坐标误差大、无校验；archify 证明"生成物必须有确定性验收"这条路，其 finalize 门禁思想可以反哺我们 PDF 产出的质量检查环节。
